# Fleet control service joins the composition — optional fleet-server (Fleet-owned root + registered projections)

**Graduated from D#16720 (FM client-side migration delta, body v12 @ 2026-08-08T19:52:47Z; final family-keyed quorum: fable AUTHOR_SIGNAL + APPROVED · Opus APPROVED (re-stamped, blockers verified closed) · GPT [GRADUATION_APPROVED] @ v12, findings closed + defer-closed at filed state).** Matrix Option A — the #16176-inherited phase-2 selection, confirmed by the day's live receipts.

## Context

The cockpit's fleet truth must be served from where the data lives. Today the shell spawns a host-side `devFleetServer` (`ai/services/fleet/devFleetServer.mjs`) that resolves ONE viewer at process boot and reads a host registry which does not exist post-hard-cut (root-cause receipt on #16699); `fleetBridgeServer.mjs` stamps that boot-bound viewer on every request behind one ephemeral local bearer. The composition (`ai/deploy/docker-compose.local-agent-os.yml`) carries chroma/kb/mc/orchestrator/ingress — no fleet service.

**This is an auth/identity boundary change, not a Compose-only relocation** (intake falsifier 1, 2026-08-08): GitHub PATs admitted by `AuthService` are not accepted by the current Fleet guard; the current server cannot simply become the image entrypoint.

## Scope

Add the OPTIONAL `fleet-server` compose service: the same `AuthService` seat kb/mc occupy, serving the fleet wire from inside the composition — with a request-time identity boundary replacing the boot-bound viewer.

### What the current source falsifies

1. **This is an auth/identity boundary change, not a Compose-only relocation.** `devFleetServer.mjs` resolves one viewer at process boot and `fleetBridgeServer.mjs` stamps that viewer on every request behind one ephemeral local bearer. GitHub PATs admitted by `AuthService` are not accepted by that Fleet guard. A composed service therefore needs an explicit request-time `AuthService` → immutable request context / `ownerPrincipal` boundary; the current server cannot simply become the image entrypoint.

2. **The durability AC currently claims stores that do not exist.** Registry/tenant/key material is file-backed, but lifecycle state is process memory and there are no Fleet-owned grant or audit stores in this surface. Registry and tenant also default to checkout-relative `.neo-ai-data/fleet`, while no declarative `AiConfig.fleet.dataDir` member exists. Under ADR 0019, the fixed root must be a resolved entrypoint-owned config member—not a use-site env re-derivation or runtime mutation—and the named volume must cover the keys and ciphertext together.

3. **The ingress wording is mechanically ambiguous and partly false.** Local Caddy is loopback HTTP; cloud Caddy terminates TLS, so “TLS pass-through” is not the current canonical pattern. The wire exact-matches `/fleet` and `/fleet/probe`; a naive `handle_path /fleet/*` would strip the prefix and miss both. Public path, upstream path, header stripping, Host/CORS behavior, and authenticated probe semantics need named rows.

4. **Optionality/readiness is under-specified.** Local product may require the service while headless remains valid, but the exact Compose profile/default activation contract is absent. A hard ingress dependency would make a Fleet-less headless profile invalid. The existing health helper is MCP-specific; TCP-listener health would not prove AuthService admission, served identity, or the fixed Fleet root.

5. **The ADR and phase boundaries are not linked.** #16747 is the carrier that amends ADR 0020/0026 and records the pure-client topology. This leaf must name its merge-order relationship to that decision record.
