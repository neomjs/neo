# Workstation Security pane has a zero-rect FLIP staging frame

## Context

While repairing #16341, the headed Workstation tour advanced beyond its original edge-bottom failure and exposed a later, independent defect twice: the Security pane entered a fixed FLIP stage with one animation frame whose `getBoundingClientRect()` was entirely zero.

The same frame retained the expected Security component/body/header/overflow identity, but no sampled point painted. This is a reproducible observation; the owning sequencing defect is not yet known.

## The Problem

A live pane can briefly become geometry-less during fixed-stage reconciliation. One blank frame is visible in a film and can invalidate geometry consumers even when final state recovers.

## The Architectural Reality

- `DockProjectionReconciler` / `DockFlip` owns fixed-stage geometry and restoration.
- The current monitor observed two stage bursts and exactly one zero-rect frame.
- Component identity survived, so replacing the pane or weakening the oracle would conceal the ordering defect.

## The Fix

First enrich the failing sample with tour beat/caption, stage burst, source/destination, and ancestor rects. Determine whether fixed-stage ownership is applied before rect seeding or whether style/ownership is cleared for one frame, then repair that lifecycle seam.

Do not add a one-frame allowance or screenplay delay.

## Classification + repair (r1) — the enriched sample convicted the seam in one run

Reverse the arithmetic from the installed inverse: `dx = first.left − 300 = −300 ⟹ first.left = 0`; `sx = first.width / 995.797 = 0 ⟹ first.width = 0`. **The First capture was `{0,0,0,0}`.**

**Root cause.** Neither candidate seam in the body holds: class + pins install in one synchronous block, and cleanup restores them in one synchronous block (both frame-atomic, source-verified). The defect is upstream: `captureFirst` records every marker's `getBoundingClientRect()` unconditionally — including a mounted-but-hidden card. The tour's overflow cue mounts Security while `heavy-tabs` keeps `alerts` active (deterministic `display:none` card), so the split's First capture is zero-area. `play()` then classifies that as witnessed mover geometry and installs the degenerate inverse `translate(-last.left, -last.top) scale(0, 0)` — `scale(0)` maps every box point onto the transform-origin, which the translate parks at the viewport origin: the exact all-zero rect. The 1–3 sample variance across runs is how many rAF samples land before the transition interpolation escapes zero; the pre-release install frame always qualifies.

**Repair at the classification seam** (`play()`): an element without presentable First area is an **entering** element — the branch that already existed for `!firstRect` (grow-in at the landing spot, unstaged, no clip crossing to stage). Symmetric same-seam hardening: a zero-area **Last** has nothing to present — no motion, the committed layout owns it (unwitnessed in the tour; unit-pinned). The now-dead zero-guards in the scale math are retired.

**Oracle updates** (`WorkstationNL`): stage-bursts 2 → 1 — the split leg legitimately never stages (a never-presented card enters); new pin `securityEnterMotionFrames > 0` (the grow-in must present, unstaged); the enriched sample payload stays as permanent diagnostics.
