**Cause identified — and the fix is already open and green.**

The 20 consecutive failures are **not** a credential or CodeQL problem. From [run 30971652217](https://github.com/neomjs/neo/actions/runs/30971652217), 550 log lines above the reported failure:

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'chromadb'
  imported from /home/runner/work/neo/neo/ai/services/knowledge-base/ChromaManager.mjs
```

`dev` today: `syncGithubWorkflow.mjs` line 1 is `import {GH_Config, GH_SyncService} from '../../services.mjs'` — the barrel, which eagerly loads `ChromaManager.mjs` → `chromadb`, a Brain-tier package absent from the CI install tier.

**PR #16496 (`#16495`) is exactly this fix** and imports both symbols directly, bypassing the barrel. It is 11/11 green and MERGEABLE, blocked only on a cross-family review seat.

**Two things in that log are misdirection, not cause:**

1. `failed under declared credential scope \`reader\`` — the annotation is prepended to *every* stage failure regardless of class, so a packaging error reads as an auth error. Filed as #16530, fixed in PR #16531.
2. `Bypassed rule violations … Code scanning is waiting for results from CodeQL` — **the push succeeded.** Those lines are informational. Ruleset `19087298` ("code scanning merge protection") targets `~DEFAULT_BRANCH` with `code_scanning` + `required_status_checks` and `bypass_actors: []`; hourly corpus commits carry `[skip ci]`, so those checks never run and can never report. Structural since the ruleset's 2026-07-17 creation, not a new regression, and repo-security configuration rather than code.

This alarm stays open until a run goes green — it is auto-maintained and is not the close target for any of the three PRs above.

* fix(ci): the Data Sync failure lead states the observed class, not a credential cause it cannot know (#16530)

Twenty consecutive pipeline runs failed on:

  Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'chromadb'
    imported from ai/services/knowledge-base/ChromaManager.mjs

while the operator-visible last line said:

  stage "GitHub Workflow corpus" failed under declared credential scope `reader`.
  If this is an authentication failure, the stage requires a scope that grants it

Not an authentication failure. A packaging one. The real error sat 550 log lines
earlier, and the annotation — being last — is the line a reader actually sees.

The annotation was prepended to EVERY stage failure unconditionally. Its original
reasoning is sound and is preserved in-source: a bare child failure reads as "the
tool is broken" when the finding is "this stage was granted `none` and needs a
credential", and a child's own missing-auth message can advise an interactive login
CI cannot perform. But it knows the SCOPE, not the CAUSE, and stating one as the
other produced the mirror-image defect.

The `If this is an authentication failure` hedge is technically honest and
operationally useless: it is only readable by someone who already has the answer.

So classify first. `classifyStageFailure` reads the child's own error:

  ERR_MODULE_NOT_FOUND / MODULE_NOT_FOUND  -> dependency
  ENOENT                                    -> entrypoint
  401/403/credentials/unauthorized/...      -> authentication
  anything else                             -> unrecognized, stated AS unrecognized

Order is load-bearing: module resolution is checked before the auth heuristic,
because an auth-shaped substring ("permission") can appear inside an unrelated stack
trace while ERR_MODULE_NOT_FOUND is unambiguous. Covered by its own witness.

The declared scope is still reported in every case — it is real context — it just no
longer LEADS with a hypothesis it cannot support.

Deliberately still not a per-stage `requiresCredential` flag. That was rejected in
the original design because it is a second hand-maintained declaration beside
`tokenScope`, free to drift. Classification derived from the observed error keeps
exactly that property.

The landed spec asserting the old wording is updated, not deleted: its stated intent
was "the annotation must carry BOTH the stage label and its declared scope", and that
still holds — only the regex had hardened around the old sentence. It now also
asserts a generic child error is reported as UNRECOGNIZED rather than as a credential
cause.

RED proven: restoring the unconditional credential framing fails the dependency
witness on the exact misleading string. The authentication case keeps its original
guidance, so the failure mode the annotation was built for does not regress.
