# Sandman Handoff Pre-Flight Workflow

At the very beginning of a newly booted session, before executing any workflow skills, you MUST read the runtime artifact `resources/content/sandman_handoff.md` and apply the predicate below.

## Fail-Open / Fail-Closed Semantics

The `sandman_handoff.md` file is `.gitignored` (line 130 of `.gitignore`); it is a runtime artifact generated by the `runSandman` daemon, NOT a tracked substrate. Three empirical states the predicate handles:

- **File missing entirely** (fresh clone; never-ran-`runSandman`): **fail-open** — proceed normally
- **File exists but no `lane-state` section**: **fail-open** — proceed normally
- **File exists with unknown `lane-state` value** (not in known-enum): **fail-closed** — halt + notify operator

## Hard-Refusal Predicate

If the `lane-state` is `AWAITING_REVIEW`, `AWAITING_HUMAN`, or any unknown value (per fail-closed rule above), you MUST halt execution of new-work intake.

## Scope Boundary

The predicate blocks explicitly:

- New ticket intake (`/ticket-intake` skill activation on a new ticket)
- Opening new PRs (`/pull-request` skill activation for new PR creation)
- Starting new substrate-evolution work (`/ideation-sandbox` Discussion authoring, new skill authoring, etc.)

The predicate does NOT block:

- Cycle N reviews of existing PRs (`/pr-review` on already-open PRs)
- A2A coordination (mailbox check + handoff messages)
- Memory-mining (Memory Core queries)
- Directly responding to operator directives

## Operator Notification

When halting, you MUST:

1. Explicitly log/state the blocked state to the human operator in your response
2. Await their explicit override before proceeding with blocked work

## Cross-Skill Composition

- **Substrate-creation discipline (separate lifecycle phase)**: `/turn-memory-pre-flight` (Epic #11256 substrate) fires on substrate-mutation, NOT session-boot. The two pre-flights compose at different agent-lifecycle phases.
- **PR creation gate**: `/pull-request` skill should verify this pre-flight passed before creating new PRs (downstream consumer).
- **Ticket intake gate**: `/ticket-intake` skill should verify this pre-flight passed before claiming new tickets (downstream consumer).
