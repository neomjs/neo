Resolves #17023

Related: #17018

Delivers AC-C of the provider-lanes epic: one durable election authority now commits coordinated vector-plane generations. The record gates PROMOTES, not reads — per-collection shadow builds stay independent on their existing primitives, and a generation becomes visible only through the two promote seams, each of which passes a stale-writer fence immediately before its renames. An uncommitted election therefore never advertises, a partially-promoted election cannot be accepted, and rollback restores the full prior set by construction.

Evidence: L3 (store-level fixtures prove the mid-promotion halt, rollback restore, and mixed-generation fences; both seams wired; 123 targeted unit greens at this head) → L4 required (one canonical-scale ~104k-row rebuild through this record). Residual: AC-E canonical run + the temporal-summary promote seam + the cutover baseline declaration, Residual-Owner: #17025.

## What ships

- **`ai/services/shared/vector/generationElectionStore.mjs`** — the plane-singleton durable election record. Lifecycle `accepted → candidate → committed → accepted`, with `rolled-back` as the abort arm; the epoch increments ONLY on visibility flips (commit, rollback). One fence rule for every status: the promoting writer's generation must be the ELECTED one at the CURRENT epoch. Fail-safe polarity: a missing record grandfathers legacy planes; a corrupt or tampered record (derived-hash consistency validation) refuses promotes while readers stay untouched. Commit refuses until every census collection carries a validation receipt; acceptance refuses until every collection reports its promote and only then retires the parked rollback authority; a rolled-back plane refuses the next candidate until every collection reports its un-park.
- **Generation identity** — the full seven-coordinate tuple (provider, model, quantization, vectorDimension, pooling, distance, strategyVersion) stored verbatim with two derived hashes: the election `generationId` over the complete tuple, and the four-coordinate `embeddingGenerationId` join key whose ONE implementation moved here from `kbEmbeddingPoisonStore` (which now re-exports it) — the same tuple can never hash differently in the two stores.
- **KB promote seam** — `VectorService.embedViaShadowSwap` captures the election view BEFORE any shadow work and passes `assertCapturedPromoteView` immediately before its live→parking / shadow→canonical renames; completion is recorded after a committed-transition promote, and a lost completion mark only blocks acceptance (never unwinds a successful promote).
- **MC promote seam** — `restoreTargetSetStorage` takes an entrypoint-resolved `electionDir`, captures ONE view per restore run (two role promotes can never split one run across generations), fences each vector-role promote (`memories → mc.memory`, `summaries → mc.session`), and reports completion per collection. The graph component is SQLite, deliberately outside the vector election; the Orchestrator call site resolves the dir from its per-server config.
- **Health surfaces** — KB and MC healthchecks report `vectorGeneration` (elected + parked identities, per-collection validated/promoted/unparked state) beside their observed plane identity; `missing` on a plane that never declared an election, never a throw.
- **Shared-mount invariant** — the record resolves beneath the resolved `plane.dataRoot`, the one anchor every KB/MC process of a plane already shares; the subpath constant lives with the store so two entrypoints cannot drift it. No new config leaf, no AiConfig import outside entrypoints.

## Deltas from ticket

- The fence gained a seam-facing captured-view form (`captureVectorPromoteView` → `assertCapturedPromoteView`): the view is captured before the build and validated at the promote moment, which additionally fences an election declared mid-build on a previously-legacy plane — a case the ticket's raw (generationId, epoch) sketch could not express.
- The four-coordinate `embeddingGenerationId` implementation moved from `kbEmbeddingPoisonStore` into the election store (re-exported for existing importers) instead of shared code importing knowledge-base internals — one id-space, layering-correct direction.
- The MC restore's graph component is deliberately OUTSIDE the vector election (SQLite, not an embedding collection), and the temporal-summary collection has no restore seam today — its promote path ships with the AC-E rebuild runner rather than as a speculative hook here.
- A completion-mark failure after successful renames logs and continues: it only keeps acceptance blocked (rollback authority retained) — a promote is never unwound for bookkeeping.

## Contract Ledger

| Producer | Consumer | Contract | Failure semantics |
|---|---|---|---|
| `createVectorGenerationIdentity` | election record, rebuild runner, poison store (join key) | complete seven-coordinate tuple; any change = new generation | invalid/missing coordinates throw; a tampered stored identity fails derived-hash validation and the record reads unprovable |
| election record | both promote seams | promote admissible only when the writer view is the elected generation at the current epoch | a stale or mismatched writer throws before any rename; a corrupt record refuses promotes while readers stay unaffected |
| per-collection validation receipts | `commitVectorGenerationElection` | all census collections validated before any visibility flip | a missing receipt refuses the commit |
| promote/un-park completion marks | `acceptVectorGenerationElection` / next `declareCandidateVectorGeneration` | full-set semantics before authority transfer | a partial promotion cannot be accepted; a partial un-park refuses the next candidate |
| `projectVectorGenerationHealth` | KB/MC healthcheck payloads, cutover acceptance | elected + parked identities + per-collection state | `missing`/`unavailable` reported as status, never a throw |

Ledger rows mirror epic #17018 AC-C; the originating ticket carries the same contract in its Fix section.
