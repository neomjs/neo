# AgentCard: render the contracted State line + give StateDot an accessible name (D2 ruling)

## Context

Implementing leaf for the **D2 design ruling** on epic #14805 ([ruling](https://github.com/neomjs/neo/issues/14805#issuecomment-5012476050)) — the last of the three design-authority items (#15493/D4 and #15500/D3 shipped). Origin: `#14619`'s audit, re-derived from source before ruling.

## The Problem

Session state reaches the operator by **hue alone**, which WCAG 2.1 **1.4.1 (Use of Color, Level A)** forbids as a sole visual carrier:

- `StateDot.mjs` renders no text, `title`, or `aria-label` — it only swaps a state class.
- `StateDot.scss` gives all seven states **identical geometry** (8px circle); only `--fm-dot` differs.
- `AgentCard.applyRecord` sets **only** the dot (`getReference('state-dot').set({live, state})`) — no state text anywhere in the card or its SCSS.

And the pulse cannot carry the signal: `TOKENS.md:41-43` is correct that the reduced-motion property holds *because* the pulse conveys nothing unique. Re-loading signal there would trade a 1.4.1 failure for a reduced-motion failure.

## The Architectural Reality

The missing channel is **already specified** and simply was never built — `CARD-CONTRACT.md:13`:

> **State line** (mock: "▲ WORKING") | `lifecycle.state` (+ `confidence`) | mono, state-colored; renders the DTO's literal state vocabulary

And the vocabulary resolver already exists: **`stateLabel(state)`**, exported from `HealthSwatch.mjs` alongside the `stateClass` that `StateDot` already imports. `HealthSwatch` proves the pattern in-tree (same class + visible text); `HealthBar` inherits it by composition and is already compliant. The card is the surface that skipped it.

So this is a **conformance gap against a contract we already wrote**, not a new design.

## The Fix

1. Render the contracted **State line** on `AgentCard`, adjacent to the dot, consuming **`stateLabel(state)`** — never a second vocabulary.
2. Give `StateDot` an **accessible name** from the same `stateLabel`. This is 4.1.2 / 1.1.1 — a *separate* criterion. It must not be treated as satisfying 1.4.1: an `aria-label` does nothing for a sighted operator who cannot separate hues. Both are required.
3. Do **not** add shape/glyph-per-state as the primary channel (ruled out: seven distinguishable glyphs in an 8px dot is a legibility problem dressed as an accessibility fix, and it forks the vocabulary). Shape may later reinforce text.

## Acceptance Criteria

- [ ] `AgentCard` renders the DTO's literal state vocabulary as text beside the dot; state is legible with colour removed (greyscale check).
- [ ] Text comes from `stateLabel(state)` — no second state→text mapping introduced.
- [ ] `StateDot` exposes an accessible name from the same resolver.
- [ ] `AgentDetail`'s dot (`:192`) covered by the same reasoning or explicitly scoped out with rationale.
- [ ] Card density holds at the measured fleet density — the design judgement this leaf owns (the SSOT mock places a state line; confirm it reads at real row counts).
- [ ] `CARD-CONTRACT.md`'s conformance checklist reflects the now-implemented State line.

### @neo-opus-grace - 2026-07-18T19:05:55Z

## Implementation spec (design-authority): place the state label beside the dot, not as a separate line

Read `AgentCard`'s vdom to shape this before it's built. The card's own structure makes the placement a real decision, not a mechanical one, so I'm making it here as the D2 authority — so implementation confirms visually rather than decides blind.

### The tension

`CARD-CONTRACT.md:13` specifies a **State line** (*mock "▲ WORKING"*, its own element). But the card is density-governed by construction — its comments are explicit: *"the density contract buys card pixels with exceptions,"* and the lane-row already spends its vertical budget on current-lane + count badge + telltale. Adding a *separate* full-width line for a single state word (`working` / `idle` / `rate-limited` / …) spends a scarce row on low-information-density text.

### The decision

**Render the state label inline, immediately after the `StateDot` in the name-row** — `[dot] [label] [name button] [provenance] [engine]` — rather than as a separate line. Reasons, in priority order:

1. **Strongest 1.4.1 resolution.** The whole failure is that colour is the sole carrier. Placing the text *adjacent to the dot* pairs the two channels at the same glance — the operator reads `● working` as one unit, so the hue is reinforced exactly where it's used. A state line two rows down is a weaker pairing.
2. **Lowest density cost** — one short mono word in an existing row, versus a new row the density contract can't easily afford at 7–17 lanes.
3. **Contract intent satisfied.** `CARD-CONTRACT.md:13`'s intent is *"renders the DTO's literal state vocabulary"* — the adjacent label delivers that; "line" was the mock's layout, not the requirement. Update the field table to record that the state line collapses into the name-row dot-label pair for density, with the conformance checklist gaining a `state-text-present` item.

### Wiring (mechanical, unit-coverable)

- Add a `component` (`fm-card-state`, mono, `flex: none`, `reference: 'card-state'`) right after the `state-dot` in the name-row.
- In `applyRecord`, alongside the existing `getReference('state-dot').set({live, state})`, set `getReference('card-state').text = stateLabel(displayState)` — reusing the resolver now colocated in `StateDot.mjs` (#15516/PR #15515). No second vocabulary.
- State-colour the text via the existing `fm-state-*` class token, not a literal — it may share the dot's colour binding so text and dot cannot disagree.

### What genuinely needs the render (not fakeable at spec time)

- **Greyscale legibility:** confirm the label reads state with colour removed (the actual 1.4.1 acceptance).
- **Density at real row counts:** confirm the name-row doesn't wrap or truncate the name at 7–17-lane density on a narrow card; if it does, the fallback is a `title`-truncated label or a state *glyph* + text, decided against the render.
- **`AgentDetail`'s dot** (`:192`): same treatment or an explicit scope-out.

This is the half of #15512 that's design work, not typing — so it stays here with the density judgement, and the wiring above lands with a unit spec (text present, follows state, unknown-state stays literal per the #15516 resolver contract) plus operator visual validation for the two render-gated ACs.
