# Enforcement-plane custody for the repo split

Graduated from [Discussion #17780](https://github.com/orgs/neomjs/discussions/17780) at §6.2 family-keyed quorum: Claude-family `[AUTHOR_SIGNAL]` + non-author GPT-family `[GRADUATION_APPROVED by @neo-gpt-emmy @ discussioncomment-18153699 / rev-4 body 2026-08-25T21:07:05Z]` ([approval](https://github.com/orgs/neomjs/discussions/17780#discussioncomment-18153737), superseding her earlier DEFERRED). ## The Problem

Enforcement custody in `neo` is distributed by author-location, not subject, and the split makes that fail three measured ways on cut day:

1. **Leaving teeth (fails loud):** `.husky/pre-push:16` — guard 2 of 3 under `set -e` — invokes `ai/scripts/lint/check-commit-authorship.mjs`, a Brain executable that leaves; every Engine push then dies mid-chain, reading as "my push is broken". Eight org-generic workflows share the pattern.
2. **Inverse straddles (police ghosts):** stay-side teeth guarding leaving subjects (`aiconfig-antipattern-lint`, `aiconfig-test-mutation-lint`, `atomic-write-shape-lint`) — silently green forever after the subject departs.
3. **Trigger starvation (silently never runs):** `pull_request` path filters watching `ai/**` never match post-move — the workflow stops running, and the absence of a run is not a red.

And the deepest finding: **a green workflow gates nothing** — live `dev` requires exactly ONE status context (`integration-parity`, App integration 15368) out of 44 workflows. Enforcement is two artifacts: the check and the binding that makes it required. Binding state (rulesets, required contexts, bypass actors, Actions policies) is mutable outside Git.

The coupling grows while unaddressed: 19 files/69 `ai/scripts` refs at #17500's filing → 20/75 (`32cc4b76d7`) → 20/73 (`467fd122f3`). **45% of the workflow tree (20/44) carries Brain-coupled teeth.**

## The Architectural Reality

The graduated custody contract: every guard names `{subject, teeth, trigger, witness, binding}` — trigger records event + path-filter reach; binding carries a read-back receipt plus revalidation triggers (plan, ruleset, visibility, required-context identity). The full unique-row census (44 workflows, twice independently measured) lives in the Discussion body's **Census v2.1** and is this ticket's migration map. Org plan tier is **Free** (operator-confirmed + live API): org rulesets/required workflows are unavailable; repo-level rulesets on public repos are available (two live today). Private repos are out of binding scope by operator disposition.

## The Fix (adopted at convergence — ED1+ED2 · EB1 · F1)

1. **Delivery seat (ED1+ED2 composition):** org-generic workflow LOGIC lives in `neomjs/.github` reusable workflows (repo to be created — operator provisioning); ONE near-static aggregated caller per enrolled repo rides the synced substrate bundle (committed, fork-visible), per D#17756's distribution mechanism.
2. **Binding seat (EB1):** per-repo rulesets/branch protection, registry-driven, receipt-verified. EB2 (GitHub App) held as revalidation alternative; EB3 rejected `current-plan-infeasible`, reopens on plan upgrade.
3. **Hooks (F1):** hooks reference only same-repo stay-side scripts. `check-commit-authorship.mjs` **relocates to `buildScripts/util/`** (sibling precedent: guards 1 and 3 already live there — structural fast-path).
4. **Fissions:** `test.yml` splits along its existing `run_integration`/`run_parity` classifier seam (integration→Brain, parity/e2e→Engine); `retry-bound-classification-lint` fissions or gains a shared owner (cross-plane watcher); `engine-brain-boundary-lint` fissions into two one-sided guards (Engine: no Brain-internal imports beyond the published package contract; Brain: inverse).
5. **Registry:** ONE canonical org registry owns repository identity/enrollment/lifecycle (52-repo org measured: 44 public + 8 private, 4 forks); this ticket derives enforcement targets from it; D#17756's C5 derives task-local `RepoContext`s from the same schema/parser/key — distinct artifacts, no duplicated fields (Euclid's OQ8 ruling, [comment 18153626](https://github.com/orgs/neomjs/discussions/17780#discussioncomment-18153626)).

## AC-10 evidence: the org Actions policy gates NOTHING — all four admin reads recorded

Operator ran the four reads from an admin seat (2026-08-25, in-session). Verbatim results:

| read | result |
|---|---|
| `orgs/neomjs/actions/permissions` | `enabled_repositories: all` · `allowed_actions: all` · `sha_pinning_required: false` |
| `orgs/neomjs/actions/permissions/workflow` | `default_workflow_permissions: write` · `can_approve_pull_request_reviews: true` |
| `repos/neomjs/neo/actions/permissions/workflow` | `write` · `can_approve_pull_request_reviews: true` |
| `repos/neomjs/neo-agent-skills/actions/permissions` | `enabled: true` · `allowed_actions: all` |

**Dispositions:**

1. **ED2 is policy-clear by rule, not just by mechanism.** Bot PRs modifying `.github/workflows/**` face no org Actions restriction (Eos's live `workflow`-scope receipts already proved the mechanism; this closes the by-rule half). **ED2's caller-sync posture needs NO adjustment.**
2. **ED1 is unconditionally viable:** `allowed_actions: all` means reusable workflows from `neomjs/.github` are callable everywhere with zero allowlist maintenance; the fresh `neo-agent-skills` repo inherited the same baseline.
3. **`can_approve_pull_request_reviews: true` org-wide** — Actions MAY approve PRs. Noted for the sync-PR flow design: GitHub permits auto-approval; whether sync PRs get it remains OUR review-discipline decision (cross-family review is a Neo institution, not a GitHub setting), decided at implementation.
4. **Deliberate current-state, recorded not prescribed:** `allowed_actions: all` + default-write tokens + approve-capable Actions is the maximally permissive posture — consistent with the current trust model (every writer is the team). The binding receipts this ticket ships (AC-6) are the guardrail layer that matters; `sha_pinning_required: false` is a future hardening candidate for the registry docs' security notes, nothing more.

These values move into the registry docs verbatim when AC-8's registry lands; this comment is the interim evidence holder. **AC-10's read is complete — the AC closes with the PR that copies these into the registry.**
