# Rows embedded before the provider-header fix keep their stale vectors, and no signal can find them

## Context

Filed on @neo-gpt's Required Action 3 against PR #17426 ([review](https://github.com/neomjs/neo/pull/17426#pullrequestreview-4985542188)): *"give existing corrupted rows a concrete owner… The parent epic alone is not an executable residual."* He was right — the residual on #17425 pointed at epic #17411, which had no child for this.

#17425 corrected the provider-input header: `buildEmbeddingInputHeader` read `chunk.type`, the published `parsed-chunk-v1` schema requires `kind` and declares no `type`, so every chunk from a schema-conforming parser embedded behind the literal token `undefined`. That fix is forward-only by construction.

Live latest-open sweep: checked latest 20 open issues at 2026-08-20T17:31Z; A2A claim sweep over the current window; no equivalent found.

## The Problem

**The affected rows are invisible to every existing signal, and the reason is structural rather than an oversight.**

1. **Their chunk ids did not change.** `createChunkHash` folds only the `hashInputs` field list (`['kind','name','content','sourcePath','parserId','parserVersion']`, `IngestionService.mjs:990`). The provider input string is *derived* and is not a member, so re-ingestion computes the same id, finds the row present, and does no work.
2. **The provider input is not stored.** `collection.upsert` writes `{ids, embeddings, metadatas}` — there is no `documents` field, so the stale text is not on disk to be pattern-matched.
3. **Metadata cannot date them.** `buildChunkMetadata` copies every chunk field, so an affected row carries `kind` and no `type` — but so does a row embedded *after* the fix. The metadata identifies the affected **population**, never which members are stale.

So the symptom is: a bounded set of rows whose vectors were computed from a string beginning with a meaningless token, indistinguishable from correct rows by id, content, or metadata.

## The Architectural Reality

**The guaranteed trigger already exists, and its docblock describes exactly this case.**

`ai/services/shared/vector/generationElectionStore.mjs:7` — *"…strategy) invalidates every existing vector. Per-collection shadow builds may proceed…"*. `createVectorGenerationIdentity` (`:196`) takes `strategyVersion` as a coordinate, and any coordinate change yields a new `generationId`.

`strategyVersion` resolves from `resolveEmbeddingInputStrategyVersion` (`VectorService.mjs:570`), anchored on:

```js
const EMBEDDING_POISON_STRATEGY_FAMILY = 'kb-embedding-input-v1';
```

whose own comment states the contract: *"It bumps when the input strategy changes **shape** — a different splitting algorithm, a different estimate space — which no measurement can infer."*

A header-format change is an input-strategy shape change. The lever is a one-token edit.

## ⚠️ The decision this ticket exists to escalate, not to make

The lever is global and the damage is partial.

| option | cost | correctness |
|---|---|---|
| **Bump `kb-embedding-input-v1` → `v2`** | invalidates **every** vector in **every** collection — a full corpus rebuild on every plane, including neo's own | complete, mechanical, uses shipped substrate, no new detector |
| **Targeted re-embed of affected rows** | compute proportional to the affected set only | **needs a detector that does not exist** — see The Problem; nothing on disk distinguishes stale from fresh within the affected population |

Neo's own corpus was never affected (all three in-repo parsers emit `type`), so a global bump rebuilds a large correct corpus to repair a smaller broken one. On an external tenant plane that is real compute the deployment owner pays for, on a lane already measured at ~0.19 chunks/min.

**This is a cost/authority fork, not a technical one**, and per the escalation ladder it belongs with the operator rather than decided inside a leaf. Both branches are implementable; what is unresolved is which cost the deployment should bear.

## Decision Record impact

`none` for the repair itself. If the global branch is chosen, the bump is an exercise of `generationElectionStore`'s existing declared contract rather than a change to it.

## Acceptance Criteria

- [ ] **The fork is resolved by the operator, on the record, before any implementation.** Which cost the deployment bears is not an agent decision, and neither branch may be started on assumption.
- [ ] **RED-PROOF for whichever branch is chosen.** Global: a fixture asserts that a `strategyVersion` change yields a different `generationId` and that the prior generation is no longer elected. Targeted: a fixture asserts the detector selects an affected row and rejects a fresh one with the *same* metadata — which is the requirement that currently has no implementation, and if it cannot be met the targeted branch is refuted rather than deferred.
- [ ] **Neo's own corpus is accounted for explicitly.** Its headers never changed; a repair that rebuilds it must say so as a cost, and one that skips it must prove the skip is safe.
- [ ] **The affected population is counted before and after**, per tenant, so "repaired" is a measurement rather than an inference.
- [ ] **No silent partial repair.** If a run repairs some rows and stops, the remainder is reported with its count; a partial rebuild that reads as complete is the failure mode this whole lane keeps hitting.

## Out of Scope

- The header fix itself — shipped in #17425 / PR #17426, forward-only by construction.
- Adding the provider input string to `hashInputs`. It would make future format changes self-repairing and it would also re-mint every chunk id in existence; that is a larger contract change with its own blast radius.
- Storing `documents` in Chroma to make the text inspectable. Same class: a storage-shape change proposed to serve one migration.

## Avoided Traps

- **Reading "repair naturally on the next `parserVersion` advance" as a plan.** `parserVersion` *is* a hash input, so an advance does re-mint ids and re-embed — but nothing schedules one. That sentence was in PR #17426's body and it was a hope with no trigger; the review was right to reject it.
- **Assuming the stale rows are findable.** They are not, by any of id, content, or metadata, and the targeted branch stands or falls on that.
- **Bumping the strategy family because it is one token.** The edit is small and its consequence is every vector on every plane.
