# Tear-out popup flashes white between route admission and theme bootstrap

## Context

The full #15252 Take 17 native corpus closes #15955's previously untested popup-birth surface. A visible white flash occurs while the tear-out popup is created mid-gesture.

The frame sequence and source falsify the obvious diagnosis: the staged `about:blank` window is not the white frame. The flash belongs to the final document's pre-theme bootstrap interval.

## Measured Failure

A 50 ms probe series over native media SHA-256 `8771781bca0cd33d8c836804d023c37214132d362074c35d195959358a3a9667` shows:

| Time | Popup URL / state | Visible content |
|---|---|---|
| `6.15s` | `about:blank` | dark neutral canvas |
| `6.20s` | `about:blank` / navigation beginning | white canvas |
| `6.25s` | final Workstation URL visible | white canvas |
| `6.30s` | final Workstation URL visible | white canvas |
| `6.35s` | final Workstation URL | themed live pane |

The interval is therefore approximately 150–200 ms in this take and is visible inside the continuous product gesture.

## Mechanism

`src/Main.mjs#windowOpen()` intentionally:

1. opens same-origin children at `about:blank`;
2. writes a one-use native-route token into the blank realm's `sessionStorage`;
3. calls `location.replace(stagedUrl)`.

That ordering was introduced by #15396 / PR #15573 because direct-opening the final URL can let a warm shared-worker child call `getWindowData()` before route authority exists.

The final `apps/workstation/index.html` has no early paint declaration. It starts `MicroLoader.mjs`; the loader imports `neo-config.json`, boots Main, and only then does the `Stylesheet` addon apply the first theme and append asynchronous CSS links. Workstation's configuration is dark-first, so its final document has a visible navigation-to-dark-theme interval whose default canvas is white.

The HTML Standard defines `<meta name="color-scheme">` specifically so a user agent can render the page background in the intended scheme immediately rather than wait for CSS. CSS Color Adjustment defines the root scheme as affecting the canvas surface color. This is the narrowest first implementation to test because it declares canvas polarity without duplicating Neo's palette.

- [HTML Standard: `color-scheme` metadata](https://html.spec.whatwg.org/multipage/semantics.html#meta-color-scheme)
- [CSS Color Adjustment: effects of the used color scheme](https://drafts.csswg.org/css-color-adjust/#color-scheme-effect)

This is a new #15955 class: **navigation/bootstrap canvas gap**. It is neither style-delta frame splitting nor dock add/remove churn.

## Proposed Fix

1. Add exactly one `<meta name="color-scheme" content="dark">` in Workstation's `<head>`, before `MicroLoader`.
2. Re-run the headed retained-frame witness across both the staged blank and final-document bootstrap intervals.
3. Only if a visible dark-to-dark step remains, add the smallest Workstation-local inline canvas background fallback and mechanically bind/validate its literal against the canonical dark token.
4. Keep theme generation/generalization out of the first repair. Promote the pattern only after this local native proof; generation alone cannot prevent later HTML/config drift.

## Architectural Requirements

- Preserve the staged same-origin route-token sequence. Direct-opening the final URL is not an acceptable visual shortcut.
- Keep the declaration Workstation-local: its configured bootstrap is dark-first; light-first apps must not be forced dark.
- Keep the early declaration minimal and declarative. Do not create a parallel app skin or copy a large SCSS surface into HTML.
- If a literal fallback color becomes necessary, mechanically bind or validate it against the default theme so it cannot drift silently.

## Acceptance Criteria

- [ ] `apps/workstation/index.html` contains exactly one valid `<meta name="color-scheme" content="dark">` in `<head>` before `MicroLoader`.
- [ ] In a headed native popup witness, every retained frame from first visible popup canvas through first themed pane avoids a white/full-luma excursion for Workstation's dark-first boot.
- [ ] The witness distinguishes the staged `about:blank` interval from the final-document pre-theme interval and covers both.
- [ ] The dark-first result holds when the host prefers light; an independently controlled light-first fixture remains light when the host prefers dark.
- [ ] Mutation control: removing the final-document meta restores the white excursion.
- [ ] Negative control: styling only the staged `about:blank` still leaves the final-document witness white.
- [ ] The same-origin native-route token is written before navigation and consumed once by the correct child; every #15573 authority-ordering and failure-path test remains green.
- [ ] Workstation's later dark-to-light theme toggle remains correct.
- [ ] The full five-beat Workstation journey remains green, including popup birth, conversion, docking, and reintegration.
- [ ] No inline palette literal is added unless the meta-only retained-frame witness fails. If a fallback is required, mutating either it or the canonical SCSS token fails a drift guard.
- [ ] #15955 records this as a confirmed third class with the native frame timestamps and this repair leaf.

## Avoided Traps

- Styling only `about:blank`: the measured blank frame is already dark; the white frames continue after the final URL appears.
- `MicroLoader`, `Neo.overwrites`, or `Stylesheet` repairs: all occur too late to guarantee the final document's first canvas.
- Removing route staging or direct-opening the final URL: reopens the authority-less-popup race fixed by #15573.
- `document.write` or a synthetic boot document: unnecessarily takes ownership of navigation, CSP, base URL, caching, and failure semantics.
- `<meta name="theme-color">`: it addresses browser UI, not the document canvas.
- `content="dark light"` for fixed dark-first Workstation boot: an opposite host preference can select light.
- Calling the flash a recorder artifact: it is a physical popup surface inside the live product gesture and is source-correlated.
- Hiding it in the edit: the video is the activation witness, not the place to conceal a product defect.
