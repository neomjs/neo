# Dock demo: wire undo/redo transactions around dock mutations + spec

## Context

The operator's 2026-08-02 flagship-film brief (90–150s, heavy drag-and-drop) names **undo/redo** as a film beat — heavy drag-and-dock mutations, then reverting them live. Fable's lane map on #15252 (issuecomment-5153855472) scoped L3 = "undo/redo wiring — dashboard transaction machinery exists; workstation surface + a deterministic spec beat needed," the natural sibling of L2. @neo-kimi-phoebe claimed L2+L3 at 2026-08-01T23:15:25Z (A2A `MESSAGE:c278901d-fdf1-4524-b275-c6ddfff83f24`). Budget clock: the Fable family may go dark within 2–3 days — every artifact lands durably same-turn.

## The Problem

**Zero transaction wiring exists anywhere in `apps/agentos/` today** (grep receipt, 2026-08-01: no `beginTransaction` / `commitTransaction` / `undo(` / `redo(` / `saveTransaction` / `replayTransaction` call sites). The machinery exists, but nothing in the demo surface drives it — so the film cannot show undo/redo and no spec witnesses it.

What exists (verified this session):

- `Neo.ai.TransactionService` — `src/ai/TransactionService.mjs:95` — app-worker-side named transactions: begin / commit / abort, per-session undo & redo stacks, audit labels (`list_transactions` summarizes `{txId, status, opCount, labels}` from `stackOf`)
- NL tools: `begin_transaction`, `commit_transaction`, `abort_transaction`, `undo`, `redo`, `list_transactions`, `save_transaction`, `replay_transaction` (batch tools write-locked; `list_transactions` read-tier)
- `recordUndo` routes operations into an open named batch, accumulating them as one undoable unit; a new commit clears the redo branch

## The Architectural Reality

- The film beat: heavy drag-and-dock mutations on the workstation (dock moves, tear-outs) wrapped in one named transaction, then `undo` restoring the prior dock state live — the "it can UNDO that?" moment
- Transactions are per App Worker session; the demo app boots on a SharedWorker, so cross-window mutations land on one heap — one transaction boundary can span windows (verify at intake)
- The deterministic drive path for film + spec is the NL tool chain, not ad-hoc UI clicking

## The Fix

1. **Verify the live path** (headed + GPU receipts only): NL `begin_transaction` → dock mutations (drag / tear-out via existing cues or NL dock operations) → `commit_transaction` → `undo` → assert dock topology restored → `redo`. Paste the receipt on this ticket.
2. **Wire the demo surface minimally** so the beat is filmable: a tour cue set (e.g. `transaction-wrap` / `undo` / `redo`) or a workspace-level binding that wraps a scripted mutation burst into one named batch. Smallest change in `apps/agentos/childapps/dockdemo` + `apps/agentos/tour`.
3. **Spec beat**: deterministic whitebox-e2e witness (sibling pattern: existing `test/playwright/e2e/agentos/*NL.spec.mjs`) asserting that undo restores the pre-transaction dock document (dockZone.v1 equality or reconciler-level verdict) and that redo re-applies it.
4. **Handoff**: filmable cue sequence posted as a comment on #15252 same-turn.
