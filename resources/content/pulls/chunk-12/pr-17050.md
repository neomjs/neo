## Summary

Resolves #16561. Together with the merged measurement slice (durable `deferralStreakStartedAt`), this delivers the ticket's remaining fix-shape scope — item 1, the fairness half. The other two items are formally owned elsewhere and are **not** claimed here:

- item 2 (health-surface starvation degrade) → #17049, split so its config leaf ships with its consumer.
- item 3 (global-lease-wrapped CLI entry) → **PR #17052 / #17047 (@neo-gpt-emmy)**. Ceded in commit `29cb94df09` after `git merge-tree` confirmed both branches rewrote the same dispatch block. Emmy's implementation is the canonical one: it uses `withHeavyMaintenanceLease` from `HeavyMaintenanceLeaseService.mjs` like all seven sibling maintenance scripts and enrolls the script in the shared lease-adoption census, whereas this branch reached past that service into the raw primitives and never enrolled.

The global heavy-maintenance lease records who HOLDS but nothing records who WAITS — so on a contended plane, a short-cadence holder (REM/dream re-acquiring cycle after cycle) structurally out-competes bootstrap tenant ingestion for hours while every health surface reads green. This is the exact production shape on the affected cloud plane: 3 of 4 tenant repos have no durable checkpoint after hours of continuous enrichment work (falsifier matrix + source correction by @neo-gpt-emmy: https://github.com/neomjs/neo/issues/16561#issuecomment-5279883557).

This PR closes it in two moves, both at the single admission point:

1. **Durable waiter ledger** (`heavyMaintenanceWaiterLedger.mjs`, Neo-free): every lease/backpressure deferral with a measurable streak upserts one self-owned entry file (`heavy-maintenance-waiters/<task>.json`) beside the lease — writers never contend, readers only glob, silent entries expire (a dead process cannot veto acquisitions).
2. **Three-rank yield gate** in `MaintenanceBackpressureService.acquireLeaseAndExecute`, before every acquisition: priority-0 waiter beats everything; **bootstrap-critical waiter beats ordinary enrichment immediately** (no starvation bound — an uninitialized corpus must not wait out a grace window while downstream cycles re-acquire); an ordinary waiter starving past `fairnessYieldAfterMs` (default 30 min) beats a fresher acquirer. Fail-open: a broken ledger read logs and proceeds (degrades to pre-fairness behavior, never halts maintenance).

**Bootstrap-critical is derived from durable truth, not config**: bootstrap-spread seeding persists `lastIngestedRev: null` for every configured repo on the first sweep, so `isBootstrapCriticalTask` reads the revisions manifest fresh on every admission decision — any remaining null rev ⇒ the class is active; the last checkpoint commit ⇒ it evaporates. Absent manifest ⇒ ordinary (a plane with no tenant repos never writes one); the age rule still guarantees the first sweep eventually runs on a contended plane, which seeds the manifest and activates the class.

Mapping onto the ticket's falsifier matrix:

| Falsifier | Mechanism | Proof |
|---|---|---|
| due bootstrap sync + due REM → sync wins | bootstrap-critical outranks ordinary at admission | spec: "beats an ordinary acquirer IMMEDIATELY" |
| REM releases with registered bootstrap waiter → waiter acquires before REM reacquires | REM's next acquisition passes the gate and yields | spec: integration arm 1 (yield) + arm 2 (waiter acquires, entry clears) |
| all checkpoints complete → no permanent priority | predicate re-reads the manifest per decision | spec: "full checkpoints end it" |
| repo not-due/backoff/refused → REM proceeds | a task not attempting admission stops refreshing; entries expire in 10 min | spec: "a silent waiter expires" |
