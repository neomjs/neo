# Day-0 agent identity provisioning script: node, wake sub, era anchor

## Context

The peer-onboarding rail's R3a leaf (split ratified with @neo-opus-vega 2026-07-10; @neo-gpt = Codex-side peer reviewer). A new REAL peer needs its runtime identity to exist before first boot: a Memory Core `AgentIdentity` node, a wake subscription, and an era anchor. Today those are hand-run fragments spread across sessions. `FleetLifecycleService.mjs`'s own header names "spawn-time identity-env + wake-subscription provisioning" as deferred work — this ticket ships the identity half as an operator-assisted setup script (the launch-env half is the sibling ticket).

Three constraints were deposited by @neo-gpt (A2A 2026-07-10, adopted verbatim as ACs here):

1. **Current-engine truth comes from per-instance `EmbodiedEpisode` metadata with `since` = onboarding date and NO backfill** — never from the flat `identityRoots.modelDesignation` (which is login-level and recorded-not-current; see PR #14910 review amendment). Until the era source exists for an instance, `engineTag: null` beats a false literal.
2. **The era-chain key question is OPEN**: fleet registry instance id vs GitHub login (the registry supports multiple instance ids per GitHub account). This ticket's body carries the question; the implementation documents the choice as a Tier-2 decision in the PR, and @neo-gpt pressure-tests it at review.
3. **Layer-1 operational identity ONLY**: handle, family, model, trust tier, mailbox address, wake route. The Social Name is Layer-4, post-boot, via the #11240 ritual (peer-sketched → criterion-audited → bearer-assented → peer-unvetoed → operator-confirmed) — seed data MUST NOT pre-assign names.

## The Problem

Onboarding peer #2 of any family requires identity substrate that no single entrypoint provisions. Manual assembly is drift-prone and unverifiable; the era schema (anti-fabrication: closes-and-appends, never rewrites) makes correctness rules precise enough to mechanize.

## The Architectural Reality

- `ai/scripts/setup/` is the owning folder (sibling precedent: the agent-identity graph seeding script referenced by `learn/agentos/IdentitySchema.md`).
- `ai/graph/identitySchema.mjs` — `createIdentityStateNode`, `createEmbodiedEpisodeNode`, `validateEraChain`: the era anchor MUST validate before any write.
- `ai/graph/identityRoots.mjs` is a COMMITTED file — this script never writes it (that is R3b, the PR-artifact generator sibling; critical gate: agents never write tracked files without branch+PR).
- Wake subscriptions ride the Memory Core admin surface (`manage_wake_subscription`).
- ADR-0019 read-gate applied: any config the script reads resolves through the owning config leaves at the use site; no env re-derivation, no defaults hidden in the script.

## The Fix

`ai/scripts/setup/provisionAgentIdentity.mjs`:

- Args: `{instanceId, family, model, displayName?, githubUsername?, mailbox?}`; **dry-run by default**, `--commit` to execute.
- Creates: the `AgentIdentity` node (Layer-1 fields only), the first `EmbodiedEpisode` era (`since` = now, no backfill, `validateEraChain` green before write), the wake subscription.
- **Idempotent**: re-run against an existing identity reports current state and changes nothing (no-op report, loud diff if divergent).
- Prints the R3b follow-up checklist (the five-surface roots/README/ModelStats/migration-note/spec-pin PR the generator sibling emits).
- Pure decision logic separated from side-effectful writes (the `deriveAgentRepoPath` idiom) so the correctness rules are unit-testable without a live Memory Core.
