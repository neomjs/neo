# Matrix-fallback witness: the keyboard command path witnessed once as the acquisition fallback on a matrix-failed platform

## Context

The AC-C carve-out from `#15485` (keyboard parity completion), split at PR assembly per the honest-close-target discipline: the delivered PR closes `#15485`'s popup-origin return, shared-affordance highlight, and popup live-region ACs truthfully, while this one AC keeps its own empirical gate.

## The Problem

`#15250` AC6 (inherited by `#15485` as AC-C): the keyboard command path must be witnessed ONCE as the documented acquisition fallback on a platform where boundary-acquisition fails per the acquisition matrix. The witness cannot exist before the matrix itself does: `#15245` (G2 popup acquisition contract) owns the measured platform defaults, and it is blocked on `#15243`'s committed matrix. Faking a matrix-failed platform without the committed matrix row would witness a simulation of a contract that does not exist yet.

## The Fix

Once `#15245`'s measured defaults land: one e2e witness on a matrix-failed platform configuration proving the chorded command path (`Ctrl+Shift+D` / the move cycle) acquires the popup where the pointer boundary-exit path cannot — the "a keystroke IS a user activation" fallback claim, made mounted truth. The command surface itself is already live (PR for `#15485`); this is witness-only.

## Acceptance Criteria

- [ ] One e2e witness runs the keyboard detach or transfer command under a matrix-failed platform configuration (per `#15245`'s committed defaults) and proves popup acquisition succeeds via the command path.
- [ ] The witness asserts the announced outcome derives from the committed terminal (the machine's existing contract), not from the keystroke.

## Out of Scope

The matrix defaults themselves (`#15245`, blocked on `#15243`) · threshold calibration (`#15443`) · any machine or host changes (the command surface is delivered).
