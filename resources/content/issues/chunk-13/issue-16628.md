# The overlay-import test class re-accumulated after its cleanup closed

## Context

Found by the #16515 census (chapter 3b/4, 2026-08-07 at dev `fed9bf6e7d`). ADR-0019 §3 C3 mandates: tests import `config.template.mjs` (canonical defaults), never `config.mjs` (the operator overlay — a thin child of deltas whose values legitimately differ per machine). #11976 repaired this class (~78 imports at its filing) and is CLOSED — yet 7 instances exist at the current head:

```bash
rg -l "\.\./config\.mjs'|/ai/config\.mjs'" test -g '*.mjs'
```
`initTier1ConfigMigration.spec.mjs` · `ContentPolicy.spec.mjs` · `TenantRepoSyncService.spec.mjs` · `orchestrator/daemon.spec.mjs` · `initServerConfigs.spec.mjs` + 2 more from the same command.

## The Problem

The class regenerated after its cleanup because it has **no mechanical guard**: ADR-0019 §7 scopes the fail-build lint to `A1·A4·A5·A6·A7·B1·B3·B4·B5(partial)·C1` — C3 is not in the set. Per the ADR's own E2 principle (codify-don't-promise) and its empirical anchor (reviewer diligence is insufficient — 4/4 missed), an unguarded class WILL re-accumulate; this ticket is the measured proof.

A caveat the implementer must classify per file: some of the 7 may test the overlay/migration machinery ITSELF (e.g. `initTier1ConfigMigration.spec.mjs` plausibly needs the overlay as its subject). C3 bans the overlay as a CONFIG SOURCE for tests, not as a test SUBJECT — the split must be explicit per file, and subject-legitimate imports get a lint-visible annotation rather than silent exemption.

## The Architectural Reality

- ADR-0019 §3 (C3 row, tagged `[live: #11976]` — that tag is now stale on both ends: the ticket closed AND the class re-grew).
- The existing lint infrastructure (`buildScripts/util/` check family + `ai/scripts/lint/config-leaf-parity.json` precedent) is the natural home for the C3 rule.
- #11976's close-out carries the original repair pattern.

## The Fix

1. Classify the 7 (config-source vs test-subject), repair the config-source imports to the template.
2. Extend the AiConfig lint set with the C3 rule (tests importing `ai/config.mjs` fail the build unless carrying the explicit subject-annotation).
3. Update ADR-0019 §3's C3 tag and §7's lint list in the same PR (the ADR self-describes its lint coverage; letting it drift re-creates the census confusion).

## Acceptance Criteria

- [ ] Zero unannotated `ai/config.mjs` imports under `test/` (the census command returns only annotated subject-tests or nothing).
- [ ] The lint fails a synthetic reintroduction (red-proven).
- [ ] ADR-0019 §3/§7 updated to match the shipped lint coverage.
