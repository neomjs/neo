# Remove the one-shot Fleet MCP target migration

## Context

Issue #16184 requires a hard vocabulary cut from public Fleet target selection to canonical MCP transport vocabulary, while this repository has one active persisted Fleet registry. The safe first landing therefore needs a bounded read-path migration in `ai/services/fleet/FleetRegistryService.mjs`: on first hydration, the retired persisted target-selection row is translated to `mcpTarget` and `registry.json` is atomically rewritten.

That migration is deliberately temporary. #16184 rejects a permanent dual-name compatibility layer, and the implementation marks the migration as an explicit deletion boundary.

Fresh duplicate sweep on 2026-07-30:

- live latest-20 open issue sweep: no equivalent cleanup ticket;
- GitHub title/body search found #16184 and the broader #16167 hard cut only;
- current A2A last-30 claim sweep: no competing claim for this cleanup;
- Knowledge Base ticket search and repository issue/discussion archive search returned no equivalent;
- the Agent OS structure map confirms `ai/services/fleet/` remains the owning service folder; no new file or subsystem is needed.

## The Problem

Merging the #16184 implementation is not enough to prove the one active registry has traversed the migration read path. Deleting the migration before that first accepted rewrite would strand the existing persisted row. Keeping it indefinitely would turn a one-installation cutover into the permanent compatibility layer #16184 explicitly rejects.

The deletion must therefore be driven by one runtime receipt: the active registry has loaded under the new implementation and its persisted output contains only the canonical `mcpTarget` shape.

## The Architectural Reality

- `FleetRegistryService.ensureLoaded()` owns persisted agent hydration and the atomic rewrite; cleanup belongs beside that owner.
- Public creation/configuration must continue to reject retired target-as-transport input. Deleting the persisted-row reader must not reopen silent compatibility at the wire boundary.
- The negative vocabulary sweep in `test/playwright/unit/ai/services/fleet/FleetRegistryService.spec.mjs` owns the mechanical no-regression boundary. Once the migration is gone, the production migration exception must disappear with it.
- This is an operationally gated source deletion, not a new migration product or a generic schema-version framework.

## The Fix

After the merged #16184 implementation has run against the active installation and the rewritten registry is verified:

1. Record a bounded receipt that the active persisted agent rows carry canonical `mcpTarget` values and no retired target-selection key/mode.
2. Delete the marked legacy target migration block from `FleetRegistryService.mjs`.
3. Delete its positive migration fixture and remove the production migration exception from the negative vocabulary guard.
4. Preserve direct-registry and Body↔Brain wire rejection of retired target-as-transport input.
5. Run the focused Fleet Registry / Control Bridge suite and the vocabulary guard.

## Acceptance Criteria

- [ ] **Post-merge runtime gate:** the active registry has loaded under the #16184 implementation and a redacted inspection proves persisted rows use canonical `mcpTarget` with no retired target-selection key/mode.
- [ ] The marked persisted-row migration block is deleted from `FleetRegistryService.mjs`.
- [ ] The positive legacy hydration fixture is deleted and the negative vocabulary guard no longer strips a production migration region.
- [ ] Direct registry input and the real Body↔Brain define path still reject retired target-as-transport input instead of degrading it to resident.
- [ ] Focused Fleet Registry / Control Bridge tests and the vocabulary sweep pass after deletion.
- [ ] No generic schema-version framework, dual-read alias, or extra compatibility timer is introduced.

## Out of Scope

- Reworking the `mcpTarget` shape, resolved plan, harness adapters, or AgentOS UI delivered by #16184.
- Forcing the rewrite through an ad-hoc mutation script before the production service reads its own data.
- Retaining fixtures for hypothetical additional installations.
- Changing tenant credentials, MCP authentication, or server protocols.

## Avoided Traps

- **Delete in the first PR:** can strand the one pre-cutover persisted row before it has been rewritten.
- **Leave indefinitely:** converts a one-shot cutover into permanent compatibility debt.
- **Build migration infrastructure:** negative ROI for one active installation and one known shape.
- **Treat wire rejection as compatibility:** rejecting a retired input prevents silent semantic drift; accepting and translating it would be compatibility.
