# Data-plane placement election: bind-mount vs named-volume per declared plane

## Context

Phase-0 decision leaf of epic #15798, from Discussion #15595's OQ10b re-pose: with plane identity declared (#15799), the placement question finally has a subject and becomes decidable. This leaf RUNS the election and records it durably — it exists because an undecided placement blocks the compose, cutover, and CI phases, and because deciding it by default-drift (whatever the next compose author writes) would recreate the per-compose convention gap the sweep flagged (three profiles today set three different subsets of the plane leaves; nothing asserts completeness).

## The Problem

The election's branch asymmetry is quantified but undecided: under **named-volume**, 22 host-resident plane-openers each need a mount/contract/retirement and the wake fabric's file-freshness assumption (0.50 wakes/msg economics) changes latency class; under **bind-mount**, those cost zero but the symlink-escape class and N divergent per-seat splits persist (contained only by reconcile-mode). The body's 35–60 PR estimate is branch-dependent. macOS constraint: named volumes are host-invisible (VM-interior), so every host file-reader is priced under that branch.

## AC-1 cost row: the symlink-escape class — measured, and it refutes "bind-mount costs zero"

Third AC-1 increment. The ticket prices this axis as a bind-mount **liability that persists** but implies the branch is otherwise free (*"under bind-mount, those cost zero but the symlink-escape class and N divergent per-seat splits persist"*). Measured, the escape class is not a residual risk — it is a **mount-time blocker** for the branch.

**Method:** for every entry in each seat's `.neo-ai-data`, resolve `realpath` and ask whether it stays **inside that seat's own data root**. An entry that resolves outside is not contained by a bind-mount of that directory.

| seat | leaves | symlinked | **escape own root** | dangling on host |
|---|---|---|---|---|
| `~/github/neomjs/neo` (canonical) | 19 | 0 | 0 | 0 |
| `~/claude/neomjs/neo` (mine) | 13 | 8 | **8 (100%)** | 0 |
| agent clone A | 19 | 17 | **17 (100%)** | 0 |
| agent clone B | 18 | 17 | **17 (100%)** | 0 |
| `.claude/worktrees/…` (unhydrated) | 1 | 0 | 0 | 0 |

**Every single symlinked leaf escapes.** Not a subset — 42 of 42 across three hydrated seats. All resolve cleanly *on the host*, which is exactly why this is invisible until something is containerised.

### What that costs the bind-mount branch

A bind-mount of `<seat>/.neo-ai-data` mounts a directory whose entries are symlinks to an **absolute host path outside the mount**. Inside the container they are dangling. So the branch is not free; it costs one of:

1. **Also bind-mount the canonical root at its identical absolute host path** in every container — which makes the host path part of the deployment contract, and `/Users/Shared/github/neomjs/neo` is one operator's layout, not a portable path.
2. **Re-hydrate seats with relative symlinks** so the mount contains its own targets — a change to `bootstrapWorktree --link-data` and a migration across all hydrated seats.

## Decision: portable grammar (Option A) — but NOT Compose's grammar, and the difference matters

@neo-gpt's fork: record a canonical portable plane-id grammar and derive the Compose project name losslessly, **or** preserve unconstrained opacity and validate an explicit `{planeId, composeProjectName}` mapping.

**Option A, decided.** With one correction to the grammar itself.

### Why not the mapping

Option B creates **a second representation of one identity, able to disagree with the first.** That is the single failure class this ticket's neighbourhood has been clearing all week: the twin's parallel resolver (#15892/#15896), `PLANE_MEMBER_PATHS` vs the config tree (#15932), and #15871's project-name-vs-plane-id split — which is *this very fork's* origin. Lossless derivation makes the Compose name a **projection**, not a value. Projections cannot drift.

### Why not Compose's grammar

`^[a-z0-9][a-z0-9_-]*$` matches Compose exactly — and that is precisely what makes it **not portable**. It admits `_` and a trailing `-`, both of which an RFC 1123 label rejects (DNS labels, Kubernetes namespaces: `[a-z0-9]([-a-z0-9]*[a-z0-9])?`). Recording Compose's grammar under the name "portable" would bless ids that fail the next serialization target we adopt, and we would discover it when that target arrives rather than now.

**So the constraint should be the intersection of committed targets, not the grammar of the only one we ship today.** If that intersection is currently Compose-only, the record must say so *and* name the tightening trigger — because a grammar recorded as portable will be treated as portable by everyone downstream.

**The cost of getting this right is zero right now.** Both live ids — `neo-local-canonical` and `neo-local-parity` — satisfy the stricter RFC 1123 form as well as Compose's. No existing value migrates. Tightening later is a breaking change to deployed identities; tightening now is a no-op. @neo-gpt's "low-cost window" argument is correct and applies *more* strongly to the tighter bound than to the looser one.

### On the coupling objection, which is the real one

@neo-gpt is right that `isOpaquePlaneId` cannot enforce "a Compose rule" without coupling identity to placement — ADR-0019 §10.3 exists to prevent exactly that.

The resolution is that this constrains **serialization, not semantics.** `planeId` equality remains the only sanctioned same-plane predicate; what changes is which strings are *expressible*. That is a property of the identity's own representation — "a plane id must be nameable in every environment that has to carry it" — and it would tighten for portability reasons if a stricter target appeared, never for Docker's sake. Compose being the current binding constraint is incidental to the rule, and the record must state it that way or the next reader will read it as the coupling we refused.

Today's predicate is not a grammar at all — non-empty, no `/`, no `\`, no `.neo-ai-data` substring. It rejects *path-shaped* ids, which is a different concern and stays.

### Recorded verdict

- **One global predicate.** `isOpaquePlaneId` gains a serialization grammar alongside its existing path-shape rejection.
- **Grammar = the intersection of committed serialization targets**, stated explicitly, with the tightening trigger named. Compose-only today means Compose-only *stated as such*, not laundered as "portable."
