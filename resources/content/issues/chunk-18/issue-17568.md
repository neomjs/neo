# Fleet util modules become classes with owned placement

## Context

The second half of #17559's law 3, extracted from #17560 at its review (the move PR relocated the 15 camelCase pure-function modules to `apps/agentos/util/` AS MODULES with imports rewritten; converting them into classes rewrites call sites in 40+ files and belongs in its own reviewable leaf). This ticket is the successor #17560's close-target contract points to — without it, the merge would close the only pointer to the deferred authoring.

It also owns the placement question #17560's review surfaced against the parent epic: several relocated modules are cockpit-scoped configuration/document builders, and the parent's `cockpit/` surface authority arguably owns them once they take class form — a per-module disposition this ticket's ledger decides, rather than a blanket rule.

## The Problem

`apps/agentos/util/` currently holds 15 camelCase function modules — Brain-style in Body-side app code. Law 3's target: Body-style classes (`Neo.util.*` precedent — static methods, `Neo.setupClass`, docs-generated) in their OWNED location: cross-surface helpers as `AgentOS.util.*`, surface-scoped builders as surface-local classes.

## The Architectural Reality

- Precedent: `src/util/*` (static-method classes extending `core.Base`); consumer graph measured 2026-08-22: `viewerTime` ← 5 surfaces, `sourceHealth` ← 7 files, `agentFreshness` ← 3, `telltale`/`nameSlot`/`familyTokens` ← card/detail; `cockpitDockDocument`/`cockpitPresets`/`fleetStartPlan`/`fleetLifecycleIntentAdapter`/`spineBanner`/`viewerWakeTelltale` ← cockpit only; `kindRegistry` ← activity only; `addAgentFlow` ← instances + accounts; `configIntentRoundTrip` ← detail + accounts.
- The conformance witness (`viewTopologyConformance.spec.mjs`) currently guards `view/**`; this leaf extends it so `util/` is class-only afterwards.
- The app-work gate (`.claude/CLAUDE.md` / `AGENTS.md` §edge_case_triggers) enforces store-binding and provider placement but neither law 0 (base-class-first primitives) nor law 1 (suffix = base family) — the gap that let the flat folder grow. This leaf carries the two gate lines (substrate-mutation pre-flight slot rationale included in its PR body).

## The Fix

1. **Disposition ledger executes per module** (the table below is the contract): cockpit-scoped builders become `AgentOS.view.fleet.cockpit.*` classes; single-surface helpers move into their surface; genuinely cross-surface helpers become `AgentOS.util.*` static classes.
2. Call sites update mechanically (`import {fn} from module` → `import Class` + `Class.fn(...)`); exported constants become static props.
3. The conformance witness gains: no camelCase modules under `apps/agentos/util/` (class-only), and the suffix/className laws extend over `util/`.
4. The app-work gate gains laws 0+1 as two trigger lines (with the required slot rationale in the PR).
5. `generate-docs-json` picks up the 15 new classes in the same commit.

## Acceptance Criteria

- [ ] Zero camelCase function modules remain under `apps/agentos/util/` or `apps/agentos/view/**`; every ex-module is a `Neo.setupClass` class with static members in its ledger-decided location.
- [ ] Every call site imports the class; zero named-function imports from the old module forms remain (grep receipt).
- [ ] The conformance witness covers `util/` and stays green; the full agentos unit tree stays green with zero behavior change.
- [ ] The app-work gate carries laws 0+1; the PR body carries the substrate slot rationale.
- [ ] `generate-docs-json` lands the 15 classes in the same commit.

## Out of Scope
