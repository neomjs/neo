# Two redundant spin-gated assertions can manufacture a false flaky

> ## ⚠️ Body substantially corrected by its author, 2026-08-15, before any work was built on it
>
> **The original filing claimed these two tests "pass vacuously" and silently stop testing under contention. That is WRONG, and I proved it wrong by running the experiment I should have run before filing.** The original framing is retained in *Superseded original claim* at the bottom so nobody re-derives it.
>
> **Detection is intact.** These tests catch the defect they guard even with the turn budget set to **zero**. The severity is inverted from what I filed: the real risk is a **loud false failure**, not a silent coverage hole.

## Context

While repairing `MailboxService.spec.mjs:1381` for #17186, I dispositioned its two `turn < 3` siblings as that ticket's AC-4 requires. My first analysis was that they invert #17186's failure mode and pass vacuously. Two experiments later, that is not what they do.

@neo-opus-vega was right to refuse the sweep, and for a better reason than either of us gave: these spins are **redundant**, not broken.

## The Problem

`test/playwright/unit/ai/services/memory-core/MailboxService.spec.mjs:1224` and `:1298`

```js
await readEntered;
for (let turn = 0; turn < 3; turn++) {
    await new Promise(resolve => setImmediate(resolve));
}
expect(payloadReads).toBe(1);        // ← pre-release, spin-gated
releasePayloadRead();

const results = await Promise.all([first, second]);
expect(projectCalls).toBe(1);
expect(payloadReads, 'record loading and mutation must share the single-flight pipeline').toBe(1);
```

**The pre-release assertion is subsumed by the post-completion one.** "Only one read has happened *so far*" is strictly weaker than "only one read happened *in total*". The post-completion assertions are deterministic — they run after both callers settle — and they carry the detection.

**Measured, twice, rather than argued:**

| experiment | result |
|---|---|
| turn budget `0`, single-flight intact | **passes** — caller 2 joins with no wait at all |
| turn budget `0`, single-flight **disabled** | **fails** at line 1272, `Expected: 1 / Received: 2` |

The second run is the decisive one. **With the wait removed entirely, the defect is still caught** — and caught by the post-completion assertion, not the spin-gated one. The turn budget contributes nothing to detection.

## The Architectural Reality — what the wait actually does

It is a **false-failure preventer**, not a detector.

Caller 1 parks inside `readFile` on the gate. The single-flight map entry is deleted when caller 1's read *resolves* (`MailboxService.mjs:1216-1220`), which happens after `releasePayloadRead()`. So if caller 2 reaches its segment-load decision **after** that deletion, it legitimately misses the pending promise, opens its own read, and `payloadReads` reaches 2 — failing the post-completion assertion **on correct code**.

The spin exists to make caller 2 decide while caller 1 is still parked. Its failure mode is therefore a **false RED**, and under `workers: 4` that surfaces as a `flaky` — which, per #15861's amended AC-2, is a **positive detection that disqualifies the sample**. So a false flaky here costs a probe sample exactly as much as a real defect does.

**That is why this still blocks #15861** — not because coverage is missing, but because it is a false-positive source aimed at the one signal the probe reads.

**Two candidate arrival anchors, both falsified.** Recorded so they are not re-proposed:

1. **The marker `readFile`.** `getGraphMarkerFileStats` (`messageWalStore.mjs:334-351`) uses `fs.stat`, not `readFile`; and `readJsonlEntries`, the only marker path that reads, is skipped on the cache hit that two concurrent unchanged callers produce (`:479-495`).
2. **The `readdir` in `listMessageWalSegmentKeys`.** Measured: `markerScans` is already **2 at turn 0**, before the wait begins, while caller 2's read decision lands around turn 2. **The anchor fires two turns early**, so it cannot prove arrival.

There is a reason no anchor exists: **when caller 2 joins, it produces no side effect at all.** Joining is silence by construction, and the only observable difference — the second payload read — *is* the failure signal. No test-side observation can distinguish "joined" from "not yet arrived".

**Also checked and cleared, so it is not re-investigated:** `projectionStatsCache` (`messageWalStore.mjs:23`) is module-scope keyed by `dir`, which looks like cross-file worker state in the class #15861 hunts. It is not — `messageWal.dirTest` derives from the active test's `memoryWal.dir`, isolating the key by construction (`ai/mcp/server/memory-core/configBase.mjs:544-549`).

## The Fix

**Delete the two pre-release assertions.** They are strictly weaker than the post-completion assertions that follow them, and they are the only part of these tests that depends on timing.

**Keep the wait, and document what it is for.** It is not proving anything; it is buying overlap so a correct implementation is not reported as broken. A comment saying so is the entire remaining deliverable — the current comment ("Give the second caller several turns to reach the same id") reads as though the wait is establishing the property under test, which is exactly the misreading that produced this ticket's first version.

**Widening 3 → a larger budget is optional and cheap**, since the wait is pure overlap insurance with no assertion riding on it and it costs event-loop turns rather than wall clock. Worth doing only with a measured justification, not by reflex.

## Out of Scope

- **`:1381`** — repaired in #17186.
- **Chasing an arrival anchor.** Both candidates are falsified above, and the reason is structural: a join produces no observable. Anyone proposing a third should explain why it is not silent by the same construction.
- **Exposing an observable from production.** Unnecessary once the redundant assertion is deleted — there is nothing left that needs to observe arrival.
- **The guard's blindness to turn-budget spins.** `check-fixed-sleeps.mjs` matches `setTimeout` at or above 1000 ms, so a spin waiting in event-loop turns is invisible to it. Related to `#17177`'s callback-form blind spot and belongs with it.

## Avoided Traps

- **My own first analysis.** I inferred the failure mode from the assertion's *shape* — a non-event assertion inverts, therefore it must pass vacuously — and filed on it. The inference was reasonable and wrong, and one experiment settled it. **A defect class that fits is not a defect that is present.**
- **Reading "has never failed" as "is correct".** Still the right instinct; here it turned out these have never failed because they *work*, which is the possibility the first version did not seriously test.
- **Deleting the wait along with the assertion.** Tempting once the assertion is gone, and wrong — the wait has a real job that the assertion never had.
- **Trusting a combined red run.** Serial mode skips after the first failure.
