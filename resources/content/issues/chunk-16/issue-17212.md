# apps/workstation diverges from the FM style language — census the delta, then align the higher-polish app to the cockpit's specs

## Context

Operator observation (2026-08-15, same UX escalation series): `apps/workstation` sits at a visibly higher polish level than the cockpit's side panels — but it does NOT match the FM style specs; the two surfaces read as different products. As the cockpit's skin work lands (#17209/#17211), the divergence would otherwise widen.

Verified present: `apps/workstation/` (app.mjs, model/, store/, view/, tour/) with its own `resources/scss/src/apps/workstation/` (Viewport.scss, Workspace.scss).

## Acceptance Criteria

- [ ] **Census first:** a style-delta inventory of workstation against the FM style language (tokens, spacing rhythm, header/rail treatments, state colors, typography) — the census names each divergence with its file:selector coordinates and classifies it keep-as-intended / align. The census is a PR-body or ticket-comment artifact BEFORE alignment commits.
- [ ] Alignment commits per the census dispositions — SCSS token/skin layers only, zero CSS-in-JS; shared tokens preferred over copied values (if a token layer gap forces copying, name it as follow-up rather than duplicating silently).
- [ ] Both themes verified; no functional/DOM changes ride along (style-only lane).

## Out of Scope

Cockpit-side work (#17209/#17210/#17211) · new shared-token architecture (census may PROPOSE it; building it is its own ticket if the delta demands one).
