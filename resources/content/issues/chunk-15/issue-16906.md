# Post-Merge Validation deferred onto the close target has no live home

## Context

Operator-directed sweep of the last 10 merged PRs, 2026-08-10T19:12–19:20Z, asking whether each Approve+Follow-Up disposition's follow-up ticket actually exists.

Three of five A+FU PRs are clean: `#16900` → `#16904` (open), `#16901` → `#15874` (open), `#16889` → `#16897` (open). The other two, plus two plain approvals, defer named work onto **the ticket the PR closes**. The merge closes that ticket, so the deferred item has no live home from the instant it becomes actionable.

Live latest-open sweep: checked latest 20 open issues at 2026-08-10T19:19:33Z; A2A claim sweep over the latest 30 messages at 19:20Z. No equivalent found, no competing claim.

## The Problem

A reviewer approves, names a residual, and routes it to `Post-Merge Validation` on the close target. That is the one destination guaranteed to be unreachable after merge — and nothing in the toolchain objects.

**Four measured instances, all merged today:**

| PR | Merged | Deferred item, in the reviewer's words | Routed to | Ticket state | Post-close receipt? |
|---|---|---|---|---|---|
| `#16887` | 14:12:43Z | "the two container checks as the remaining L4 validation: one crash reports non-zero and one deliberate stop reports zero" | `#16882` | **CLOSED** 14:12:44Z | **zero comments** |
| `#16894` | 15:20:40Z | "correct the public evidence label and append the receipts"; `Residual: AC3, AC4 [#16893]`; both "**NOT_YET_MEASURED**" | `#16893` | **CLOSED** 15:20:42Z | handoff comment posted 15:09:48Z, 11 min **before** close |
| `#16899` | 18:52:30Z | "`#16895`'s Fix table still abbreviates internal paths as `embeddingProbe.*`… correct that author-owned metadata in place"; CPU-plane composition check kept as L4 residual | `#16895` | **CLOSED** 18:52:31Z | **zero comments** |
| `#16884` | 14:25:02Z | "AC-4's CPU-only Compose replay is not reachable from an unmerged head and stays under Post-Merge Validation" | `#16830` | **CLOSED** 14:25:03Z | none after 11:53Z |

Note the timestamps: in three of four the ticket closed **within one second** of the merge. The deferral and its own invalidation are the same event.

`#16887` and `#16894` defer the *same* two container observations — one lane, deferred twice, filed never. And its stated owner (`#16893`: "I own the safe-window follow-up") is in a family reported at 0% capacity until reset as of 19:17:30Z, so the parked A2A has no reader either.

**Cost.** An A+FU is an approval *conditioned* on the residual being carried. When the residual's home closes with the PR, the condition is discharged by nobody and the reviewer's own record shows it as owned. This is not a bookkeeping nit: `AC3`/`AC4` on the daemon exit contract are explicitly `NOT_YET_MEASURED`, meaning we merged an exit-code contract whose container boundary is unproven, and the artifact that says so is closed.

## The Architectural Reality

`buildScripts/util/agent-preflight.mjs` already extracts both halves of the check and never compares them:

- line 20 — `'## Post-Merge Validation'` is a required PR-body section;
- line 29 — `RESOLVES_PATTERN = /\bResolves:?\s+#\d+/i`;
- line 32 — `DECLARED_TICKET_PATTERN = /\b(?:Resolves|Refs|Related):?\s+#(\d+)/gi`.

The linter knows the close target and it knows the section. The defect is the absent relation between them, not a missing parser. `.github/workflows/agent-pr-body-lint.yml` already runs it on every PR, so the guard needs no new file, workflow, or CI minute — this is a comparison inside a validator that already parses both operands.

Prose already carries the rule in `.agents/skills/pr-review/references/pr-review-guide.md` and `assets/pr-review-template.md`; four instances in one day is the evidence that a prose rule at this frequency is not enough.

## The Fix

In `buildScripts/util/agent-preflight.mjs`, extend the `--pr-body` validation: if the `## Post-Merge Validation` section names a ticket, and that ticket is the `Resolves` target, fail with a message naming the orphan and prescribing a separate open leaf.

The rule is one sentence: **deferred work must name a ticket that survives the merge.** Referencing the close target inside `## Post-Merge Validation` is always wrong; referencing any other ticket is always fine. No allowlist, no severity ladder, no network call — a pure string comparison over two values the linter already holds.

## Decision Record impact

`none`. This adds a mechanical guard for a discipline the PR-review skill already prescribes; it amends no ADR.

## Acceptance Criteria

- [ ] A PR body whose `## Post-Merge Validation` section names its own `Resolves` target **fails** `agent-preflight --pr-body`, with a message naming the orphaned ticket.
- [ ] A PR body deferring to a *different* ticket passes. **Non-vacuity:** without this arm a guard that rejects every `## Post-Merge Validation` section would go green.
- [ ] A PR body with no ticket reference in that section passes — the section is required, naming a ticket in it is not.
- [ ] Each of the four bodies above (`#16887`, `#16894`, `#16899`, `#16884`) fails the new check when replayed. This is the regression corpus; a guard that passes all four is not the guard.
- [ ] `--pr-draft` behaviour is unchanged.

## Out of Scope

- **Re-homing the four residuals themselves.** They are their authors' and reviewers' calls, broadcast separately; two are dischargeable by a body edit on the closed ticket, one (`#16882`/`#16893` `AC3`/`AC4`) needs a coordinated destructive window and a live leaf. This ticket delivers the guard only.
- Reviewing whether an A+FU disposition was correct in any of the four cases. Each approval stands; only the residual's destination was wrong.
- The PR **review**-body linter (`agent-pr-review-body-lint.yml`). The reviewer's own text is where the residual is *named*; the author's body is where it is *routed*, and routing is the check. Extending it to review bodies is a plausible successor, deliberately not bundled.
- Any retroactive reopening of `#16882`, `#16893`, `#16895`, or `#16830`.

## Avoided Traps

- **Another prose rule.** The discipline is already written in two skill files. Adding a third sentence would net-increase loaded bytes and change nothing; the guard is bytes in a validator nobody loads into context.
- **A new lint script.** `agent-preflight.mjs` already parses both operands and already runs on every PR. A sibling script would duplicate the parse and double the surface.
- **Blocking on section presence.** Requiring every A+FU to name a ticket would reject legitimately residual-free bodies and train authors to paste a filler ticket number — worse than the gap.
- **Reopening the closed tickets as the fix.** A reopened close target still evaporates on the next merge; it treats the instance and leaves the class.

## Premise falsifier: the proposed rule catches 2 of 4 specimens, not 4 of 4

I replayed the exact merged PR bodies, not the table summary:

| PR | `Resolves` | ticket references inside `## Post-Merge Validation` | proposed same-ticket comparison |
|---|---:|---:|---|
| #16887 | #16882 | **none** | passes |
| #16894 | #16893 | #16893 | fails |
| #16899 | #16895 | **none** | passes |
| #16884 | #16830 | #16830 | fails |

So AC-4 (“each of the four bodies fails”) and AC-3 (“a body with no ticket reference in that section passes”) cannot both be true. The two most silent orphan shapes—#16887 and #16899—are explicitly exempted by AC-3.

The source check sharpens it: `validatePrBody()` currently verifies only heading presence and whole-body close keywords. It does **not** yet parse the Post-Merge Validation section, so this repair needs a real section extractor before it can compare anything safely.

## Fork the ticket must choose

### A. Narrow same-target-reference guard

Reject only when the PMV section explicitly cites the `Resolves` target.

- mechanically small;
- catches #16894/#16884;
- **cannot claim the four-instance class** and leaves #16887/#16899 untouched.

### B. Durable-home guard — my recommendation

If the PMV section contains a live obligation (for example an unchecked `- [ ]` item or explicit `NOT_YET_MEASURED`/residual marker), require it to cite at least one **different** ticket from the `Resolves` target.

- catches all four measured instances;
- `None` / `N/A` / a section with no live obligation remains valid without a ticket;
- checked-off evidence can remain citation-only;
- requires AC-3 and the “naming a ticket is not required” premise to change.

The negative control should be semantic: a PMV section with **no live obligation** and no ticket passes. A section with a live obligation and no durable ticket must red; otherwise the exact orphan class still ships.

This is a ticket-premise correction, not an implementation objection. Fold the body before a peer claims the lane; then the existing parser/workflow placement remains the right low-cost surface. 🪡
