Resolves #17716

`onPipelinePush()` looked its key up as received while insertion converts it, so a key whose type differed from the stored one was a miss rather than a near-miss — and an upsert answers a miss by appending. Two records under one identity, steady, with nothing in the path that removes either.

Evidence: L2 (exact-head unit, 3009 passed locally at `2eb8297e`, plus a per-falsifier red proof against `origin/dev`) → L2 required (every AC is a repository-local store contract). Residual: component-project coverage for the three call-site changes, deferred to exact-head CI — see Test Evidence.

## AC Evidence

| AC | Evidence |
|---|---|
| String key against an `Integer` Store updates rather than forks | `StorePush.spec.mjs` — push `id: '1'` against stored `1`: `count` stays `2`, and one record holds identity `1`. |
| Symmetric case holds for a `String`-keyed Model | New `StringKeyPushModel` fixture — push `id: 1` against stored `'1'`: `count` stays `1`. An int-only rule leaves this forking, which is why the arm exists. |
| Stored key is canonical after an insert | Push `id: '3'` with `upsert`: `store.get(3)` resolves, so a later canonical lookup cannot miss the record it just created. |
| Un-canonicalizable key takes an explicit disposition | Push `id: 'bad'` against an `Integer` Store: refused, `count` unchanged, `store.get('bad')` null. |
| Primitive matches what `RecordFactory` stores | `getCanonicalKey()` **delegates to** `parseRecordValue()` rather than mirroring it, so the two cannot drift by construction. |
| Three hand-rolled sites consume the primitive | `list/Base.mjs`, `Gallery.mjs`, `Helix.mjs` — their identical `getKeyType()?.includes('int') → parseInt` blocks are gone. |
| No coercion inside `Collection.get()` | Unchanged; see Boundary. |

## Deltas from ticket

None. One ticket assumption was checked rather than carried: the `(type === 'int') && value` guard in `parseRecordValue()` looked like it would leave a falsy key uncoerced, but `'0'` is a truthy string so it parses to `0`, and numeric `0` is already canonical. Both converge, so no divergence from `RecordFactory` was needed.

## Boundary

- Coercion is **not** introduced into `Collection.get()`. It is a hot path, and forgiving type mismatches there would mask genuine identity errors everywhere instead of surfacing them at the boundary that owns them.
- A calculated key field is passed through untouched — it is derived from a record that does not exist at lookup time.
- `#14392`'s `pushInsertStrategy` vocabulary and its filter / remote-projection semantics are unchanged; only the key's type handling moves.
- Key extraction now uses `getKey()`, which already handled Record instances, dotted key properties, and field `mapping` — the previous `data[getKeyProperty()]` silently returned `undefined` for the last two.
