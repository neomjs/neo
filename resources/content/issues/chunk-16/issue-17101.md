# Cockpit wake consumer: EventSource + poll-digest catch-up (S7 slice 3)

## Context

Slice 3 of #16741 (S7, epic #16168) — the client half of the reshaped fork: the cockpit consumes the slice-2 SSE stream for latency and uses slice-1's shipped `poll-digest` (`WakeSubscriptionService.pollDigest`, `ai/services/memory-core/WakeSubscriptionService.mjs:1584`, PR #16796) as the reconnect/catch-up truth primitive. SSE drops events across disconnects; every reconnect performs the catch-up read — **push for latency, poll for truth**. Sequenced after slice 2; slice 4 (last-poll telemetry) may land either side — absent producers render calm per the tier-degradation contract.

## The Fix

1. **Cockpit EventSource consumer** (apps/agentos) — connect to the slice-2 SSE endpoint through the authenticated ingress; on open/reconnect, run the `poll-digest` catch-up with the client-held watermark (F3: client-held, plane cursor-stateless).
2. **Delivery-axis wiring** — replace the typed-unknown stubs via the `FleetManager.wakeStateOptions` injection points (`devFleetServer.mjs:149-153` defaults, `:198-202` injection): `resolveDeliveryLiveness` / `resolveTerminalDeliveryFailures` derive from what the plane can now vouch (`fleetWakeRoutesSource.mjs:47-49` contracts).
3. **Push-failure-ladder isolation (constitutive, not optional):** pull/poll routes are structurally unreachable by push-failure semantics — nothing is ever pushed to them, so push-failure state applied to them would fabricate degradation (author falsification pass, ledger row 4 sharpening). Their health derives from subscription state + (once slice 4 lands) last-poll recency.
4. **Honest-degraded rendering:** a dead SSE channel renders "wake push unavailable — reason", absence-of-signal vocabulary, never a verdict; a failed poll is DISTINCT from an empty digest (v1.1 AC).

## Acceptance Criteria

- [ ] Remote-only journey (D#16720 criterion 7): a no-checkout cockpit has a working wake story — SSE receipt live, reconnect catch-up via poll-digest proven (the missed-event window is closed by derive-at-read).
- [ ] Pull routes never display push-failure states (witness: injected push-failure state does not touch a poll-only route's rendering).
- [ ] Watermark is client-held and echoed, never server-persisted (slice-1 contract preserved).
- [ ] App-gate discipline: store-bound data path, state.Provider at the view root, zero CSS-in-JS; whitebox-e2e for the consumer journey.
