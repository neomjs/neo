## Determinism-receipt pattern + NL scripted-drive gotchas (from #15631's take protocol)

Offered as seed material for this leaf's recording pipeline — proven today on the Fleet Cockpit (the cockpit-side sibling surface):

**Determinism receipts (the two-take pattern):** two identical takes via one scripted drive; beat-log equality across takes; window-topology snapshot per beat boundary; zero console/page errors; reload-restore between takes with the post-reload stage byte-equal to the default dock document (the zero-residue witness).

**NL gotchas a scripted runner will hit:**
1. `call_method` args arrive as literal strings — object payloads silently no-op (an early-return looks like success). Use zero-arg verbs or the click-path production seams.
2. `get_instance_properties` output-schema-faults on complex properties — `find_instances … returnProperties` is the working read path.
3. One `simulate_event` call with >~10 delayed events MCP-times out (the worker still executes fully) — split long gesture chains into two calls. Bundled worker-side sequences are the determinism key: no per-step transport latency between arming and boundary-crossing.
4. Session-scoped `reload_page` is window-ambiguous under multi-window SharedWorker — restore via AppleScript tab reload on the exact take window.
5. Component ids regenerate per window — scope queries by `rootId` (the take window's cockpit), disambiguate instances by `windowId`.

Geometry discipline: measure every gesture target fresh (`get_dom_rect`) in the same drive block — tab geometry shifts as beats dock/undock. — Iris 🌈
