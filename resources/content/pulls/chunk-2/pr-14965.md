Resolves #14937

The peer-onboarding rail's capstone: `ai/scripts/fleet/onboardPeer.mjs` — one dry-run-first command walking an operator from "I want a new resident" to "a supervised harness runs in its own home, awaiting exactly one login," as a **thin two-phase conductor over owned contracts**. It re-implements nothing: every write goes through the owning fleet surface, and identity + wake substrate arrive via the roster ceremony (per the operator layer-audit that closed #14915).

- **Phase A** (`define` → `repo` → `roster`): registry agent definition (curated intent only — the raw-launch stop-line untouched), `metadata.repo` coordinates via `FleetManager.setRepo`, then PRINTS the #14950 roster-generator invocation. The roster PR + cross-family review **is** the membership ceremony; this script never writes committed files.
- **The operator gate** (printed, never automated): merge the roster PR → pull → restart the Memory Core server. Boot seeding materializes the resident's `AgentIdentity` node (with its `subscriptionTemplate`) from the committed roster; the peer's FIRST boot materializes its wake route itself via the wake-subscription `bootstrap` action from the real boot envelope.
- **Phase B** (`preflight` → `launch` → `auth`): preflight verifies the roster entry in THIS checkout AND the seeded graph node via a read-only probe — three-valued honestly (`OK` / `REFUSE` naming the exact missing operator step / `WARN` when no graph is reachable, because unverifiable is never verified); launch is `FleetManager.startAgent` (the existing provision-then-start turnkey through the merged #14918 curated templates); auth prints the per-home login line (`CODEX_HOME=<home> codex login` / claude-code equivalent) — secrets never touch the script.

The planner is pure (facts injected; the CLI gathers them from registry/roster/graph/lifecycle reads), dry-run and `--commit` derive from the SAME plan, `--commit` refuses on any REFUSE segment, and every segment is idempotent because every underlying contract already is. Engine/model and name inputs have **no surface** (observation-owned and ritual-owned respectively).

Evidence: L2 achieved — live read-only dry-run receipts at this head against the real checkout: a hypothetical `neo-gpt-2` renders the true Phase-A delta (CREATE/CREATE/PRINT + the gate message), and a rostered resident renders Phase B (preflight WARN in a graph-less worktree — the honest unverifiable path, itself a receipt) with launch/auth segments. L1: 11-test matrix on the pure planner + a spawned fresh-process `--help` regression (bare exit 0, no Neo bootstrap — the lazy-bootstrap contract from the #14953 lineage applied from birth).
