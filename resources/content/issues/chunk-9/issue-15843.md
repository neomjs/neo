# B4 enforcement completeness: the config-mutation gate never scans ai/**

## Context

Successor for two residuals on #15838 that PR #15839's `Resolves #15838` would otherwise erase, surfaced by @neo-gpt-emmy's exact-head review. Filed separately because both are edits to *other* artifacts (the lint-staged config, CI, an ADR) and burying them in the matcher-fix PR would conflate a mechanical build change with a governance/scope change.

## The Problem

**1. The B4 gate never scans `ai/**` — only `test/**`.** The lint-staged glob for `check-aiconfig-test-mutation` is `test/**/*.mjs`, and the CI workflow scans the same. B4's danger is **symmetric**: a *production* script that points the `AiConfig` singleton at a test collection is the #12335 orphan-bleed incident from the other direction. On the current head, the matcher already flags two production files that CI never checks:

- `ai/scripts/maintenance/recreateGraphDb.mjs` — 1 Class-A assignment.
- `ai/scripts/migrations/migrateMemoryCore.mjs` — 2 assignments, one setting a **`test-re-embed-memories`** collection name in a migration.

These are flagged by the exported matcher but invisible to the enforced gate.

**2. ADR-0019 §4 points at a CLOSED cleanup ticket.** The B4 row and §4 footnote cite `#12435` as the live cleanup ("~21 test files; #12435"), but #12435 is **closed**. So the ADR's own map points at finished work while the class stays reachable — a stale pointer in the governance record for the exact class this gate protects.

## The Architectural Reality

- `package.json` `lint-staged` — `test/**/*.mjs` runs `check-aiconfig-test-mutation`; `ai/**` is unscanned by it.
- The CI workflow mirrors that scope.
- `buildScripts/util/check-aiconfig-test-mutation.mjs` — the matcher itself is scope-agnostic; only the invocation globs are `test`-only.
- `learn/agentos/decisions/0019-aiconfig-reactive-provider-ssot.md:62,87` — the `#12435` pointers.

## The Fix (direction)

1. **Widen the enforced scope to `ai/**`** (lint-staged glob + CI), and disposition the two production files: migrate to a non-singleton-mutating form, or grandfather explicitly with a stated reason — never leave them silently passing once in scope.
2. **Correct the ADR-0019 §4 / B4-row pointer** from the closed #12435 to the live disposition (this ticket, and the by-construction migration state).

**Sequencing:** widening the glob changes what must pass for **every future `ai/** commit`, and the two production files fail until dispositioned — so this is deliberately its own reviewed change, not a rider on #15839's matcher fix.

## Acceptance Criteria

- [ ] `check-aiconfig-test-mutation` runs against `ai/**` in lint-staged AND CI — proven by a seeded `AiConfig.storagePaths.graph = x` in a scratch `ai/` file being blocked pre-commit.
- [ ] `recreateGraphDb.mjs` and `migrateMemoryCore.mjs` are each dispositioned (migrated or explicitly grandfathered with a reason), not silently passing.
- [ ] ADR-0019's B4 row and §4 footnote cite a live disposition, not the closed #12435 — the both-sides discipline: the doc and the enforcement state agree.
- [ ] Red-proof: the seeded `ai/` mutation is blocked; removing the scope widening lets it through.

## Out of Scope

- The matcher grammar (identifier-shape, `$Config`, allowlist) — closed by PR #15839 under #15838.
- The PascalCase rename (#13532) and its seeded-fire AC amendment (that AC lives on #13532, re-homed to its owner).
- Config-varying (Class-B) leaves — no by-construction story yet, as the lint documents.

## Live evidence for this ticket, from someone else's boot-fatal crash

@neo-fable-clio root-caused her #15803 AC-5 parity-boot failure to `ai/mcp/server/shared/logger.mjs:365` (#15875), and it is a textbook instance of what this ticket describes.

**The defect** — an A1 re-derivation of a config-owned path, inline in the fallback chain:

```js
const logDir = loggerConfig.logPath || data.logPath ||
    path.resolve(data.neoRootDir || data.projectRoot || process.cwd(), '.neo-ai-data/logs');
```

`process.cwd()` as the terminal fallback re-derives the canonical logs root from ambient state rather than resolving it from `AiConfig` — the pattern ADR-0019 §3 lists as A1 (re-derive / env-read). In a container whose cwd is not the plane root it silently resolves somewhere else, which is how it presented as boot-fatal rather than as a wrong path.

**Why no gate caught it — the mechanical proof this ticket asked for:**

```js
// buildScripts/util/check-aiconfig-test-mutation.mjs:290
spawnSync('find', ['test', '-type', 'f', '-name', '*.mjs'], {cwd: gitRoot, …})
    .filter(f => f.startsWith('test/'));
```

The gate walks `test/` and filters to `test/`. **It is structurally incapable of seeing `ai/`.** Not a missed pattern, not a rule gap — the file is outside the scan set by construction, so no amount of rule-tightening inside the checker would reach it.

That is exactly this ticket's premise, and it now has a live reproducer instead of an argument: a **boot-fatal** A1 violation, in production `ai/` code, in a file the enforcement cannot read.

**What this sharpens:**

- The severity framing here has been "enforcement completeness" — a coverage gap. Clio's crash upgrades it: the uncovered region contains a defect that takes a stack down at boot, so the gap is not theoretical debt.
- It also bounds the fix. Extending the scan to `ai/**` is not merely more coverage — `ai/` is *production* code, where the B4 test-mutation rules do not apply unchanged. A1 (re-derive) and C1 (non-entrypoint import) are the classes that transfer; the test-only rules are not. Whoever takes this needs that split explicit, or the extension will produce noise and get muted.

**Not claiming Clio's fix.** #15875 is hers and correctly scoped — she found it by booting the thing. This is the enforcement-side evidence, recorded here so it does not live only in a crash report.

## Enforcement-sufficiency audit (intake §9.2) — the fix does not belong where this ticket puts it

The ticket's premise holds: `check-aiconfig-test-mutation.mjs` scans `test/` only. But its *implied* fix — extend that scanner to `ai/**` — is wrong, and the audit is what caught it.

### `ai/**` is already scanned, by a different lint

`ai/scripts/lint/lint-config-template-ssot.mjs:59` — `const SCAN_ROOT_REL = 'ai'`, walking every `.mjs` under it. It already carries two A1-adjacent detectors: **inline-env leaf defaults** and **module-scope leaf captures**.

So extending the B4 test-mutation checker to `ai/**` would stand up a **second scanner over the same tree with overlapping rules** — the duplication ADR-0019 exists to prevent, added by a ticket written to serve that ADR. The A1 rules belong in the lint that already owns `ai/**`.

### The real gap is narrower and sharper than "never scans `ai/**`"

The existing module-scope detector says so itself:

> *"Function bodies and module-scope functions that read AiConfig when invoked are **intentionally out of scope**."*

That exclusion is **correct for the harm it targets** — a value frozen at module-evaluation time can be ignored by a runtime self-heal. A function-body read is re-evaluated per call, so it is genuinely not that defect.

**But A1 covers two different harms, and only one is enforced.**

| harm | mechanism | covered? |
|---|---|---|
| **staleness** — a resolved leaf frozen at module load | `detectModuleScopeAiConfigCaptures`, `depth === 0` | ✅ module scope only |
| **ambient re-derivation** — inventing a config-owned value from `process.env` / `process.cwd()` | — | ❌ **nothing, at any scope** |

#15875 is the proof. Its boot-fatal defect lived at `logger.mjs:365` **inside a function**, and its harm was not staleness — it was `process.cwd()` as a terminal fallback silently re-deriving a path the config owns. The staleness detector would not have flagged it at module scope either, because staleness is not what was wrong.

### Census: the class is live in 32 places

```
$ rg -n --glob 'ai/**/*.mjs' 'process\.(env\.[A-Z_]+|cwd\(\))\s*\|\|' | wc -l
32
```

Across `deploy/`, three MCP `Server.mjs`, two `toolService.mjs`, `MemoryCoreRecorderService`, `seatMemoryLayerTemplate` and more. `logger.mjs` itself is now clean — @neo-fable-clio's #15876 fixed the exemplar — so this is 32 *other* instances of a class whose one known instance was boot-fatal.

Not all 32 are violations; some will be legitimate host-boundary reads where no config leaf exists yet. Classifying them is the work, and the count is the argument that the work is worth doing.

### Revised prescription

1. **Detector lands in `lint-config-template-ssot.mjs`**, beside the two A1 detectors it already runs, sharing its `SCAN_ROOT_REL` walk. No second scanner.
2. **Target the re-derivation harm explicitly**, at any scope — the module-scope restriction belongs to the staleness detector and must not be copied across, since it is exactly what let #15875 through.
3. **Baseline the 32**, mirroring how this lint already baselines its existing classes, so the ratchet bites new offenders while the census burns down. That is the #15887 shape, and it is the same trap: an entry must carry a justification, never a migration promise.
4. **C1 still sequences behind PR #15896**, unchanged from the classification above.

This narrows the ticket further and makes it cheaper: no new scanner, no new walk, one detector plus a baseline in a lint that already runs on every PR.

Proceeding on that shape.

And that one is `ai/deploy/mock-openai-embedding-server.mjs` — a standalone test double with no AiConfig in scope by design.

**So the class is empty.** The other 23 are genuine host-boundary facts with no leaf to defer to: `NEO_AGENT_IDENTITY`, `USER`, `PATH`, `ComSpec`, `TMUX_SESSION`, `XDG_DATA_HOME`, `NEO_SESSION_ID`. A regex-shaped `process.env.X ||` detector would have flagged **~31 of 32** as violations. That is the muting mechanism, delivered.

### cwd re-derivation: 36 sites, ~2 genuine

`process.cwd()` is the shape that actually caused #15875. But the census splits cleanly, and most of it is *good* design:

| shape | example | verdict |
|---|---|---|
| **injectable default param** — `cwd = process.cwd()` | `PolicyService:100`, `heartbeatLock:136`, `structureMap:204`, `PrimaryRepoSyncService:197` | **correct** — the caller can override; this is `planeConfig`'s own idiom |
| **standalone CLI/diagnostic** | `check-substrate-size:11`, `audit-discussion-lifecycle:20` | **correct** — cwd is the intended input |
| **the config establishing its own anchor** | `configBase.mjs:16`, per-server `configBase.mjs:8` | **correct** — nothing sits above it to defer to |
| **config-owned path re-derived from ambient cwd, no seam** | see below | **the actual defect** |

Genuine candidates, and there are two:

- **`ai/agent/AgentOrchestrator.mjs:71`** — `path.resolve(process.cwd(), '.neo-ai-data/agent-orchestrator/golden-path-outcomes.jsonl')`. This resolves **into the plane data root** from ambient cwd. It is a plane-member path that never declared itself a plane member, which is the alternate-realities defect the plane epic exists to remove.
- **`ai/agent/AgentOrchestrator.mjs:40`** — same shape into `resources/content/`.

`syncGithubWorkflow.mjs:56` is borderline: it reads the config chain first and uses cwd only as a terminal fallback — the #15875 shape exactly, but with a real config read ahead of it.

### Why a lint is the wrong artifact here

Two sites do not justify a detector, and the false-positive ratio measured above (~31:1 on the naive form, and the decidable form matches almost nothing) means any lint broad enough to catch them would be muted within a week. That is negative-ROI substrate by intake §9.2's own test — and I would be adding it to the very lint whose blind spot I documented an hour ago.

**Worse, the two genuine sites are invisible to the runtime guard too.** `assertPlaneMemberCoherence` checks *declared* members against the resolved root; an ad-hoc `path.resolve(process.cwd(), '.neo-ai-data/…')` never declares itself, so the boot assertion cannot see it either. The gap is real — it is just far smaller and differently shaped than "the gate never scans `ai/**`" implies.

### Revised scope, third narrowing

1. **Fix the two `AgentOrchestrator` sites** — derive from the resolved `AiConfig.plane.dataRoot` instead of ambient cwd. Small, and it removes a live plane-coherence violation.
2. **Drop the general A1 lint.** Measured empty on the decidable definition; the undecidable definition is a noise generator.
3. **Consider a narrow guard instead** — flag `process.cwd()` composed into a `.neo-ai-data` path, which is mechanically decidable, has a stated harm, and would have caught both sites. That is a candidate, not a commitment; two instances may not justify even that.
4. **C1 half still sequences behind PR #15896**, unchanged.

The ticket's premise was true and its evidence (#15875) was real. What the census changes is the *prescription*: the class is a handful of instances to fix, not a population to mechanize.
