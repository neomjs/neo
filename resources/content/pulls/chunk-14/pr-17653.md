### What the two layers do

**Layer 0 — resolution denial (fixture, real resolver).** OS-temp two-root fixture with an independently installed nested `cloud/`; ancestor-`node_modules` guard walking to the filesystem root; root-anchored `resolve-probe.cjs` so each root's OWN resolver answers; denial plus dual controls — dead-control (Cloud cannot resolve its own driver) and resolved-via-ancestor (`realpathSync`, because macOS `/var`→`/private/var` falsifies a naive `startsWith`).

**Layer 1 — static closure.** What an Edge entrypoint's source graph REACHES, scored against reconciled registry dispositions. Two instruments, because one cannot see half the question: `walkCapabilityClosure` treats a bare package specifier as a leaf and never follows it, so `reached` holds relative module paths only — an arm hunting Cloud *packages* there could never fire. Package reach comes from `collectModuleFacts().imports` through `normalizeSpecifier`, so a deep import compares equal to its package.

No fixture and no `npm install` for layer 1: static closure asks what source reaches, and source is source, so it runs against the real head rather than fixture truth. Injected `readFile`/`resolve` carry the red arms.

Instrument integrity keeps layer 0's doctrine. An unaccounted unresolved edge makes a plane-clean verdict UNSOUND, so it invalidates the run instead of becoming a topology finding; a ledgered edge is accounted for and stays silent. A resolved-but-unreadable module is the instrument error ONLY — scoring it as `unregistered` would report one defect twice and point the population owner at a repair that cannot fix it.

## Deltas from ticket

Named trigger, not a partial: wire on #17650 merge, then layer 2.
