What it should be

The bar is a control room, not a config panel: you see the whole fleet's state at a glance, watch its work stream in real time, and command it — start, stop, restart — without a terminal. A live multi-agent fleet with high-frequency streams, views that split across monitors on one heap, object-permanent state: this is the exact app Neo's engine is built for. Done right it's the flagship demo. Done as it is now, it undercuts the whole story.

03

The lanes that build the product

peers self-select; owners are suggested
Lane A

The shell

owner: Ada (holds #13033)

Electron build root — boots the Agent OS in-process, one window serves the harness app. Nothing UX-real exists until the shell hosts it. This is the critical-path head; everything downstream waits on it.

  • A1Electron build root boots; Agent-OS main-process host; child-process supervision as the capped fallback.
  • A2Multi-window primitive — a view splits into a second OS window on the shared App-Worker heap (the one Neo-native proof).
  • A3Re-invoke mechanism lives here — the FM hosts the instances, so waking a parked agent = the host re-invoking a process it owns. Not an external-harness sidecar thrown away in v13.2 (Vega's insight).
Lane B

The cockpit — UI / UX

owner: Fable (fresh) · design-led

The product surface above, built to the direction in §01. This is the lane that decides whether the FM is a flagship or an embarrassment — it gets a real design pass, not a form generator. Consumes Clio's #13158 docking as the container contract.

  • B1Cockpit shell + fleet grid — live agent cards (status form + family rail + current-lane line); the health summary bar.
  • B2Live activity stream — A2A / PR / lane-state events, real-time, bounded. The engine's real-time story made visible.
  • B3Agent detail + pop-out — drill into one agent (thought-stream, lane, repo, PRs); drag to its own OS window.
  • B4Controls — start / stop / restart per agent + whole-fleet; the one-click morning start.
Lane C

The wiring

owner: Euclid / GPT (NL/MCP lane)

Neural Link / MCP bridge: the cockpit reads the existing fleet-services spine (the 16 closed Brain leaves) live. No faked state — status/activity come from the real services or degrade honestly. This is where "the spine is done" finally pays off.

  • C1Live status/activity feed — bridge the lifecycle + A2A + PR services into the cockpit's real-time streams.
  • C2Control round-trip — cockpit start/stop/restart → the lifecycle service → settle-or-reject the runtime MCP-restart class.
Lane D

Credentials + onboarding

owner: Opus (conserve) · security-sensitive

The "add an agent cold" flow + the credential boundary the MVP names. PATs stay Brain-side, encrypted at rest, never transit the browser — the two-hemisphere security rule is non-negotiable here.

  • D1Add-agent flow — username + PAT + harness type → the Node-side registry (#13031 exists); the UX for it does not.
  • D2Encrypted PAT-at-rest — OS keychain / encrypted store; the credential-boundary AC.
  • D3Remote-tenant connect — tenant URL + PAT → remote MC/KB (the design-partner cohort's actual entry).

05

Surface Registry

direction + constraints; spec detail lives in build-ticket ACs

One compact entry per cockpit surface: placement, object-model, composition constraints, scope state. Entries are the citation target for build tickets (the #15242 sign-off pattern) and the bar the next conformance audit checks against. Dispositions ruled in D#15249; visual primitives stay centralized in TOKENS.md · CARD-CONTRACT.md · VisualSystem.md — the registry references them, never re-specs them.

S1

Agent mailbox pane

v13.2 · read-onlyruled: D#15249

A tab inside AgentDetail — object permanence: the mailbox belongs to the agent object, not to a global inbox view. This is the observe-the-swarm telemetry surface, and read-only is its complete form.

  • modelFlat-chronological rows with thread-collapse where partOfThread exists. Freshness labels the pane (data-as-of) — messages are immutable timestamped facts; per-row freshness is noise.
  • must-notNo operator mark-read. Unread IS the swarm's actionable queue — an operator-side mark silently swallows peer handoffs. Reply-as-operator is deferred with chat: it needs the operator-as-sender authority contract first (distinguishable sender identity, owning service, audit trail).
  • composeDock-liftable later under the docking grammar (D#15204) — no dock coupling at first render. Convergence rule: chat (v13.3) is the actionable evolution of THIS pane; a second parallel communication surface is forbidden.
S2

Wake + throttle telltales

v13.2ruled: D#15249 · pairs #14537

Two orthogonal state axes, never one enum — the lived incident this design answers had both at once (wake daemon hand-disabled + a session rate limit, both invisible in the cockpit). Pure composition of existing primitives; the taxonomy below is the only new vocabulary.

axisstatesrender rule
wakeon · off · suppressed · unknownException-based: nominal earns zero card pixels (the #15037 density contract); any non-nominal state on either axis earns exactly one compound chip; the full two-axis readout lives in detail. Honest degradation: unknown renders as unknown — never as healthy.
throttlenone · overage · rate-limited · unknown
  • truthWake state has substrate today (#14537's control verb + the daemon toggles). Throttle truth has no service surface yet — a named W2 wiring leaf; the telltale ships with unknown as the honest default until it lands. Design never blocks on wiring.
S3

Catch-up view

v13.2ruled: D#15249 · feeds #14620

A projection of the ActivityStream (#14606) — same feed contract, digest mode. Invoked, not ambient, so the density contract does not bite. A separate surface would fork the feed contract; this entry forbids that fork.

  • modelFleet digest is the entry; agent digest is the drill-down — the cockpit's fleet→agent object model, applied to time.
  • anchorAn explicit "mark caught-up" pins the anchor; soft fallback = last cockpit visit for first-run. Last-operator-action is rejected — it conflates reading with acting.
S4

Chat

deferred · v13.3ruled: D#15209 beats 5–6

Out of v13.2 by criticality, not capacity: operator↔agent chat is not on the front-door critical path, and shipping it without the operator-as-sender authority contract would be the half-baked failure mode applied to a brand-new surface. Design prior art stands (chat-creation-plan.html). When it returns, it evolves S1 per the convergence rule — one communication surface, maturing read-only → actionable.
