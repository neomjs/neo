# One navigation vocabulary for the cockpit shell: keeper tabs vs edge-rail items

## Context

Operator critique 2026-08-16, verbatim intent: "huge tabs left, default neo styling (tab bar), versus tiny menu items at the right edge" — the shell speaks two navigation dialects at once, and neither is designed for this surface.

**Scope widened 2026-08-18 (operator session, full IA audit):** the shell in fact speaks FOUR grammars, and the model must also reserve places for three surfaces the operator named (instance switcher #17328, Tasks pane #17329, System view #17330). The audit's findings live in the navigation-model decision comment on this ticket.

## The Problem

The cockpit's "places" are reachable through visually unrelated vocabularies:

1. **Keeper-view navigation** renders as default-Neo tab-bar styling (framework-default size and skin — correct for a demo app, undesigned for the product surface).
2. **The auto-hidden drawer panes** render as small edge-rail tabs on the right — SEVEN items mixing three kinds (inspector, tools, content reading surfaces) in one squeezed strip.
3. **The top preset buttons** (`fm-preset-button` row) LOOK like view tabs but are dock-layout snapshots (`activatePerspective`) — including a name collision: "Fleet" (preset) and "Fleet" (keeper tab) are simultaneously visible and mean different things (`apps/agentos/view/fleet/cockpitPresets.mjs`).
4. **The best path is invisible:** clicking an agent-card name opens the detail WITH content, while the explicit Review preset lands on the "Select an agent to inspect" empty state — implicit navigation beats the chrome.

The result: the SAME class of act — "go to a place" — looks like different applications, and the size relationship is inverted relative to importance (primary navigation huge and default-styled, secondary drawers tiny and cramped; the fleet's proven headline reading surface, Memories, sits as rail item 5 of 7 while the fixture-fed Activity zone owns ~40% of the screen). #17211 fixes the rail's sizing DEFECTS; this ticket decides and designs the vocabulary those fixes should express.

## The Fix

Design-first: ONE navigation model for the shell, answering — what deserves a persistent tab, what lives on the edge rail, what is a transient drawer, what is chrome; one designed tab anatomy for the cockpit (replacing framework-default tab styling on this surface with §04-consistent type/density/mark treatment); the rail as the DESIGNED secondary tier (consistent anatomy at its size, not a squeezed afterthought); the preset switcher de-costumed into an explicitly-labeled layout control (no longer tab-shaped); the south zone as the fleet-level content-tab family (Activity · Tasks · Memories · Mailbox · Catch-up — expressible as pure dock-document data, `cockpitDockDocument.mjs` `stream-tabs` items). Then implement across the keeper navigation + the rail chain, tokens-only, without changing the dock mechanics underneath.

## Navigation-model decision — DRAFT for the AC1 spec-first review

Operator-directed IA audit, live session 2026-08-18. Every claim below is source-verified, not screenshot-interpreted. This comment is the one-page decision AC1 demands; the body carries the widened scope.

### Findings: four grammars, one inversion

| # | Grammar | Evidence | Defect class |
|---|---|---|---|
| G1 | Keeper tabs (left) | `apps/agentos/view/Viewport.mjs` — `tab.Container`, `tabBarPosition:'left'`, framework-default skin | undesigned primary |
| G2 | Top preset buttons | `cockpitPresets.mjs` — "Focus" = `sizes:[0.85,0.15]`, "Review" = `sizes:[0.45,0.55]` + `detail.autoHidden=false`; handler `activatePerspective` | layout actions costumed as tabs; **"Fleet" preset vs "Fleet" keeper tab name collision, both visible at once** |
| G3 | Right edge rail | `cockpitDockDocument.mjs` `secondary-rail` — 7 `autoHidden` items across 3 kinds: inspector (detail) + tools (perspectives, add-agent, wake-routes) + **content reading surfaces** (catch-up, memories, operator-mailbox) | mixed jobs in one squeezed tier |
| G4 | Implicit card-name click | card header → detail WITH the agent loaded; the explicit Review preset → "Select an agent to inspect" | best path invisible; explicit path lands empty |

**The inversion:** the Memories pane — the surface the `#17271` L1 session proved as the fleet's headline reading surface — is rail item 5 of 7 in miniature vertical text. The Activity zone — still `FIXTURE_ACTIVITY` sample data — permanently owns ~40% of the screen. Importance and reachability are inverted.

### Decision criteria (tab vs rail vs drawer vs chrome)

- **South content tab** — fleet-scoped continuous READING surface an operator returns to many times per session.
- **Keeper view** — a distinct SUBJECT (fleet vs planes vs identities), not a variant of an existing one.
- **Right tier** — selection-scoped INSPECTION (context of the current selection, opened by selecting).
- **Invoked/transient** — tools and forms: used, then dismissed. Never resident.
- **Top chrome** — root context + instance-wide actions/status. Nothing navigational.

### Target model

| Region | Job | Content |
|---|---|---|
| Top chrome | root context + actions | instance switcher (#17328) · Start fleet · Reconnect/banner · wake telltale · **layout control** (presets, explicitly labeled, de-costumed; "Fleet" preset renamed e.g. "Overview") |
| Keeper rail | places | Home · Fleet · **System** (#17330) · Accounts · Chat |
| Fleet center | ambient WHO | grid + health bar |
| Fleet south tabs | reading surfaces | Activity · **Tasks** (#17329) · Memories · Mailbox · Catch-up |
| Fleet right | inspector | Agent detail only — card-name click opens it loaded; Review preset pins it; empty-state repaired (last-inspected default) |
| Invoked | transient tools | Add agent (already ruled invoked-not-ambient) · Compose · Wake routes |
| Settings | rare | instance profiles (#17328) · theme |

**Proof of cheapness:** the south-tab family is pure dock-document data — `stream-tabs` is a `tabs` node holding one item today; multi-item tabs nodes, cross-zone drops, and snapshot rematerialization are already shipped mechanics. The target's first cut edits `cockpitDockDocument.mjs` + `cockpitPresets.mjs` only.

### Implementation cuts (landing order)

1. **Document + presets** — south-tab family, preset rename, Review empty-state default. Small, immediately visible, no new mechanics.
2. **Tab anatomy design** — THIS ticket's core: designed keeper-tab + rail + south-tab anatomy, §04 ladders, tokens only.
3. **Content design per pane** — #17268, unchanged.

Coordination: #17211 (@neo-opus-grace) — if cut 1 moves three content panes south, the rail's remaining population is inspector + tools; the sizing work shrinks in scope, same defect class. #17313 geometry is unaffected structurally; landing order coordinated. #17315/#17316 (memories pop-out/drill-in) are placement-orthogonal and proceed.
