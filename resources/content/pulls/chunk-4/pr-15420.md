## Premise

The successor gate to my own #15353/#15355 CodeQL-coverage lane. **A file CodeQL cannot parse produces zero alerts, so it clears the alert-gate (ruleset 19087298) clean** — "unparseable" and "clean" are indistinguishable at every gate we had. #15353 fixed the one file (`serving-cost-meter.mjs`); this is the general mechanical guard so the *next* unparseable file fails CI instead of silently dropping scanning coverage.

## The trap the obvious implementation falls into

The intuitive oracle — `analyses[].warning` — is **empirically empty** on a run whose own Analyze-job log carries the drop (Clio-verified on run 29568877624; re-confirmed here). I also probed the API-served SARIF: it **strips `invocations`** (`invocations: 0`), so its `toolExecutionNotifications` are gone too. Both API surfaces are non-discriminating.

The surface that stays honest is the **Analyze-job log**, where the extractor writes its own verdict (both forms **verified byte-for-byte** against run 29568877624's real log):
- `##[group]Could not process some files due to syntax errors (N results)` — authoritative group header
- `  * <repo-path>#L<line>C<col>:<col>: A parse error occurred: ...` — per-file bullet

## The gate

A `needs: analyze` guard job fetches **every completed Analyze matrix leg's log** for this run via the Actions API and fails CI naming the dropped file(s) and leg(s). It **complements, never duplicates** the alert-gate (alerts and processing-warnings are different signals).

- **Fail-closed:** an unreadable leg log exits non-zero, never certifying clean from a surface it never read.
- **Correctness anchored on the group header:** a dropped file fails the gate even if the per-file bullet format drifts.
- **Matrix-robust:** every matching Analyze leg is inspected; a drop in any leg fails the aggregate gate.
- **Dependency-free:** Node built-ins + global `fetch`, so the guard needs no `npm install`.

## Deltas

| Area | Before | After |
|---|---|---|
| Unparseable-file coverage loss | invisible — zero alerts ≡ clean; `analyses[].warning` empty; served SARIF strips invocations | a `needs: analyze` guard reads every Analyze-leg log and fails CI naming the dropped file(s) and leg(s) |
| Discriminating surface | none consumed | the extractor's own log verdict (group header + per-file bullets), verified against a real drop-log |
| Matrix coverage | first matching Analyze job could certify the run | every matching leg is fetched and aggregated fail-closed |
| Failure mode on an unreadable surface | n/a | fail-closed (exit non-zero) |
