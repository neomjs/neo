A live multi-agent fleet with high-frequency streams, views that split across monitors on one heap, object-permanent state: this is the exact app Neo's engine is built for. Done right it's the flagship demo. Done as it is now, it undercuts the whole story.

State reads at a glance

Status is encoded in form, not just text — an avatar (the keeper from the implemented view), a colored pulse, a family rail, a one-line "what it's doing now." You know the fleet's health before you read a word.

Real-time is the spine

The activity feed and every status is live — no refresh. This is where the engine's 40k-updates/sec, object-permanent architecture stops being a claim and becomes the product.

Operable cold

Add an agent = a name + a token. Start the fleet = one button. The success test is a person who has never seen it running their team by end of the first morning.

The lanes that build the product

peers self-select; owners are suggested
Lane A

The shell

owner: Ada (holds #13033)

Electron build root — boots the Agent OS in-process, one window serves the harness app. Nothing UX-real exists until the shell hosts it. This is the critical-path head; everything downstream waits on it.

  • A1Electron build root boots; Agent-OS main-process host; child-process supervision as the capped fallback.
  • A2Multi-window primitive — a view splits into a second OS window on the shared App-Worker heap (the one Neo-native proof).
  • A3Re-invoke mechanism lives here — the FM hosts the instances, so waking a parked agent = the host re-invoking a process it owns. Not an external-harness sidecar thrown away in v13.2 (Vega's insight).
Lane B

The cockpit — UI / UX

owner: Fable (fresh) · design-led

The product surface above, built to the direction in §01. This is the lane that decides whether the FM is a flagship or an embarrassment — it gets a real design pass, not a form generator. Consumes Clio's #13158 docking as the container contract.

  • B1Cockpit shell + fleet grid — live agent cards (status form + family rail + current-lane line); the health summary bar.
  • B2Live activity stream — A2A / PR / lane-state events, real-time, bounded. The engine's real-time story made visible.
  • B3Agent detail + pop-out — drill into one agent (thought-stream, lane, repo, PRs); drag to its own OS window.
  • B4Controls — start / stop / restart per agent + whole-fleet; the one-click fleet start.
Lane C

The wiring

owner: Euclid / GPT (NL/MCP lane)

Neural Link / MCP bridge: the cockpit reads the existing fleet-services spine (the 16 closed Brain leaves) live. No faked state — status/activity come from the real services or degrade honestly. This is where "the spine is done" finally pays off.

  • C1Live status/activity feed — bridge the lifecycle + A2A + PR services into the cockpit's real-time streams.
  • C2Control round-trip — cockpit start/stop/restart → the lifecycle service → settle-or-reject the runtime MCP-restart class.
Lane D

Credentials + onboarding

owner: Opus (conserve) · security-sensitive

The "add an agent cold" flow + the credential boundary the MVP names. PATs stay Brain-side, encrypted at rest, never transit the browser — the two-hemisphere security rule is non-negotiable here.

  • D1Add-agent flow — username + PAT + harness type → the Node-side registry (#13031 exists); the UX for it does not.
  • D2Encrypted PAT-at-rest — OS keychain / encrypted store; the credential-boundary AC.
  • D3Remote-tenant connect — tenant URL + PAT → remote MC/KB (the design-partner cohort's actual entry).

S1

v13.2 · read-onlyruled: D#15249

A tab inside AgentDetail — object permanence: the mailbox belongs to the agent object, not to a global inbox view. This is the observe-the-swarm telemetry surface, and read-only is its complete form.

06

The design bar — type, density, chip & motion, specified

the contract the §04-pass implementation subs score against

The cockpit's mechanics landed leaf by leaf; its visual language was never designed — three status-chip idioms grew up independently in one month, type and density were never laddered, iconography is library default, motion is one mechanism. This section is the bar, at implementable depth: five ladders, each with its token contract (values live in TOKENS.md — the §04 token appendix) and an acceptance sketch. It specifies; it does not restate the honesty SEMANTICS the idioms already share — those are landed and referenced, never re-litigated. The token contract is a floor, not a ceiling: a delta is a recorded design decision on a ticket, never silent drift (the standing TOKENS.md rule).

T1

Type + density ladder

consumers: every cockpit surface; the rail/drawer ergonomics subs

Five type roles, as tokens — no seventh size. A surface picks a ROLE; it never picks a pixel. The measured population below the display tier is six sizes, three of them within 1px of a neighbour (12.5 / 12 / 11 / 10.5 / 10 / 9 across 68 literals) — accumulated drift, not a scale. This ladder is a correction of that population, not a description of it: values codify the covered share, the disposition row rules the rest, and the only deliberate moves beyond it are the rails/drawers ergonomics findings this pass answers.

T2

The chip system — one family, five current idioms

consumers: every status/kind surface

One designed family: mark + text + optional detail affordance. The mark carries severity/kind in geometry and token color; the text carries the whole message; the detail affordance (title/drill) answers what the chip had no room for. Three classes on one class axis — exception-only (nominal earns zero pixels), always-rendered (furniture that must be findable before it matters), affordance (an action, never an observation). Color is always supplemental and token-only: the text is the message, the mark is the accent — neither channel load-bearing alone (WCAG 1.4.1 as design law, below).

T3

Iconography — which glyphs are load-bearing

consumers: controls, rails, drills

The cockpit's icons are library default (Font Awesome via button glyph). The bar is not a custom set — it is a stated rule for where a glyph may carry meaning at all, and a review venue for the ones that mislead.

  • ruleLoad-bearing glyphs are the short, named list: the control verbs (state-derived play/stop, restart — AgentCard, actions-in-flow), the tear-out/pop-out affordance, the rail entries (add-agent, perspectives, the drawer panes), the fleet-start verb. Every other glyph is decoration and may be swapped without a design decision.
  • must-notNo icon-only state, no icon-only kind. State and kind are text+mark (the chip system); an icon may decorate, never substitute. No expander glyph on the card — the name is the one disclosure route (CARD-CONTRACT, deliberate).
  • replaceDefaults get replaced only where they mislead — a glyph whose library meaning fights its cockpit meaning (candidate class: restart-as-undo, wake-as-bell). Replacements land token/class-level (SCSS skin layers only, zero CSS-in-JS) and are recorded on the implementing sub.
  • sketchAcceptance: the load-bearing list above renders in the baseline with accessible names matching visible purpose (icon buttons keep tooltips per the VisualSystem interaction contract); a grep finds no glyph-only state or kind carrier.

T5

Instants — viewer-local presentation, UTC wire

consumers: activity stream, catch-up, memories, wake-route; every future pane rendering a time

Four surfaces rendered instants and all four derived their string from UTC. The drift was not four competing formats — it was one format copy-pasted three times plus a variant, which is the harder kind to see, because each surface looks locally consistent and no one owns the rule. An operator seat in Europe/Berlin did offset arithmetic on every glance at surfaces whose whole purpose is at-a-glance truth. This ladder makes the presentation edge a rule rather than a habit; it does not touch the wire, and the distinction between the two is the substance.

layerrulewhy it is that way
wire (DTOs, envelopes, receipts)ISO-8601 UTC, always. Never localised, never written back from a viewreceipts and cross-agent evidence tables depend on wire-time being zone-free — two agents citing one instant must produce the same string
human textViewer locale + zone via Intl.DateTimeFormat, through the one shared helper (util/ViewerTime.mjs)the reader is a person in a chair, not a log parser; a surface built for glancing must not require arithmetic
same-day vs oldersame viewer-calendar day → time only; older → compact locale date + timea bare 10:15 on a three-day-old row is misleading rather than terse; the day boundary is judged in the VIEWER's calendar, never UTC's
receiptthe exact ISO instant rides title / hoverthe operator and the agent citing the row as evidence are both served, so neither has to lose
miss-copythe helper returns null; the surface owns its own empty wordsa dense stream row wants —, a prose pane wants unknown time — collapsing them trades a real duplication for a fake uniformity
  • bindingNo bespoke per-surface formatter. A surface that needs a time imports the helper; a surface that needs a NEW shape extends the helper and this row, never its own local copy. That is the rule the four duplicates existed for want of.
  • testingPin the zone in specs that assert formatted output — an ambient-zone assertion passes in a UTC runner while proving nothing about the defect, since the runner's own zone is the one case that cannot detect it. Pane specs assert the SENTENCE they compose; the format contract is proven once, against a pinned locale and zone.
  • sketchAcceptance: zero toISOString()-derived human strings in cockpit views (greppable); a viewer in a non-UTC zone reads local wall-clock with the ISO instant on hover; the same-day ladder flips on the viewer's midnight, not UTC's.
