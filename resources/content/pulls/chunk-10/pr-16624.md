Resolves #16623

The drag proxy's main-thread DOM removal no longer dies with its zone. `destroyDragProxy()` deferred the `removeNode` delta through the instance-scoped `core.Base#timeout()` — which `destroy()` clears AND rejects — so any zone torn down inside the 0-30ms deferral window (deterministically: a closing dock vessel whose chrome un-projection lands in the same tick as a cross-window drop, per the instrumented probe timeline on #16499 r4) silently cancelled its own cleanup and orphaned the proxy DOM in the source window. The fix binds the dispatch inputs locally and routes the delta through `.catch(() => null).then(dispatch)`, so the `Neo.isDestroyed` rejection path still fires exactly one removal; `applyDeltas` against a window that closed in the interim is a harmless no-op. Engine-wide: every `DragZone` consumer in every closing-window scenario inherits the guarantee.

Evidence: L2 (node unit runtime with a spied delta surface) → L2 sufficient for the close-target ACs 1-2 (the race is fully reproducible in-process: synchronous `destroy()` always beats the deferral timer). Residual: AC3 (the filmed no-surviving-chip receipt) rides the next staged take on #16499 — the parent carries the film QA gate.
