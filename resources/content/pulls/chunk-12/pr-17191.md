Resolves #16929

> 🌿 A directory name, a header, a token list — every retired attempt asked the code what it was called. This one asks what it reaches, and the difference is that the code cannot lie about the second.

Derives each `ai/scripts` entrypoint's execution plane from its transitive capability closure, cross-checks it against the orchestrator's declared authority, and projects the result into the structure map.

Evidence: L4 (93 arms over the resolver, the map projection and the parity registration, red-proved eight ways, plus the whole lint run against the real 62-entrypoint population) → L4 required (every AC is a local, in-process observable). Residual: none.

## Deltas from ticket

**The ticket's own Fix step 1 cannot satisfy the ticket's own red-proofs, and I measured that rather than discovering it in review.**

Step 1 says *"walk each entrypoint's static import graph to fixpoint, collecting reached capabilities."* Both sound readings of that fail, in opposite directions:

| reading | `backup` (AC-4) | `githubWorkflowSync` (AC-3) |
|---|---|---|
| every REACHABLE capability | **host-required — convicts the ADR** | host ✓ |
| only what executes on import | not host ✓ | **not host — the false negative** |

Counting everything reachable marks `backup.mjs` host-required, because its closure reaches `spawn` inside `ConnectionService.spawnBridgeProcess()`, `execFileSync` inside a `collect` arrow in the skill-manifest lint, and `spawn` inside a `gitMirror` promise executor. **None of those run because `backup.mjs` was imported** — so the prescribed algorithm reproduces the exact false positive AC-4 exists to prevent. Counting only module-scope execution gives **0 host-edge of 62**, because real code puts shell calls inside functions.

**Reachability is not invocation.** The rule that satisfies both: a capability is required when the entrypoint's own code calls it, when a reached module runs it at module scope, **or when the entrypoint directly calls into a module that runs it** — one level, no further.

```
backup                 authority=container-plane   required=0
githubWorkflowSync     authority=host-edge         required=1
```

Same import-graph shape, opposite verdicts, and the only difference is the call.

**Two smaller deltas:**

- **AC-7's projection is opt-in (`--planes`), not default.** Measured, not stylistic: the closure walk costs ~2.2s against the structure map's ~160ms. Making a navigation tool 14× slower by default is how it stops being reached for. The default path now measures 63ms.
- **`shared-primitive` is a valid authority class the closure never derives.** It resolves host-edge or container-plane only, and defers to the authority when one exists. Recorded rather than papered over.

## The shape

**Requirement vs USE is the load-bearing distinction**, and ADR-0014 is the fixture that settles it. `backup.mjs` stamps a bundle with `git rev-parse HEAD` inside a swallowing try; the ADR rules that *not* a host dependency because it degrades to `null`. So a capability counts only when its call site can actually abort the program — a bare call, or one inside a `try` whose `catch` rethrows or exits.

That test needs real syntax, so this parses with `acorn` (already a direct dependency) and hand-rolls an ancestor visitor rather than adding `acorn-walk` for one traversal. **A regex over try/catch nesting would have been the same unit error the retired token classifier made, wearing a better costume.**

Authority is **consumed, never re-derived**. For a task in `TASK_AUTHORITY_BY_NAME` the declared class is the answer and the closure's job is to disagree loudly. The two directions are not the same defect: an in-plane declaration against a host closure means the script breaks where it is declared to run; the reverse is usually over-declaration or a runtime dependency static analysis cannot see.

**One soundness rule the ticket does not name**, added because the asymmetry is real: an unresolved edge makes a NO-HOST verdict unsound — the capability could hide behind the edge we could not follow — but leaves a HOST verdict standing, because more reachable code cannot remove a requirement already found.

## Two false negatives in my own detector, both caught by real fixtures

1. **`backup.mjs` reported ZERO capability sites.** It calls `const execFileAsync = promisify(execFile)`, and only import bindings were tracked — so the file ADR-0014 uses as its canonical fixture looked clean, rather than looking like a detector that cannot see. Fixed by tracking derivation through aliasing and single-argument wrappers.
2. **A silent-empty stub.** I first wrote `buildDefaultPlaneProjection()` returning `{}`, which would have rendered folders with no tally — indistinguishable from "this folder has no entrypoints". That is the exact silent-default shape this lane exists to remove, written by me, inside the lane about it. `includePlanes` without an injected projection now **throws**, pinned by an arm.

Neither was found by reasoning. Both came from running the thing against the real tree.

**Five of seven folders hold more than one plane.** That is the directory-keyed predicate's falsifier rendered as output rather than argued — the folders are named after the verb, and a name cannot tell you.

## On the unresolved population

27 of 62 entrypoints resolve to `null`, and **that is a finding rather than a shortfall.** The dominant cause is a single site — `ai/ConfigProvider.mjs:529`, `await import(absolutePath)` on a runtime-resolved overlay path — which alone blocks 8 entrypoints.

**Deliberately not special-cased.** A dynamic import on a runtime path could statically carry anything, and an exemption to make the number look better is precisely the hand-authored metadata this lane exists to remove. The lint ratchets the edge count against a measured baseline instead: it may only ever be lowered, because a baseline that can be raised records drift rather than gating it.

**Red-proved eight ways**, each a plausible wrong implementation rather than a strawman:

| mutation | arms failed |
|---|---|
| capability is REQUIRED whenever reached | 1 |
| drop promisify/alias derivation | 2 |
| unresolved edge falls back to a plane | 1 |
| stop reporting authority conflicts | 1 |
| treat `try/finally` with no catch as swallowing | 2 |
| promote deferred capabilities from ANY reached module | 2 |
| drop call attribution entirely | 1 |
| promotion overrides graceful degradation | 1 |
| **remove the scan-root registry entry** | **1** |

A defensive arm also caught a regression mid-lane: adding invoked-import tracking left the *unparseable* early return without an `invokedSpecifiers` field, so the walker threw on any tree containing one bad file. Its comment now records that it has earned its keep.

## Post-Merge Validation

Nothing is owed. Every AC is a local observable and each is armed. The new workflow exercises itself on the next PR touching `ai/**`.

One thing worth naming for whoever reads the lint's output next: **it is not a required status context** on `dev` (#17171), so a red result is loud and visible without making a PR ineligible to merge. The workflow header says so rather than implying a closure it does not have — a correction I had to make to my own spec-retirement workflow earlier today.

## Evolution

The instructive part is that the ticket's prescribed algorithm was wrong and the ticket's red-proofs were right. Had I implemented step 1 as written and trusted the ACs to catch it, AC-4 would have failed against an accepted ADR — but only if someone ran it against `backup.mjs` specifically. **The fixtures were load-bearing and the method was not**, which is a good argument for naming canonical fixtures in a ticket even when the approach seems settled.
