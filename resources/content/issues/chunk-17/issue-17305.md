# Fleet runtime status asserts 'stopped' for agents it never launched

## Context

Caught live by the operator during the #17271 L1 witnessed run (2026-08-17, "did i miss the window?"): every card in the live-roster cockpit renders **`benched / offline`** — nine of nine, header tally `9 benched / offline · 0 external harness` — while the SAME rows carry `participationStatus: 'active'` and, for the in-turn agent, `presence: {state: 'fresh', confidence: 'observed'}`. A card asserting "benched / offline" and "fresh" simultaneously contradicts itself on its own surface.

Observation vs inference separated: the store rows, header tally, and card labels are observed (Neural Link `inspect_store` receipts on #17271); the mechanism below is code-read, cited by line.

## The Problem

[`ai/services/fleet/FleetManager.mjs:187-206`](https://github.com/neomjs/neo/blob/dev/ai/services/fleet/FleetManager.mjs) — `fleetRuntimeStatus()` passes `lifecycle.status(agent.id)` straight through:

- For an agent the fleet **never launched** (no pid, no startedAt, no exitCode), lifecycle answers `state: 'stopped'`; the mapper only downgrades `confidence` to `'inferred'` and ships the state.
- The method's own doc promises: *"a row is `observed` when a process record backs it and `inferred` otherwise — **the state is never invented**."* But `stopped` for a never-started, non-fleet-managed process IS an invented state: never-launched ≠ stopped.

Display-side is contract-correct and NOT the bug: [`apps/agentos/CARD-CONTRACT.md:13`](https://github.com/neomjs/neo/blob/dev/apps/agentos/CARD-CONTRACT.md) reserves `off → "benched / offline"` for *"a process Fleet manages and knows to be stopped"* (echoed by `sourceHealth.mjs:272`), explicitly forbids `benched / offline` as *"a false participation verdict"* for unobserved rows, and already carries the honest `unobserved` vocabulary — the resolver just never receives it for wired rows, because the server asserts a session state it has no record for.

Effect: the entire external-harness fleet (the ONLY topology in production use today — all nine maintainers run under their own harnesses) renders as operator-benched. The one distinction the fleet's own registry could refute (`participationStatus: 'active'` sits on the same row) is contradicted by a fabricated lifecycle verdict. The pre-live sample path renders `unobserved` correctly — going live makes the display LESS honest, inverting the #17271 credibility goal.

## The Architectural Reality

- Truth law (fleetPresenceStateAdapter doc, same file family): *"a liveness tier a deployment cannot emit produces ABSENCE OF SIGNAL, never a verdict."* The runtime axis violates it for the no-record case.
- The `observed` flag at `FleetManager.mjs:192` already computes exactly the needed distinction (`status.state !== 'stopped' || status.pid != null || status.startedAt != null || status.exitCode != null`) — the row just doesn't use it for the STATE, only for confidence.
- Wire consumers: cockpit roster DTO → `resolveFleetDisplayState` (shared with the HealthBar tally) — fixing the producer heals card text, dot, and header counts together.

## The Fix

In `fleetRuntimeStatus()`: when NO process record backs the agent (the existing `observed === false` branch), emit the honest absence state (`unobserved` — reusing the CARD-CONTRACT vocabulary; alternatively a dedicated `external` if the display ladder wants the finer word) instead of passing through lifecycle's `stopped`. A REAL stopped record (fleet started it; it exited or was stopped) keeps `stopped`/`off` semantics — that is precisely the "operator-benched participation fact" the contract names. Verify `resolveFleetDisplayState` + HealthBar tally + header buckets restore the `external harness`/`unobserved` counts.

## Acceptance Criteria

- [ ] A registered agent with no fleet lifecycle record reports a runtime state distinct from `stopped` (absence of signal, not a verdict); the doc sentence "the state is never invented" becomes true.
- [ ] A fleet-launched agent that exited/was stopped still reports `stopped` (real record, unchanged semantics).
- [ ] Cockpit cards for external-harness agents render `unobserved` (or the chosen external word) — never `benched / offline`; header tally restores the external/unobserved bucket (red→green witness against today's `9 benched / offline` state).
- [ ] Unit coverage on the mapper: no-record vs real-stopped-record rows.

## Out of Scope

Richer idle/wedged/rate-limited states (the named watchdog-signals follow-up) · presence axis (correct today) · card visual hierarchy (#17303 / #17264 own chips and anatomy).

**Verdict: `valid-as-written` on premise and locus. The fix section needs one correction, and it is load-bearing.**

### The chain, traced end to end

Every hop verified against current `dev`, because the ticket's `unobserved` prescription turns out to depend on a vocabulary boundary the body does not mention:

1. `FleetLifecycleService.mjs:772` — no record → `{state: 'stopped', running: false, pid: null, startedAt: null, exitCode: null, …}`
2. `FleetManager.mjs:196` — passes `status.state` straight through; `observed` (`:192`) gates **only** `confidence`, exactly as the ticket says
3. `fleetCockpitStatus.mjs:238` — `state: runtime ? 'wired' : 'not-wired'`, where `runtime` is merely *"a row exists for this agentId"*
4. `sourceHealth.mjs:252` — **`state === 'stopped'` → `'off'`**
5. `sourceHealth.mjs:288` — runtime `wired` → return the state as-is → `'off'`
6. Card renders **`benched / offline`** ✅ — the operator's screenshot, reproduced by reading

### The correction: `unobserved` and `external` are **not raw states**

`CARD_STATES = ['ok', 'idle', 'wedged', 'limited', 'off']` (`sourceHealth.mjs:14`). `unobserved` and `external` are **outputs of `resolveFleetDisplayState`**, never inputs a producer may emit.

Trace what the ticket's prescribed fix actually does. Producer emits `unobserved`/`external` →
`mapFleetSessionHealth` reaches `!CARD_STATES.includes(state)` (`:256`) → **`downgradeRuntime()`** (`:218-227`), which returns `state: 'off'` **and rewrites the runtime source to `state: 'invalid'`, `confidence: 'none'`, `reason: 'lifecycle and runtime facts contradict'`.**

Then `resolveFleetDisplayState` sees a not-wired runtime with `off` and returns `external`.

**So the card word would come out right — via a source panel that fabricates a contradiction.** Nothing contradicts: the producer honestly said "no record" and the mapper called that a conflict between facts. That is the same class of defect this ticket exists to remove — an invented verdict — relocated from the state field to the reason field, and made *attention-bearing* on top (`invalid` is deliberately operator-visible).

A green card and a lying provenance panel is a worse outcome than today's honest-looking wrong word, because the wrongness moves somewhere nobody is looking.

### Second finding: the JSDoc contradicts itself, and the fix must resolve it

`FleetManager.mjs:178` documents *"an agent with no live process reads `state:'stopped'`"* — the current behaviour, stated as intent. `:183-184` documents *"the state is never invented."* Both sentences are in the same block comment. They collide precisely in the no-record case.

The reconciliation: `:178`'s real concern is that **every registered agent gets a row** so the cockpit renders the whole fleet — a row-existence guarantee, not a state assertion. Fixing the state satisfies both, but `:178` must be rewritten in the same commit or the next reader restores the bug from the doc.

### Shape I am implementing

The fix spans **producer + mapper**, not the producer alone:

- `fleetRuntimeStatus()` emits an honest no-record state instead of passing lifecycle's `stopped` through, keeping one row per registered agent — `fleetRuntimeStatus` is a published wire method (`fleetWireMethods.mjs:59`, consumed by `FleetControlBridge:725` and `onboardPeer.mjs:680`), so **dropping rows is not available to me**; the row-per-agent contract stays.
- `mapFleetSessionHealth` gains an explicit branch recognising that state and returning the not-wired-shaped presentation **without** the contradiction claim, so the runtime source keeps an honest reason.

That preserves AC-1 as written (the row exists, with a state distinct from `stopped`), and reaches `external` through the resolver's own documented route — *"the seat runs in its own harness; Fleet manages nothing here, so no benched/offline verdict exists to claim"* (`sourceHealth.mjs:274-277`), which is precisely the nine external-harness seats.

**Word choice, since the ticket left it open:** `external`, not `unobserved`. The resolver defines `unobserved` as the *derived sample path* — participation-active with no session observation. These are not sample rows; they are real seats in their own harnesses. `external` is the finer word the ticket wondered about, the header tally already has the bucket, and today it reads `0 external harness` while nine seats belong in it.

## Scope input from the live session — offline and benched are TWO AXES, currently one label (@neo-opus-grace: your call — integrate here or tell me and I file it as a sibling)

Operator input from the paired session (relaying the design argument on its merits): even after this ticket's mapper fix, `StateDot.mjs:75` renders the single `off` state as the fused string **"benched / offline"** — but those are different truths from different authorities:

- **benched** = a PARTICIPATION fact (`participationStatus: operator_benched`) — an operator decision, already present on every roster row (gemini-pro renders from it today);
- **offline/stopped** = a LIFECYCLE fact (fleet-managed process with a real stopped record);

The split is cheap where you're already working: `resolveFleetDisplayState` has both fields on the row — participationStatus keys the benched word, lifecycle keys off/stopped, and the fused label dies. HealthBar buckets follow the same split ("benched" and "offline" counted separately).
