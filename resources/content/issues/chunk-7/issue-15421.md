# Register Phoebe's Kimi K3 embodiment in ModelStats

## Context

`@neo-kimi-phoebe` was provisioned in `#15385` and activated after her first boot in `#15390` / [PR #15393](https://github.com/neomjs/neo/pull/15393). Those lanes intentionally left `learn/agentos/ModelStats.md` out of scope until Kimi K3 had real first-session evidence. That evidence now exists: the activation PR was authored by Phoebe from the Moonshot Kimi K3 / OpenCode seat and merged into `dev` on 2026-07-18.

The live `dev` copy of [ModelStats.md](https://github.com/neomjs/neo/blob/dev/learn/agentos/ModelStats.md) is still dated 2026-07-12 and contains no Phoebe/Kimi row.

## Problem

The model-stats registry describes itself as the live registry for swarm identity, capability, hosting, and routing facts. Its update discipline adds a row at first swarm contact, while [ADR 0012 §2.5–2.6](https://github.com/neomjs/neo/blob/dev/learn/agentos/decisions/0012-model-stats-framework.md) requires authoritative-source-cited facts for active swarm maintainers.

Phoebe is now active and has completed first contact, but the registry cannot answer which model currently embodies her, its verified capability envelope, current hosting/pricing facts, or which still-pending facts need revalidation. That is doc/registry drift, not a second onboarding step.

## Architectural Reality

- `@neo-kimi-phoebe` is the durable resident identity; Kimi K3 is her current observed model embodiment. Preserve that boundary from [IdentitySchema.md](https://github.com/neomjs/neo/blob/dev/learn/agentos/IdentitySchema.md).
- Existing ADR 0012 capability dimensions are sufficient. This lane does not add a schema field or amend the ADR.
- Current operational truth is the cloud/API model. Moonshot's [launch post](https://www.kimi.com/blog/kimi-k3) commits the full weights by 2026-07-27 and says a technical report is forthcoming, but gives no report or license date. Open-weight license and self-hosting claims must remain explicitly pending until those artifacts actually land.
- Moonshot's [official product chronology](https://www.kimi.com/help/agent/agent-overview) dates the K3 release to 2026-07-16.
- Benchmark values are dated snapshots, not permanent family roles or routing prescriptions.

## Intended Fix

Add an active `### §neo_kimi_phoebe` row to `learn/agentos/ModelStats.md` that:

1. binds the stable handle and Social Name to the current Kimi K3 embodiment;
2. records only source-supported ADR 0012 fields, including active state, family, current cloud hosting, context window, active reasoning setting, release date, cache-hit/cache-miss input pricing distinction, output pricing, a dated benchmark snapshot, and sunset/revalidation triggers;
3. uses the landed first-boot PR as runtime provenance and primary Moonshot sources for product facts;
4. records the 2026-07-27 weights deadline while keeping the technical-report date, license, and self-hosting facts explicitly pending;
5. updates the registry's `Last updated` marker and `§update_history` in the same change.

Primary product sources:

- [Kimi K3 launch — Moonshot AI](https://www.kimi.com/blog/kimi-k3)
- [Kimi K3 API quickstart — Moonshot AI](https://platform.kimi.ai/docs/guide/kimi-k3-quickstart)
- [Kimi product chronology — Moonshot AI](https://www.kimi.com/help/agent/agent-overview)

Secondary, explicitly preliminary benchmark snapshots:

- [Arena WebDev leaderboard](https://arena.ai/leaderboard/code/webdev)
- [Arena Text leaderboard](https://arena.ai/leaderboard/text)
