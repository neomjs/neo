# Turnkey peer onboarding runbook: one dry-run-first script chains define → repo → identity → launch → auth handoff

## Context

The peer-onboarding rail's capstone leaf (parent #13015). The rail's pieces are now MERGED: **PR #14918** (#14914 — curated per-family launch templates, isolated instance homes, minimal child env, `authRequired` surfacing) and **PR #14950** (#14916 — the four-surface roster generator, whose `identityRoots.mjs` payload includes the resident's `subscriptionTemplate`).

**Re-scoped 2026-07-10 (operator layer-audit):** the originally planned identity segment (a Day-0 provisioning script, #14915 / PRs #14919+#14931, both closed) is **satisfied by composition** — no script needed:

- **Identity node**: the roster PR merges → `GraphService.initAsync` seeds the `identityRoots.mjs` entry into the graph at the next MC boot (idempotent, once, at the owning service).
- **Wake route**: the seeded AgentIdentity carries its `subscriptionTemplate`; the new peer's FIRST boot materializes the subscription via `WakeSubscriptionService`'s `bootstrap` action from the real boot envelope. Pre-boot wake delivery is valueless (mailbox is the truth; drains at first boot).
- **Instance linkage**: lives in the FM registry (its core job), never duplicated into graph nodes.

## The Fix

`ai/scripts/fleet/onboardPeer.mjs` — operator-assisted, dry-run by default, `--commit` to execute, now a THIN conductor over owned contracts (it re-implements nothing):

**Phase A — before the roster merge:**
1. **Define** — `FleetRegistryService.defineAgent({githubUsername, harnessType, id})` (curated intent; the launch stop-line untouched).
2. **Repo** — the `startAgentProvisioned` / `deriveAgentRepoPath` provisioning seam.
3. **Roster ceremony** — print the #14950 generator invocation; the roster PR + cross-family review IS the membership ceremony (human-gated merge).

**Operator gate (printed, not automated):** merge the roster PR; restart the Memory Core server (boot seeding creates the identity node + template).

**Phase B — after the gate:**
4. **Preflight** — verify the roster entry exists on dev AND the graph node is seeded (read-only probes; refuse with the exact missing step named).
5. **Launch** — `FleetLifecycleService.start(id)` through the curated template → supervised child in its isolated home.
6. **Auth handoff** — read `status(id).authRequired`, print the per-home login line (`CODEX_HOME=<home> codex login` / claude-code equivalent). Secrets never touch the script.

Idempotent per segment (every underlying piece already is); re-runs report per-segment EXISTS/CREATE. Dry-run renders the true per-segment delta and which PHASE the onboarding is in.
