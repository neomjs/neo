1. **SharedWorker heap-join on second pop-out within one browser context** — the child joining the freshly-restarted SharedWorker kills it (registration collision or re-entrant boot on the vessel registry). The shared-window name `fm-agent-detail-neo-fm-fleet-cockpit-1` is identical across runs; the main-thread `openWindows` entry IS cleaned on close (`src/Main.mjs:847`), but the SharedWorker-side registration lifecycle for closed vessels was not yet audited (start: `Neo.Main` windowOpen/native-route handshake `src/Main.mjs:959-1035`, `WorkerManager` window registry).
2. **Child-app boot exception inside the SharedWorker** — the widget childapp's boot crashing the shared process only when the parent's prior vessel lifecycle ran once before.
3. **A teardown ordering defect in the reattach path** — run-1's close leaves the heap in a state where the next vessel's join is fatal.

## Root cause found — and the vessel heap-join machinery is exonerated

**The defect is not in Neo code. It is the e2e config's Chrome launch flags.** `test/playwright/playwright.config.e2e.mjs` passed `--use-gl=desktop` — a legacy GL selector modern Chrome no longer accepts (macOS allowlist is ANGLE-only: `egl-angle × {opengl, metal, swiftshader}`), so the request resolves to `gl=none,angle=none` and the GPU process fails init. The config ALSO passed `--disable-software-rasterizer`, forbidding the swiftshader fallback that would have rescued it. Result: the GPU process dies at **every window birth**, and Chromium's internal GPU-crash threshold then terminates the **entire browser**:

```
ERROR: Requested GL implementation (gl=none,angle=none) not found in allowed implementations:
       [(gl=egl-angle,angle=opengl),(gl=egl-angle,angle=metal),(gl=egl-angle,angle=swiftshader)]
ERROR: GPU process exited unexpectedly: exit_code=11        ← at every window birth
FATAL: GPU process isn't usable. Goodbye.                   ← threshold crossed at run-2's popup
<process did exit: exitCode=null, signal=SIGTRAP>           ← whole browser gone
```

Run-2's popup birth crosses the threshold **deterministically** (launch burns ~2 GPU spawns, run-1's popup one more, run-2's popup is the goodbye). Every observed signature follows: headed-only (headless never exercises the real viz path), run-2-only (the counter), child stalls at `about:blank` (no compositor for the new renderer → navigation cannot commit), App Worker "orderly disconnect" ~1.3s after popup birth (the SharedWorkers die WITH the browser; the NL bridge socket drop is what ConnectionService logs), `Target App not found` (NL registry after the socket died), and **pre-existing at `c201de8bcb~1`** (environmental, not app code). @tobiu's live observation during the repro runs corroborates: window-shell operations (open, drag, titles) work while popup URLs stay `about:blank` — the shell is browser-process, the commit is the dead GPU path.

**Diagnostic method** (Phoebe's protocol was the right entry — full credit; her SharedWorker-side registration hypothesis was the first thing my instrumentation falsified, which is exactly what a good falsification target is for): instrumented `worker.Base` ports registration + `manager.Window` + heap read-out via the NL fixture → registration tables PRISTINE at run-2 pre-popout (the SharedWorker does not even survive the between-runs reload; every run gets a fresh worker). Then main-thread span logs → the span completes; the child never commits. Then an on-failure liveness probe → `Target page, context or browser has been closed`. Then `DEBUG=pw:browser*` → the browser's own stderr confessed. Worker-truth receipts at every layer; the moving console-cutoff across rounds was event loss from the dying browser, not execution stops.

**Fix** (`41bfc7e6cd`): remove `--use-gl=desktop` + `--disable-software-rasterizer` from the e2e config. Chrome's default ANGLE on macOS is **Metal — actual hardware acceleration**, which is what these flags always intended (`gl=none` means the suite's GPU-acceleration flags have never delivered GPU acceleration). Verified: the kinetic witness `FleetCockpitKineticNL.spec.mjs` now passes **headed 2/2-runs with identical beat logs** (was: deterministic browser kill at run-2 pop-out, 4/4 repro before the fix on this seat) AND headless (CI mode) unchanged-green. Full 87-spec e2e suite validation running; tally lands on the PR.

**#15648 same-machinery verdict: NOT the same root.** Its repro was manually-launched Chrome profiles (no e2e flags) — a genuine connect-window calibration/observability issue under load. This fix removes the biggest artificial boot-slowdown from the *witness environment*, but #15648 stands on its own; noting there separately.
