Resolves #17586

## The defect

The OpenCode wake envelope names one seat's coordinates, and two seats on one host can end up sharing the file. `<XDG_DATA_HOME>/opencode/wake-envelope.json` is per-seat **by construction** — until two seats run under one `HOME` with no per-seat `XDG_DATA_HOME`, at which point whichever booted last silently owns wake delivery for every OpenCode seat on that machine.

Nothing on the path noticed, because `readOpenCodeEnvelope` validated six coordinate fields and never the owner.

**Observed live**, and reported by the seat receiving them: `@neo-preview`'s own `AGENT:*` broadcasts echoed back into its session inside envelopes addressed *for another seat*, three times in 22 minutes. Self-sustaining — each defect-note about the bleed fanned out and caused the next one.

## This restores an existing contract rather than inventing one

`deliverKimiPullBridge` in the same file already refuses on `record.route.agentIdentity`:

```js
if (agentIdentity !== record.route.agentIdentity || …) {
    throw new Error('kimi-pull-bridge envelope does not match the configured seat owner');
}
```

The OpenCode adapter is the sibling that was missing it. Same shape, same wording, same fail-closed posture.

## What changed

- **Writer** — the generated boot hook stamps `agentIdentity` from `NEO_AGENT_IDENTITY`. Read from the env rather than argv because the seat `.env` already carries it: no new flag, no new config, and it cannot disagree with the identity the seat actually boots as. Normalised to the `@handle` spelling the registry and every wake subscription already use, so the reader compares **exactly** rather than tolerantly — a tolerant comparison is how two identities start looking like one.
- **Reader** — `readOpenCodeEnvelope` requires the field with the same non-empty discipline as the other six, and returns it.
- **Delivery** — refuses a mismatch **before any POST**, and again after a rebind re-read. The pre-existing tuple check compares the envelope against *itself* across a retry; it cannot see an owner change, which is the case that matters here.
- **Probe** — `probeSessionContext` already had `record` and simply did not pass the identity down. It **reads session messages**, so a misrouted probe leaks a peer's transcript rather than misplacing a wake. Fixing delivery alone would have left that open.

## Red-proof — each arm run against unmodified `dev`

| arm | on `dev` | with the fix |
|---|---|---|
| refuses an envelope written by another seat, issues **no** request | **failed** | pass |
| refuses a pre-#17586 envelope carrying no owner | **failed** | pass |
| probe refuses a foreign envelope instead of reading its transcript | **failed** | pass |
| **POSITIVE CONTROL** — same wake delivers when the envelope is its own | **passed** | pass |

The control passing on `dev` is what makes the other three mean something: the spec discriminates the defect rather than the environment, and a guard that refused everything would fail it. Each arm was run individually, because `describe.serial` stops at the first failure and would otherwise have proven only one.

The refusal **reason** is asserted, not just the outcome — a `failed` that happened to come from an unreadable file would satisfy the outcome alone and prove nothing about ownership.

`71 passed` across `localWakeAdapters.spec.mjs`, `generateOpenCodeSeatConfig.spec.mjs` and `receiver.spec.mjs`.

## Two fixtures updated, deliberately not worked around

- `localWakeAdapters.spec.mjs` — two existing OpenCode envelope fixtures predated the field and went red the moment the reader required it. They now name their seat. That they broke is the reader change biting where it should.
- `generateOpenCodeSeatConfig.spec.mjs` — a frozen sha256 of the emitted artifact set. Hook content changed, so the digest is **bumped with a dated reason**, following the convention already in that comment. It is not relaxed: catching exactly this kind of change is what it is for.

## Merge-order note

The stopgap on the reporting host is the envelope file moved aside, which fails Phoebe's leg closed. That worked only while the guest seat had **no** wake subscription.

PR #17584 has since merged, so `participationStatus` is `active` — but `@neo-preview` is still absent from `fleet-identities`, i.e. no route is registered yet (nothing auto-registers at boot, per #16991). So the bleed is **latent, not live**, and this PR closes it before the first `subscribe` makes it live again.

## Out of scope

Per-seat `XDG_DATA_HOME` separation — the deployment-shape half, and the ticket's own Out of Scope. Worth doing, and it prevents the collision by **arrangement**; this makes misrouting impossible by **check**. They are complementary, and only the check belongs here.
