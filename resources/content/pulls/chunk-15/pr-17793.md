The canonical skill store now exists and is enforceable. `neomjs/neo-agent-skills` carries the 38-skill tree, its manifest and schema, and an `AGENT_SUBSTRATE_REVISION` receipt pinning the tree by content-addressed hash. This repo becomes the first consumer of that receipt: it carries its own pin and calls a reusable guard that measures two independent things — that the tree is canonical byte-for-byte, and that the harness façade equals what the manifest declares. Those axes are separate on purpose; a façade differing from the canonical tree is legitimate, a façade differing from the manifest is drift, and a guard that conflates them either rejects every real harness view or accepts real forking.

Evidence: L3 (guard executed against two live repositories — `neomjs/devindex@5a5e1f0` red, this repo green — plus a 6-case fixture suite with a negative arm per case) → L4 required (AC-7 branch-protection binding is an admin-gated repository-settings change). Residual: AC-7, Residual-Owner: #17783.

## Deltas from ticket

**AC-1's "public facts schema/renderer" has no standalone artifact to ship.** `git ls-files | grep -iE "facts.*(schema|render)"` returns empty; the only facts-adjacent code is `ai/daemons/orchestrator/services/bootIdentityFactStore.mjs` and `ai/scripts/diagnostics/check-identity-facts.mjs`, both Brain-plane runtime rather than a public schema or renderer. The facts *ledger* that D#17756 discussed lives at `.agents/skills/neo-identity-update/references/facts-ledger.md` and **is** in the seeded tree. I did not invent a schema to satisfy the phrase. If the intended artifact is the per-repo committed facts head from the A4/A5/A6 thread, it is unbuilt and wants its own leaf.

**The guard verifies the façade rather than only generating it.** The ticket frames AC-4 as generation; generation alone cannot detect a hand-edited façade in a consumer that never runs the generator. Shipped both: the generator owns the projection, the guard's leg B independently enforces it.

**Enrollment rows are the four repositories I could verify, not all 52.** Each carries measured state (`devindex` and `neo-agent-brain` both confirmed to lack `.agents` via live 404). Populating the remainder is the sync campaign, not this PR — and per AC-6 the mechanism reads a predicate, so an unlisted repo is UNDECIDED and reports red rather than passing silently.

**A `.gitignore` was added to canonical.** During seeding, `cp -R` carried a git-ignored `.DS_Store` that the fresh clone staged, and the receipt's tree hash caught it — the mismatch is what surfaced it. Without an ignore file it recurs as spurious diffs in every enrolled repo.

## Evolution

The guard was first written to resolve the tree hash from the git index so it would see staged-but-uncommitted changes. That added three fallback strategies, one of which shelled out and printed `fatal: ambiguous argument` on every run plus a Node deprecation warning. The scenario it defended against does not occur in CI, where `actions/checkout` produces a committed ref — so it collapsed to a single quiet `git rev-parse HEAD:<path>`. The elaborate version was defending a case that cannot happen at the cost of noise on every case that can.
