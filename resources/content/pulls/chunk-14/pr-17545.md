Related: #17539

`Neo.dashboard.DockWorkspace` is the engine-owned reducer-container every docking workspace hand-rolled: the committed document, the pure reducer, the deferred promise-chained re-projection through `DockLayoutAdapter` and `DockProjectionReconciler`, the FLIP motion bracket, and the in-window cross-zone drop path — with a consumer contributing only its own panes and a handful of hooks (owner-preserved item ids, pre-refresh chrome sync, extra projection options, reconciler fast-path options, the dock-host reference and shell index). The example host migrates as the minimal consumer (816 → 619 lines; the hand-rolled loop is gone, the perspective toolbar re-syncs through the hook, the app root keeps the viewport contract explicitly), ADR 0029 §2.1 names the class as the normative host with a §5 leaf row, and the guide's adoption step teaches the class in place of the "deliberately small surface" sentence the measurement on #17539 falsified. Zero diff under `apps/`. The class JSDoc carries the theme boundary Grace ruled on the epic: the once-per-workspace `neo-dock-workspace` root is the override anchor, the projected `.neo-dashboard` stays the default carrier, and the defaults never move.

Evidence: L1 achieved (the unit suite plus the headed Neural Link witnesses that target the example, executed on the author host at the exact head) → L1 required (#17541 ACs 6, 7 and 11 name headed witnesses).

## Deltas from ticket
- **The example root keeps the viewport contract explicitly, in four traits, because theme files load per class.** Single inheritance puts the dock host on the example, so it stopped being a `Neo.container.Viewport`; the first headed run then failed seven journeys. The mechanism took three runs to pin honestly: restoring `autoMount`, the body class and the `neo-viewport` sizing class (`7243856a6a`) changed nothing, because `body > .neo-viewport` lives in `Viewport.scss`, and with no Viewport instance on the page that stylesheet was never loaded — the root rendered as a 583×154 px content box centered by `neo-body-viewport`, every main tab overflowed into the menu, and every pointer/geometry witness died. The example now declares `additionalThemeFiles: ['Neo.dashboard.Container', 'Neo.container.Viewport']` (`ad3a866b98`); the message of `7243856a6a` names the collapse correctly but credits the wrong repair. The ticket's implementer's-call clause resolved toward "the example extends the class" because every witness addresses the holder by the example's class name through the DockService component id, which refuses parent walking by design.
- **The reveal resolver stamps the FLIP marker** exactly as the tab-flow resolver does — the old example's module-level resolver stamped every config and `DockMotionNL` locates the revealed pane by that marker.
- **FLIP playback is gated on the capability** (`typeof flip.play === 'function'`), not on the addon's presence: a partial addon (the `DockFlip` unit double registered in the shared test worker; a degraded main thread) lands the layout instantly instead of throwing after the document already committed. The invocation stays synchronous.
- **Two dashboard specs that borrowed the example's loop** through duck-typed owners (`DockFlip.spec.mjs` marker identity, `DockTabEnterButton.spec.mjs` refresh owner) now borrow `DockWorkspace.prototype` and supply the hook members the loop consults.
- **The in-window cross-zone drop stays the class default**; composing the `DockDragAffordances` layer (preview renderer + drop indicators as persistent host siblings) is wired through `getDockProjectionOptions` by the hosts that use it and lands with their migration leaves under #17539.
