# Cockpit timestamps render viewer-local via Intl; wire stays UTC

## Context

Operator feedback, live during the #17271 L1 paired session (2026-08-17): "date and time shows UTC, local time and time formatting would be better (easy in JS)." The activity stream renders `HH:MM` derived from UTC instants; the operator seat sits in Europe/Berlin (+2 in August) — every glance at the surface whose whole point is at-a-glance truth requires mental offset arithmetic.

## The Problem

Human-facing instants across the cockpit (activity rows, presence `lastSeenAt`, catch-up entries, mailbox panes) render raw-UTC-derived strings. No §04-bar rule exists for time presentation, so each surface invents its own — the exact per-surface drift the design SSOT (#17263 → PR #17279) exists to prevent.

## The Architectural Reality

- `apps/agentos/view/fleet/ActivityStream.mjs` renders row times; coalesced same-actor runs show the newest event per the documented run contract.
- The §06 design SSOT + `apps/agentos/TOKENS.md` (merged via PR #17279) is the governing home for a presentation rule; panes (#17268) inherit from it.
- Wire DTOs (fleet snapshots, presence envelopes) carry ISO-8601 UTC and MUST stay that way — receipts and cross-checks (e.g. the #17271 AC2 evidence table) depend on wire-time being zone-free.

## The Fix

1. One rule in the §06 SSOT (+ TOKENS.md appendix line): human-facing instants render via `Intl.DateTimeFormat` in the VIEWER's locale/zone; wire stays ISO-UTC; the exact ISO instant rides `title`/hover for receipt-grade reading. Same-day instants render time-only; older rows gain a compact locale-aware date part.
2. First consumer: the ActivityStream row template (coalesced runs: newest instant).
3. Sweep remaining cockpit surfaces to the rule (presence lastSeen, catch-up, mailbox panes) — same PR or an explicitly listed follow-up.

## Acceptance Criteria

- [ ] Stream rows render viewer-local time (Intl); ISO-UTC on hover/title.
- [ ] SSOT §06 + TOKENS.md carry the time-presentation rule (spec merged with implementation).
- [ ] Wire DTOs unchanged (ISO UTC).
- [ ] Unit coverage: formatter honored under a mocked non-UTC zone; same-day vs older-row format switch.
- [ ] One shared helper, token-governed — no bespoke per-surface formatters left in touched surfaces.

## Out of Scope

Relative-time vocabulary ("3m ago") — a separate design question; absolute-local is this ticket. Pane-level information design (#17268).

times plus a variant: CatchUpPane, MemoriesPane and WakeRoutePane each carried a
byte-identical `toISOString().replace('T',' ').slice(0,16) + 'Z'`, and
ActivityStream had `toISOString().slice(11,16)`. That is the harder kind to
notice — every surface looks locally consistent, and nobody owns the rule.

The split that matters, and it is the whole design: the WIRE stays ISO-8601 UTC
because receipts and cross-agent evidence depend on wire-time being zone-free —
two agents citing one instant must produce one string. Only the PRESENTATION
edge localises. `viewerTime.mjs` is that edge, applied at render, never written
back.

Same-day instants render time-only; older ones gain a compact locale date,
because a bare `10:15` on a three-day-old row is misleading rather than terse.
The day boundary is judged on the VIEWER's calendar — judged in UTC, 23:30
Berlin would be "yesterday" for half the evening. The exact ISO instant rides
`title`, so the operator reading a row and the agent citing it as evidence are
both served.

Format is single-sourced; MISS-COPY is not. The helper returns null and each
surface keeps its own empty words — a dense stream row wants an em dash, a prose
pane wants "unknown time". Collapsing those would trade a real duplication for a
fake uniformity.

Spec merged with implementation: SSOT §06 gains ladder T5 (the design bar was
four ladders, now five — both the intro count and the caption updated) and
TOKENS.md records why this ladder mints no token: there is no value to bind, the
rule is a behaviour.

WHAT THE CHANGE EXPOSED, and it is worth more than the feature: wakeRoutePane's
spec pinned `captured 2026-08-03 20:01Z` and two sibling lines — a pane spec
quietly asserting UTC FORMAT from a surface whose subject is the SENTENCE it
composes. It broke on a change touching neither the presence nor the failure
axis, and once fixed naively would have passed or failed on the runner's own
zone. Those assertions now cover composition; the format contract is proven once
in viewerTime.spec against a PINNED locale and zone — an ambient-zone assertion
passes in a UTC runner while proving nothing, since the runner's zone is the one
case that cannot detect the defect.

Mutation-proofed: forcing the formatter back to UTC fails 3 of the 6 new specs.
739 specs pass across the agentos surface."
