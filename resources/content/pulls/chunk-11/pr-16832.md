Resolves #16588

The `tools/list` description compaction capped the operation line and shipped the schemas beside it whole — every `description:` inside `inputSchema` / `outputSchema` rode the listing in full. This PR adds the sibling projection: `compactToolSchemas` strips ONLY the `description` annotation key, recursively (blacklist, not whitelist — every shape-bearing key survives by construction, so the projected schema validates the identical accept/reject set), and relocates the fully-described schema into the existing `get_mcp_tool_handbook` payload. Opted in on all six MCP servers beside their existing `compactToolDescriptions: true`; the default stays `false` and default-off output is byte-identical (spec-pinned).

Evidence: L2 (unit matrix over the pure projection + the real file-system contract + the full unit suite) → L2 required (all six ACs are projection-contract ACs reachable in-sandbox). Residual: none — AC-6's measurement is below.
