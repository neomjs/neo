# lint-guides hard-fails ticket ids in learn/guides — operator rule: guides describe, trackers decide

## Context

Operator rule (2026-08-22, verbatim): *"please NEVER use ticket ids in guides. they rot."* The two dock guides were swept to zero ids the same evening (PR #17572, commit `efc1552391`); the rule currently lives only in that PR's history and in agent memory — nothing enforces it for the next guide author.

## The Problem

A guide that cites `#12345` reads as evidence today and as archaeology in a year: the id re-targets nothing in the prose when the ticket closes, migrates, or is renamed, and the reader cannot tell load-bearing citation from decoration. A repo-wide sweep at the time of filing found exactly two remaining guides carrying ids:

- `learn/guides/fundamentals/CodebaseOverview.md`
- `learn/guides/specificfeatures/TearOutPortabilityMatrix.md`

(`grep -rln "#1[0-9]\{4\}" learn/guides/` — the pattern also generalizes to `#[0-9]{4,}` for future-proofing.)

## The Fix

1. **Mechanize the rule:** `ai/scripts/lint/` guides lint gains a HARD rule — any `#[0-9]{4,}` token in `learn/guides/**/*.md` fails with the message "ticket ids rot in guides — describe the repair, cite files or authority documents instead" (exact wording at implementer's discretion). Code fences and inline-code spans need a decision: ids inside code examples are equally rot-prone in guides, so the simplest correct rule is no exemption; if a legitimate counter-case surfaces during implementation, record it in the lint's comment.
2. **Sweep the two remaining files** in the same PR, re-phrasing each citation as timeless prose (the dock guides at `efc1552391` are the worked pattern: war stories keep their measurements, lose their pointers).
3. Scope boundary: `learn/guides/` only for the hard rule. `learn/agentos/` decision records and contract docs cite tickets BY DESIGN (they are the tracker-adjacent tier); the lint must not fire there.

## Acceptance Criteria

- [ ] The guides lint hard-fails on ticket-id tokens under `learn/guides/`, green everywhere else.
- [ ] The two files above are swept; `ai:lint-guides` green repo-wide.
- [ ] A red control: a scratch guide with an id fails the lint in the PR's evidence.
