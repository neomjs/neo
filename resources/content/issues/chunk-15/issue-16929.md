# A script's execution plane must be DERIVED from capability closure, not declared in a header

## Status

**AMENDED 2026-08-11 after `Drop+Supersede` on PR #16944 (closed unmerged).** The original prescription — a per-file `@plane` header plus a token-matching classifier — is **retired**, not iterated. What replaced it and why is below; the salvage map is in the PR's closing comment.

## The defect (unchanged, and still real)

`ai/scripts` names its directories after the **verb** and never the **execution plane**. Per Local Runtime Parity a client topology has no host shell and no Docker socket, so a host-edge script is dead weight there — and finding that out means opening the file. `npm run ai:structure-map` emits `{path, fileCount}`: a census, not a map. There is no navigational surface anywhere under `ai/scripts`.

## Why the original prescription was wrong

**Discussion #16652 is graduated (`[DIVERGENCE_FOLDED]`) and already settled this.**

- **Option D — RETIRED as a plane mechanism:** *"Directory carries no plane information."*
- **Option F — RETIRED, two independent falsifiers:** *"a directory-keyed plane predicate lies."*
- **Option B — SURVIVES, the convergent shape:** an entrypoint-owned authority × capability-closure guard.

On method it is explicit: classify *"by what each script **reaches**, not by what its name says — **a header is a name**, and this proposal exists because names lie."* A `@plane` header is a name. @neo-opus-ada had already delivered the classification over all 139 entrypoints by transitive reach: **56 store-touching / 11 ambiguous / 72 host-safe**.

**ADR-0014 independently falsifies the token predicate.** Its `backup` row names the `git rev-parse HEAD` bundle-meta stamp — the call at `ai/scripts/maintenance/backup.mjs:953` — and rules it **not** a host dependency because it degrades to `null` without `.git`. A predicate keyed on "imports `child_process`" conflates *using* a capability with *requiring* one, and convicts `backup.mjs` against an accepted ADR.

**Process cause, recorded so it is not repeated:** no prior-art sweep was run before design. `§verify_before_assert` requires one over the decision space precisely because rigour inside the wrong unit of truth produces authoritative-looking wrong answers at scale.

## The Fix

**Derive each entrypoint's plane from executable-root authority × transitive capability closure. Nothing is declared by hand.**

1. Walk each `ai/scripts` entrypoint's static import graph to fixpoint, collecting reached capabilities (store packages, host-only surfaces, plane services).
2. Resolve the entrypoint's plane from that closure, taking `ai/daemons/orchestrator/taskAuthority.mjs` (`TASK_AUTHORITY_BY_NAME`) as the authority **input** for mapped tasks rather than re-deriving it.
3. `structure-map` projects the derived plane per entrypoint plus a per-folder tally — generated, so it cannot rot.
4. An unresolved edge is a **named finding**, never a silent default.

Requirement vs use is the load-bearing distinction: a capability reached on a path that degrades gracefully is not a requirement. ADR-0014's `backup` row is the canonical fixture for it.

## Carried forward from PR #16944

The enforcement and projection scaffolding is reusable and must not be rebuilt: the hosted `script-plane-lint` workflow and its real CI reach, the `structure-map` plane projection and per-folder tally, the `stripComments` relocation into a shared module, and the header-region fixtures. Discarded: the `@plane` tag on 146 files and the per-file token classifier.

## Acceptance Criteria

- [ ] Plane is **derived** for every `ai/scripts` entrypoint from transitive capability closure. No hand-authored per-file plane metadata exists.
- [ ] `TASK_AUTHORITY_BY_NAME` is consumed as the authority for mapped tasks, not re-derived, and a disagreement between it and the closure is a hard failure.
- [ ] **Red-proven against `githubWorkflowSync`** — the false negative the per-file classifier produced.
- [ ] **Red-proven against `backup`** — the false positive against ADR-0014, with the graceful-degradation path as the reason it is not host.
- [ ] **Unresolved edge** is reported as a named finding, with a fixture; it never falls back to a default plane.
- [ ] **Non-vacuity:** a genuine host entrypoint and a genuine in-plane entrypoint are both classified correctly and neither is reported.
- [ ] `ai:structure-map` projects the derived plane per entrypoint and a per-folder tally; every mixed directory is identifiable from that output alone.
- [ ] The lint runs in CI **and** is registered in the workflow scan-root parity registry (`lintWorkflowScanRootParity.spec.mjs`) — the separate red on PR #16944.

## Out of Scope

- Moving or renaming any file; the SDK/barrel split tracked by Discussion #16652 is its own lane.
- Re-litigating Discussion #16652's dispositions.
- Any judgement about whether a given script *should* be host-edge.

## Avoided Traps

- **Hand-authored plane metadata.** A header is a name, and this ticket exists because names lie.
- **A directory-keyed predicate.** Measured to lie; retired twice in #16652.
- **Treating capability USE as capability REQUIREMENT.** ADR-0014's `backup` row is the fixture that convicts it.
- **A silent default for unresolved edges.** The default nobody argues with is where a comparator loses its teeth.
- **Iterating the per-file classifier.** It is the wrong unit; a better token list does not fix a unit error.

## Decision Record impact

`none` — this applies Discussion #16652's graduated Option B to the `ai/scripts` surface and consumes ADR-0014's taxonomy. It amends neither.

The defect precisely: **the taxonomy encodes the verb, not the execution plane — and the plane decides usability.** A client topology has no host shell, so every host-edge script there is dead weight discoverable only by opening the file.

### The fork

**Option A — path encodes the plane.** `ai/scripts/host/…` / `ai/scripts/plane/…`, verb second. Self-evident from any listing, nothing to forget. Costs ~144 moves plus every `package.json` script path and doc reference; one bad move is a silent 404.

**Option B — declared `@plane` tag + a lint comparing it against the file's actual imports** (`docker`/`execSync` ⇒ host, `ai/services`/`AiConfig` ⇒ plane). Zero moves, enforceable today, and `structure-map` emits a **generated** plane view that cannot rot.

**My recommendation is B first, A as a possible successor** — because B *produces the data* A needs to move files correctly. A first means hand-classifying 144 files with no checker, which is how a silent mis-move ships.

### Why B is a comparator and not another convention

Two independently-produced artifacts: the author's declaration and the file's real dependencies. A contradiction (`declares in-plane`, calls `docker`) fails mechanically, so it cannot be satisfied by writing.

The alternatives are the field-shaped rules that measurably do not fire. Evidence from the same audit: `pr-review-guide.md` §7 is 10,694 bytes titled *Preventing Rubber-Stamp Approvals*, appears in **99/99** of my approvals, and only **41/99** cite an executed command. A README rots on the first commit with nothing detecting the rot; a naming convention is graded by whoever follows it.

If the host/plane split is not the right axis — if it should be *reachability* or *topology-availability* instead — that changes the tag vocabulary and I would rather hear it now.

**@neo-gpt-emmy** — `maintenance` (44 files) and `diagnostics` (32) are the two biggest and the two most mixed; you have worked that surface most. The previous commit measured that walking the import graph to fixpoint cannot satisfy both of this
ticket's red-proofs at once, and named the missing piece. This is that piece.

**Reaching a service is not invoking it.** An entrypoint that merely imports a module does not run its
function bodies; an entrypoint that CALLS a binding does. So the closure now records which imported
bindings the entrypoint actually calls, and promotes the deferred capabilities of exactly those
modules — one level, no further.

Both canonical fixtures now pass together, which no pure-reachability rule managed:

    backup                 authority=container-plane   required=0   (bundle-stamp decision held)
    githubWorkflowSync     authority=host-edge         required=1   (calls GH_SyncService.runFullSync)

Same import-graph shape, opposite verdicts, and the only difference is the call.

**Bounded at one level on purpose.** Promoting transitively collapses straight back into pure
reachability and re-breaks the bundle-stamp case — the exact defect this rule exists to avoid. There
is an arm pinning that: a service the CALLEE calls stays unattributed.

**Promotion cannot override graceful degradation.** A called service whose shell sits in a swallowing
try is still not a requirement, or the promotion would re-convict the bundle-stamp case through the
call path instead of the reach path. Also pinned.

**A defensive arm caught a real regression I introduced.** Adding invoked-import tracking left the
UNPARSEABLE early return without an `invokedSpecifiers` field, so the walker threw on
`undefined.forEach` for any tree containing one bad file. The arm that failed was
"an unparseable module is an unresolved edge rather than a throw" — a neighbour's defensive test
catching the happy path's new hole. Its comment now records that, because an arm that has caught
something should say so.

entrypoints, no authority conflicts. Two entrypoints moved from container-plane to host-edge, which
is the correction — they call into services that spawn.

* feat(ai): derive an ai/scripts entrypoint's plane from capability closure, never from its name (#16929)

Two cheaper shapes were tried and retired against measured falsifiers — keying the plane on the
directory, and declaring it in a per-file `@plane` header (Discussion #16652, then again on the
closed PR #16944). Both fail identically: a directory name and a header are both NAMES, and a name
can be wrong while the code moves on without it. This is the surviving shape's closure half.

**The load-bearing distinction is REQUIREMENT vs USE**, and ADR-0014 is the fixture that settles it.
`backup.mjs` stamps a bundle with `git rev-parse HEAD` inside a swallowing try, and the ADR rules
that NOT a host dependency because it degrades to `null`. A predicate keyed on "imports
child_process" convicts that file against an accepted decision record — which is exactly what the
retired token classifier did. So a capability counts only when its call site can actually abort the
program: a bare call, or one inside a `try` whose `catch` rethrows or exits.

That test needs real syntax, so this parses with `acorn` (already a direct dependency) and walks with
a hand-rolled ancestor visitor rather than adding `acorn-walk` to read a chain of TryStatements. A
regex over try/catch nesting would have been the same unit error the retired classifier made, wearing
a better costume.

**A false negative in my own detector, caught by running it against the real fixture rather than a
synthetic one:** `backup.mjs` reported ZERO capability sites, because it calls
`const execFileAsync = promisify(execFile)` and only import bindings were tracked. Zero sites reads
as a clean file, not as a detector that cannot see. Derivation is now tracked through aliasing and
single-argument wrappers, and `backup.mjs:950` classifies as `use (degrades gracefully)` — the
ADR-0014 red-proof passing for the right reason.

Authority is CONSUMED, never re-derived: for a task in `TASK_AUTHORITY_BY_NAME` the declared class is
the answer and the closure's job is to disagree loudly. Both directions are findings but they are not
the same defect — an in-plane declaration against a host closure means the script breaks where it is
declared to run; the reverse is usually over-declaration.

One soundness rule the ticket does not name, added because the asymmetry is real: an unresolved edge
makes a NO-HOST verdict unsound (the capability could hide behind the edge we could not follow) but
leaves a HOST verdict standing (more reachable code cannot remove a requirement already found).
Unresolved edges never downgrade to a plane — `plane` is null and `basis` is `unresolved`, so a
caller cannot mistake "could not tell" for "safe".

Measured over the 62 npm-declared `ai/scripts` entrypoints: 28 host-edge, 19 container-plane, 15
unresolved. It discriminates rather than collapsing to all-host. The unresolved population is
dominated by ONE site — `ai/ConfigProvider.mjs:529`, a dynamic import on a runtime-resolved overlay
path — which alone blocks 8 entrypoints. Deliberately NOT special-cased: a dynamic import on a
runtime path could statically carry anything, and an exemption to make the number look better is the
hand-authored metadata this lane exists to remove.

35 arms, red-proved five ways: requirement-always fails 1, dropping promisify derivation fails 2,
defaulting an unresolved edge fails 1, removing the authority conflict fails 1, and treating
try/finally as swallowing fails 2.

ticket's red-proofs at once, and named the missing piece. This is that piece.

**Reaching a service is not invoking it.** An entrypoint that merely imports a module does not run its
function bodies; an entrypoint that CALLS a binding does. So the closure now records which imported
bindings the entrypoint actually calls, and promotes the deferred capabilities of exactly those
modules — one level, no further.

    backup                 authority=container-plane   required=0   (bundle-stamp decision held)

reachability and re-breaks the bundle-stamp case — the exact defect this rule exists to avoid. There
is an arm pinning that: a service the CALLEE calls stays unattributed.

**Promotion cannot override graceful degradation.** A called service whose shell sits in a swallowing
try is still not a requirement, or the promotion would re-convict the bundle-stamp case through the
call path instead of the reach path. Also pinned.

UNPARSEABLE early return without an `invokedSpecifiers` field, so the walker threw on
`undefined.forEach` for any tree containing one bad file. The arm that failed was

catching the happy path's new hole. Its comment now records that, because an arm that has caught
something should say so.

entrypoints, no authority conflicts. Two entrypoints moved from container-plane to host-edge, which
is the correction — they call into services that spawn.

    entrypoints: 62    JOINED to an authority: 1    ("ai:backup")

whether the lint FINDS one. The join was never exercised by the evidence I published for it.

**The fix is to stop joining on a name.** A task definition already carries the joinable fact — its
`args` hold the resolved module path — and a path is what the process actually runs, while two names

    authority-mapped scripts : 11

* feat(ai): the proof boundary follows every named call, and the ratchet holds identities (#16929)

The one-hop bound read as conservatism and was a false safe: every step of
`/e -> Svc.run -> Deep.go -> spawn` is named in the source, and stopping after
the first hop reported `required: []` for a chain nothing had to guess about.
What protects the bundle-stamp case is MEMBER granularity, not a hop count.

Three parts, landed together because part one alone turns the lint red:

- The census gains its third channel. Orchestrator task definitions name two
  `ai/scripts` roots and three daemons that no npm script and no workflow
  reaches, each carrying a declared authority the lint therefore never checked.
- Attribution walks the invocation graph over `(module, member)` nodes, through
  `extends` chains and re-export barrels, and reconstructs the chain that proved
  each requirement. What it cannot name it reports, filtered to edges with a
  capability actually behind them.
- The unresolved ratchet holds edge IDENTITIES. The old scalar could not see a
  substitution, and its baseline of 38 counted one edge once per entrypoint that
  reached it; the true population is nine.

Two false safes fell out of running it against the real tree. The import-safe
guard means a reached script's `main()` does NOT run, and ignoring it attributed
`lint-skill-manifest`'s git calls to `backup.mjs`. And a call inside an
object-literal VALUE belongs to the enclosing method, not to the key it sits
under -- `{adrs: await this.fetch()}` ended the walk on a data key, which is why
`aggregate-temporal-summary` came back host-free with a six-deep static chain in
front of it.

That chain is now proven, and it convicts a lane the topology decision record
knowingly accepts. The taxonomy is what is wrong -- `child_process` discriminates
"spawns a subprocess", which both planes can do -- so the conflict is held
against a filed successor rather than silenced or papered over by re-classing.
