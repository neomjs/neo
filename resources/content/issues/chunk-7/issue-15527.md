## Clean-consumer probe — RESULT: FAIL at boundary 2 of 3+ (full map inside)

Executed per Emmy's falsifier shape: `npm pack` the exact artifact (neo.mjs-13.1.0.tgz, 6,771 files, 35.3 MB packed) → `npm init` in an empty dir → `npm install <tarball> --ignore-scripts` → drive the FM packaging path through the installed dependency only (no sibling checkout, no `node_modules` patching). Tarball produced from dev @ current head; probe host: macOS arm64, node 25.9.0.

### Boundary 1 (cleared by experiment): the build-toolchain boundary — devDependencies are invisible to a clean consumer

`harness/pack.mjs:323` runs `node buildScripts/build/themes.mjs` inside the installed artifact. First failure: `ERR_MODULE_NOT_FOUND: autoprefixer` — the themes toolchain (`autoprefixer`, `postcss`, `sass`, `cssnano`, plus `chalk`/`envinfo`/`fs-extra`/`commander`/`inquirer`) lives in neo.mjs's **devDependencies**, and `npm install <tarball>` installs `dependencies` only. Note also: **`dist/` is NOT in the artifact** — so the prebuilt-CSS shortcut does not exist today; the pack stage MUST rebuild themes in the consumer.

*Experiment:* installing the toolchain at the consumer root (up-tree resolution; the installed `neo.mjs` itself untouched) clears the build — the pack stage proceeds.

*Maturity options:* (a) ship prebuilt `dist/` CSS in the npm package + make the themes build conditional (skip when `dist` exists) — the clean-consumer fast path; (b) promote the themes toolchain to production dependencies (heavy — every consumer gets sass/postcss); (c) document "packaging requires the build toolchain" as the standing boundary and have the pack fail with a named error (it currently fails raw).

### Boundary 2 (the stopper): manifest strictness meets an undeclared import — `playwright`

`buildOrganismManifest` (pack.mjs:247) scans the staged trees for bare imports and pins each to a version declared in the repo's package.json — hard error on any miss. The staged `ai/` tree includes `ai/scripts/diagnostics/genesisProbe.mjs:1267`, which **dynamically imports bare `playwright`**. `package.json` declares only `@playwright/test` — a hoist-shadowed undeclared import that the checkout masks (the transitive package is present, so it works locally). Result: `organism manifest: no declared version for imported package(s): playwright`. Not fixable within the falsifier's rules (declaring it, allowlisting it, or extending `OPTIONAL_LAZY` all mean editing the dependency).

*Maturity options:* (a) declare `playwright` in package.json — arguably correct hygiene: it IS a runtime import for #15291's Genesis proof; (b) exclude `ai/scripts/diagnostics/` from the staged allowlist (diagnostics are not FM runtime surface); (c) extend `OPTIONAL_LAZY_PACKAGES` (weakest — playwright is not lazily-optional for the probe that needs it).

### The tail (named, unprobed past boundary 2)

Once F2 is fixed, the remaining chain is: staged `npm install` (pack.mjs:348), `npx @electron/rebuild` (:352 — harness devDep + Electron ABI download ~100 MB + network), `initServerConfigs` (:358), and `electron-builder` dist. These are the next frontier; the probe does not claim them.

### The A-supersession verdict

**FAIL today.** The installed dependency cannot package FM clean. Option E (storefront) stands unchallenged; Option A's supersession case needs boundary 1's maturity (prebuilt dist or conditional build) + boundary 2's maturity (declare, or allowlist-out diagnostics) + the tail mapped. None of the three argues moving source today; two of the three are small, honest packaging work.

### Owner + decay trigger (AC-2)

Owner: the kimi seat until the twin's seat warms, then the kimi family. Decay trigger: re-run on (i) `.npmignore` / pack-stage allowlist changes, (ii) ADR-0034 implementation changes, (iii) Electron major bumps, and (iv) before ANY Option-A reconsideration. The probe harness is a five-command sequence (pack → init → install → run → read the error); recorded here for re-execution.
