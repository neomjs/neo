# Tasks pane: the orchestrator schedule as a first-class cockpit surface

## Context

Operator, live session 2026-08-18: "a very polished view for the orchestrator scheduler tasks (what is running, % done if possible, next scheduled tasks)." The cockpit's center answers WHO (FleetGrid: agents + state); nothing answers WHAT (work in flight, progress, queue).

## The Problem

Mission control without the work axis. The operator reads "0 working · 9 unobserved" but cannot see the running ingestion, the REM backlog, or the next scheduled run. The fleet's memories became a proven surface in the `#17271` L1 session; the schedule is the missing operational twin — WHO is only half of mission control.

## The Architectural Reality

- Scheduler substrate exists Brain-side: D#11857 (open) tracks the orchestrator scheduler decomposition; the orchestrator runs as a compose service in `ai/deploy/docker-compose.local-agent-os.yml` (services: chroma, kb-server, mc-server, orchestrator, fleet-server, ingress).
- Progress truth exists TODAY for some lanes: KB ingestion progress and MC REM-pipeline state are served by existing plane verbs — the log-proxy pattern (peer-verified 2026-08-13: workload truth answered entirely by proxies).
- D#16990 (capture-only): our instruments default to binary verdicts and miss "in progress" — this pane is the counter-example by construction: progress IS its subject.
- Pane siblings: `MemoriesPane`/`CatchUpPane` (`apps/agentos/view/fleet/`) — snapshot-held, intent-firing, cockpit-owned authenticated bridge reads; the Tasks pane follows the same pane contract.

## The Fix

A **Tasks** pane in the south content-tab family (#17269's target model): running tasks (with progress where a truth verb reports it), queued/next-scheduled (with source), recently completed — provenance-labeled per source. Where the orchestrator-schedule verb does not exist yet, the pane renders the honestly-labeled sample state (spine-banner honesty discipline) — it never fakes liveness. The narrowest missing wire verb is named at implementation time as its own service ticket, after D#11857's decomposition settles what serves it.

## AC-1 design sketch — the Tasks pane, §04-consistent (spec-first gate)

Verified against live substrate 2026-08-21: both named truth verbs called, shapes recorded below; the §04 token layer this sketch consumes is PR #17491 (in review). Implementation starts only after this sketch passes review AND #17491 lands (token dependency).

### 1 · Placement + composition

- `stream-tabs` gains a `tasks` item after `stream` (pure dock-document data, the #17269 south content-tab family — the reserved place this ticket exists to fill): `tasks: {componentRef: 'tasks-pane', title: 'Tasks', kind: 'panel'}`.
- Pane contract = the MemoriesPane/CatchUpPane sibling contract verbatim: mount-agnostic root (host owns surface/padding/rhythm — the drawer-shell #17209 discipline), root declares no frame, inner rows own the scroll (`overflow: auto`, `min-height: 0`), snapshot-held cockpit-owned bridge reads, intent-firing refresh.
- In-shell + pop-out parity via the established childapp widget-route registration (the componentRef pattern every south sibling follows).

### 2 · Anatomy — three sections, one row grammar

Section order answers the operator's question order: **Running** (what is in flight) · **Queued / next** (what comes) · **Recent** (what finished).

- **Section label**: `--fm-text-chrome` + `--fm-text-chrome-tracking` + uppercase — the InstanceManager section-label idiom exactly.
- **Row**: `[time] [name] [progress | state-word] [provenance]`
  - time — `--fm-text-micro`, viewer-local via `viewerTime.mjs` (T5: wire stays UTC, ISO rides `title`)
  - task name — `--fm-text-body`, ink; one line, ellipsis (the density-frozen-window rule)
  - state word — `--fm-text-micro`, dim; **"in progress" is a first-class rendered state** (D#16990's counter-example by construction), never an absence
  - provenance — the freshness-pill register (micro, `line-height: 1`, pill radius): the ONE freshness language, `.fm-freshness` vocabulary verbatim (S1 rule)
- Row spacing rides the rhythm tokens; row plate = the sibling card idiom (`--fm-panel`, `--fm-line-soft`, radius 6).

### 3 · The progress idiom — three truths, three renders

Never hue-alone (law-1); motion is decoration (law-2).

1. **Determinate run** (a verb reports a fraction): a 4px (`--fm-space-1`) track/fill bar — track `--fm-panel-2`, fill `--fm-signal` — PLUS the percentage as micro mono text beside it. The bar is the glance, the text is the 1.4.1 channel. Width updates transition on `var(--motion-base)` (state-transition class, vocabulary read — chip precedent); reduced-motion collapses at the vocabulary layer.
2. **Indeterminate run** (active, no fraction): NO fake bar — the state word carries it ("running · started 14:02"). A bar that lies is worse than a word that doesn't.
3. **Backlog gauge** (queue-depth truth, not run-truth): rendered as `digested / total` text + the same bar as a fraction-of-backlog — labeled "backlog", never "progress": a queue is not a task.

### 4 · Binding map (shapes verified live, not assumed)

| Row source | Verb (authenticated bridge) | Verified shape → render |
|---|---|---|
| KB ingestion | `get_ingestion_progress` | `{status, active, phase, totalChunks, embeddedChunks, stalled, startedAt, lastRunSummary, observedScope}` → Running (determinate: embedded/total; `stalled: true` earns the wedged word — text, not hue); `observedScope: "this-process-only"` + `crossProcessHint` ⇒ the row's provenance pill carries the scope ("KB · this process") — the caveat is part of the truth |
| MC REM pipeline | `get_rem_pipeline_state` | `{undigested: 960, digested: 1040, sessionNodes, recentCycles}` → the backlog gauge (§3.3); "running" claimable only from `recentCycles` freshness, else it is a queue fact |
| Orchestrator / tenant lanes | `get_deployment_state_snapshot` (the crossProcessHint's named home) | scoped rows where the snapshot reports lane activity; absent → absent |
| Schedule (next runs) | **no verb yet — D#11857 owns the decomposition** | the honestly-labeled sample state: section-level provenance pill `sample`, spine-banner honesty discipline — the pane never fakes liveness; the narrowest wire verb becomes its own service ticket once D#11857 settles the serving shape |

Absent sources render as absence (an honest empty line per section, the drawer-shell item-5 idiom) — never invented rows.

### 5 · States

- **Cold spine** (no bridge): every section sample-labeled — the pane still teaches its shape, exactly like the static roster.
- **Partial** (some verbs live): per-SECTION provenance, mixed truthfully — live rows never inherit a sample label and vice versa.
- **Live**: provenance pills stay rendered (furniture class — findable before it matters).

### 6 · Type/spacing/motion conformance ledger

Every text node resolves through a role token (display is not used — no identity surface here); spacing on `--fm-space-*` + the pill/chip geometry tokens; motion = `--fm-motion-panel` for any reveal, `var(--motion-base)` for state transitions, zero literals; zero CSS-in-JS; both themes by token construction.

### Implementation deltas (2026-08-22, the gate met: operator acceptance in session — "plan sounds solid"; #17491 merged)

1. **§4 binding map — Queued · next is LIVE.** The "Schedule (next runs): no verb yet" row is falsified by the snapshot itself: `tenantRepoSync.repos[].nextDueAt` / `due` (per-repo next run, identity-hash-labeled, backlog gauge from `corpusOutstanding`), `maintenance.retry.nextAttemptAtMs` (under its phase word), and the sweep's `task.running` / `lastCompletion` all ride `get_deployment_state_snapshot`. `recoveryRuns.entries[]` (in flight → Running, finished → Recent) and `selfHeal.summary.currentlyFrozen[]` (Running, word "frozen") join too. The honest sample survives only on the cold spine.
2. **`get_ingestion_progress` binds in in-process mode only** — the plane client proves identity against the Memory Core plane and holds no Knowledge Base session; plane mode answers that axis as the typed `unwired` state (no degrade). The snapshot carries the deployment's real ingestion lane in both modes.
3. **§2 row grammar renders the state word AND the optional progress** (`[time] [name] [state] [progress?] [provenance]`): the word is the always-present text channel, the bar additive. The determinate bar is the native `<progress>` element (data = `value`/`max`; no script-written style) styled through `--fm-panel-2` / `--fm-signal` at `--fm-space-1` height.
4. **The cockpit drives the read** at boot, on every liveness tick (own in-flight cap) and on reconnect; the pane never reads on its own (sibling contract) and still fires the refresh intent.
5. **§5 cold spine is told apart structurally:** a transport-level fallback carries no source axes → labeled sample (the Activity stream's fail-closed-never-blank convention); a source-level unavailable read (axes present, all failed) → the honest empty lines under the reason. Live rows never sit beside a sample.
6. **Placement:** `tasks` joins `stream-tabs` directly after `stream` (WHO above, WHAT beside Activity), per #17269's south content-tab family.
