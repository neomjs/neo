## 1. Mechanism map (today, source-cited)

- Push path: `SENT_TO_ME` → wake daemon digest → adapter → (a) `a2a-webhook` POST to a host-reachable listener, or (b) `kimi-pull-bridge` append to a **host-file** outbox (`deliverViaKimiPullBridge`, `ai/daemons/wake/daemon.mjs:1616`). Both terminate host-side. A no-checkout cockpit machine can be neither.
- The shipped pull-inversion consumer (`consumeWakeOutbox.mjs`) polls that host file under a strict lock with three owner legs (agentIdentity, sessionId, pid+pidStartedAt) — all **same-host process proofs**.
- Subscription **state** already crosses the authenticated MCP surface (`readSubscriptionsOverMcp.mjs`, #16431). Envelope/digest **content** has no authenticated remote read surface at all. That is the whole gap.
- The daemon's own delivery contract states: *"A wake digest is derived from current unread state rather than from a queued payload, so the next natural flush re-includes anything still unread"* (`daemon.mjs` delivery-classification JSDoc). And `buildWakeDigest(identity, {messages, tasks, permissions, heartbeats})` (`wakeDigestBuilder.mjs:117`) is a **pure function over event arrays**.

## 2. The fork

**Option A — poll-over-ingress, derive-at-read (my recommendation).** A new authenticated MCP read verb (working name `poll_wake_digest`) on the memory-core surface. At read time it derives exactly what the daemon would push — the caller's current unread/pending event sets through the *same* `buildWakeDigest` — and returns it, or a closed empty state carrying its reason. Properties:

- Zero new storage, zero new daemon path, zero server-initiated channel, zero host listener.
- Honors the #15665 twin anti-goal **by construction** — nothing is spawned; the client pulls.
- Self-healing for free: the digest is derived from current state, so a missed poll re-includes anything still unread (the daemon's own property, quoted above).
- Owner-proof translation: the consumer's three host-local legs (pid/start-time/ppid descent) exist only to prove *same-host process ownership*. Over the ingress, the authenticated caller identity **is** the owner proof — one leg, stronger, already enforced. (`X-PREFERRED-USERNAME` lesson from `readSubscriptionsOverMcp`: verify identity agreement, never trust the header was honored.)
- Route health stays subscription-STATE-derived + last-poll watermark, never delivery counts (AC4, at-least-once guard).

**Option B — server-initiated over ingress (SSE/WS).** Held connections, reconnect bookkeeping, a new infrastructure class we do not operate — and it duplicates what the poll already proves. Rejected as v1 weight, named for completeness since the AC texts say "poll **or** server-initiated".

**Option C — plane-side outbox accumulation + drain.** Keep daemon digests, write them to a plane-side store, poll drains. Fallback if F1 below falsifies A.
