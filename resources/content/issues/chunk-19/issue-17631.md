# Reconcile out-of-AgentOS consumers before relocation

## Context

Epic #17500 now records a post-graduation correction from [D#17489](https://github.com/orgs/neomjs/discussions/17489): the extraction inventory omitted live imports into AgentOS implementation from outside the moving `ai/` population. The evidence and author fold are at [DC_kwDODSospM4BFJRU](https://github.com/orgs/neomjs/discussions/17489#discussioncomment-18125908).

The predecessor #17525 / PR #17530 delivered its exact stated eight populations and remains resolved. Its registry has no `test/playwright/fixtures.mjs`, `restoreEmptyTargetMeasurementAdapter.mjs`, `apps/agentos` spec, or tracked seat-hook identity; reopening it would erase the fact that this is a newly discovered consumer-edge population.

Current source proves the gap:

- `test/playwright/fixtures.mjs` imports seven `ai/services/neural-link/*` host services plus the Neural Link config template, and finds the Bridge through an ancestor-owned npm script;
- `test/playwright/restoreEmptyTargetMeasurementAdapter.mjs` imports Memory Core/graph helpers and directly imports `better-sqlite3` / `chromadb`;
- `test/playwright/{unit/apps/agentos,e2e/agentos}` includes both Engine UI specs and AgentOS service-implementation integrations;
- tracked Claude, Codex, and Kimi hooks resolve lane-state, wake, presence, and Memory Core modules relatively from the target checkout.

The full structure-map command was run at creation time and reproduced the known `Cannot create a string longer than 0x1fffffe8 characters` failure. Scoped maps verified the existing homes: `ai/scripts/diagnostics/agentOsExtractionInventory.{mjs,json}` and `test/playwright/unit/ai/scripts/diagnostics/agentOsExtractionInventory.spec.mjs`. This leaf extends them; it creates no new `.mjs` placement.

## The Problem

The delivered inventory can report zero residue while a repository cut still breaks Engine tests, app specs, and every provisioned seat hook. None of those imports belongs to the registry populations the tool claims to reconcile.

The tempting repair—add the extracted Agent OS package as an Engine `devDependency`—would contradict the selected dependency covenant and the onboarding result. Epic #17500 now requires zero Engine `dependencies` or `devDependencies` edges to Agent OS. Engine-only test tiers must load without Agent OS; Neural-Link Whitebox is a separate cross-repository tier against an externally provisioned runtime.

Without a source-owned consumer-edge population, later move/re-provision/proof leaves must rediscover these imports under cutover pressure, and a new edge can enter silently after this measurement.

## The Architectural Reality

- `agentOsExtractionInventory.mjs` is the rerunnable census authority; its JSON registry owns exact dispositions and its existing unit spec owns missing/stale/mutation failures.
- C′ preserves one-way AgentOS→published Engine dependency. `src/ai/**` stays Engine-owned as the Body-side Neural Link contract/client.
- Custody follows subject, not the shared test directory: Engine regression clients/UI specs stay; Memory Core/Fleet server implementation tests move or become served-contract integration.
- Named Brain hooks move with AgentOS source. Seat re-provisioning materializes ignored target artifacts from `agentosRuntimeRoot`; Engine-only contributor guards with no Brain dependency stay Engine.
- This is a pre-relocation ledger/guard leaf. It neither chooses the future client implementation nor moves any source.
- It is blocked behind #17533 to avoid changing the registry/consumer surface while the active paired-proof owner consumes proof 1.

## The Fix

Extend the existing extraction inventory and registry with one exact **out-of-AgentOS consumer-edge** population:

1. Derive every tracked static and literal-dynamic import from outside the moving AgentOS population into an AgentOS implementation/config path. Reuse the existing import/closure parsing primitive; do not add a second regex-only graph walker.
2. Give each edge a stable semantic identity: consumer path, normalized specifier/target, import kind, and source coordinate.
3. Require one closed disposition per edge:
   - `engine-contract-client`
   - `served-contract-integration`
   - `moves-agentos-test`
   - `generated-target-artifact`
   - `stays-engine-guard`
4. Record a non-empty rationale plus a successor phase (`move`, `seat-reprovisioning`, or `engine-continuity`) for every non-staying edge. Native Epic children remain graph authority once those phases are filed; this registry does not hardcode a child list.
5. Add a package-direction guard proving Engine manifests contain no Agent OS dependency or devDependency.
6. Emit the consumer population and residue in the existing deterministic human/JSON receipts. Missing, stale, duplicate, invalid, same-count-substituted, or unowned rows fail non-zero.
7. Link the current-head receipt on Epic #17500 before any relocation leaf starts.

## The boundary crossing runs BOTH ways — here is the outbound population, measured

### Why this belongs to this leaf rather than to the inventory

These are not a population gap — the registry never claimed `src/**`, so scoring them as unregistered would point the inventory owner at a repair that is not theirs. They are **boundary crossings that only become crossings at the cut**, which is exactly this leaf's subject.

And post-cut they are governed by ADR 0040 §2.3, which is unambiguous: *"The extracted repository consumes the Engine as a **published package**. The Engine never imports from the extracted repository."* Today `ai/**` code reaching `src/**` is an ordinary relative import inside one repo. The moment `ai/` moves, every one of these 48 must resolve through the published Engine package or it is a broken import — and 35 of them land in `src/**`, the Engine's own source.

So the two directions have **different** repairs and only one of them is in scope here today:

- **inbound** (this ticket's current population) — Engine-side consumers importing AgentOS implementation. ADR 0040 §2.3's covenant is absolute in this direction: no Engine `dependencies`/`devDependencies` edge on the extracted repo, dev-time included. These get reconciled via the two-tier test contract.
- **outbound** (the 48 above) — AgentOS code importing Engine source. Sanctioned, but only *through the published package*, which means each one is a real edit at cut time rather than a covenant violation.

### Suggested scope amendment, not a claim on the leaf

I would add the outbound 48 as a second population with its own AC — "every outbound Engine reach resolves through the published package, or is dispositioned" — rather than fold it into the inbound one, because the repairs differ and conflating them would hide that 35 of the 48 are Engine-source imports that simply need a package specifier.
