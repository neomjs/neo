Refs #15065

> **Close-target: intentionally NOT `Resolves`.** #15065 stays open. AC1 (adapter spec loadable) is delivered + verified here, but AC2 (two-window cross-window drag safety, browser-witnessed) is a real, unmet safety AC on a drag-critical change. Evidence owner: **Grace** — I own the two-window browser witness on the corrected head. Cross-family review (Euclid, cycle 1) additionally found a first-gesture move/end ordering race (the base `onDragMove` awaits a one-frame macrotask, so a non-awaited `DomEvent.fire` release can finalize before the move engages the coordinator). Cycle 2 pins it (coordinator preloaded off the drag hot path at construction + `processDragEnd` drains the in-flight move before the coordinator-end call) with a fire-and-forget-ordering regression test, then witnesses AC2.

`DockLayoutAdapter` statically imports `DockTabSortZone` (for its projected `sortZoneConfig`), and `DockTabSortZone` imported `DragCoordinator` at module scope. `DragCoordinator` imports `manager.Window`, a `@singleton` whose `construct()` touches `Neo.currentWorker.on` at `setupClass` (import time). The unit loader stubs `currentWorker` only *inside* its `setup()` call — which ESM hoists *after* the import graph evaluates — so the whole chain threw at load, and `DockLayoutAdapter.spec.mjs` surfaced as **"No tests found."** That blocked my #14771 RA-2 falsifiers (PR #15062) and Euclid's isolation testing.

## Fix

`DockTabSortZone` touches `DragCoordinator` only in its two async, `sortGroup`-gated drag methods (`processDragEnd`, `onDragMove`) — never at module/class scope. So resolve it via a cached-promise **lazy import** at drag time:

```js
resolveDragCoordinator() {
    return this._dragCoordinatorPromise ??= import('../manager/DragCoordinator.mjs').then(module => module.default)
}
```

The adapter imports the SortZone but never constructs or drags it, so the `Window` chain never evaluates in the unit env. `processDragEnd`'s ordering invariant (the coordinator arms `remoteDropCommitted` before the local drop check) is preserved: `await` the import, *then* `onDragEnd` (which arms the flag synchronously on the same stack), *then* the local check.

Evidence: L2 — a local, reversible, call-semantics-identical import-timing change; verified by running the previously-unloadable spec (19/19, below).

**Cross-window drag runtime — NOT verified this pass; an open safety AC, not "designed-safe."** Cycle-1 review corrected my initial "call-semantics-identical" framing: because `DomEvent.fire()` invokes the drag handlers without awaiting them and the base `onDragMove` awaits a one-frame macrotask, a drag-time async boundary can let a fast release finalize before the move engages the coordinator (missed remote engagement, not a cosmetic lag). Cycle 2 pins the ordering (see the close-target note above) and then witnesses the two-window browser AC. Until that lands, AC2 is unmet and owned by Grace.

### 🔬 Depth Floor

**Challenge:** `Neo.manager.DomEvent.fire()` invokes `dragZone.onDragMove(data)` and `dragZone.onDragEnd(data)` without awaiting either. The new `DockTabSortZone.onDragMove()` first awaits `super.onDragMove(data)` and only then awaits `resolveDragCoordinator()`. `processDragEnd()` reaches `resolveDragCoordinator()` before its coordinator-end call.
