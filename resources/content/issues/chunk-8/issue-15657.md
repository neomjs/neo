# FM cockpit: vessel-narrow (~314px) layout — rail behavior + zone priority

## Context

The ~314 CSS px vessel window (a popped-out narrow detail window; the Retina-corrected geometry from `#15649`'s visual-matrix review) currently renders the FM cockpit **clipped and unreachable-by-scroll**: at a 314px viewport the cockpit measures ~971px scrollWidth against a 314px body, so the Start fleet button and right-hand content are simply off-window.

This is a layout surface, not a paint fix. Measured while working `#15649`:

- `.fm-fleet-cockpit` carries `flex: 1 0 100%`; with default `min-width: auto` its floor is the widest child's min-content (the nowrap `.fm-spine-banner`, ~536px).
- `.fm-spine-banner` has `flex: none` + `white-space: nowrap` — its ellipsis rules never engage (shrink forbidden).
- Each descendant needs its own shrink floor (grid zone wrapper, cards grid, card, stream) — zeroing them one level at a time just pushes the pressure down the tree until both dock zones collapse toward their padding boxes (fleet zone 32px, stream 28px) while the right-edge rail keeps its share.
- Conclusion: the honest fix is a vessel-narrow LAYOUT decision (rail behavior + zone priority at narrow widths), not per-element floors.

Live latest-open sweep: checked latest 20 open issues at 2026-07-21 ~20:20Z; no equivalent found. A2A in-flight claim sweep (last 60 min): no competing claim.

## The Fix (design surface)

Define and implement the cockpit's vessel-narrow layout: what the right-edge rail does at ~314 (collapse to icons? hide? bottom-dock?), which zone wins the width (fleet grid vs activity stream), and how the cockpit bar wraps with the banner ellipsizing. The spine banner's `flex: none` shrink-forbiddance is part of the surface regardless of the chosen shape.

## Acceptance Criteria

- [ ] At a 314 CSS px window the cockpit's interactive core (cards, Start fleet, pop-out toggle) is reachable — wrap, collapse, or scroll by explicit design
- [ ] `.fm-spine-banner` ellipsizes under pressure instead of forcing layout width
- [ ] The `cockpit-vessel-314` visual receipt (`FleetCockpitVisual.spec.mjs`) is regenerated at the repaired layout, with the overflow assertion removed
- [ ] No regression to the desktop baselines (default shell, fleet grid, activity stream)

## Vessel-narrow layout — design decision (intake + design phase)

**Intake verdict: valid-as-written.** Premise re-verified at source 2026-07-24: `SpineBanner.scss` still carries `flex: none` (L22) + `white-space: nowrap` (L33) with the ellipsis rules dead, and the committed `cockpit-vessel-314` receipt (`FleetCockpitVisual.spec.mjs:82`) still asserts the overflow as tracked truth. Short-horizon sweep: #15649 / #15652 / #15634 / #15648 all merged without touching this surface.

### Design authority consulted

- **ADR 0029** — the rail is the auto-hide contract's surface (reveal = **overlay, never push**); the committed dock document is worker-owned layout SSOT. Consequence: the vessel-narrow treatment must be **pure projection/presentation** — the committed `dockZone.v1` document stays byte-identical at every width.
- **Own-width discipline** (cited to ADR 0029 in `AgentCard.scss:4`): components respond to their own width via `@container`, never the viewport. Landed precedents: AgentCard `@container (max-width: 289px)`, AgentDetail `@container (max-width: 315px)` (#15652). The cockpit has no container context yet — this ticket adds it.

### The decision

1. **Spine banner shrinks everywhere (AC2, unconditional).** `flex: none` → `flex: 0 1 auto`. The landed `min-width: 0` + `max-width: 100%` + ellipsis rules engage; the honesty line truncates before it ever forces layout width. This kills the ~536px nowrap floor at all widths, not just narrow — the banner already opts into ellipsis; only the shrink-forbiddance blocks it.
2. **The cockpit becomes its own width-query context.** `container-type: inline-size` on `.fm-fleet-cockpit` (mirrors both landed siblings). Side benefit: inline-size containment stops child min-content from escalating into the vessel window's floor.
3. **Vessel-narrow mode** at `@container (max-width: ~570px — threshold measured and pinned at implementation, derivation: card floor 289 + stream usable floor + rail 34 + splitter 6)`:
   - **Cockpit bar wraps** (`flex-wrap: wrap`): presets, Start fleet, pop-out toggle flow to a second row — the interactive core stays reachable (AC1) instead of forcing width.
   - **Zone priority: neither zone hides — the split stacks.** The projected two-zone split re-orients column-wise: fleet grid first (interactive core wins the top), activity stream below (telemetry stays visible — silently hiding the stream would be dishonest chrome). Committed `sizes` proportions map to heights; splitter drag is disabled at narrow (axis mismatch) rather than re-axed.
   - **Rail: unchanged.** 34px is affordable at 314; ADR 0029 §rail-reveal already renders reveals as overlays sized by workspace-extent fraction, which is narrow-safe by contract.
4. **Receipt (AC3/AC4).** `cockpit-vessel-314` regenerated at the repaired layout; the overflow assertion is **replaced by its inverse** (scrollWidth === viewport + Start fleet visible), not merely removed. Desktop baselines untouched.

### Named implementation fork (resolved by a spike, not by taste)

The split projection is `DockLayoutAdapter.projectSplitNode` → hbox/vbox layouts (`DockLayoutAdapter.mjs:738`). If child extents land as inline styles, a pure-SCSS restack can't cleanly win. Two strategies, spike decides:
- **A (preferred):** pure SCSS `@container` restack — zero runtime involvement.
- **B (fallback):** a cockpit-owned narrow-mode class toggled from its own resize observation, which the projection SCSS keys on — still presentation-tier, still zero document mutation.

Implementation follows on `agent/15657-vessel-narrow-layout`; PR sequenced behind the current cross-family review-queue drain.

## Adjacent width-axis touch, recorded rather than filed

PR #17341 (#17313) adds `min-height: 0` / `min-width: 0` at five selectors on the AgentOS shell spine — `.neo-tab-container`, `.neo-tab-body-container`, `.neo-dashboard-dock-tabs`, `.neo-dashboard-dock-edge-band`, `.fm-fleet-cockpit` — scoped to the `agent-os-viewport` cls.

Four of those are on the width axis, which is this ticket's axis.

**I am not claiming a reproduction, and the direction differs.** The work that collapsed both dock zones to 32/28px was per-level `min-*` pressure pushed *down* the tree; this is containment applied *up* the spine so a tall pane scrolls inside its slot instead of lifting the shell. Different intent, same boxes.

What makes it worth a note rather than silence: **nothing in the repository exercises this app below 900px.** The only `setViewportSize` in the entire agentos e2e directory is `900×1000`, and the guard added by that PR sets no viewport at all. So if the width axis does degrade under narrower geometry, no existing test would notice — the same blind spot that let the original collapse through.

Raised by @neo-opus-ada during review of #17341, verified against the tree, and recorded here so whoever picks this ticket up sees the adjacent change rather than rediscovering it from a diff.
