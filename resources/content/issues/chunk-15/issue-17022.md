# Prove provider-lane composition on the canonical plane

Sub of epic #17018 (AC-B proof boundary and AC-D stage 3). This leaf consumes #17021's rendered role map and canonical two-lane profile. It does not own the `{1,2,4}` resource-performance election.

## Context

Discussion #17015 r6 makes D+F conditional on Neo-owned canonical-plane proof. Configuration and green unit tests are insufficient: the final evidence must show that the rendered role map reaches distinct provider services, that each lane enforces its own runtime contract, and that failure in one lane does not silently migrate work or recycle the other.

Live duplicate sweep (2026-08-12T12:06Z): latest open issue search for `provider lane`, `NEO_GRAPH_PROVIDER`, and `vector generation election`, plus the current A2A lane-claim page. No existing issue owns this composition/containment proof. The adjacent `{1,2,4}` resource-performance election remains a peer lane.

## The Problem

The repository has useful but disconnected diagnostics:

- `ai/scripts/benchmark/keep-alive-probe.mjs`
- `ai/scripts/benchmark/gemma4-rem-benchmark.mjs`
- `ai/scripts/benchmark/serving-cost-meter.mjs`
- one-shot diagnostic siblings under `ai/scripts/diagnostics/`

None consumes the canonical rendered role map and answers the release question as one bounded receipt:

- Did every role reach the declared service DNS/provider/model coordinate?
- Did each runtime enforce the lane's per-slot context contract?
- Can abandoned embedding work be contained on the replacement engine?
- Can either lane restart without invalidating the other lane's identity or routing?
- Does an inconsistent split fail before it becomes a healthy-looking deployment?

Without that instrument, the external revision would inherit assertions assembled from unrelated tests.

## The Architectural Reality

This is a validation consumer, not another configuration authority. It consumes the rendered profile from #17021 and the immutable deployment inputs elected by the adjacent resource-performance lane. It must not infer provider selection from process names, re-read env as a second configuration system, or write into KB/MC state.

All fault injection and provider work run only on Neo's canonical/disposable validation plane. The tool has no external-plane endpoint, token, or deployment mutation path.

Structural pre-flight: the full `npm run --silent ai:structure-map -- --files --loc` currently fails with V8's maximum-string error; the scoped diagnostics map succeeds. A new `ai/scripts/diagnostics/providerLaneComposition.mjs` follows the existing one-shot/read-only sibling pattern of `genesisProbe.mjs`, `mcpHealthcheck.mjs`, and `pilotPlaneTerminal.mjs`; its unit coverage belongs under `test/playwright/unit/ai/scripts/diagnostics/`.

## The Fix

Add one bounded composition validator that:

1. consumes #17021's rendered composition receipt and the actual canonical runtime identities,
2. records service DNS, role, provider, immutable image/model coordinate, and observed endpoint for every route,
3. exercises one valid request and one over-limit refusal per lane without writing KB/MC data,
4. proves embedding cancellation/abandonment containment on the replacement engine with a bounded post-disconnect idle observation,
5. proves restart isolation in both directions,
6. fails on a wrong-lane mutation, duplicate role ownership, missing digest, inconsistent DNS, or hidden fallback,
7. emits a stable machine-readable receipt plus a concise terminal verdict.

Reuse existing benchmark/probe primitives where their contracts match; do not create a parallel provider client or configuration parser.

## Contract Ledger

| Producer | Consumer | Contract | Failure semantics |
|---|---|---|---|
| #17021 rendered composition | composition validator | complete role → lane → provider → model → DNS map | missing/duplicate/inconsistent entries are terminal before inference |
| canonical disposable provider profile | bounded lane probes | immutable runtime identity and per-slot context contract | mismatch or silent truncation fails the receipt |
| replacement embedding runtime | abandonment-containment arm | caller disconnect cannot leave unbounded admitted work | no bounded idle/settlement evidence means NOT_PROVEN |
| lane restart arm | opposite lane and route resolver | one lane's restart preserves the other's identity and routing | cross-lane outage or fallback fails |
| validator | release gate | one JSON receipt with per-arm evidence and a non-success exit code on any required failure | never converts missing evidence to PASS |

## Acceptance Criteria

- [ ] `ai/scripts/diagnostics/providerLaneComposition.mjs` validates the rendered #17021 composition against observed canonical runtime identities and emits deterministic JSON plus a human-readable verdict.
- [ ] Every chat, graph, Ask synthesis, and embedding route is represented exactly once with service DNS, provider, immutable image/model coordinate, role, lane, and observed endpoint.
- [ ] One valid request and one over-limit input per lane prove the declared per-slot contract; silent truncation or cross-lane routing fails.
- [ ] A bounded replacement-engine arm proves embedding cancellation/abandonment containment, including post-disconnect provider settlement/idle evidence. An inconclusive arm reports NOT_PROVEN, never PASS.
- [ ] Restart-isolation arms prove chat-lane restart leaves embedding routing/identity intact and embedding-lane restart leaves chat/graph/Ask routing/identity intact.
- [ ] Mutation tests cover wrong-lane routing, duplicate ownership, missing digest, inconsistent DNS, and a falsely healthy split.
- [ ] The instrument cannot accept external-plane endpoints/credentials and all production-shaped execution is restricted to Neo's canonical/disposable validation plane.
- [ ] Focused unit coverage is green using Neo's unit-test configuration; `git diff --check` is clean.
- [ ] The PR publishes a machine-readable canonical receipt but does not claim the separate resource-performance election or vector-generation migration is complete.

## Decision Record Impact

Implements the validation evidence required by amended ADR-0014 and #17018. No new ADR or AiConfig leaf is required.

## Out of Scope

- Declaring the `{1,2,4}` winner or measuring the joint-load SLO (adjacent peer resource-performance election).
- Building or promoting KB/MC vector generations (AC-C/AC-E siblings).
- Editing canonical provider routing or Compose (#17021).
- External-plane probes, experiments, credentials, or partial deployment.
- General-purpose benchmark framework work.

## Avoided Traps

- Treating a rendered Compose file as proof that traffic reached the intended service.
- Reusing a chat cancellation result as embedding-containment evidence.
- Passing on missing runtime identity or provider settlement.
- Mutating canonical KB/MC data during provider validation.
- Turning this bounded release proof into a second performance-election harness.
