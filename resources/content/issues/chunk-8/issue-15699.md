## The Problem

“Every post gets a cover” is easy to state and costly to sustain. Without an explicit production and review boundary, it decays into one of two failures: bespoke artwork throttles the publishing cadence, or low-effort filler weakens the hero-piece quality bar. The current blog workflow cannot distinguish a missing required cover from a deliberate no-cover post, and it has no receipt proving safe-area, alt-text, source/provenance, or visual acceptance.

## The Architectural Reality

- /blog-post owns article eligibility, authoring, registration, and public-review gates.
- /imagegen owns raster-generation/editing mechanics; this issue must specify the brief and accepted artifact, not duplicate provider/tool parameters.
- blog.json is a navigation registry today, while [BlogNeo.mjs](https://github.com/neomjs/neo/blob/dev/apps/portal/model/BlogNeo.mjs#L17-L58) models only the existing navigation fields. Graduation must decide whether cover metadata belongs there, in post front matter, or in a separate bounded manifest.
- #13383 owns the sustained blog stream and is the correct parent.
- No new .mjs placement is prescribed before graduation. Any graduated executable/schema proposal must run structural pre-flight first.

## Reservation-Era Recommendation (superseded)

Adopt a **default cover with a bounded path**: every publishable post receives a distinct cover unless its selected profile explicitly opts out; the default path uses a reusable brief/template, safe-area variants, accessible alt text, immutable source/final references, and a fast human visual-acceptance receipt. If that path cannot stay cheap across the first measured packages, revert the universal default to profile-triggered covers.

## Reservation-Era Fix Sketch (superseded)

1. Define the post profiles for which a cover is default, optional, or refused.
2. Add a reusable cover brief with thesis, claim references, aspect/safe-area variants, alt text, disclosure/provenance, source hash, and immutable accepted-artifact identity.

4. Select the metadata owner only after comparing post front matter, blog.json, and a package manifest.
5. Define the bounded visual-review receipt and the decay trigger measured by the longitudinal sibling ticket.
