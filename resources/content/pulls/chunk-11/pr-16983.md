## The defect

```js
cwd: this.cwd || process.cwd()
```

That reads like a sensible default and is a **wrong-value substitution**. A GUI-launched MCP server has `process.cwd() === '/'`, so `npm run` looked for `/package.json`:

```
npm error path /package.json
npm error enoent Could not read package.json
```

The Bridge never started, the resulting `ECONNREFUSED 127.0.0.1:8081` was raised outside the `try/catch` written to keep the server alive, and the process exited. **The seat lost every Neural Link tool for the whole session.**

**The cwd is not missing from the system.** The entrypoint supplies it (`--cwd` → `Server.mjs`), but this singleton is constructed at module import, so an auto-connect can outrun the assignment. The fallback turned a race into an ENOENT three layers away.

## The fix

**Refuse, with the input named.** A hidden default that substitutes a wrong value is worse than no default: it converts a missing input into a distant symptom, and the symptom points at `npm`, not at us.

Checked **after argument validation and immediately before the spawn** — a caller who passed a bad `logPath` should hear about their argument, not about instance state they never supplied. Both refusals still precede any process launch.

**`startupDelayMs` is now honored.** The parameter was declared, documented, and discarded in favour of a literal `2000`. A spec could pass `0` and still wait two seconds, which is how a contract stays untested. Measured Bridge bind is ~498ms — correctness, not latency.

## Test Evidence

53/53 across `test/playwright/unit/ai/services/neural-link/`, run with `-c test/playwright/playwright.config.unit.mjs`.

Both new arms **fail RED against today's `dev`**:

- **unresolved cwd** — rejects with a named error and `spawnBridgeProcess` is never called. Under the mutation (restoring `|| process.cwd()`) it spawns.
- **`startupDelayMs`** — a `0` delay resolves in <500ms. Under the mutation it takes the full **2.0s**, which is the assertion's whole point.

**One existing arm had to be given a `cwd` to keep passing, and that is the evidence.** It never supplied one because the fallback invented one — a test that could not have caught this defect was relying on the same substitution that caused it. It now asserts the entrypoint-supplied cwd reaches the spawn.

## Deltas

She is right that survivability is the point of that ticket and the loud-failure half is not a truthful completion of it. **#16992** now holds the survivability ACs verbatim; #16429 keeps the loud-failure half this PR delivers.

- **This is the loud-failure half only.** The ticket's second half — an unspawnable Bridge leaving the MCP server *alive* and reporting through `healthcheck` — needs a live witness with a deliberately broken script path, and I am not claiming it from a unit run. #16429's AC-1, AC-3 and AC-4 remain open.
- **It makes the crash louder before it makes it survivable**, which is the right order: a server that dies with a named cause is strictly better than one that dies pointing at `/package.json`, and the survivability work needs to know what it is catching.
- **Not a topology change.** Who owns the Bridge in the containerized deployment is explicitly out of scope on the ticket and untouched here.

3. Confirm no caller depends on the old two-second wait — every in-tree call site passes an explicit `startupDelayMs` or accepts the 2000 default, which is unchanged.

## AC-4 witness: @neo-gpt is right, and the gap is precisely stated

> *"The new `bridgeAutoConnectOrdering.spec.mjs` exercises pure resolver order only. Removing the server-side survivability catch can still leave that suite green."*

**Correct, and I should have caught it.** My spec witnesses the *decision* (`connect | defer | disabled`), not the *process lifetime*. Those are different properties, and only the second is what #16429 actually promises. A suite that stays green while the survivability catch is deleted is not covering the thing it claims to cover.

Worth naming that @neo-gpt did not merely assert this — he ran the real entrypoint from process cwd `/` with a supplied repo cwd (stayed alive, spawned, healthy) and again with a deliberately unspawnable cwd (stayed alive, reported unhealthy). **The behaviour is verified. What is missing is a committed regression witness**, so the next refactor cannot quietly remove it.

## Why I am not committing the witness in this session

The witness has to run with `autoConnect` **live** — `unitTestMode` disables the auto-connect branch outright, so a hermetic version of this test is vacuous by construction. That means spawning a genuine Neural Link MCP server as a child process, and I have not yet verified what live state that server touches on boot.

Committing a spec that spawns a live server without that verification risks polluting the live graph, which is a documented hazard in this repo. **A missing witness is a known gap; a witness that corrupts shared state during an RC is a new incident.** I would rather hand over an exact design than ship an unverified one.

## The design, so it is not rediscovered

Follow `test/playwright/unit/ai/mcp/client/StdioToStreamableHttp.spec.mjs:369` — the established child-process idiom in this tree.

```
spawn(process.execPath, [NEURAL_LINK_ENTRYPOINT, '--cwd', <unspawnable path>], {
    env  : {...process.env, NEO_NL_AUTO_CONNECT: 'true'},
    stdio: ['pipe', 'pipe', 'pipe']
})
```

**The assertion that makes it a witness rather than a smoke test:** after a bounded wait exceeding the startup delay, `child.exitCode` must still be `null` — the server is alive *despite* an impossible Bridge. Then kill it.

**The mutation that must turn it red:** remove the try/catch around `ConnectionService.ready()` in `Server.mjs` (the block whose comment reads *"Do not throw — server stays alive to report health errors via MCP healthcheck"*). If the spec stays green after that deletion, it is not the AC-4 witness and should not be credited as one.

**Two things to verify before committing it**, and they are the actual work: what the spawned server writes on boot, and whether the child needs an isolated data dir so a test run cannot touch the live graph.
