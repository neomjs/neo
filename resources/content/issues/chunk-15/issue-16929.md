# A script's execution plane is unknowable from its path, and nothing checks it

## Context

Operator-named, 2026-08-11: *"let us drop 139 files into `ai/scripts`, a wild mix of host-edge and cloud plane… who cares if no one will ever have a chance to find anything or know when to use what. but hey, i checked MY ACs."*

Debt paid before opening: nine tickets closed 2026-08-10, including `#16910` and `#16914`. Live sweep at 2026-08-11T00:05Z; no existing owner for script-plane classification.

> **CORRECTED 2026-08-11T01:40Z, before implementation.** The measurement table originally published here was wrong, and the detector this ticket specified produced false positives on both sides. Both corrections are below, with the numbers that replaced them. The defect and the fix are unchanged; the evidence for them is now measured rather than asserted.

## The Problem

`ai/scripts` holds **144** `.mjs` files. They are **not** a flat dump — there are 9 subdirectories and **0** loose files at the top level. That part of the complaint is not literally true.

What is true is worse than untidiness: **the taxonomy encodes the VERB and not the EXECUTION PLANE — and the plane is what decides whether a script is usable at all.** `maintenance` means "this maintains something"; it does not tell you whether the thing needs the operator's shell and Docker socket or runs against services.

Per the Local Runtime Parity constraint a client topology has **no host shell and no Docker access**, so every host-edge script is dead weight there — discoverable only by opening the file.

**And there is no navigational surface at all:** no `README`, no index, anywhere under `ai/scripts`. The one instrument that should answer this does not — `npm run ai:structure-map` emits `{path, fileCount}`, a **census** rather than a map.

### What the corpus actually measures

| plane | scripts | how it is known |
|---|---:|---|
| `host` | 38 | shells out, drives docker, reads the operator home dir, or signals host processes |
| `in-plane` | 106 | needs none of the above |

**8 of the 10 directories containing `.mjs` are mixed** (`benchmark`, `diagnostics`, `lifecycle`, `lint`, `maintenance`, `migrations`, `runners`, `setup`). Only `benchmark/helpers` and `fleet` are homogeneous.

~~The original table claimed 5 of 9 mixed, with `maintenance` at 6 host-edge / 37 in-plane.~~ That "in-plane" column was computed as the **complement** of host-edge rather than as a positive detection, which inflated the classified population and hid the fact that most files carry no detectable signal at all.

### Detection is partial, and that is the point

Positive detection speaks for **77 of 146** scripts. The remaining **69 are silent** — a pure helper genuinely requires nothing, and no import-based detector can see that `diagnostics/seatCostReport.mjs` reaches into `~/.kimi-code/sessions`.

Those files are exactly why a declaration is needed: it states what detection cannot, and the lint re-checks it forever after, so the moment a silent file grows an `execSync` its stale declaration reds.

### The detector this ticket originally specified was wrong

Both false-positive classes were measured before a line was written, and both would have convicted correct files:

- **Prose read as code.** `maintenance/restore.mjs` mentions `compose` twice, both times in a JSDoc paragraph about bind-mount paths.
- **Substring matching read a sibling as a service.** `diagnostics/captureParityLatencyPair.mjs` matched "plane" on `./mcpHealthcheck.mjs`, a sibling script.

The shipped detector strips comments before reading evidence and resolves import specifiers to real paths.

## The Fix

**Each script declares its execution plane, and a lint compares the declaration against what the file actually depends on.**

1. A `@plane host` / `@plane in-plane` tag in the script's header JSDoc.
2. `lint-script-plane` fails on a **contradiction**, an **absence**, an **illegal value**, or a **conflict**.
3. `structure-map --plane` emits the declared plane per script plus a per-folder tally, so the map is **generated** and cannot rot.

**This is deliberately a comparator, not a convention.** The declaration is read from the COMMENTS and the evidence from the CODE — two texts that are disjoint by construction — so it cannot be satisfied by writing. A README rots on the first commit with nothing detecting the rot; a naming convention is graded by whoever follows it.

### Conviction is asymmetric, and must be

Only one direction is checkable:

| declared | evidence | verdict |
|---|---|---|
| `in-plane` | host | **contradiction** — it claims to run where it demonstrably cannot |
| `host` | plane imports | pass — an operator-run script may reach services over the network |
| either | none | pass — the declaration is the only source |

**Host evidence proves a requirement; plane evidence never proves sufficiency.** 15 scripts both shell out AND import a plane module — `backup.mjs` imports a config module only to learn *which container* to act on. A symmetric rule would fail every one of them.

## Open fork — resolved

- **Option A — path encodes the plane** (`ai/scripts/host/…`, `ai/scripts/plane/…`). Self-evident from a listing; costs ~144 moves plus every `package.json` path and doc reference, and one bad move is a silent 404.
- **Option B — declared tag + lint** (implemented). Zero moves, enforceable today, generated map.

**B first, A as a possible successor**, because B *produces the classification data* A needs to move files correctly; A first means hand-classifying 144 files with no checker. Routed to @neo-opus-grace and @neo-gpt-emmy before implementation; an A preference remains cheap, since B's output is A's input.

## Acceptance Criteria

- [ ] Every `.mjs` under `ai/scripts` declares `@plane host` or `@plane in-plane`, with the population read from the filesystem so a new untagged file cannot pass by being absent from a list.
- [ ] The declaration must live in the file's own header block — a tag parked on the first function's JSDoc does not count.
- [ ] `lint-script-plane` fails a script declaring `in-plane` that carries host evidence. Proven by a fixture, not by inspection.
- [ ] `lint-script-plane` fails a script with no `@plane` tag, an illegal value, or two conflicting values.
- [ ] **Non-vacuity:** a correctly-declared host script and a correctly-declared in-plane script both pass.
- [ ] **Asymmetry:** a `host` declaration is NOT failed by plane imports, and a comment mentioning `docker` is NOT evidence.
- [ ] **Mutation conviction:** flipping one real script's tag to the wrong plane reds the lint, and the run output is quoted in the PR.
- [ ] `ai:structure-map --plane` includes the declared plane per script and a per-folder tally.
- [ ] Every mixed directory is identifiable from `ai:structure-map` output alone, with no file opened.
- [ ] The lint runs in CI beside the existing lint family.

## Out of Scope

- **Moving any file.** Option A is a named successor, not this leaf.
- Adding a `README` to `ai/scripts`. A generated map cannot rot; a hand-written one is stale on the next commit.
- Re-organising the verb directories, splitting `maintenance` (44 files), or deleting anything.
- Scripts outside `ai/scripts` (`buildScripts/**`).
- Any judgement about whether a given script *should* be host-edge.

## Avoided Traps

- **A README instead of a comparator.** It rots on the first commit and nothing detects the rot.
- **A naming convention instead of a lint.** Graded by the person following it; no second artifact.
- **Option A first.** Hand-classifying 144 files with no checker is how a silent mis-move ships.
- **A symmetric contradiction rule.** Measured: it would fail 15 correct scripts.
- **Extending the tag to a taxonomy** (`host,plane,either`). `either` becomes the default nobody argues with and the comparator loses its teeth. ~~A genuinely dual script is a finding, not a category.~~ **Corrected:** dual-signal scripts are not hypothetical — 15 of them exist. The two-value rule survives for a different and better reason: host evidence *dominates*, so a dual-signal script has a determinate answer (`host`) rather than an ambiguous one.
- **Trusting the census.** `structure-map` reported file counts and nothing about what those files are for; a count is not an answer to "when do I use what."
