# One multi-input embedding batch monopolizes every engine slot, starving interactive canaries behind it

## Context

Live external-plane evidence, 2026-08-13 10:34–10:52Z: one Memory Core dynamic embedding batch (openAiCompatible path) held the dedicated embedding lane at ~594% CPU for 18 minutes. llama.cpp fans a single multi-input request out across all `n_parallel` slots, so one fat batch occupies the entire engine; the KB and MC health canaries queued behind it timed out repeatedly (~47s deadlines, KB streak 3) and both healthchecks read degraded — during completely legitimate work.

Per-process serial dispatch protects consumers from each other *between* processes; nothing protects slot capacity *within* the engine from a single caller's batch width.

## The Problem

Two compounding shapes: (1) the MC dynamic batch wrapper submits unbounded input counts in one HTTP call, so slot occupancy equals batch width; (2) every caller class rides the same request deadline, so an interactive canary with a ~47s expectation shares queue fate with a 60-minute-ceiling batch. The generous batch ceiling (correct — it prevents timeout-churn) makes the monopoly window legally long.

## The Fix (shape)

1. **Batch width cap** on the MC dynamic embedding wrapper for multi-slot engines: submit at most `slots − 1` inputs per call (or a config leaf), leaving one slot's worth of capacity for interactive work to interleave.
2. **Ceilings per caller class**, not one global number: canary/interactive calls keep short deadlines with retry; bulk batch calls keep the long ceiling (the existing env becomes the batch-class leaf).
3. Canary timeout streaks that coincide with an in-flight bulk batch should be reported as `busy-behind-batch`, not as provider failure — the health surface distinguishing load from fault (feeds the #16561/#17044 signal family).

## Acceptance Criteria

- [ ] A synthetic wide batch against a 4-slot engine leaves ≥1 slot's capacity interleavable; a concurrent small embed completes within its own deadline class (fixture with an injected multi-slot fake).
- [ ] Caller-class deadlines are separately configurable; defaults preserve current behavior for bulk and shorten nothing silently.
- [ ] A canary failing behind a known in-flight batch reports the distinguishing classification on the health surface.
