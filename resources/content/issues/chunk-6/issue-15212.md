# FM cockpit card click no longer opens the agent-detail drill

## Context

The FM cockpit's card→detail drill — the design SSOT's core inspection journey and a shipped acceptance surface of the agent-detail view — is silently regressed on `dev`. Its e2e witness `test/playwright/e2e/agentos/FleetCockpitDrillNL.spec.mjs` is red on a clean `dev` checkout (verified 2026-07-16, stash-isolated run), and the custom e2e configs do not run in CI, so nothing surfaced it. Discovered while building the pop-out round-trip witness on the same surface.

## The Problem

Reproducer (clean `dev`):

```bash
NEO_E2E_PORT=8119 NEO_TEST_SKIP_CI=true npm run test-e2e -- test/playwright/e2e/agentos/FleetCockpitDrillNL.spec.mjs --workers=1
```

The spec clicks a resident card's avatar (`[id="<cardId>"] .fm-card-avatar` — the always-sized, non-control region the whole-card domListener catches) and waits for `.fm-agent-detail`. The inspector never renders.

**The failure is discriminated, not just observed:**

- After the avatar click, the committed dock document is byte-unchanged — `items.detail.autoHidden` stays `true`. The select handler's reveal commit never ran.
- Driving the SAME production seam directly — `callMethod(<FleetCockpitController id>, 'onAgentSelect', [{agentId}])` via the Neural Link — commits the reveal (`autoHidden: false`) AND renders the inspector (`.fm-agent-detail` DOM count 1).
- Zero page errors, zero worker console errors — the click is swallowed silently.

So the reveal machinery (controller handler → `setItemAutoHidden` commit → projection) is fully healthy; the broken link is exactly the **card-click → `agentSelect` event dispatch chain** (domListener → card select handling → the event reaching the cockpit controller).

## The Architectural Reality

- `apps/agentos/view/fleet/AgentCard.mjs` + `AgentCardController.mjs` own the whole-card domListener and the `agentSelect` fire; `FleetCockpitController.onAgentSelect` consumes it (source-resolved record, store fallback, auto-hide reveal through the standard commit loop).
- The drill e2e was born green with the agent-detail view (merged 2026-07-12). The regression window is the card-surface commits since then. Prime suspect: the cockpit keyboard-a11y pass (roving focus, Enter/Space activation — it reworked card activation semantics on exactly this surface). Secondary: the dock-projection reconcile refactor in the same window. Neither is verified as the cause — the window is named for the bisect, the discriminator above is the truth anchor.
- The drill e2e spec itself is correct and should be treated as the acceptance witness: no changes to it should be needed by the fix.

## The Fix

1. Bisect the named window over the discriminator (avatar click → does `items.detail.autoHidden` flip?) — one command per candidate commit.
2. Restore the click→`agentSelect` dispatch on the card surface without regressing the keyboard-a11y behavior (both must hold; the a11y spec and the drill spec are the paired witnesses).
3. Re-green `FleetCockpitDrillNL.spec.mjs` unchanged.

- Getting the custom e2e configs into CI (a real gap this bug exposes — worth its own ticket if not already tracked).
