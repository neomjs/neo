Resolves #16222

Related: #16223, #16224

Evidence: L2 (pure gate suite + reader-only/backoff/recovery service tests) → L3 required (live canary-rate + recovery measurements on a saturated plane). Residual: AC measurements land at the #16208 run boundary [#16222].

## Why

A failing embedding write canary was never cached (deliberately: "so degraded probes still retry immediately"), so under provider saturation every container probe re-ran the expensive canary, attempts overlapped (probe interval < canary deadline; Docker abandons the probe while the in-server canary keeps computing), and the failing regime sustained its own load. Measured on two deployments in #16222; the same class burned a CPU-only deployment for days.

## What changed

**`embeddingCanaryGate` (new pure helper)** — single-flight (join point assigned before any await, cleared on settle; a thrown canary converts to a failed RESULT so it backs off instead of bypassing the cache), BOTH outcomes cached (healthy: 60s TTL; failed: exponential backoff `failureTtl * 2^(streak-1)` capped at `failureTtlMax`), `readLast()` never runs anything, late-bound clock for test injection.

**`HealthService`** — liveness probes are now READERS: `#getEmbeddingWriteCanary` returns `readLast()`; the canary runs on its OWN cadence (self-scheduled unref'd loop, immediate first tick, `cadenceMs <= 0` disables). Cold start reports `pending` without degrading (container `start_period` owns that window). Failed results degrade with a reason that now carries the backoff state ("backing off Nms, streak S" — saturated-and-throttling is distinguishable from failing-now; the provider-timeout vs unreachable classification already existed in the block builder). A healthy result older than three scheduler windows degrades as "canary loop not running" — a dead scheduler must not read green forever. `clearCache()` resets gate + timer; `runEmbeddingWriteCanaryNow()` is the on-demand seam for tests and operator diagnostics, still gate-governed.

**Config** — four declarative leaves (cadence 60s, healthy TTL 60s, failure TTL 30s, failure TTL max 10m), ADR-0019 shape, parity snapshot in the same commit.

## AC mapping (#16222)

1. probe issues NO embedding request → test: 3 probe storms at cadence 0, zero embed calls.
2. attempts DECREASE, never overlap → gate suite: 8 concurrent probes = 1 attempt; 10 probes inside a backoff window = 0 attempts; exponential window growth capped.
3. recovers without operator intervention → service test: fail → backoff → provider recovers → next scheduled attempt restores healthy.
4. canary on its own configured cadence → the loop + leaves.
5. degraded carries its reason → backoff-annotated detail line.

## Deltas

- The block builder's provider-side abort on timeout already existed and is unchanged — this PR fixes the CACHE layer that sat above it.
