Chat-Creation — the Keeper Flow

design SSOT · #14645 · apps/agentos module

A stranger types an intent and gets a live app in its own window. chat → "build me a neo grid" → a docked peer panel → drag to its own OS window → use / share. This surface is the impedance-match wedge — legible to someone who never read a line of Neo code. The pipeline that runs behind it (#14655 intake route · #14656 instance registry) is a peer's lane; this artifact fixes what the human sees and touches.

Transcript treatment — the conversation is the medium

The keeper flow is a dialogue, not a form. The transcript renders under Neo's markdown-VDOM constraints — streamed tokens, fenced code, and the inline blueprint are VDOM nodes diffed in place, never innerHTML. Turns stay compact; the blueprint preview is a first-class turn, not a wall of prose.

you
build me a grid of the fleet's open PRs
keeper
A Grid over the open-PR store — title, author, state. Streaming as it resolves:
blueprint · Grid · store: pulls · cols: title · author · state
you
make state a coloured chip

Constraints the treatment honours: streamed text appends via VDOM deltas (no layout thrash); code and blueprint blocks are components, not markdown-to-HTML; long transcripts virtualise; the newest turn stays in view. The transcript never becomes the app — it's the lane the app arrives through.

Follow-up — the app is live; keep talking to it

Materialize is not the end of the conversation. The same thread iterates on the live app — every follow-up is another intent → blueprint-diff → apply, against the instance that already exists. No regeneration from scratch; the widget mutates in place.

"filter by author"
Intent scoped to the live instance, not a new app.
diff
Blueprint delta
Only the change previews — an add, not a rebuild.

Mutates in place
Same instance updates; state & scroll preserved.

The follow-up affordance lives where the eye already is — an inline input pinned under the live panel and the transcript's tail resolve to the same thread. Follow-ups route through the safety gate too (a refinement is an intent). Undo restores the previous blueprint, never a blank slate.

Body-idiom binding — for the view-leaf builders (per #14714)

This surface is Body-hemisphere code (apps/agentos) — it follows src/ neo-core idioms, not ai/ ones (#14714, operator-ratified after two violations shipped). The state machine above binds to the core contracts this way:

The five states = ONE shared surface (state.Provider)

  • a shared state.Provider · data.flowState — empty→composing→generating→materialized→error live on the create-module's state.Provider as ONE binding surface (the many consumers — chat surface, blueprint preview, pane chrome, promote affordance — bind to it rather than reaching into one component's config), never a parallel store (the #14712 lesson: the transition table is the pure legality oracle for the state, not a second copy beside it). Realized in CreationStateProvider (#14719).
  • Transitions batch via one guarded setData() — a state change + its reason go through the provider's ONE oracle-guarded writer (applyFlowEvent), one batched write; an illegal transition mutates nothing and returns a bounded reason (never chained assignments, never throws — mirroring the pipeline's {accepted, reason}).

Resolution, lifecycle & the allowed plain half

  • Neo.get(id) resolves the materialized widget (auto-registered via afterSetId) — never a bespoke resolveComponent seam; neo core's Symbol.hasInstance already guarantees the instance shape.
  • Pure data-plane stays plain — the intake validateRequest, the edit-grammar parser, and the transition table are plain util modules (childapp-precedented, #14714's explicitly-allowed half). The idiom boundary is instance mutation + view state, nothing below it.

notAuthority — the surface proposes, the gate disposes

The chat and its blueprint preview are provisional. They never bypass the constrained-blueprint safety gate (#14644) — the gate is the authority, not the conversation.
This is the #14548 firewall applied to creation: a persuasive intent must not become a live app by persuasion alone. What the human types is a request; what the gate passes is what runs. The error state exists precisely so a refused blueprint reads as a boundary, not a failure of the person.

M2 demo — the one-shot gesture, beat by beat

The canonical M2 demo is a single unbroken take: a stranger goes from a sentence to a shared, running app without touching code or config. Storyboard for the recordable walkthrough (#14646 binds these beats to NL-driven steps):

beat 1 · 0:00
Empty invitation
One field: "Describe an app to build." Nothing else on screen — the stranger isn't taught, they're invited.
beat 2 · 0:04
Say it
Types "build me a grid of the fleet's open PRs". The blueprint streams in as a preview turn.
beat 3 · 0:09
Generate
Confirms. Honest progress; the Grid materializes as a docked panel — real data, not a mock.
beat 4 · 0:15
Use it live
Sorts a column, follows up "colour the state" — the panel mutates in place. The app works.
beat 5 · 0:22
Pop out
Drags the panel to its own OS window on the shared heap — object-permanent; nobody dragged a file.
beat 6 · 0:27
Share
Copies the hosted URL; a second person opens the running app. Built & shipped, code unread.

The falsifier: a viewer who has never seen Neo follows every beat without narration. No performance numbers appear (per #13032) — the claim is legibility, not benchmarks.
