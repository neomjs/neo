Resolves #17070

Truncated embeddings can no longer be silently stored. Three independent floors now stand between an oversized input and a stored prefix-vector: **composition** — the provider-lane analyzer can fail a lane whose per-slot context is below Neo's safe band, and the production CLI supplies the canonical band (a forked compose with a guessed small context now fails composition naming both numbers); **readiness** — the embedding serving canary reports not-ready (`embedding-context-below-safe-band`) when the discovered loaded context is below the band, firing on knowledge, never on doubt; **dispatch** — the OpenAI-compatible embedding path now sends `truncate: false` on the wire and refuses pre-dispatch with the typed `EMBEDDING_INPUT_TRUNCATED` code whenever the provider's `/slots`-observed per-slot context cannot hold the input or the band, and a provider refusal naming the input/context bound is translated into the same typed code. The Knowledge Base boundary maps it to the bounded `KB_VECTOR_EMBED_INPUT_TRUNCATED` — counted separately from timeouts and refusals, and classified **rejected** (the same input truncates again on every retry; deferral cannot repair a cut vector).

Transport spike verdict (the ticket's open question — "whatever the transport reports"): llama-server reports per-request truncation in its server-side slot log, **not** in the `/v1/embeddings` HTTP response; the only response-side token field is `usage.prompt_tokens`, and comparing it against Neo's client-side estimate (`bytesToTokens`, bytes/3) is too fuzzy to be a witness. So the response-read arms are: the `truncate: false` request flag (llama.cpp honors it and refuses; spec-tolerant servers ignore it, and the estimate-based floors are the guard that does not depend on provider cooperation) plus refusal-prose classification on 400/413. The exact, deterministic guarantees are the floors.

Evidence: L2 (isolated-process wire-level arms against a real local HTTP server; analyzer driven against the canonical template; classification + readiness arms) → L3 required (a live llama-server's `truncate: false` honoring and the external plane's slot floor observation are deploy-gated). Residual: live-provider verification. Residual-Owner: #17072.

## Deltas from ticket

- **AC-3's mechanism is floors-first, response-read second.** The ticket's item 2 asked for reading the truncation signal; the spike found no per-request flag on the HTTP response, so the persisted-never guarantee comes from pre-dispatch refusal (exact) and the wire flag (provider-cooperative), with refusal-prose mapping as the response-side arm. `usage.prompt_tokens`-vs-estimate comparison was evaluated and rejected: the estimate's error bars make both false positives and false negatives reachable.
- **The composition floor is opt-in at the analyzer and wired at the CLI** (`analyzeProviderLaneComposition`'s `safeProcessingLimitTokensEmbedding`, supplied by `main()` from the canonical constant). The deliberately small 8,192-token fixture lanes the election specs drive are not production lanes serving safe-band inputs; a default-on floor broke seven fixture arms, and threading the band through every internal election call was the worse shape. The floor fires exactly where real deployments are verified.
- **AC-2's split:** the readiness canary floor covers the flavor whose context it can discover (LM Studio loaded-model metadata, knowledge-gated — an absent `contextLength` stays probe-only, matching the non-authorizing-incomplete-metadata doctrine); all flavors get the dispatch-path `/slots` floor; an unobservable lane fails open with the wire flag as the remaining defense (documented, not silent).
- **The band literal moved into `ai/embeddingSafeBand.mjs`** (the ADR-0019 §10.1 shared-constant shape, sibling of `planeConfig.mjs`): the leaf declares its default from it, and Neo-free deploy tooling reads the same declaration — one literal, one env binding.
- **Fix-shape item 5 (corpus audit path) is declined here:** the floors stop future damage; auditing an already-damaged corpus is a plane-local operation with its own decision (re-embed vs accept), not a precondition for the guard.
- The `#13944` retry-spec arm now distinguishes request classes: one `/v1/embeddings` POST exactly, plus at most one flavor-agnostic `GET /slots` floor probe — the LMS-CLI-skip contract it pins is unchanged.
