Resolves #16202

> 🌿 Neural Link kept its data in a file only Neural Link could read; after this, "we archived that transaction" is no longer a claim whose truth depends on which checkout you happen to be running.

## What this is

Epic #17500's sole remaining open child. `RecorderService` opened `better-sqlite3` **from a host process** — dynamically, which is why static-import greps missed it — so NL telemetry and transaction archives accumulated in a store nothing else read. NL itself stays host-resident, because it drives a real browser and must. Only its **data** moves.

`Evidence:` premise re-verified live before a line was written: the writer was still at `RecorderService.mjs:141/143`, and all four target operations resolved **0 files** against a positive control of 6 for `add_message`.

## The three defects this closes

**1. Two realities.** A replay's success depended on which checkout ran it. The archive now lives in the one graph.

**2. Telemetry relocated an identity.** The host's `sequenceId` was `${agentId}_${turnId}` — the correlation key **was** the agent's identity. A census of every production READ also found `result`, `agent_id` and `reward` have no reader at all. Porting the record set wholesale would have relocated dead data *and* an identity, so the admitted set is decided instead: server-minted opaque `sequenceId`, server-generated row id (one caller cannot address another's row), and an **allowlist** so a future NL version's new payload key cannot become durable telemetry nobody chose to keep.

**3. Dormant methods.** `querySequences` and `pruneOlderThan` had no production caller. They are removed rather than ported — the ticket's own AC refuses "porting a dead method and calling retention governed" — and their absence is **asserted**, so a later reader does not restore them believing it an oversight.

## Round-1 repair — two falsifiers from @neo-gpt-emmy, both confirmed

Emmy held formal review and named two pre-review falsifiers. I verified both rather than taking them, and both were real:

- **The orphaned consumers.** Confirmed at `GapInferenceEngine.mjs:431` and `genesisProbe.mjs:955`. Her second observation — that the server minted one `sequenceId` per row while the digest groups by shared sequence — is exactly what AC-5 forbids in its own words ("a fresh opaque correlation token" *plus* "Memory Core generates the storage row id" are two identifiers, and I had made them one).
- **The detached rejection.** Confirmed at `src/core/Base.mjs:305/314`: `#readyPromise` is built with a resolver only, and `initAsync` is awaited inside a detached chain. `Client.initAsync` throws on both a missing credential and a refused connect, so my `ready.catch(() => {})` was armed on a promise that cannot reject. I had named the failure mode correctly in the comment and then guarded the wrong promise.

The guard now observes the rejection where it surfaces, **re-raises anything it does not own** so installing a process listener never swallows another subsystem's fatal error, and outlives the deadline by one window so a late connect failure is not handed back to the default policy after the caller was already answered.

**And CI proved a listener is not sufficient.** The unit job failed with `Missing required environment variables for 'memory-core': NEO_MCP_REMOTE_TOKEN` — inside `McpServerListToolsSmoke`, a spec that only lists tools and had merely imported the recorder. A listener stops the *default policy*, but every registered listener still runs, so a harness fails whatever test is in flight regardless. The client is therefore never constructed without its credential. **The first version of that arm asserted the process SURVIVED and passed with the fix deleted** — the listener already guaranteed survival, so it measured a property true either way. It now counts emitted rejections and drains on a later tick; mutation-verified at `Expected 0, Received 1`.

## Design decisions worth a reviewer's attention

- **The archive is a node, not a table** — `GraphService` is the only sanctioned graph writer and is node/edge-oriented. Lossless because the host already serialised `ops` and `originWriter` to JSON before insertion. I named this fork on the ticket with its falsifier (replay fidelity) before building.
- **No host-local fallback.** An unreachable Memory Core fails **by name**. The friendlier alternative is exactly how two realities come back.
- **The data-only guard stays host-side.** JSON transport cannot carry a function or a cycle, so a container-side re-walk would only ever see a shape error with no idea which op produced it. The spec proves the call never leaves the host.
- **Injected clock refused on the wire.** Three parity-baseline rows: the Zod facade strips undeclared keys, so declaring `now` would make it caller-supplied — letting a host backdate an archive stamp or a replay mark. Same refusal as `who_is_online.now`.
- **Admission rules restated container-side.** A writer that trusts its caller's validation has no admission rule of its own.

## Test Evidence

**65 pass** in `test/playwright/unit/ai/services/neural-link/`, **5** in the new `nlRelocationComposition.spec.mjs`, **38** in `DreamService.spec.mjs`, **524** across `scriptPlaneClosure` + `ai/scripts/diagnostics/`. `lint-script-plane` and the extraction inventory both clean (`ok: true`, zero residue).

**The composition arm is the one that was missing, and it is the point.** Both halves of the relocation were green about themselves while disagreeing with each other: admission wrote `nl-action-telemetry` nodes, `GapInferenceEngine` read the `nl_action_log` table, and because that reader probes `sqlite_master` first it returned its clean-degradation answer instead of failing. A permanently dead digest and a quiet week are indistinguishable from the outside. `nlRelocationComposition.spec.mjs` writes through admission and reads through the digest against a real store, so it is the only test here that *can* fail on that. **Mutation-verified:** restoring the per-row token kills 4 of its 5 arms and leaves the archive round-trip green.

Two spec files hung past ten minutes mid-lane and the diagnosis is recorded because it generalises: with a credential present the real MCP client **waits on a live connection**, and `ready()` has no reject path of its own — an unreachable ingress yields a *pending promise*, not an error. Fixed three ways: a transport **injection seam** so no unit spec reaches a transport, a **connect deadline** so production refuses instead of hanging, and a **dynamic client import** so merely importing `RecorderService` no longer pulls the transport stack in at module load. I guessed twice before taking a control; the control was the credential.

`## Post-Merge Validation`

`## Deltas`
- `RecorderService.db` is gone; `initAsync` opens nothing.
- `querySequences` / `pruneOlderThan` removed.
- The archive record is a graph node; `nl_action_log` / `nl_transaction_archive` tables are no longer created by any host path. Both were measured empty at cut time, so there is no data migration.
- `memoryCoreArchiveClient` is new and exports `setArchiveTransport` — a test seam, not a production knob.
- `GapInferenceEngine.readNlActionRows` reads `nl-action-telemetry` nodes; `collectNlActionTargets` / `parseJsonValue` are removed, not ported — raw `args` no longer reach the container, so both had nothing left to parse. The allowlist itself moved verbatim to `RecorderService.projectTargets`, **including the condition that a bare `id` counts only for component/instance tools** — the first port widened it, which would have linked weak evidence to records and windows.
- `genesisProbe.readAggregateTelemetry` reads a seat-written JSON aggregate instead of `SELECT ... GROUP BY tool`. Absent means nothing recorded; corrupt still raises, which keeps the existing "deletion survives a failed capture" arm honest.
- `ParityTopology.integration.spec.mjs`'s enabled-arm regex named a log line that no longer exists — a silently dead guard, now pointed at the message that ships.
- `memoryCoreArchiveClient` refuses **before constructing a client** when a required credential is absent, reading `requiredEnv` from the same client config that declares the endpoint so the check cannot drift from what `initAsync` enforces.
- Not in scope: containerizing NL, #15184's local Streamable HTTP interoperability, a cloud NL, or MC's ingress/auth surface.
