# Redeploy preflight blesses a bundle whose own manifest declares an empty substrate

## Problem

`redeployPreflight.mjs` authorizes a container-affecting deploy against a bundle that cannot restore the Knowledge Base, because `"non-empty"` is evaluated on the **sum across substrates** rather than per substrate.

Reproduction (read-only, ~40s):

```
node ai/scripts/maintenance/redeployPreflight.mjs --compose-project <project> --json
```

Observed:

```
decision    : PROCEED_VERIFIED
proceed     : true
reason      : "A verified, non-empty, restorable pre-transition bundle exists."
verdictCode : RESTORABLE
rowTotal    : 34239
```

Ground truth for the very bundle it selected:

```
bundle-meta.json → {"kb":0,"memories":32462,"summaries":1777}
kb/ payload      → 0B, 0 entries
```

`rowTotal 34239` is `memories + summaries` alone. The KB contributes **zero** and the gate proceeds anyway. A deploy that went wrong would have no KB to roll back to — which is the entire purpose of the gate.

The bundle *declares* `kb:0`. The information needed to refuse was in the field the gate already read.

## The class, not the instance

Any aggregate-over-substrates verdict can hide a fully-empty substrate. #16510 / #16520 already shipped per-collection restorability facts — *"the restorability verdict reports per-collection facts, not only their sum"* — but `verifyLatestBackupRestorable` / `runRedeployPreflight` still **decide** on the aggregate. Audit every other consumer of that verdict for the same sum-vs-per-substrate read before closing.

## Acceptance criteria

- [ ] The gate refuses when ANY required substrate is empty, and names which one in `reason`.
- [ ] A bundle with `kb:0` either walks back to an older genuinely-restorable bundle or refuses outright.
- [ ] Unit coverage pinning the refusal on a `kb:0` manifest whose sibling substrates are healthy — the exact shape that passes today.
- [ ] Every other consumer of `verifyLatestBackupRestorable` audited for the aggregate read; findings recorded even where no change is needed.

## Related

- #16563 — the producer side: KB export reports success on zero rows. This ticket is the **consumer** side; even once the producer is fixed, the gate must not bless an empty substrate again.
- #16510 / #16520 — per-collection restorability facts already available and unused here.

Evidence: L1 live tool invocation plus the on-disk manifest of the selected bundle, reproduced 2026-08-06.
