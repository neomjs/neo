# Re-entry paints the pane in both embodiments and stacks the landing region

## Context

Two operator-captured stills from the take-18 WIP film cut at t≈29–31 (cut-relative; raw = +11.3s; dev head `2cd55fdd7d`; capture sha256 `3dfc1d13bd13d93077de8eb4ec8b1491582135d97c05999ae6f807bbb2ef6495`), corroborated by 6fps frame bursts. During the native vessel's return drag and drop: (a) the `System Metrics` pane content is visible **simultaneously** in the native vessel AND inside the main window's right column, with a floating `LIVE METRICS` label over the matrix area and the `Evidence Audit` card rendering ghosted label-over-label; (b) one frame later, the landing region shows `Evidence Chain` AND the squeezed `Live Metrics` card **stacked at once** — where tab semantics should render exactly one active pane — plus a truncated `Me…` tab header painted PAST the main window's right edge mid-relayout. Sweeps: live latest-20 open (2026-08-04 ~12:15Z) no equivalent; A2A last-30 no claim; the label-over-label paint class is `#16406`'s family (tab-drag label paint, open, distinct scope — referenced, not duplicated).

## The Problem

The re-entry chain (native vessel → claim → drop into `right-top-tabs`) produces a window of visibly wrong render truth: double embodiment of one pane, ghosted label compositing, then a post-drop region rendering two panes' content simultaneously with a tab header escaping the container bounds. Part of this MAY be the documented transient proxy embodiment (the dashboard drag proxy carries `computedOpacity 0.7` by design) — but the observed frames show full-opacity content in both places, and the post-drop stacked state persists beyond staging frames.

## The Architectural Reality

- The transfer path publishes preview/placement via the harness dock preview (`neo.harness.dockPreview.v1`, placement kinds like `tab-into`) and the beat receipts carry `targetProxy` + placement — the classification can bind each frame to the receipt's declared state.
- Candidate seams: (1) the projection commit racing the vessel retirement (both embodiments live because the source vessel has not retired when the target renders — adjacent to `#16497`'s conversion boundary but a distinct symptom: RENDER truth, not gesture timing); (2) FLIP staging frames presenting measured-but-unstaged content (`#16356`'s closed class, entering-classification); (3) tab activation rendering the incoming pane before the region's prior active pane deactivates (stacked content); (4) the escaped tab header = mid-relayout header toolbar painting outside its clipped container (overflow/clip seam in `src/tab/` chrome during item insertion).
- Reproduction: film-paced five-beat native-titlebar beat (`NEO_FILM_TAKE=1 … --headed --grep "native titlebar"`), frames at the drop moment.

## The Fix

Classification first, frame-by-frame against the semantic receipts: for each symptom (double embodiment, ghost labels, stacked region, escaped header) bind the frame to the receipt state (`converted`, placement kind, activeItemId) and split {documented-transient | staging-frame | real double-render}. Repair the real ones at their owning seams; explicitly document any accepted transient with its bounded duration so the film QA gate can pin it.

## Acceptance Criteria

- [ ] Each of the four symptoms is classified with a frame+receipt pair naming its owner.
- [ ] After repair: no frame shows one pane's content at full opacity in two embodiments; the landing region renders exactly one active pane's content post-drop; no tab header paints outside its container during relayout.
- [ ] Accepted transients (if any) are documented with bounded frame counts and covered by the film QA oracle.
- [ ] Witness at film pacing, red-proven at the pre-fix head.

## Classification r3 — r2's candidate mechanism FALSIFIED by the contract read; the real seam is one level up (and the repair got smaller)

**Correction of my own r2:** `preserveItemIds` does not mean "keep these panes alive during re-stage." Its contract ([DockProjectionReconciler.mjs:288-289](https://github.com/neomjs/neo/blob/dev/src/dashboard/DockProjectionReconciler.mjs#L288)): *"Owner-held panes which are absent from this projection but must survive without their obsolete tab buttons"* — i.e., panes that **departed** for another workspace and must not be destroyed. The `:1744` vs `:1750` asymmetry I flagged is therefore semantically **correct as written** (main→vessel: main loses panes → they need survival; vessel→main return: panes arrive, none depart → empty set is right).

**The real S-1 mechanism:** `reconcileProjection` has two paths — a strict **stable-topology fast path** (in-place reconciliation on the retained shell) and a **full path** (stage a hidden new shell, move chrome, swap). The fast path with `reconcileItems: true` explicitly admits *"tab item/active deltas while retaining the proven-identical structural shell"* (:123-124) and runs the same `reconcileTabChrome` that materializes arriving pane/button pairs. But `refreshDockWorkspace` keys that admission to **`operation === 'detachItem'` only** (:2115) — and the return-transfer call site passes **no operation** (:1750). So a stack-return adoption — which is topologically stable (structural node set identical; one tabs node's items grow) — is forced through the full path: hidden shell staged, whole workspace re-materialized, swap. The measured ~40ms whole-workspace blank (S-1) and the FLIP re-stage ghost (S-2) are the swap's paint signature.

**Repair A (small, safe-by-construction):** thread the operation through the return call site (`refreshDockWorkspace({operation: 'transferNode'})` at :1750) and widen the `retainTopology` admission to include it. The stable-topology validator remains the gate: any transfer that genuinely changes the structural node set (e.g. a split-creating placement) fails its identity checks, returns `null`, and takes today's full path unchanged. The fast path only engages when provably stable — the strictness check IS the falsifier.

**Witness (discriminating, deterministic):** worker-side pane identity survives BOTH paths (`resolveItem` reuses live instances — which is why scene-4's existing `getPaneIdentity` pins pass today). The discriminator is **DOM node identity** of an unmoved pane across the return transfer: tag the live DOM node pre-return (JS property, not attribute), assert the same node post-settle. Full path re-materializes the subtree → tag gone → RED at pre-fix head; stable path retains the shell → GREEN. Extends scene 4; red-proof via src-stash run before the fix lands.

**Noted, not yet in scope:** the outbound main→vessel transfer (:1744) also passes no operation and takes the full path — same defect class, symmetric one-line fix, but its witness rides a different scene; decision at PR time whether it lands here or as an immediate follow-up.
