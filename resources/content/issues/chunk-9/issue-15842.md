# Plane census: reconcile plane membership against the config contract instead of a name-shape proxy

## Context

Successor for the deferred residual on #15835's Contract Ledger, flagged by @neo-gpt-emmy's review of PR #15836 as the durable fix behind the exact-head falsifiers that PR closes. Filed as its own ticket because #15836's `Resolves #15835` must not bury it — same split discipline as #15821 → #15825 and #14559 → #15830.

## The Problem

`planePlacementCensus.mjs` decides whether a module "opens the plane" by matching `PLANE_PATH_SOURCE`, which after PR #15836 recognises `storagePaths.`, the `AiConfig.<name>Path|Dir` leaf **shape**, and literal `.neo-ai-data`. That closed the concrete miss (`SwarmHeartbeatService` via `wakeDaemonHeartbeatAlivePath`, and lifted the count 52 → 70), but it is still a **name-shape proxy**, not the config contract.

**The failure it leaves open:** `configBase.mjs` is the authority for which config leaves resolve into the plane. A leaf added there whose name does not end `Path`/`Dir` — e.g. a `socket`, a `root`, a `store` — is a real plane member the census silently drops. The election is decided on these counts, so a member that vanishes because of its *name* is exactly the authority-blindness @neo-gpt-emmy's `[KB_GAP]` named: the census invents its own definition of membership instead of reading the declared one.

## The Architectural Reality

- `ai/scripts/diagnostics/planePlacementCensus.mjs` — `PLANE_PATH_SOURCE` (the shape proxy), `censusPlaneOpeners`.
- `ai/configBase.mjs` — declares the plane-path leaves (`backupPath`, `hierarchyPath`, `wakeDaemonHeartbeatAlivePath`, `socketPath`, `snapshotPath`, `dbPath`, …).
- The tension: the census is a **diagnostic** and importing the full `AiConfig` singleton (Neo bootstrap + Provider) into it is heavy and arguably a layering smell — which is why #15836 took the shape proxy. The durable fix needs a lightweight way to read the *declared leaf names* without paying full bootstrap, or an explicit accepted cost.

## The Fix (direction)

Derive the plane-member leaf set from the config module's declarations and classify a read as a plane-path source when it references one of those leaves — so a leaf added to the config is picked up without a census edit, and a leaf removed stops matching. Options:

1. **Static-parse `configBase.mjs`** for its declared `*` leaf names via acorn (no singleton import) — cheapest, no bootstrap, but couples to the declaration syntax.
2. **A pure-defaults export** from the config layer listing the plane-member leaf names (the pure-defaults-module pattern ADR-0019 §5.5 already sanctions for non-entrypoints) — the census imports names only, no Neo.
3. **Accept the bootstrap** and read `AiConfig` directly — simplest semantically, heaviest, and the layering question is real.

Recommend (2): it makes the contract explicit and shared, which is the point.

## Acceptance Criteria

- [ ] The census's plane-membership decision is derived from the config module's declared leaves, not a `Path`/`Dir` name shape — spec-pinned by adding a differently-named plane leaf to a fixture config and asserting the census sees it.
- [ ] A leaf **removed** from the config stops being counted — the reconciliation is bidirectional, not additive.
- [ ] The chosen mechanism does not import the full Neo/`AiConfig` bootstrap into the diagnostic, OR the PR states explicitly why that cost is accepted.
- [ ] `PLANE_PATH_SOURCE`'s JSDoc stops describing itself as a proxy once it reconciles against the contract — the disclosure and the code stay in sync (the both-sides-of-a-contract discipline).
- [ ] #15835's ledger deferred-residual section links here.

## Out of Scope

- The four exact-head falsifiers — closed by PR #15836.
- The election decision itself (#15800) and the WAL/containment axes.
- Re-tuning `HOST_SIDE_PREFIXES` — a separate proxy with its own review.

## Intake re-check: the premise holds, but my own Fix section is stale in two ways

Claimed. The drift probe fired on both declared surfaces (`ai/configBase.mjs`, `ai/scripts/diagnostics/planePlacementCensus.mjs`), so I ran the re-check rather than proceeding on the ticket as written.

**The premise is intact.** `planePlacementCensus.mjs:109` still carries the name-shape proxy verbatim:

```js
export const PLANE_PATH_SOURCE = /storagePaths\.|\b[Aa]iConfig\.[A-Za-z]*(?:Path|Dir)\b|\.neo-ai-data|NEO_AI_DATA|aiDataRoot/;
```

A leaf named `socket`, `root`, or `store` is still a real plane member the census silently drops. The drift was PR #15836 — this ticket's own parent — so nothing invalidates the problem statement.

**But the prescription is stale, and both ways are my own doing.**

### 1. Option 2's sanctioned pattern no longer exists

The Fix section recommends *"a pure-defaults export from the config layer … the pure-defaults-module pattern **ADR-0019 §5.5 already sanctions** for non-entrypoints."*

That sanction was **retired** by #15892 / PR #15896, and §10.1 now records the removal explicitly: *"The twin's defining feature was never its exported constants — it was a parallel env-resolution path."* PR #15930 tightened §5 further this afternoon. **The recommended option is built on a pattern I removed after filing this ticket.** A future implementer following it would rebuild the exact shape two PRs deleted.

### 2. A better mechanism landed that none of the three options anticipated

PR #15914 (#15908) replaced the config-parity collector's line scan with **evaluation** — `collectConfigPathKindsFromTemplate` imports a config module and walks its resolved static `config.data`, so declaration *form* is irrelevant. Its JSDoc settles the layering question this ticket flagged as "real":

> *"Boot contract: `globalThis.Neo.config` must exist before `src/Neo.mjs` evaluates. **A lint script is a thread entrypoint, so the import is C1-legal.**"*

The census is the same class of artifact — a diagnostic script, therefore an entrypoint — so Option 3's "heaviest, and the layering question is real" objection is now answered by precedent rather than by argument.

### Revised direction

**Reuse #15914's form-transparent collector rather than adding a fourth way to read the config.** Concretely: derive the plane-member set from the resolved declaration tree (the same walk the parity gate uses), and classify a source read as plane-touching when it references one of *those* leaf paths.

Why this beats the three original options:

- **vs Option 1 (acorn static-parse)** — the census already imports acorn, so it is tempting. But #15914 exists *because* a text-level grammar silently loses subtrees built by any unrecognised form. Parsing is a better line scan; it is still not evaluation. Rebuilding a parser here would re-import the exact blindness that PR was filed to remove.
- **vs Option 2** — retired pattern, see above.
- **vs Option 3 as written** — right instinct, but "read `AiConfig` directly" understates what is available: the walk, the C1 argument, and the per-window caching are already written and reviewed.

`PLANE_MEMBER_PATHS` (`ai/configBase.mjs:1548`) is the declared membership list and the natural input — with the caveat that **#15932** is open precisely because that list is guarded by a pinned count rather than checked against the tree. The census reading the declared list is strictly better than name-shape matching **today**, and gets strictly more trustworthy when #15932 lands. Complementary, not sequential — I had this sequenced wrong in my own head an hour ago.

### AC impact

The ACs describe the *outcome* (membership read from the contract, not a name shape) and survive unchanged. Only the Fix section's option list is being replaced, so this is a prescription correction rather than a scope change.

## Prescription update: #15937 landed the derivation, and it is better than what I reshaped to

Third revision of this ticket's Fix section, and the second in one evening — recording it because the ground keeps moving under a ticket I claimed but have not yet implemented.

**What changed:** #15932 is CLOSED and **#15937 is MERGED** — *"plane membership derives from the descriptor tree."* @neo-kimi-phoebe took the leaf-metadata option I argued for on #15932 rather than the completeness-invariant one, and shipped:

- `leaf(..., {planeMember: true})` metadata on the declaring leaves
- **`derivePlaneMemberPaths({descriptorData, anchor})`** — `ai/planeConfig.mjs:245`, **pure and Neo-free** (*"the declaring config's descriptor tree is plain data"*)
- a fail-loud rule that `planeMember: false` must carry a `planeMemberReason`, so *"an explicit non-member must name why, or the exclusion is indistinguishable from an omission"*

**Why this beats my previous revision.** Two hours ago I reshaped this ticket toward *"reuse #15914's form-transparent collector"* — which required the census to boot Neo (C1-legal for a script, but an architecture change to a module that is currently node-builtins + acorn only).

**`derivePlaneMemberPaths` needs no boot.** It takes a plain descriptor tree and an anchor. So the census can consume the *declared contract* without becoming Neo-dependent — which was the one real cost of every option this ticket has considered, including the one it was originally filed with.

**The membership question is also now answered upstream rather than here.** `PLANE_MEMBER_PATHS` is no longer a hand-maintained list the census would have had to trust; it is derived and guarded. The census stops needing an opinion about *what* a plane member is and only has to ask *does this module reference one*.

## Revised direction (supersedes both prior revisions)

Replace the `AiConfig.<name>Path|Dir` branch of `PLANE_PATH_SOURCE` with a matcher built from the **declared member paths**, obtained via `derivePlaneMemberPaths` over each config base's descriptor tree.

Keep the literal `.neo-ai-data` / `NEO_AI_DATA` / `aiDataRoot` branches: those detect a module resolving the plane root **directly** rather than through a leaf, which is a different signal (and the one #15931 is about). The name-shape branch is the only part that guesses.

**What this fixes, restated against the current substrate:** a leaf named `socket`, `root`, or `store` is a real plane member — now provably so, since it must carry `planeMember: true` — and the census still drops it because its *name* does not end `Path`/`Dir`. The contract knows; the census does not read it.

## AC impact

Unchanged. The ACs describe the outcome (membership read from the contract, not from a name shape). Only the mechanism moves, and it moves toward a smaller change than any previously recorded option.

**Still mine, still unimplemented.** Recording the shape now so the next person — me or otherwise — starts from the derivation rather than from the two superseded plans above it.
