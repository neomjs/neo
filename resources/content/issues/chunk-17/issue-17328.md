# Agent OS instance switcher + managed connection profiles

## Context

Operator, live session 2026-08-18: FM should configure WHICH Agent OS instance it connects to — "right now to our dockerized local version on this machine, but it could be a cloud based deployment." The connection DATA layer already shipped its first leg: #16742 (C1 connection broker — profile identity contract, credential custody; session-only custodian executable via #17181 / PR #17176). What exists nowhere: the operator-facing UX for holding SEVERAL configured instances, seeing which one the cockpit is bound to, and switching.

## The Problem

The cockpit renders one implicit instance. The spine banner speaks about "the fleet server" as if there were exactly one; connection profiles exist as a contract with no surface. An operator running the local dockerized composition plus a remote deployment cannot (a) see which instance the truth on screen belongs to, (b) switch, (c) manage endpoints and credentials per instance. Instance identity is the ROOT CONTEXT of every cockpit surface — fleet, activity, memories, tasks, diagnostics are all instance-relative — so its absence is an information-architecture gap, not just a missing form.

**Sharpened 2026-08-18 (operator, live session — the seat-machine reality):** on a machine that hosts only AGENT repo clones, there is NO operator-owned environment to carry an operator PAT — every checkout's forge identity is a seat account, and the env-var journey does not exist for the person at the keyboard. **The FM UI is therefore the ONLY viable credential entry path for an operator on a seat machine.** Credential entry through this surface is the operator's PRIMARY onboarding act, not an edge case of instance management: without it, every send impersonates a seat (the exact `#17310` incident class, now detected but not curable in-product). Per-forge reality included: a GitHub PAT for a GitHub-planed instance, a GitLab PAT for a GitLab-planed one — the subject comes FROM the credential (no username field; the token proves the name), riding the forge-generic admission (#16736).

## The Architectural Reality

- `apps/agentos/fleet/connectionProfiles.mjs` (C1 leg 1, PR #17176): `normalizeFleetEndpoint`, `deriveFleetProfileId`, `createFleetProfile`, `isStaleProfile`/`rehydrateProfile` — the profile record IS the instance record; credentials never enter Body-readable state (the Option-D falsifier).
- `apps/agentos/view/Viewport.mjs` top chrome toolbar (logo · title · theme switch) — the switcher's natural home per the #17269 navigation model.
- Spine banner + `reconnectFleet` (`apps/agentos/view/fleet/FleetCockpit.mjs`) — today's single-instance connection-state UI; #16744 (C3) extends its vocabulary with remote states.
- D#16720 (closed, graduated): FM-as-client — FM never runs a plane, FM connects; a remote instance is the same client path with a different endpoint + PAT custody.

## The Fix (design-first)

1. **Instance switcher in the top chrome**: bound instance name + state dot; menu lists configured profiles; switching rebinds the cockpit through the C1 custody path; the banner narrates the transition in #16744's vocabulary.
2. **Manage-instances surface** (Settings-class, deliberately NOT Accounts — accounts are agent identities, instances are connection targets; mixing them muddies both): profile CRUD over the C1 contract, per-custodian affordances (session-only today; Electron-main and env-indirection legs render honestly as unavailable until #16742 legs 2–3 land), per-profile health probe.
3. **Scope naming**: instance-scoped surfaces reference the switcher as the one scope authority.

## Design sketch — switcher + manage surface (AC-1, spec-first)

Scored against the SSOT §06 bar (`apps/agentos/design/fleet-manager-cockpit-plan.html`, five ladders) + the `TOKENS.md` §04 appendix. Every token named below exists in the appendix; nothing new is minted.

### 1 · Placement (the #17269 consistency point)

The **switcher lives in the top chrome, left cluster, directly after the "Agent OS" title** — scope reads left-to-right: product → instance → (everything below is instance-relative). Today's chrome is `[logo · title · '->' · theme]` (`Viewport.mjs:71`); the switcher becomes the third member. The **manage surface is NOT a new rail keeper view**: its primary route is the switcher menu's terminal row ("Manage instances…"), keeping the rail grammar untouched and reachability owned by the scope control itself. If #17269's reserved-places decision later wants a rail entry, that is an additive rebind, not a redesign.

### 2 · The switcher trigger — §06 anatomy

An **affordance-class chip** (T2 third class — an action, never an observation; `.fm-chip` idiom, 6px radius recorded as the affordance distinction):

```
[ ● local-docker ▾ ]
```

- **State dot** = the family's mark-only member: hue from `--fm-state-*` via ONE local indirection (unmatched class renders quiet, never a borrowed severity). **Two-channel rule holds:** the dot carries hue; the state WORD rides `title`/hover on the trigger and stands as text inside the open menu — never hue-alone (law-1).
- **Instance label** = the profile's `label` at `--fm-text-chrome` (11px/1 · .08em · uppercase · mono — toolbar furniture tier, same register as the rail tabs).
- **Caret** = decoration per T3 (never load-bearing); the accessible name is "Instance: <label> — <state word>".
- The chip consumes family geometry (`--fm-chip-pad-y/x`, `--fm-chip-gap`); selection/press is structural (border + weight + wash), the affordance-class law.

### 3 · The menu (reveal/dismiss class)

Panel below the trigger, `--fm-motion-panel` reveal with the token-layer reduced-motion collapse (T4 — instant, never removed). Rows, one per configured profile:

```
● local-docker      http://localhost:8080     [session]
○ cloud-eu          https://fleet.example.io  [session]
──────────────────────────────────────────────
Manage instances…
```

- Row anatomy: state dot + **name** (`--fm-text-body` 12px sans) + **endpoint** (`--fm-text-detail` 11px mono) + **custodian badge** (`--fm-text-micro` 10px mono chip, family geometry). Spacing on the 4/8/12/16 rhythm.
- The BOUND profile is marked **structurally** (mark + weight, the selector-chip precedent), never hue-alone.
- Unreachable/auth-refused instances render their **reason-carrying state as text in the row** (#16744's vocabulary when it lands; the existing cold/degraded words until then) — an unreachable instance is pickable (switching to it shows the honest degraded cockpit), never hidden.
- Any "last connected" instant: `viewerTime.mjs` helper, ISO on `title` (T5 — no bespoke formatter).

### 4 · Switching (the rebind arc)

Menu pick → rebind through the C1 custody path (`connectionProfiles.mjs` is the ONLY profile authority) → the existing `reconnectFleet`-class transition runs under the new binding → **the spine banner narrates the transition** (its exception-only contract already owns cause+remedy text; it gains the profile LABEL in its sentence — "the fleet server" language retires, see §6). No reload. Generation-guarded reads (the shipped `gridReadGeneration` pattern) make the no-bleed AC mechanical: a row from the old instance cannot land after the switch advanced the generation.

### 5 · The manage surface (Settings-class, NOT Accounts)

A drawer-tier pane (T1 density: prose caps 68ch, list panes fill their measure). Content:

- **Profile list**: a provider-scoped `data.Store` OVER the C1 records (the `FleetTenants` pattern — the store is the view BINDING; `connectionProfiles.mjs` stays the only persistence/custody authority: hydrate via `rehydrateProfile`, mutate via `createFleetProfile`/retire. "No second storage" holds by construction — the store holds what the module returns, every write goes through the module).
- **Editor**: endpoint (validated by `normalizeFleetEndpoint`, id derived by `deriveFleetProfileId` — never typed), label, custodian picker over `PROFILE_CUSTODIANS`. **Session-only is the one enabled custodian today; `electron-main` / `env-indirection` render as visible-but-disabled rows with the reason as TEXT** ("lands with #16742 leg 2/3") — honest absence as design law, availability never carried by color.
- **PAT entry** (the primary journey, §6 below): password-type field, submit-to-wire, never echoed, never in Body-readable state (the Option-D falsifier stays the falsifier).
- **Per-profile probe**: a verb button per row; result renders the reason-carrying state word + instant (helper-formatted).

### 6 · The PAT journey — AC-4's arc, end to end

1. Operator opens manage surface → picks the instance → enters the forge PAT (`FLEET_BEARER_PATTERN` gates locally before any wire).
2. Submit rides the **`connectTenant` lifecycle-write class** (`fleetWireMethods.mjs:73` — the existing skeleton; the read half stays descriptor-only).
3. The session re-establishes as the credential's subject — **the subject comes FROM the credential; there is no username field** (#16736's forge-generic admission).
4. **The visible proof: the #17310 conflation marker clears** — the boot-time + beside-compose marker (merged today, `FleetCockpit.mjs:3038`) is the journey's success indicator. The marker's honest cost: session-only custody means re-entry per session, and the surface SAYS so at the field.

### 7 · Scope authority (AC on naming)

The switcher is the ONE scope authority. Instance-scoped surfaces (fleet grid, activity, memories, tasks) carry **no per-pane instance labels** — they inherit scope. Exactly two places speak the instance name: the switcher itself, and the spine banner's transition/degradation sentences (which gain the profile label and retire "the fleet server").

### 8 · Deliberately not decided here

The custodian legs themselves (#16742 legs 2–3) · the remote-state vocabulary words (#16744 owns them; this sketch only reserves the text slots) · grants/sharing (#16745) · any new state color (the `--fm-state-*` set is closed; nothing here needs one).

**A torn-out pane is scope-anonymous, and the sketch's own rule is what makes it so.**

## §7 decision — answering the gate finding (review [above](https://github.com/neomjs/neo/issues/17328#issuecomment-5330875527))

Taking **shape 1**, and stating the fact that makes shape 2 come along for free:

**1 · Torn-out panes follow a switch BY CONSTRUCTION — the follow/not-follow fork was never actually open.** A tear-out is a separate render window over the SAME SharedWorker heap: the widget window's panes read the same app-worker stores, and every bridge consumer resolves `AgentOS.fleet.registryBridge` per call (12 sites in `FleetCockpit.mjs`), so a re-published bridge rebinds them on their next poll exactly as it rebinds the main window — behind the same generation fences. The shell provider's own contract says it: windows are render targets; state is window-agnostic. "Torn-outs do not follow" would require *adding* isolation machinery, so the stated rule is: **they follow.**

**2 · The naming gap closes at the window property, per your shape 1.** Scope becomes a per-window fact: every torn-out window's **`document.title` carries the instance label** — set by the cockpit at the tear-out connect handshake (`tearOutConnects[itemId] = {windowId}` at `FleetCockpit.mjs:2211` already lands the windowId), and re-pushed to every entry in `tearOutConnects` by the switch owner via `main.addon.DocumentHead.setTitle` on every switch. §7's rule amends to: *exactly two places per MAIN window (switcher + spine banner); a torn-out window speaks its scope in the OS chrome — the title — which is the disambiguator the taskbar/window-switcher user actually needs with two instances configured.*

**3 · The operator's styling gloss, answered structurally:** the widget child-app has its own viewport class and its own SCSS surface — and this feature adds **zero components and zero styles to it**. The title mechanism is an addon call from the cockpit side; nothing new renders in the widget window, so there is no childapp styling surface to miss.

**4 · #17333 overlap, defused for this seam:** the title push rides the connect handshake + the owner-held `tearOutConnects` map — main-thread addon calls from the cockpit/controller, never string listeners resolved through the torn-out pane's controller chain — so the #17333 handler-loss class cannot reach it.

**Non-blocking, adopted:** the accessible name **"Instance: <label> — <state word>"** becomes the tested AC surface in the switcher specs (asserted as the string, so a refactor cannot satisfy the visual law while dropping the text channel).

AC-6 gains the clause on the ticket body (disclosed edit): torn-out windows follow-by-construction + title-carried scope.

Implementation proceeds on this decision. Thank you for constructing the tear-out topology instead of trusting my §7 sentence — the rule reading "total" while a whole window class sat outside it is exactly the find the gate exists for.
