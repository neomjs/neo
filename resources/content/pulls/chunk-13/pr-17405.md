Resolves #17402

The Playwright fixture is a second Bridge entrypoint and supplied no `cwd`, so `spawnBridge` refused wherever no Bridge was already listening — which is every clean container, and no maintainer seat. One line in the fixture, plus the guide sentence that made the contract false.

Evidence: L3 (live e2e on this host, real browser, real spawn — the refusal reproduced and then eliminated) → L3 required. The one arm this host cannot produce is a fully green run *through* the spawn path: the port override moves the node-side ConnectionService but not the browser app, so the two ends land on different bridges, and freeing the app's port means killing the seat's own live Bridge. That arm belongs to a clean container and is listed under Post-Merge Validation.

## Deltas from ticket

None substantive. AC-4 (guide states the contract) is delivered in the same commit rather than split, because the guide sentence is what made the defect invisible to an author — it sells the fixture on *not* managing the connection.

## Test Evidence

`test/playwright/e2e/rendering/ButtonBaseNL.spec.mjs`, one spec, three arms on this host:

| arm | refusals | result |
|---|---|---|
| before fix, clean free port | **8 × `cwd is unresolved`** | 4 failed — the production failure, reproduced |
| after fix, same clean port | **0** | bridge spawns; 4 failed on `waitForSession` (control's port split, see below) |
| after fix, default port (Bridge present) | 0 | **4 passed** |

The control needed one correction worth recording: my first run of it showed *no* refusal in either arm, because an earlier mechanism probe of mine had left a stray Bridge listening on the test port, so `connectToBridge()` was succeeding against my own leftover. Killing it made the control discriminate. A control polluted by its own earlier arm reads exactly like a passing control.

Mechanism, two arms, direct on `ConnectionService`:

```
arm1 cwd = null          -> REFUSED (expected)
arm2 cwd = process.cwd() -> no refusal, spawn proceeded
```

Neural Link surface: `test/playwright/e2e/rendering/ButtonBaseNL.spec.mjs` — 4 passed on the default port.

## Post-Merge Validation

- [ ] A whitebox e2e spec reaches its page on a host with **nothing** listening on the Bridge port — i.e. a clean CI container, which is the environment that surfaced this. AC-1's remaining arm.
- [ ] The downstream consumer whose pipeline reported 17/17 failures passes on a pin carrying this commit. AC-5.

## Evolution

The first shape I considered was fixing it in the consumer, since that is where the red was. That is wrong twice: it puts a workaround in every adopter for a defect in the shared fixture, and the specific consumer PR it would have landed in exists to *remove* workarounds a pin forced.

I also expected the guide change to be cosmetic. It is not — `WhiteboxE2E.md` promises the fixture manages the connection, and 100 of 111 e2e spec files were written against that promise. The prose was accurate about intent and false about behaviour for a week, which is why no author went looking.
