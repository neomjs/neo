## The defect

A genuinely empty tenant repository carries an authoritative full-materialization manifest with `pathsAfterPush: []`, but it produces no ingest/delete effect. The prior guard therefore refused it as `KB_TENANT_REPO_SYNC_EMPTY_MATERIALIZATION`.

The first implementation returned `null` from the orchestrator guard. That made the immediate run report `completed`, but persisted no committed attempt id. `classifyTenantRepoCheckpoint()` consequently still returned `failed`, `requiresTenantRepoCheckpointRevalidation()` stayed true, and every later sweep replayed from a null base. The permanent trap was only hidden, not broken.

## The repaired contract

The proof now originates at the producer boundary:

1. `IngestionService` observes the authoritative manifest after reconciliation.
2. When it is empty and the summary has zero errors, it persists the ordinary digest-bound receipt for the current attempt.
3. `TenantRepoSyncService` accepts zero effect only when **both** the manifest declares no content and that receipt proves the current attempt.
4. The checkpoint persists `lastCommittedMaterializationAttemptId`, classifies `complete`, disables revalidation, and the next ordinary sweep carries `lastIngestedRev`.

This is deliberately not a blanket zero-effect exception. A non-empty manifest with zero effect still fails. A forged current receipt on a non-empty manifest still fails. A prior unacknowledged positive receipt is preserved and settles exactly once; a stale already-committed receipt is not laundered into a new success.

The earlier body described “never committed only” as a load-bearing condition and left post-commit empty repositories open. That was the cycle-1 shape. The repaired producer-owned proof makes a **new authoritative empty materialization** valid regardless of prior checkpoint history while retaining the stale-receipt refusal. That supersedes the old fork without weakening #16045.

## Additional diagnostic split retained

The PR also preserves Vega's adjacent correction: a non-empty materialization whose chunks are all refused as oversized raises `KB_TENANT_REPO_SYNC_CONTENT_NOT_EMBEDDABLE` and remains failed, rather than being mislabeled as empty.

| manifest | effect | proof | disposition |
|---|---:|---|---|
| authoritative empty | 0 | matching current receipt | complete |
| non-empty | 0 | absent or forged | `EMPTY_MATERIALIZATION` |
| non-empty, all oversized | 0 | no durable effect | `CONTENT_NOT_EMBEDDABLE` |
| delete-only retry after checkpoint-write loss | already applied | prior unacknowledged receipt | settle once |
