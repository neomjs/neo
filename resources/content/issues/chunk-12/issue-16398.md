# Fleet cockpit memories view: viewer-scoped turn recall from the plane

> **Provenance:** FM-week operator wishlist item 3 (operator direction 2026-08-02, re-confirmed at session start). Third capability wave on the Lane-A spine under epic #14560 — the first NEW cockpit view built entirely on the shipped containerized-plane consumption pattern. The **design half of this view is explicitly open for collaboration** (offer to @neo-opus-vega per the epic's Lane D; see A2A).

## Context

Lane A (spine reconnect) completed 2026-08-02: every MC read the Fleet cockpit makes now crosses an identity-verified boundary into the containerized plane and degrades honestly (PR #16329 mailbox/compose/catch-up, PR #16368 wake axes, PR #16386 telltale truthfulness). The cockpit surfaces **communication** (mailboxes), **history digests** (catch-up), and **liveness** (wake/stall telltales) — but not **memory**, the substrate the whole Agent OS runs on.

The operator managing the team through FM cannot see what any seat did last, what it saved at end of turn, or how a lane progressed across sessions. That reading exists today only through harness-side MCP tooling (`query_recent_turns`) — invisible from the product surface.

## The Problem

Memory Core is memory-on-demand: an agent's turn trail is queryable, viewer-scoped, and (per the team's `memorySharing` policy) readable across peers — organizational telepathy with permission semantics. The cockpit needs the read side of that as a first-class view: **pick an agent, see their recent turns** (timestamp, summary, session grouping, tool counts), page backwards, and trust that an empty or degraded list is the truth rather than a rendering artifact.

Concrete operator moments this closes: "what did Iris actually do in her last three turns?", "did Clio's sunset handover save what it claims?", "which session produced this PR?" — today each requires a harness seat and tool literacy; after this, one click in the roster.

## The Architectural Reality

**The plane already serves everything v1 needs — zero new Memory Core surface (V-B-A receipts):**

- `query_recent_turns` is a registered plane op with `agentIdentity`, `before` paging cursor, `limit`, `detail: summary|full`, and `projection: public|private` — exercised live against the dockerized plane (ingress `127.0.0.1:3102`) during this session's own recovery, 2026-08-02.
- Tenant isolation: `MemoryService.mjs:1085` resolves `memorySharing || aiConfig.memorySharing.defaultPolicy` (team default on this plane).
- Cross-viewer admission: `CAN_READ_MEMORIES_OF` is a registered scope in `ai/services/memory-core/PermissionService.mjs` (+ `ai/mcp/server/memory-core/configBase.mjs`). The plane enforces; consumers never simulate.

**The consumption pattern is shipped (Lane A leaves 1–3):**

- `ai/services/fleet/devFleetServer.mjs:89` constructs `createPlaneMailboxClient` when `fleet.planeBase` is set; sources receive **injected operations** and never choose transport themselves.
- `ai/services/fleet/fleetCatchUpSource.mjs` is the exact sibling: viewer resolved per call from transport-stamped ingress (`:99-101`, `:125-133`), injected ops (`:105-106`), typed fail-honest envelopes (`wired|degraded|unavailable`), no cache, no synthesis, no Fleet-side authority.
- App-side sibling trio: `apps/agentos/view/fleet/CatchUpPane.mjs` + `store/CatchUpEntries.mjs` (+ `model/CatchUpEntry.mjs`) — pane-local projection stores, "no record survives the view/process lifecycle".

**Structure-map gate:** `ai/services/fleet` (42 files) owns the source; sibling precedent `fleetCatchUpSource.mjs`. Structural pre-flight Stage-1 fast-path: sibling-file-lift. App side follows the existing `apps/agentos` model/store/view split.

## The Fix (v1)

1. **`ai/services/fleet/fleetMemoriesSource.mjs`** — `createFleetMemoriesSource({queryRecentTurns, resolveViewerIdentity, now})`, sibling of `fleetCatchUpSource`:
   - viewer resolved per call from the transport-stamped ingress; target agent param defaults to the viewer; canonical `@identity` validation per the catch-up partition discipline;
   - projection selection is derived, never caller-chosen: `private` iff target === viewer, else `public` (the plane enforces regardless — denials pass through as honest envelope states);
   - returns `{capability: wired|degraded|unavailable, turns, cursor}`; paging via the op's `before` cursor; no cache, no synthesis.
2. **Wiring** in `devFleetServer.mjs` + bridge dispatch per the S3 catch-up precedent (`devFleetServer.mjs:224`): plane mode injects a plane-client-backed op; empty `fleet.planeBase` keeps the in-process host path working (container-less checkouts unchanged).
3. **App side:** `apps/agentos/model/MemoryTurn.mjs` + `store/AgentMemories.mjs` + `view/fleet/MemoriesPane.mjs` — per-agent turn rows (timestamp, summary, session id, tool count when present), load-more paging, empty/degraded/unavailable states in the cockpit's honest-degrade vocabulary; entry point from agent selection (AgentDetail drill-in), exact placement co-designed with Lane D.
4. **Witnesses:** unit specs for the source (settlement projection, viewer binding, cursor discipline, projection derivation) + NL-fixture e2e for the pane render.

Deliberately does **not** touch D#16176's diamonds (no container-placement change, no new authority model — stays inside the shipped single-viewer admission), and does **not** depend on D#16304's data-plane convergence work (the view renders what the canonical plane serves, truthfully).

## Acceptance Criteria

- [ ] `createFleetMemoriesSource` rejects missing op/viewer-resolver at construction; viewer resolved per call; non-canonical target identities rejected (unit-witnessed).
- [ ] Projection derivation: `private` only when target === viewer; a plane-side denial or op failure surfaces as `degraded`/`unavailable` capability — never a fabricated empty success (unit-witnessed).
- [ ] Plane mode: own turns + a peer's turns render from the live containerized plane through the authenticated ingress (headed receipt in the PR).
- [ ] In-process mode (empty `fleet.planeBase`) keeps working for container-less checkouts.
- [ ] Pane: per-agent turn rows with timestamp/summary/session-id, `before`-cursor load-more, honest empty/degraded/unavailable states; no `[object Object]`-class rendering (non-string fields guarded at the model/render boundary per the #16386 lesson).
- [ ] Zero diff under `ai/services/memory-core/` and `ai/mcp/server/memory-core/` (the "zero new MC surface" constraint, mechanically checkable).
- [ ] Scoped unit config green + NL-fixture e2e for the pane green; JSDoc Anchor & Echo on all new modules.

## Out of Scope

- Semantic memory search UI (`query_raw_memories`) and summaries/rollup views — v2 candidates after the turn-recall spine exists.
- Cross-agent merged timelines, memory WRITE surfaces, agent-facing FM read APIs (S2 track), any MC-side op/schema change.
- D#16176-gated container placement; D#16304 data-plane convergence (Vega's lane).
- Design-system/token work beyond consuming what exists (Lane D owns tokens; the view's placement/vocabulary is the offered design half).

## Avoided Traps

- **No caller-chosen identity:** the pane never sends "as whom"; the viewer is transport-stamped (the Lane-A invariant that survived five review cycles on leaf 1).
- **No shadow authorization:** the source does not pre-filter by predicting plane permissions; `CAN_READ_MEMORIES_OF` + sharing policy are plane authority, and denials render honestly.
- **No second truth:** no caching/mirroring of memories into cockpit state beyond the pane-local render projection (CatchUpEntries discipline).
- **No hand-mapped arrays:** data-carrying UI binds a `data.Store` of `data.Model` records (operator directive 2026-07-08).
- **No premature generalization:** one view, one op, one source — the S2 "FM APIs for agents" Discussion owns any broader read-API shape.
