# A deployment acceptance gate: the two plane symptoms must be provably red before a candidate ships

## Problem

Nine mechanisms have been proposed for the incident tracked in #16706. **All nine were falsified.** The common cause is not a shortage of diagnosis — it is that each candidate was *reasoned* and none was ever **run against the failing plane first**.

A gate nobody has watched go red certifies nothing. Four of the nine trails die to that single rule.

## Intended solution

A fail-closed assertion over deployment state that answers one binary question — **are the two symptoms gone?** — and is meant to be run BEFORE a deploy against the currently-deployed revision, where it must be observed FAILING.

**It adds no instrumentation.** Every field it reads is already published by `get_deployment_state_snapshot`. The contribution is the assertion, which is why this is not another diagnostic tool.

## Acceptance criteria

- **AC-1** — `validateDeploymentAcceptance()` is a pure exported function returning `{accepted, blockers}`, matching the `validateMergeReady.mjs` precedent in the same directory.
- **AC-2** — **S1 requires both halves.** A cgroup-capped container reports the same CPU number whether busy or wedged, so pinning alone must never reject; only pinned **and** no-inference is the symptom. A pinned provider whose request log carries real inference must be ACCEPTED.
- **AC-3** — **S2 requires ≥2 tenants** carrying a non-null `lastIngestedRev`. A single working repo has satisfied every partial attempt so far.
- **AC-4** — the `running: true` / `pid: null` wedge is asserted **separately** from the ingested count, because a plane whose sweep died hours ago can still show stale successes from before it wedged.
- **AC-5** — every unmeasured input fails CLOSED, and a null request log is never read as zero inference. Not-measured and measured-as-none are different facts; conflating them is how an absent instrument becomes a finding about the world.
- **AC-6** — the spec's load-bearing case feeds the **verbatim measured values from a plane exhibiting both symptoms** and asserts rejection **by blocker content**, not merely by `accepted === false`. A non-vacuity control asserts a healthy plane is accepted.

## Evidence

Implemented and verified against a live plane, not fixtures: the gate exits `1`, reporting 3 of 4 tenant repos have NEVER ingested plus the sweep wedge, and correctly **abstains** on S1 at `399.47%` because that window carried 4 real `/api/embed` requests. The same plane at 19:49 showed zero inference while pinned, so the discriminator separates the two states it exists to separate.
