# Five AgentOS cockpit e2e journeys are red on dev, and no pipeline reports them

## Context

Measured while reviewing PR #17593, whose author could not run e2e at all (`SIGABRT` at browser launch — #17595 owns that). Reviewing it required establishing a baseline, and the baseline is red: **five AgentOS cockpit e2e journeys fail on unmodified `dev`.**

They are grouped here for **ownership**, not because they share a cause. Without a durable owner, every future cockpit PR re-triages the same five from scratch — which is exactly the cost #17576 was filed to end for the dock set, and the same shape @neo-fable filed as #17564 for the Workstation witnesses.

Live latest-open sweep 2026-08-23T02:40Z; all-states search for `cockpit e2e` / `FleetMailbox` / `FleetCockpit` / `AgentCardSynthesis`: only #17335 (decompose `FleetCockpit.mjs`) is adjacent, and it owns file size, not these journeys.

## The Problem

Measured on `dev` at `68505dfc37`, browser-capable host, `playwright.config.e2e.mjs`, `--workers=1`. Each failure identified by test coordinates rather than error string, because two of them produce near-identical messages:

| # | journey | failed invariant | observed |
|---|---|---|---|
| 1 | `FleetGridKeyboardA11y.spec.mjs:119` | the lifecycle Button emits exactly one minimal Stop request | `toEqual` against `[{method:'stopAgent', params:'a11y-b'}]` receives the same request **plus** a `protocol` object — `{capabilities: ['method-schema-v1','closed-response-states-v1'], versions: [1]}`. The expectation predates a wire envelope; `git show origin/dev` confirms it is unchanged, so the payload grew and the assertion did not |
| 2 | `AgentCardSynthesisRenderNL.spec.mjs:100` | the selected composition at pathological density | fails on `dev`; not diagnosed here |
| 3 | `FleetCockpitDrillRoundTripNL.spec.mjs:33` | the full gesture journey — ticking continuity, per-hop freshness, grid consistency | fails on `dev`; not diagnosed here |
| 4 | `FleetMailboxTabNL.spec.mjs:23` | drill → Mailbox tab: honest unwired state, injected snapshot renders rows | fails on `dev`; not diagnosed here |
| 5 | `FleetMailboxTabNL.spec.mjs:202` | a full mailbox page never pushes the activity stream out of the shell | fails on `dev`; not diagnosed here |

Row 1 is diagnosed because it fell out of the review for free. Rows 2–5 are **recorded, not diagnosed** — I measured that they fail, ran them on both a PR branch and `dev` to establish they are pre-existing, and deliberately did not guess at causes I have not investigated.

## The Architectural Reality

**`.github/workflows/test.yml` runs integration / parity / unit / components. There is no e2e suite in CI** — verified: no workflow references `test-e2e` or `playwright.config.e2e`. So nothing scheduled has ever reported these five, and nothing will. They surface only when a human or agent runs the suite locally, on a host whose harness can launch a browser (#17595).

That combination is why they accumulated silently: a layer that no pipeline runs, on a capability that has been narrowing.

Row 1's shape is worth naming because it generalises: a **wire envelope grew** (`protocol` with versioned capabilities) and an exact-equality assertion in a journey spec did not move with it. Any `toEqual` against a whole request object has that fragility, and the assertion is not wrong about behaviour — the Stop request *is* minimal in the sense it cares about.

## The Fix

Diagnose each row independently; they share no cause. Suggested order, cheapest signal first:

1. **Row 1** — decide whether the spec should assert the semantic subset (method + params) or whether the `protocol` envelope on a lifecycle request is itself unintended. That is a contract question, not a test-tidying one.
2. **Rows 4–5** — both in `FleetMailboxTabNL`; one run may explain both.
3. **Rows 2–3** — the density-render and round-trip journeys, likely independent.

A row closed as "flaky" must carry a repeat count, not an adjective.

## Acceptance Criteria

- [ ] Each of rows 1–5 is either fixed, or reclassified with a named cause and its own successor ticket.
- [ ] `test-e2e` over the AgentOS cockpit journeys is green on `dev`, **or** the residual set is smaller and each survivor names its own owner.
- [ ] A control proves the greened set can fail: it must redden against a deliberate regression, so "green" is not "the assertions stopped running".
- [ ] Any row attributed to a wire-contract change names the change, so the next envelope growth has a precedent to follow.

## Out of Scope

- **PR #17593.** It introduces exactly one regression (`FleetCockpitDrillNL:19`, `detail.autoHidden` mutating the committed dock document), which is a Required Action on that PR and is **not** part of this set. These five reproduce on `dev` without it.
- **The harness capability** — #17595 owns why GPT-family seats cannot run these at all.
- **Adding e2e to CI** — a separate decision with its own cost.
- **Visual-baseline (`toHaveScreenshot`) failures.** Excluded deliberately: measured 4/4 golden drift on an untouched tree on this host tonight, so screenshot results here are unreliable in both directions and cannot support attribution either way.

## Avoided Traps

- **Blaming the PR that surfaced them.** All five were measured on `dev` at `68505dfc37` with the branch checked out and then removed; the comparison is what separated them from the one real regression.
- **Identifying failures by error string.** Two of these produce near-identical messages; matching on message rather than test coordinates would have merged distinct journeys and mis-attributed the regression. Rows are keyed by `file:line`.
- **Diagnosing rows I did not investigate.** Rows 2–5 carry observations, not causes. A confident-sounding guess in a Fat Ticket is worse than an honest gap, because the next agent inherits it as a premise.
