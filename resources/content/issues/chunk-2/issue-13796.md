# Generic-by-default harness adapter surface — minimize per-family (Claude / Codex / Antigravity / …) logic

## Observation (operator-surfaced)

The harness carries a growing amount of **per-family** logic — Claude-specific (e.g. `.claude/hooks/laneStateStopHook.mjs`, `.claude/` settings) and Codex-specific adapters. A NEW family (**Antigravity**, and any future one) has **none** yet → onboarding a new family currently means writing a new per-family logic fork, not dropping in a thin adapter.

## Question

Should the harness logic be **mostly generic** (family-agnostic core + thin per-family adapters), so a new family plugs in via a small adapter instead of a logic-fork?

## The pattern already exists — extend it

`ai/scripts/lifecycle/stopHookDecision.mjs` is the model: *"Shared pure decision primitives for lane-state Stop hooks. Harness adapters own payload extraction and transport behavior; this module owns the no-hold decision semantics so Claude and Codex cannot drift."* The generic core (pure decision) + thin per-harness adapter (payload/transport) is the right shape. The just-merged deference + hold-lexicon work (#13740) lives in that shared core — good.

## Direction (design surface — may graduate to ideation)

- Audit where per-family logic lives vs the generic core (hooks, settings, identity binding, transport).
- Extract family-agnostic decision/semantics into shared modules; keep ONLY payload-extraction + transport in per-family adapters.
- Define the adapter contract so **Antigravity** (the forcing function) onboards via a thin adapter — no logic fork.
- Net: N families × thin adapters, not N × logic forks.

## Out of scope
- The shared decision semantics themselves (those stay generic by definition).

Surfaced by @tobiu; filed by @neo-opus-ada as the follow-up to the open-PR sweep.

## Live audit: “shared semantics” is not enough — require one behavioral contract (2026-07-21)

The operator sharpened this ticket’s premise today:

> Hook rules should be exactly the same for all peers.

A live Codex continuation-chain specimen shows why the current “shared decision primitives + harness-owned extraction” boundary is still too porous.

### Empirical specimen

- The shared classifier admits a mid-chain operator turn only when the adapter supplies `promptingTextHumanFiltered: true` (`ai/scripts/lifecycle/stopHookDecision.mjs`).
- Claude’s adapter supplies that attestation from its provenance-aware transcript walk.
- Codex calls `classifyPromptingContext({stopHookActive, promptingText})` without the attestation. Its existing unit fixture explicitly pins `stop_hook_active: true` + visible operator-like text to `operatorInLoop=false`.
- In the live Codex session, `UserPromptSubmit` persisted the ordinary operator prompt at `2026-07-21T21:24:41.388Z`. The following Stop audit at `2026-07-21T21:27:06.837Z` reported `promptSource=transcript_path, operatorInLoop=false` and blocked a valid terminal. The session transcript confirms the ordinary operator record immediately precedes the injected hook continuation.
- This is **not a regression** from PR #15210. That PR explicitly stated that Codex passed no attestation and retained fail-closed semantics. Today’s run is the previously accepted parity gap becoming visible.
- Current drift surface: `.claude/hooks/laneStateStopHook.mjs` is 867 LOC and `.codex/hooks/codex-lane-state-stop.mjs` is 602 LOC, beside the 413-LOC shared decision module. LOC is not the defect, but it shows how much policy-adjacent behavior still lives outside the alleged single authority.
- Repository wiring currently exposes the Stop hook for Claude and Codex; no Kimi-equivalent tracked Stop adapter is present. “All peers” therefore also needs an explicit capability matrix rather than treating missing enforcement as invisible parity.

### Stronger invariant

The shared substrate should own **behavior**, including the provenance threshold for each logical turn kind. A harness adapter may differ only in:

1. decoding its raw event/transcript schema into one canonical, provenance-bearing turn-boundary envelope; and
2. serializing the shared decision into that harness’s block/allow transport.

It must not independently decide whether a visible operator prompt is sufficiently authoritative. Unsupported harness capabilities should become an explicit `unsupported/unverified` input to the same shared rule, not a harness-local semantic fork.

A useful contract shape to investigate is:

```text
raw harness event
  -> adapter normalization (payload schema + provenance only)
  -> shared TurnBoundaryEnvelope
  -> shared classification / validation / admission / directive rendering
  -> adapter transport
```

The cross-harness fixture matrix should feed the same logical cases through every adapter: direct operator prompt, autonomous wake, forced continuation after operator input, mid-turn operator arrival, synthetic hook feedback, handoff-to-autonomous, and missing/unverifiable provenance. Equivalent logical envelopes must produce equivalent decisions.

### Placement challenge

The operator suggested `ai/agent/hooks/` as one candidate. Structural pre-flight does **not** make that an automatic fit:

- `ai/agent/` is currently the internal cognitive runtime (`Loop`, `AgentOrchestrator`, `Scheduler`).
- `ai/scripts/` is documented as one-shot operator scripts + thin wrappers, so the existing 413-LOC policy core in `ai/scripts/lifecycle/` is also an increasingly weak canonical home.
- A shared hook-policy subsystem is structurally significant and cross-harness. This ticket should compare `ai/agent/hooks/`, `ai/hooks/`, and a lifecycle-owned domain using the actual import/consumer graph before choosing. A new canonical home requires the Architecture Overview map update; an ADR is warranted if the extraction establishes a durable cross-system adapter boundary.

### Routing

No new broad refactoring ticket is needed: **this issue already owns it**. Issue #14420 remains the symptom/corpus owner for operator-prompt blindness; PR #15210 / issue #14440 are the Claude-only precedent. The next useful artifact here is a payload/capability census plus the normalized-envelope contract, not another Codex-only policy patch.

## Cross-harness capability census — shared imports are not shared behavior

This is the payload/capability census requested by the prior audit, against `origin/dev@74a6a1954e1db5aef6af5b668bf881989c8cb522`. Evidence deposit only; **not a claim on implementation ownership**.

### 1. Current matrix

| Surface | Claude Code | Codex | Kimi Code | Antigravity / Gemini |
|---|---|---|---|---|
| Tracked turn-boundary wiring | `.claude/settings.template.json`: `UserPromptSubmit`, `PostToolUse`, enforcing `Stop` | `.codex/hooks.json`: `UserPromptSubmit`, enforcing `Stop` | Seat-local TOML example: `UserPromptSubmit`, `PostToolUse`, `Stop`, `StopFailure`, `Interrupt`; `SessionStart` wake-envelope recipe | No tracked Stop adapter/wiring found |

| Mid-chain human provenance | provenance-aware transcript walk; passes `promptingTextHumanFiltered:true` | extracts text but passes no attestation; chained operator text stays fail-closed | absent from lane-state policy | absent |

| Turn presence | start + progress; no configured terminal writer | start via UserPromptSubmit context hook; no progress/terminal wiring | start + progress + completed/aborted terminal | no tracked adapter found |

The key code-level asymmetry is mechanical:

- Claude calls `classifyPromptingContext(... promptingTextHumanFiltered:true)`, evaluates `cleanTerminal` and `materialArtifact`, and calls the shared decision with `laneContinuation`, `cleanTerminal`, and `materialArtifact`.
- Codex calls `classifyPromptingContext({stopHookActive, promptingText})` and calls `decideStopHookAction` with only enforcement, operator, and transport inputs.
- Kimi's `Stop` event is wired to `turnPresenceHook.mjs`, not to lane-state policy.

So “both import `stopHookDecision.mjs`” proves API reuse, not behavioral parity.

### 2. The closed-ticket lineage explains the drift

The missing rows were not accidental partial implementations; their tickets explicitly scoped them to Claude:

- #15274 / PR #15371 — clean-terminal acceptance.
- #15404 / PR #15435 — material-artifact key.
- #15216 / PR #15222 — attachment/mid-chain provenance; Codex explicitly out of scope.
- #14420 — active symptom/corpus owner for prompt blindness.

A live duplicate sweep found no narrower open issue for Codex clean-terminal/material-key parity, Kimi lane-state Stop enforcement, or Antigravity Stop enforcement. This ticket is therefore the correct composition owner.

There is also documentation drift on current `dev`: `learn/agentos/Hooks.md` says prompting-message classification is one of the questions that “must not drift” and describes both autonomous allow edges as the hook contract, while only Claude composes those edges today.

### 3. Stronger contract: normalize facts, centralize policy

The adapter boundary should not be “extract some text and optionally attest that it was filtered.” It should be:

```text
vendor payload/transcript
  -> thin adapter: normalize vendor facts + explicit capabilities
  -> canonical HarnessTurnBoundary envelope
  -> ONE shared evaluator
       prompt provenance/classification
       lane-state parse + evidence validation
       deference classification
       dialogue/active-lane rule
       material-artifact + clean-terminal admission
       stable reason codes + directive model
  -> thin adapter: serialize allow/block/audit transport
```

The canonical envelope should carry evidence facts, not an adapter-authored policy verdict: final assistant source, prompting-record source/kind/provenance, continuation-chain state, canonical tool-use/result events, session/identity correlation, transcript availability, and an explicit capability vector. Unsupported capability is a first-class `unsupported/unverified` input; it must not hide as a harness-local semantic fork.

A shared decision result should expose stable reason codes and a directive model. Vendor prose/JSON transport may differ, but equivalent canonical envelopes must produce the same action and reason code.

### 4. Placement pre-flight

The operator suggested `ai/agent/hooks/`. Source topology argues against making that the default:

- `ai/agent/` is the in-process Neo-class cognitive runtime (`Loop`, `AgentOrchestrator`, `Scheduler`).
- Turn-boundary hooks run out-of-process at vendor harness edges and are pure/fail-open modules.
- `ai/scripts/` is documented as one-shot operator scripts + thin wrappers, so the current shared policy cluster under `ai/scripts/lifecycle/` is also the wrong long-term canonical home.

**Provisional best fit: a new top-level `ai/hooks/` domain** for canonical envelopes, shared policy, audit/admission helpers, and conformance fixtures. Keep `.claude/hooks/`, `.codex/hooks/`, and `.kimi-code/hooks/` as thin vendor adapters/wiring only.

This is a structurally significant new Agent-OS boundary, not a file shuffle. If selected, the implementation must:

1. add the `ai/hooks/` Structural Inventory row;
2. update `learn/agentos/Hooks.md` from claimed parity to the executable contract;
3. record the cross-system adapter boundary in an ADR (or explicitly extend an existing ADR if peer review finds a true authority fit);
4. retain compatibility imports only as a bounded migration seam, not permanent dual authority.

### 5. Conformance gate before extraction

Build the logical fixture matrix first and run it through every adapter:

- direct operator prompt;
- `[WAKE]` / synthetic hook prompt;
- operator message during a forced continuation;
- dialogue + `active-lane`;
- valid autonomous terminal + material artifact;
- valid fully handed-off clean terminal after ratchet;
- absent/malformed prompt provenance;
- absent/malformed lane-state;
- unsupported transport/provenance capability.

The first success criterion is not equal LOC or equal file names. It is:

> For every equivalent logical turn boundary, all capable harnesses produce the same shared action and reason code; an incapable harness produces the same explicit unsupported-capability classification.

Only after that characterization should Claude be migrated as the reference adapter, Codex parity filled, and Kimi/Antigravity capability proofs determine their adapter shapes. Keep this as one coherent #13796 lane unless an empirical capability wall forces a genuine dependency split.

## ADR successor-risk

`ADR successor-risk: adr-aligned — artifact #13796/2026-06-21 predates merged ADR 0035 (PR #15103); merged ADR 0002 (PR #10356) owns wake delivery/presence; evidence: ADR 0035 §§1.2, 2.8 + ArchitectureOverview Structural Inventory; route: preserve both authority fences and graduate a separate turn-boundary design/ADR before implementation.`

The later records reshape the boundary without superseding this goal:

- **ADR 0002** owns wake transport, presence, and delivery policy. A normalized Stop envelope must not quietly become a second wake router.
- **ADR 0035** owns live-lane enrichment projection and explicitly gives enrichment **zero admission effect**. Its hook reader must remain separate from the no-hold admission evaluator.
- ADR 0035 also deliberately declines to place future files. It therefore does not decide `ai/hooks/`, but it does constrain what that domain may absorb.

## Required narrowing before a branch

1. **Scope the first contract to the turn boundary.** Do not combine Stop admission, wake delivery, turn presence, settings generation, identity provisioning, and live-lane enrichment into one “generic harness” subsystem.
2. **Graduate the design surface.** Compare the current `ai/scripts/lifecycle/` home with a new top-level `ai/hooks/`; `ai/agent/` is the in-process cognitive runtime and is not justified by the current consumer graph. A new `ai/hooks/` row is a durable cross-system boundary and earns an ADR (or an explicit extension of an existing ADR after peer review).
3. **Normalize evidence facts, not policy verdicts.** Define a canonical `HarnessTurnBoundary` plus an explicit capability vector; one shared evaluator returns stable action/reason codes; vendor adapters only decode vendor payload/transcript facts and serialize the result.
4. **Write the cross-harness conformance matrix first.** Feed equivalent logical cases through each capable adapter: direct dialogue, autonomous wake, forced continuation with mid-chain operator input, dialogue + `active-lane`, material-artifact, clean-terminal, malformed/absent provenance, malformed/absent lane-state, and unsupported capability.
5. **Add the Contract Ledger to the authority artifact.** At minimum it must name the Claude, Codex, Kimi, and currently-unverified Antigravity/OpenCode event/provenance contracts, their source of authority, required capability, fallback behavior, and verification owner.
6. **Make migration authority singular.** Compatibility imports from `ai/scripts/lifecycle/` may be bounded migration seams; they cannot become permanent dual policy authority.

The executable success criterion remains:

> Equivalent canonical turn-boundary evidence produces the same shared action and reason code on every capable harness; an incapable harness produces the same explicit unsupported-capability result.

I am adding the existing `design` label. No implementation claim or branch should start until the design/contract artifact supplies this narrowing.
