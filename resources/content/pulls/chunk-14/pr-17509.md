Resolves #17311

The operator's first-send friction, fixed at both controls: a selected recipient is now REMOVABLE — click the row again (a new opt-in `toggleOnClick` on `Neo.selection.ListModel`, default false, so no existing consumer changes), or activate the action-named close button on its chip. The current selection renders through `RecipientChipList` — a projection over the picker's OWN Store instance (shared, never owned) drawing the selected subset of the SAME records, so a roster rename or removal after selection converges into the chips, the picker rows, and the eventual `to` array instead of freezing in a snapshot. The `AGENT:*` broadcast sentinel is now DEFINED as exclusive: it and named picks never co-exist; whichever side was newly picked wins. Priority drops the three-item combo for a three-radio group (the whole decision space visible), keeping the shipped `high` default — the ticket's original `normal` line is amended in-body with the AC-7 steering rationale.

Evidence: L3 achieved (the full journey runs as a real-click e2e: select→chip, toggle-deselect, chip close by mouse AND keyboard with its `Remove <name>` accessible name asserted, both exclusivity directions, live roster rename/removal converging into standing chips, radio move — `OperatorComposeControlsNL.spec.mjs`, 1/1 green on this seat: `npx playwright test agentos/OperatorComposeControlsNL -c test/playwright/playwright.config.e2e.mjs --workers=1`) → L3 required (every AC names click-observable behavior). Residual: none.

## Deltas from ticket

1. Engine half taken as the ticket's sanctioned option A: `toggleOnClick` config on `selection.ListModel` (opt-in; the click path maps the record through `getSelectionItemId` before the `isSelected` check — the same entry conversion `select()`/`deselect()` apply), now with its own engine unit covering default-off, multi-select toggle through the vnode-id conversion, and singleSelect immunity.
2. Chips are a Store/Model data path end-to-end: `RecipientChipList` (a `list.Chip` subclass) renders the picker Store's records directly — `autoDestroyStore:false`, the same shared-Store contract the fleet's menu list uses — and `RecipientChip` upgrades the close affordance to a native `<button>` carrying `Remove <recipient>` as its accessible name (keyboard activation from the platform). One delegated list-level listener owns every chip's close click.
3. Priority default `high`, not the ticket's original `normal` — in-body amendment with rationale (shipped AC-7 decision + the wake-priority incident as its living proof).
4. Radio-group theme gap: none encountered — `form.field.Radio` renders acceptably in both skins; nothing filed.
5. Environmental find during verification, NOT this diff (stash-falsified, defect-note broadcast, repro offered to @neo-fable whose dock-layout look it touches): the cockpit south tab-set intermittently projects only Activity on bridge-connected boots — the e2e instances (bridge deferred) render all four reliably.
6. A selection survives a roster replacement by CANONICAL id, not by rendered item id: replacing `store.data` rotates internal record ids, so `afterSetRecipientOptions` reads the canonical ids out first, then re-selects the survivors onto the new records — recipients the roster dropped are pruned by construction.
