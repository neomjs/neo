# Remove the five devDependencies the census proved unreachable

## Context

Follow-up of #16204 (the devDependency census, PR #16354). The census classified all 45 devDependencies by AST-verified importers (static + dynamic + `require`), tool-usage (bins/hooks), and mention evidence. Five packages came back with **zero verified usage of any class**. Per the census ticket's Out of Scope, removals are their own ticket — this is it. Full adjudication: #16204 issuecomment-5158183571.

Live latest-open sweep at 2026-08-02T14:12Z (20 newest) + A2A in-flight claim scan (15 newest): no equivalent found.

## The Problem

Five devDependencies sit in every contributor's install with no importer, no bin invocation, and no asset-path consumer:

| package | census evidence | note |
|---|---|---|
| `clean-webpack-plugin` | zero references anywhere | webpack 5 `output.clean` supersedes it |
| `glob` | 329 mention files, all English (`global`, `fast-glob`); zero imports/bins | `fs.globSync` (Node 22+) era |
| `mermaid` | zero script tags / asset loads; only docs prose + a lint regex | nothing renders through it |
| `webpack-node-externals` | zero references anywhere | — |
| `yargs` | zero references anywhere | `commander` + `inquirer` are the used CLI libs |

None is native-build, so removal buys install weight only — no compile relief (that question belongs to the tier ticket). The risk is the reverse: removing something a lane still needs. That risk is what the census exists to bound.

## The Architectural Reality

- Evidence class per package is on the census comment — reproducible in seconds: `node ai/scripts/diagnostics/devDependencyCensus.mjs`.
- The instrument's zero-importer section prints mention evidence per package; the adjudication table on the ticket converts that evidence into keep/remove verdicts (the six keeps — `@fortawesome`, `monaco-editor`, `highlightjs-line-numbers.js`, `@chroma-core/default-embed`, `webpack-cli`, `webpack-dev-server` — are NOT in scope here; they have asset-path or bin-delegate consumers).
- `package.json` + `package-lock.json` are the only touched surfaces; no source file changes.

## The Fix

Remove the five rows from `devDependencies`, regenerate the lockfile, and prove the two things that could secretly consume one of them: the theme/app builds and the test suite.

One PR, one commit per package is NOT required — a single removal commit is fine (the five share one evidence class and one verification pass), but each package's removal must be named in the commit body so a bisect can isolate it.

## Acceptance Criteria

- [ ] All five rows removed from `package.json`; `package-lock.json` regenerated cleanly (no manual edits).
- [ ] `node ./buildScripts/build/themes.mjs -f -n -e dev -t all` builds clean after removal (the build is the likeliest hidden consumer — webpack plugins and CSS pipeline live there).
- [ ] `npm run build-all` or the CI-equivalent build passes after removal.
- [ ] Full unit suite passes: `UNIT_TEST_MODE=true npx playwright test -c test/playwright/playwright.config.unit.mjs` (receipt in the PR).
- [ ] Post-removal re-run of the census shows the five gone and zero NEW zero-importer packages (a removal that orphans a transitive consumer shows up here).

## Out of Scope

- `better-sqlite3`, `chromadb`, and every keep-verdict package — placement/tier questions live in the tier follow-up, not here.
- Any source-code change. If a build or test failure reveals a hidden consumer, that package is RESTORED in the same PR and the finding is reported on the census ticket — the census's verdict was wrong there, and that is a finding, not a failure.
