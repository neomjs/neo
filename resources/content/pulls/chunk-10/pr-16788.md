Resolves #16412

Both tour-reset call sites declared `geometryOnly: true` over what can be a topology change. They now derive it. A reset to the initial document is only geometry-only while the live layout still shares the initial topology — after a tear-out, split or convert, the same reset replaces nodes, and since #16403 that flag is forwarded into `DockFlip.play`, whose contract reads *"no topology swap can be pending"*. The existing guards absorbed a false declaration by accident of their own strictness, never by contract; option 1 from the ticket ("compute, don't assert") turned out to be cheap because the `dockZone.v1` diff vocabulary already ships as `DockTopologyDiff`.

Evidence: L3 (unit execution over the real `initialDocument` through the actual `runTourSpec` call site) → L3 required (the close-target ACs are all reachable through the derivation and the two call sites; no host or visual effect is claimed). Residual: none.

## Deltas from ticket

Two beyond the prescription, both found while implementing:

**Fail-closed on diff errors, which the ticket did not name.** `diffDockDocuments` gates each input through a shape walk and returns **empty categories alongside `errors`** for a malformed or cyclic document. A categories-only test — the obvious reading of "a `moves/adds/removes/tabReorders`-empty diff IS topology-stable" — would therefore report *topology-stable* for a document it could not parse, and hand the fast path to the one input least deserving of it. The derivation tests `errors` first.

**An existing spec was asserting through an unparseable fixture.** `the entry projection requests validated in-place admission` fed a `{nodes: {marker: 'live'}}` stub and asserted `{geometryOnly: true}`. That passed while the flag was a literal; with a derived flag the stub fails the shape gate and the assertion would have quietly become a statement about a broken fixture rather than about same-topology admission. I did **not** relax the expectation to match the new output — that would have pinned the bug and contradicted the test's own name. The fixture is now a real same-topology document, so the test asserts the invariant it claims, and a paired case pins the divergent half at the same call site.

## What changed

- `Workspace.isTopologyStableReset(before, after)` — a static derivation over `DockTopologyDiff.diffDockDocuments`. Topology is the four structural categories; `resizes` and `autoHideFlips` are excluded **deliberately**, because moving or hiding a node without replacing one is exactly the case the flag exists to admit. A test documents that choice so an over-strict "tighten it" edit fails loudly rather than silently costing every resize the staged shell swap.
- Both call sites capture the live document *before* the clone overwrites `me.dockModel`, then pass the derived flag.
- The `resizeSplit` derivation (`geometryOnly || operation === 'resizeSplit'`) is untouched — it was already *certain* rather than asserted.
- The `runTourSpec` comment block previously opened "The ENTRY projection **declares** `geometryOnly`". It now says derives, and states why; leaving it would have been a docblock asserting the behaviour this PR removed.
