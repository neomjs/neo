Resolves #16551

Backoff on the tenant-repo sync lane reads `consecutiveFailures` and `lastRunAttemptAt`, and both advanced only *after* the work returned. A failure that prevents the work from returning — OOM, SIGKILL, host sleep, container stop mid-sweep — therefore left no record that anything was tried: `due` stayed true and the lane retried at full cadence indefinitely. A crash loop is precisely what backoff exists to dampen, and it was the one failure class where backoff provably could not engage, because the dampening was only ever available to failures polite enough to return. This ships a write-ahead attempt record so a killed process still leaves evidence for its successor to commit.

Evidence: L2 (spec-driven contract tests driving a simulated non-returning attempt; fixture-local, no live plane) → L3 required (the original AC6 live-lane observation — a widening retry interval read from the orchestrator log after deploy). Residual: AC6 [#16551].

## The shape, and why it is a sidecar

The record cannot live in the revisions manifest. That file is a commit log and its commit-point fence is a hard contract, pinned by two sibling specs: `commit-point fence: an evicted writer aborts without writing` compares it byte-for-byte, and `renewal failure aborts before protected work` asserts it does not exist at all. Writing scheduling state into it before the work completes does not defeat a proxy for those properties — it removes the properties.

An in-flight attempt is by definition uncommitted, so it lives beside the manifest in `<revisionsFilePath>.in-flight`:

- **written** after the lease fence and before the git phase, so a repo that never entered protected work (not-due, revalidation-deferred, or lease-lost at the fence) records no attempt — matching the existing lease-lost contract that deliberately leaves backoff state untouched for the successor to own;
- **cleared** in the per-repo `finally` that success, caught failure and lease-lost abort all already pass through. Per-repo rather than one sweep-terminal truncate, because with `concurrencyLimit >= 2` a crash during repo B would otherwise fold repo A's completed attempt into a spurious failure;
- **folded** at sweep start, before the due checks, so a crashed attempt dampens the very next decision rather than one sweep later.

Commit-then-clear on recovery: a crash between the two re-folds the same attempt, over-counting one failure and dampening harder — the safe direction. Clearing first would lose it, which is the defect being fixed.

`isRepoDue` is untouched. It was always correct given honest inputs; the fix is entirely upstream of it, which the original ticket had right.

## Evolution

**Manifest-resident → sidecar.** The obvious implementation advanced the counters directly in `persistedRevisions` after `leaseGuard()`. It works, and it breaks the two `#15763` lease specs. My first reading was that those specs assert *proxies* (bytes, file existence) for the real invariant and could be restated. That was wrong: the first spec's name states the property directly — *aborts without writing* — and the manifest is a commit log whose commit-point fence is that ticket's whole subject. Writing scheduling state into it before the work completes removes the property rather than defeating a proxy. Retracting the entry on the lease-lost branch does not rescue it either: that restores the semantics but not the bytes, and needs its own durable write inside an abort path — more machinery defending a shape that was wrong to begin with. Discarded rather than committed for a reviewer to reject.

**The cap nearly hid a broken multiplier.** The first spec asserted `nextDueAt === crashedAttemptAt + 2h` with a 60min base and one failure. The configured `backoffCapMs` is also 2h — so that assertion would have passed whether the exponential term worked or the value merely hit the ceiling. Writing the N>1 spec surfaced it (8× resolved to 2h, not 8h). Both specs now run with `backoffCapMs: 0`, which is what makes them measure the multiplier instead of the ceiling. The wider AC was worth reaching for on its own; it also repaired an assertion that could not fail for the reason it claimed.
