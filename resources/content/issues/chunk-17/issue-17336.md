# A chunk that kills the embedding provider never graduates to undeliverable

## Context

Observed live on a deployment running the `openAiCompatible` embedding lane (llama.cpp server, `qwen3-embedding-0.6b`), 2026-08-18. Its container memory ceiling was set below what one admitted chunk requires, so the kernel OOM-killed the engine on the first band-sized batch. `restartCount` reached **36** in ~50 minutes with **14 unplanned restarts inside one 15-minute window**, and the knowledge base stayed at **152** vectors against a corpus of roughly 93,500 semantic units.

The ceiling itself was a deployment error and is fixed there. **This ticket is about what neo did in response, which was to retry indefinitely and then suppress every repository.** The sweep ended with `completedCount: 0`, three repositories at `backoff-suppressed` with `consecutiveFailures` of 41, 60 and 66, and `lastIngestedRev: null` — no corpus progress at all.

Separating observation from inference: the OOM attribution is inferred from memory pinned at 99.94% of cap (two authoritative `critical` evidence facts, `recoveryClass: exhaustion`), a restart count that only climbs, and container logs in which every incarnation ends mid-`launch_slot_` with no error, assertion or exit line. `inspect.state.oomKilled` reads empty because `state` describes the live incarnation, not the one that died, so the flag is not available as proof.

## The Problem

Neo already has the right disposition for this shape. #17129 built it: a chunk the current geometry cannot deliver graduates to `KB_VECTOR_EMBED_UNDELIVERABLE_AT_GEOMETRY`, stops being offered, and the corpus advances past it. `VectorService.mjs` is explicit that this is content-neutral — *"healthy content the current geometry cannot deliver"* — and deliberately distinct from a content-poison disposition.

**That graduation is gated on timeout-class evidence only.** The strike counter at [`ai/services/knowledge-base/VectorService.mjs:1450`](ai/services/knowledge-base/VectorService.mjs#L1450) increments on single-input **call-ceiling expiry**, and its own log line names the evidence: *"after N consecutive single-input call-ceiling expiries (~X tokens against a Yms ceiling)"*. #17129's title says the same thing — `ceiling-fired-twice must classify as undeliverable`.

An OOM-killed provider does not time out. It refuses the connection. We observed exactly that: `KB_VECTOR_EMBED_CONNECTION_REFUSED` on the one repository that had previously ingested, alongside `KB_EMBED_BATCH_SKIPPED` on the rest. Connection-refused accrues **no strike**, so the offending chunk never graduates, is offered again on the next sweep, kills the provider again, and the repository walks its `consecutiveFailures` up until backoff suppresses it permanently.

**The trap is structural, and it is the direct consequence of a correct rule.** `isolateFirstFailedBatch` states it plainly at [`VectorService.mjs:920-923`](ai/services/knowledge-base/VectorService.mjs#L920): *"a provider that dies during isolation therefore aborts instead of quarantining the remainder"*, reinforced at line 1011 — a dead provider *"proves nothing about content and must never be bisected into a poison disposition."* That reasoning is right for **content** poison. But a chunk too large for the provider's memory is *deterministically* the cause of the death. So the one failure mode with a single, reproducible, chunk-shaped cause is precisely the one neo is designed never to attribute to a chunk.

The result is a hole between two well-built mechanisms: the timeout path converges, the death path never does.

## The Architectural Reality

- [`ai/services/knowledge-base/VectorService.mjs:1450`](ai/services/knowledge-base/VectorService.mjs#L1450) — strike accrual, keyed on call-ceiling expiry; `undeliverableTimeoutStrikes` is the threshold.
- [`ai/services/knowledge-base/VectorService.mjs:1464`](ai/services/knowledge-base/VectorService.mjs#L1464) — `onPoisonEntries` graduation to `KB_VECTOR_EMBED_UNDELIVERABLE_AT_GEOMETRY`.
- [`ai/services/knowledge-base/VectorService.mjs:917-930`](ai/services/knowledge-base/VectorService.mjs#L917) — `isolateFirstFailedBatch`, whose contract aborts on provider death rather than quarantining.
- [`ai/services/knowledge-base/IngestionService.mjs:512`](ai/services/knowledge-base/IngestionService.mjs#L512) — `KB_EMBED_BATCH_SKIPPED`, raised once retries are exhausted; a skipped batch is correctly reported as a hole rather than a clean run.
- The `tenant-repo-sync` scheduler consumes the failure as a repo-level `consecutiveFailures` increment; per-repo backoff is `2^consecutiveFailures × cadence` capped at 30 minutes, from persisted state.

The distinction this ticket needs is **provider death that reproduces against one isolated input under a freshly recovered provider**. That is not ambient provider instability, and it is not a content claim — it is evidence about deliverability at the current geometry, which is exactly what `UNDELIVERABLE_AT_GEOMETRY` already means.

## The Fix

Admit a second, death-class evidence path into the same graduation, with a discriminator strict enough to preserve the existing content-neutrality rule:

1. Classify provider death (connection refused, socket reset, unexpected EOF mid-request) as its own failure class, distinct from both timeout and provider-refusal.
2. Accrue a strike **only** when a single-input dispatch kills the provider *and* the provider subsequently returns healthy — the recovery is what makes the correlation attributable rather than ambient. A death with no recovery remains unattributable and must keep today's abort behaviour.
3. On reaching the threshold, graduate the suspect to `KB_VECTOR_EMBED_UNDELIVERABLE_AT_GEOMETRY` with the existing receipt shape, so the corpus advances and the disposition still says *geometry*, never *content*.
4. Surface the death-class strike count in the ingestion summary so an operator can see convergence happening instead of watching `consecutiveFailures` climb with no explanation.

## Decision Record impact

`none` — this extends a disposition #17129 established rather than challenging any ADR.

## Acceptance Criteria

- [ ] A single-input dispatch that kills the provider, followed by provider recovery, accrues a death-class strike against that input.
- [ ] A provider death with **no** subsequent recovery accrues nothing and preserves today's abort-rather-than-quarantine behaviour (regression guard on the `VectorService.mjs:920` contract).
- [ ] At threshold, the suspect graduates to `KB_VECTOR_EMBED_UNDELIVERABLE_AT_GEOMETRY` with a receipt, and is no longer offered until the embedding generation changes.
- [ ] A corpus containing one provider-killing chunk completes ingestion of every other chunk in the same sweep — asserted on kind and count, not merely on absence of error.
- [ ] Death-class strike progress appears in the ingestion summary.
- [ ] Red-proof: a fixture whose oversized input kills a stubbed provider must fail on `main` by never graduating, and pass after the change. The stub must reproduce **death**, not timeout — a timeout fixture would pass on `main` and prove nothing.

## Out of Scope

- Changing batch sizing or adaptive stride. That is #16972, which is narrowed to isolation rate and gated on first-ingest evidence.
- The deployment's memory ceiling, which is a deployment concern and already corrected there.
- Any change to content-poison classification.
- The recovery actuator's action set — separate ticket.

## Avoided Traps

- **Do not widen the timeout strike counter to "any failure".** That would let ambient provider instability graduate healthy chunks to undeliverable and silently shrink the corpus. The recovery-confirms-correlation requirement is what keeps the evidence attributable.
- **Do not classify this as content poison.** `VectorService.mjs:1011` is right; a dead provider says nothing about whether the bytes are valid. The disposition must remain *geometry*.
- **Do not treat the container's restart count as the trigger.** Neo cannot see it in the general case, and a deployment may not restart at all — the evidence has to come from the request path.
