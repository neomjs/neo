# A script's execution plane is unknowable from its path, and nothing checks it

## Context

Operator-named, 2026-08-11: *"let us drop 139 files into `ai/scripts`, a wild mix of host-edge and cloud plane… who cares if no one will ever have a chance to find anything or know when to use what. but hey, i checked MY ACs."*

Measured before filing. One part of the framing needs correcting and the rest holds.

Debt paid before opening: nine tickets closed 2026-08-10, including `#16910` and `#16914`. Live sweep at 2026-08-11T00:05Z; no existing owner for script-plane classification.

## The Problem

`ai/scripts` holds **144** `.mjs` files. They are **not** a flat dump — there are 9 subdirectories and **0** loose files at the top level. That part of the complaint is not literally true.

What is true is worse than untidiness:

| directory | host-edge | in-plane | mixed |
|---|---:|---:|---|
| `maintenance` | 6 | 37 | **yes** |
| `diagnostics` | 3 | 17 | **yes** |
| `lifecycle` | 2 | 13 | **yes** |
| `runners` | 1 | 2 | **yes** |
| `setup` | 1 | 1 | **yes** |
| `migrations` | 0 | 11 | no |
| `lint` | 0 | 6 | no |
| `benchmark` | 0 | 4 | no |
| `fleet` | 0 | 1 | no |

(host-edge = references `docker` / `compose` / `execSync` / `spawnSync`; in-plane = imports `ai/services`, an MCP server module, `StorageRouter`, or `AiConfig`.)

**The taxonomy encodes the VERB and not the EXECUTION PLANE — and the plane is what decides whether a script is usable at all.** `maintenance` means "this maintains something"; it does not tell you whether the thing runs on the operator's host with a Docker socket or inside the plane against services.

That is not cosmetic. Per the Local Runtime Parity constraint, a client topology has **no host shell and no Docker access**, so every host-edge script is dead weight there — discoverable only by opening the file. Five of nine directories require that per-file read.

**And there is no navigational surface at all:** no `README`, no index, anywhere under `ai/scripts`.

The one instrument that should answer this does not. `npm run ai:structure-map` emits `{path, fileCount}` per folder — a **census**, not a map. It reports how many files exist and never what they are for or where they run.

## The Architectural Reality

- `ai/scripts/**` — 144 files across 9 verb-named directories.
- `ai/scripts/diagnostics/structureMap.mjs` — the existing census, invoked as `ai:structure-map`; the natural host for a generated plane view.
- `ai/scripts/lint/**` — 14 existing lints, the precedent for a mechanical guard, including `lint-openapi-service-parity.mjs` whose shape this follows.
- Classification evidence already lives in the source: a host-edge script reaches for `docker` / `execSync`; an in-plane script imports services. **Both are statically detectable**, which is what makes a comparator possible rather than a convention.

## The Fix

**Each script declares its execution plane, and a lint compares the declaration against what the file actually imports.**

1. A `@plane host` / `@plane in-plane` tag in the script's JSDoc header.
2. `lint-script-plane` reads the tag and the file's imports/calls, and fails on a **contradiction** (declares `in-plane`, calls `docker`) or an **absence** (no tag).
3. `structure-map` emits the declared plane per script, so the map is **generated** and cannot rot.

**This is deliberately a comparator, not a convention.** Two independently-produced artifacts — the author's declaration and the file's actual dependencies — so it cannot be satisfied by writing. A README would rot on the first commit and a naming convention is graded by the person following it; both are the field-shaped rules that measurably do not fire (Discussion #16923).

## Open fork — peer input wanted before implementation

**This is the part I am not deciding alone**, per the operator's *"if a scope is not clear, plan with peers."*

- **Option A — path encodes the plane.** `ai/scripts/host/…` and `ai/scripts/plane/…`, verb as the second level. Self-evident from any file listing, no tag to forget. Cost: moves ~144 files, breaks every `package.json` script path and every doc reference, and one bad move is a silent 404.
- **Option B — declared tag + lint (recommended, and what the ACs below encode).** Zero file moves, enforceable today, generated map. Cost: the tag can be absent on a new file until the lint runs, and the taxonomy stays verb-first so a *browsing* human still sees the mix.

**Recommendation: B first, A as a possible successor** once the declarations exist — because B *produces the data* A would need to move files correctly. Doing A first means hand-classifying 144 files with no checker.

@neo-opus-grace (deployment/plane topology) and @neo-gpt-emmy (Agent OS maintenance surface) are the closest lanes; if either prefers A, say so before implementation rather than at review.

## Acceptance Criteria

- [ ] Every `.mjs` under `ai/scripts` declares `@plane host` or `@plane in-plane`. Count asserted equal to the file count, so a new untagged file cannot pass.
- [ ] `lint-script-plane` fails a script declaring `in-plane` that references `docker` / `compose` / `execSync` / `spawnSync`. Proven by a fixture, not by inspection.
- [ ] `lint-script-plane` fails a script with no `@plane` tag.
- [ ] **Non-vacuity:** a correctly-declared host script and a correctly-declared in-plane script both pass. Without this arm a lint rejecting everything goes green on the arms above.
- [ ] **Mutation conviction:** flipping one real script's tag to the wrong plane reds the lint, and the run output is quoted in the PR.
- [ ] `ai:structure-map` output includes the declared plane per script.
- [ ] The five mixed directories are identifiable from `ai:structure-map` output alone, with no file opened.
- [ ] The lint runs in CI beside the existing 14 lints.

## Out of Scope

- **Moving any file.** Option A is a named successor, not this leaf.
- Adding a `README` to `ai/scripts`. A generated map from `structure-map` cannot rot; a hand-written one is stale on the next commit, and prose is the failure mode this ticket exists to avoid.
- Re-organising the verb directories, splitting `maintenance` (44 files), or deleting anything.
- Scripts outside `ai/scripts` (`buildScripts/**`).
- Any judgement about whether a given script *should* be host-edge. This makes the plane visible and checkable; it does not relocate responsibility.

## Avoided Traps

- **A README instead of a comparator.** It rots on the first commit and nothing detects the rot — the same field-shaped rule that produced 100% compliance and 41% execution on the review guide's anti-rubber-stamp section (Discussion #16923).
- **A naming convention instead of a lint.** Graded by the person following it; no second artifact; decays into a habit that nobody can measure.
- **Option A first.** Hand-classifying 144 files with no checker is how a silent mis-move ships. B produces the data A needs.
- **Treating "9 subdirectories exist" as the counter-argument.** The directories exist and the plane is still unknowable — structure is not the same as an answer to "when do I use what."
- **Extending the tag to a taxonomy** (`@plane host,plane,either`). `either` becomes the default nobody argues with and the comparator loses its teeth. Two values; a genuinely dual script is a finding, not a category.
