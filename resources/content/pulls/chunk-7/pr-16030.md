Resolves #16027

Related: #15931

This PR removes the cwd-relative heavy-maintenance lease fallback and makes the configured orchestrator data root authoritative across the reusable lease service and all seven operator-runnable heavy-maintenance scripts. Pure primitives remain config-free and now fail before filesystem access when no explicit path authority is present; config-aware boundaries resolve the active `AiConfig.orchestrator.dataDir` at use time.

Evidence: L2 (focused unit filesystem, inheritance, source-contract, and seven-caller census witnesses) → L2 required (AC1–AC8; the close target explicitly excludes running heavy jobs against live data). No residuals.

## Contract delivery

| Surface | Authority | Delivered behavior |
| :--- | :--- | :--- |
| Heavy-maintenance lease primitives | Explicit `leasePath`, or an injected absolute `dataDir` for the shared resolver | No cwd-relative default; missing or relative fallback authority fails before filesystem I/O |
| `HeavyMaintenanceLeaseService` | Current `AiConfig.orchestrator.dataDir` at each operation | Explicit `leasePath` wins; otherwise the current configured root resolves `heavy-maintenance-lease.json` without module-load capture |
| Seven manual/script callers | Existing config-aware script boundary | Each caller passes the resolved configured path alongside its existing owner, TTL, and held/error semantics |
| Inherited-token cascade | Parent and child use the same resolved lease path | A relocated-root child recognizes the parent token and does not acquire a second lease |
| Operator guidance | Active orchestrator configuration | The Sandman incident guide points to the configured data directory, not a cwd-relative literal |

## Deltas from ticket

- Explicit caller-owned `leasePath` values remain verbatim for backward compatibility; only the `dataDir` fallback is required to be non-empty and absolute.
- The ticket proposed mutating the configured root in a service test.
