## Context

Phoebe's [non-author D#15673 challenge](https://github.com/neomjs/neo/discussions/15673#discussioncomment-17733084) proposed measuring the next three profiled publishing packages instead of settling production economics by intuition. The Build Week film proves that a strong package can be valuable, but its multi-day production lane is also a warning against universalizing an unmeasured cost curve.

This ticket is separate from the cover and package-contract reservations because its closure horizon spans three later publications. It reuses the reach-contract work in [#14841](https://github.com/neomjs/neo/issues/14841) and the corrected measurement/direction split in [#10120](https://github.com/neomjs/neo/issues/10120); it does not invent another analytics subsystem.

## The Problem

Without comparable receipts, the first successful package becomes folklore: later agents remember that video and covers “gain traction” but forget how long they took, how many correction cycles were bespoke, which assets were reusable, and whether public reach was defensible. Conversely, one expensive film can make us reject a package form whose marginal cost would fall after reusable substrate lands.

A retrospective Memory Core query is not enough. The observations need a declared window, stable package identity, bounded production measures, confounds, and links to the existing reach evidence so that both “this scales” and “this backfires” can be falsified.

## The Architectural Reality

- #13383 owns the blog stream and explicitly distinguishes production from reach.
- #14841 defines a falsifiable per-demo reach shape with stable identity, window, value, query, confound disclaimer, and provenance.
- #10120's convergence correction separates measurement producers from operator-owned direction; raw deficits must not silently mint priorities.
- D#15673 has not selected universal, profiled, or opt-in packaging, so this ticket cannot yet define its final cohort.
- The measurement record is a consumer of accepted package receipts; it must not become the package coordinator or a second artifact SSOT.

## Reservation-Era Recommendation (superseded)

Observe the **first three graduated, profiled publication packages** with a compact comparable record: package/profile ID, artifact set, elapsed and active production time, paid/provider cost when observable, correction cycles by class, reused versus bespoke assets, gate bypasses, publication links, reach-metric references, confounds, and a falsifier verdict. Re-audit the package/skill boundary after package three or earlier after two repeated bypasses.
