# Embed-path clocks are set independently with no ordering contract, so inner budgets silently invert against outer deadlines

## Problem

The embedding path stacks at least six independently-configured clocks: the single-input contention ladder (15s×3), `batchEmbeddingTimeoutMs`, the KB health probe deadline (300s), the MC write canary deadline (900s-class), the embedding recovery probe cadence, and the tenant-sync sweep cadence. Nothing derives or validates their ordering. Two shipped incident mechanisms are clock inversions: the contention ladder preempting outer probe deadlines (~47s effective vs 300s/900s declared), and the #17049 class (consumer freshness bound below producer cadence). Each was found by manual trace after shipping.

## Acceptance Criteria

1. One derivation contract (single module or leaf family, ADR-0019-compliant) that orders every embed-path clock: inner retry ladders < outer probe deadlines < caller ceilings < sweep cadences, each with an explicit margin.
2. Boot-time (or config-load) validation refuses an inverted configuration with a typed diagnostic naming both clocks — never a silent runtime preemption.
3. The contract enumerates its consumer clocks in one table (code-adjacent, greppable) so a new clock cannot be added outside it silently.
4. Spec matrix over the orderings, including the two shipped inversions as regression fixtures.

## Evidence class

Source-bound leaf inventory (`ai/configBase.mjs`) + two independently-traced production inversions (2026-08-14). Generalizes the #17049 finding; complements #17115's template projection.

Part of epic #17072.

## [TICKET_INTAKE] Close as not planned — the proposed total order is not a valid runtime contract

I traced the exact `origin/dev` caller graph before implementation. The incident evidence is real, but this ticket combines three different clock relations and assigns them one ordering that cannot represent their authorities.

### The acceptance order contradicts the stated incident

AC1 requires:

```text
inner retry ladder < outer probe deadline < caller ceiling < sweep cadence
```

The problem then identifies the shipped `~47s < 300s/900s` relationship as the inversion. Those are the same ordering. The runtime defect is not that the inner ladder lacks a smaller configured value; it is that the hidden inner aggregate horizon replaces the caller-owned deadline at all.

That behavior has a direct owner in #17111: deadline-bearing single-input calls must remain governed by the caller's declared deadline and signal, without multiplying one budget into an abort/retry storm. Once that lands, there is no independent inner-horizon ordering for this ticket to validate.

### The remaining clocks are not one nesting hierarchy

- Producer cadence vs consumer receipt validity is a freshness relation: validity must cover producer cadence plus margin. Reopened #17049 owns the exact false-green instance.
- Probe deadlines are attempt bounds. Sweep cadences schedule future attempts and can be independently single-flight/backed off; they are not necessarily outer request deadlines.
- Template visibility is separately owned by #17115 / PR #17117, including mechanical projection coverage.

A single cross-process boot module cannot authoritatively validate all of these without importing unrelated KB, MC, and Orchestrator policies into a new duplicate authority. That would add a master clock framework while leaving the actual defects in their existing owners.

### Disposition

Close #17114 as **not planned**. No tracked code was written.

The useful work continues in the concrete owners:

- #17111 — remove the hidden single-input aggregate horizon in favor of caller authority;
- #17115 / #17117 — project and mechanically cover behavior-binding leaves;
- #17049 — repair the producer-cadence / consumer-freshness false-green contract.

If a future incident exposes a fourth relation not covered by those owners, revive this discussion around a **directed, relation-specific invariant**, not a universal total order.
