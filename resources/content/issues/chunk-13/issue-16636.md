# raise-ceiling is reachable only by stores, and sanctioned by no ADR

Split out of #16630 after PR #16634 shipped 8 of its 10 ACs. This is the **act half**: #16630 made the ceiling declared and measurable, and this makes the immune system *do* something about it.

## Context

PR #16634 closed #16630's detect half — both MCP servers declare a `command:`-scoped `--max-old-space-size`, the `memory-saturation` denominator became `min(containerLimit, declaredHeapCeiling)` for the service class, and ADR-0025 §2.4 carries the amendment. Two ACs did not ship, and the reason recorded on that PR was **wrong in a way worth stating plainly**, because the wrong reason is the one a future reader would inherit:

> *"Extending it changes what the actuator does to a live container, which is the highest-risk item in the ticket."*

**That is false.** Verified after the fact: `raise-ceiling` has **no actuator implementation anywhere**. It is a diagnosis-side label that nothing consumes. Routing a service to it today would change which string a recorded diagnosis carries and nothing else. The real blocker is the opposite of high-risk-action — it is that the action does not exist yet at the acting end, and the ADR that governs the action set does not list it.

## The Problem

### 1. `raise-ceiling` is an action class with no actuator, and ADR-0026's matrix does not list it

| probe | result |
|---|---|
| `grep -rn 'raiseCeiling' ai/ --include='*.mjs'` | 2 hits, both in `ContainerHealthDiagnosisService.mjs` (`:22` declaration, `:729` the single prescribing site) |
| `grep -rn 'raiseCeiling' learn/` | **0 hits** — absent from every ADR, including ADR-0026 §2.4's admitted-action matrix |
| `grep -n "'raise-ceiling'" ai/` | only the enum entry — **no heal operation, and it is not in `HEAL_ACTIONS`** (`ai/services/memory-core/helpers/healActionDispatch.mjs:30`) |
| the same probe for `throttle-shed` | enum entry **plus** `createThrottleShedHealOperation` (`Orchestrator.mjs:652`) **plus** membership in `HEAL_ACTIONS` |

So `throttle-shed` is a wired action and `raise-ceiling` is a recommendation nobody implements. ADR-0026 §2.4's matrix, amended 2026-08-02 by `#16374` to be per-target-kind, admits `restart`, `warm-provider`, `reconfigure` and `redeploy` — and explicitly records which listed actions are unimplemented (`recycle`, `throttle`, `shed`) so *"a reader of this section must be able to tell which of the listed actions they can actually call."* `raise-ceiling` is not in that list at all, which means it fails the section's own stated purpose: it is callable-looking in code and invisible in the ADR.

**This is a pre-existing gap, not one PR #16634 introduced.** It arrived with the store-ceiling diagnosis and has simply never been exercised, because nothing acts on a diagnosis label.

#### ⏱ Time-bounded: PR #16638 gives `raise-ceiling` an actuator for the STORE variant. Read the two tables above as "true at filing, 2026-08-07T14:09Z."

@neo-fable-clio shipped the store-side actuator within the hour (PR #16638 / #16637, a leaf sub of #16596): `RECOVERY_KNOBS` gains `container-memory-ceiling` with a derived 8–16 GiB band, the L0 lifecycle-write set gains `update-memory-limit` for a live cgroup move, and `RecoveryActuatorService` gains a store-variant executor whose **omission of `restartComposeService` is the contract** — mutation-proven, re-adding it reddens the centerpiece spec. She also folded **one disclosure sentence into §2.4** covering this class.

Consequences for this ticket, all narrowing it:

- *"`raise-ceiling` has no actuator implementation anywhere"* stops being true on that merge. The remaining gap is the **service** variant, and the store executor is now the shape to follow rather than a thing to invent.
- **AC-1's disclosure half is already closed** by her §2.4 sentence. What remains here is the mechanical **guard** so the next unaccounted class cannot ship silently — a guard is what makes a disclosure durable, and the disclosure is what makes the guard passable today.
- Her store executor raises a **cgroup memory limit** on a running container. A Node service's wall is its **V8 heap ceiling**, which is a process-start argument and cannot be moved live — so the service variant is *not* a parameter swap on hers. It has to mutate the declared ceiling in the durable overlay and then restart, i.e. exactly the `reconfigure` = mutate+restart row of the two-row split, whereas hers is the mutate + live-activate row. **The two-row distinction I handed her in #16596 is what separates these two, and this ticket is the other row.** Worth stating because "reuse Clio's executor" is the obvious wrong first move.

### 0. Superseding scope note: no controller consumes container-health decisions for ANY action class

Independently probed and confirmed from both sides — mine here, and Clio's on #16596, which reports *"the genuinely-global gap the probe confirmed: NO reactive controller consumes container-health decisions for any action class yet — that's a design lane, not a leaf."* Two probes, same conclusion, arrived at separately.

That reframes what "reaches `raiseCeiling`" can mean in AC-2 below, and the AC is written accordingly: this ticket makes a service-class exhaustion **prescribe** `raiseCeiling` in its recorded diagnosis. It does **not** connect that prescription to an actuator, because no such connection exists for any class and building one here would be a controller design smuggled in as a routing fix. **That design lane is explicitly out of scope** and belongs where Clio put it — with the parent, not a leaf.

Stated up front because the ticket title reads like an act-half ticket and half of "act" is not available yet to any class.

#### Amended on filing day — it is TWO of five, and checking the siblings is what found the second

Filed naming `raise-ceiling` alone. Running the same probe across all five action classes — the *"fix the class, not the reported instance"* check — found a second, and its shape is the inverse:

| action class | in `learn/agentos/decisions/` | lifecycle actuator operation |
|---|---|---|
| `record` | 219 hits | n/a, terminal |
| `restart` | 78 hits | yes |
| `warm-provider` | 6 hits | yes |
| `throttle-shed` | **0** | **none in the lifecycle world** |
| `raise-ceiling` | **0** | **none anywhere** |

`throttle-shed` is not simply undocumented. ADR-0026 §2.4 states *"`recycle`, `throttle` and `shed` remain specified but UNIMPLEMENTED — no consumer exists"* — while `createThrottleShedHealOperation` (`ai/services/memory-core/helpers/throttleShedHeal.mjs:30`) is fully implemented and registered at `Orchestrator.mjs:652`. That implementation is **collection-keyed** and lives in the **data-recovery** actuator's operation map beside `quarantine` / `freeze` / `restore-empty-target` — ADR-0027's world, not ADR-0026's. So the ADR is right that the *lifecycle* actuator has no throttle/shed, and `ContainerHealthDiagnosisService:739` nonetheless prescribes `throttleShed` for **container** resource exhaustion, where the only implementation takes a collection.

**The generous reading is probably the correct one, and it is why this is a reconciliation rather than a bug hunt:** ADR-0026 §2.2 gates the B1 container-lifecycle consumer on a separate sub (`#13884` / `#13915`), so these classes are plausibly forward declarations for a consumer not yet wired. That is a legitimate state. What is not legitimate is that §2.4 was amended by `#16374` *specifically* so **"a reader of this section must be able to tell which of the listed actions they can actually call"** — and two of the five the diagnosis emits are not in that section at all. The section cannot do the job it was amended to do.

Which is why AC-1 below is the **general** guard over all five rather than a fix for `raise-ceiling`. One instance was visible; the second only appeared because the siblings got the same probe.

### 2. A service at its ceiling still has no route

`ContainerHealthDiagnosisService.mjs:726` gates the only `raiseCeiling` prescription on `storeMemoryFacts.length > 0`, and those facts are filtered by `isStoreBackedService(fact.serviceKey)`. `mc-server` and `kb-server` are `SERVICE_CLASSES.transient` in `SERVICE_CLASS_BY_KEY` (`:58-59`), so a service crossing the ceiling that just became measurable falls through to `resource-exhaustion` → `throttleShed`.

**And for a service, `throttle-shed` is not obviously wrong** — which is the part #16630's AC stated too flatly. A Node service's heap is process-local, so a restart genuinely frees it; unlike a store, whose footprint tracks rows already persisted. The store rationale at `:700-719` does not transfer. What makes `mc-server` a raise-ceiling case is narrower and it is measurable: **it died at a self-imposed wall with ~460 MiB of its own container allowance unused.** Raising is only coherent when headroom exists inside the container budget.

### 3. The undeclared-ceiling record has no home, and the failing tests are the finding

I implemented AC-4 during #16630 and reverted it. Emitted as a health fact it appeared in `evidenceFacts` and broke 3 existing assertions — while the comment I had written beside it claimed it *"must never contribute to a heal decision."* The comment was false the moment it was written, and the 3 failures are why.

The mechanism is visible in the code: `selectEvidenceFacts(facts, <class-specific>)` is called with the **whole** `facts` array at every classification branch (`:676`, `:691`, `:731`, `:741`, `:752`, `:780`), so any new member of `facts` is a candidate piece of evidence for every existing class. A statement about *observability* ("this service's saturation is unmeasurable") is the wrong shape for that array, and adding it there is not a smaller version of the right change — it is a different one.

## The Architectural Reality

- `ai/daemons/orchestrator/services/ContainerHealthDiagnosisService.mjs:22` — the `raiseCeiling` action-class constant.
- same file, `:720-734` — the store-gated prescription; `:736-744` — the `throttleShed` fallthrough a service reaches instead.
- same file, `:54-61` — `SERVICE_CLASS_BY_KEY`; `kb-server` / `mc-server` are `transient`, `chroma` is `store`.
- same file, `:1096` (post-#16634) — `parseDeclaredHeapBytes`, which already yields the second term the headroom condition needs, and `null` when undeclared, which is exactly the undeclared signal.
- `ai/services/memory-core/helpers/healActionDispatch.mjs:30` — `HEAL_ACTIONS`, the wired-action list `raise-ceiling` is absent from.
- `ai/daemons/orchestrator/Orchestrator.mjs:652` — `createThrottleShedHealOperation`, the shape a `raise-ceiling` operation would follow.
- `ai/daemons/orchestrator/services/DeploymentStateBridgeService.mjs:80` — *"No public route, socket mount, shell, or write actuator is introduced"*, and `:476` — the `deployment-state-bridge-diagnostics` record type. The bridge is the observe path; `:772` states it must not perturb what it observes. A candidate home for the undeclared-ceiling signal that is not the health-fact array.
- `learn/agentos/decisions/0026-recovery-actuator.md` §2.4 — the per-target-kind action matrix and its explicit unimplemented-action disclosure; AC-9 forbids widening the closed action set via an implementation sub.

## The Fix

1. **Admit `raise-ceiling` into ADR-0026 §2.4's matrix, or delete it from the code.** Those are the only two honest states; an action class that exists in the enum and in no ADR is the condition §2.4 was amended to prevent. Deciding this first is what makes the rest reviewable, because it fixes whether this ticket is extending a sanctioned action or documenting an unsanctioned one.
2. **Route service-class ceiling exhaustion on the HEADROOM condition, not on the service class alone.** A non-store memory-saturation fact whose denominator was the *declared heap ceiling* (i.e. `declaredHeapCeiling < containerLimit`) means the process is dying at a self-imposed wall with room above it → `raiseCeiling`. A service whose declared ceiling is at or near the container limit has nothing to raise into → the existing `throttleShed` path, unchanged. Derived from evidence the facts already carry rather than from a caller-supplied hint, matching the discipline the store branch states at `:702-704`.
3. **Give the undeclared-ceiling signal a home outside `facts`.** The bridge's diagnostics record is the leading candidate: it is an observability channel, already exists, and cannot reach `evidenceFacts` by construction. Whatever is chosen, the AC below asserts the negative — it must not appear in any classification's evidence.
4. **The existing store route is asserted unchanged**, as a control, so the new branch cannot silently capture `chroma`.

## Acceptance Criteria

- [ ] ADR-0026 §2.4's matrix accounts for **every** member of `CONTAINER_HEALTH_ACTION_CLASSES` — either admitted for a target kind, or explicitly disclosed as unimplemented the way `recycle`/`throttle`/`shed` already are. Asserted by a spec over a curated enum→matrix mapping, **not** a grep: the ADR spells `throttle` and `shed` separately while the enum carries one hyphenated `throttle-shed`, so an exact-string guard would report a divergence that is only a naming difference. The guard is the general one, so the next unaccounted action class cannot ship the same way.
- [ ] Service-class ceiling exhaustion **is prescribed** `raiseCeiling` in its recorded diagnosis — *prescribed*, not actuated, per §0 above — and **only when the declared ceiling is below the container limit**. Asserted with a fixture at a declared ceiling under the limit (prescribes `raiseCeiling`) and a control at a declared ceiling equal to the limit (stays `throttleShed`), so the headroom condition is what fires rather than the service class.
- [ ] The existing `store-ceiling-exhaustion` route is asserted **unchanged** — same reason, same action class, same confidence — as a control.
- [ ] A Node service with **no** declared heap ceiling produces an `undeclared-ceiling` record naming the service; `record`-terminal, no action, no privilege, no restart.
- [ ] That record is asserted **absent from `evidenceFacts` for every classification branch**, not merely absent from one. The #16634 revert failed because the fact array feeds every branch, so the negative has to be universal to mean anything.
- [ ] **Negative control:** a service comfortably inside both ceilings produces neither the record nor a saturation fact.
- [ ] ADR-0025's `Amended` row gains the undeclared-ceiling condition alongside the effective-ceiling denominator line PR #16634 added.
- [ ] Mutation-verified: each new guard is shown to fail when the behaviour it asserts is removed, with the mutation's application proven rather than assumed (a silent no-op substitution exits 0 — `#16630`'s own near-miss).

## Out of Scope

- **The declared ceilings and the denominator** — shipped in PR #16634. This ticket does not revisit them.
- **A `raise-ceiling` executor for the SERVICE variant.** The store variant landed in PR #16638 as a live cgroup move. A service's wall is its V8 heap ceiling — a process-start argument that cannot be moved live — so the service executor is a mutate-the-overlay-then-restart operation, the *other* row of #16596's two-row split. It is a B1-privilege change on a restart path and deserves its own pass rather than riding a routing ticket. Filing it here would also make this ticket depend on the controller that §0 says does not exist.
- **The reactive controller that would consume any container-health decision.** §0: none exists for any action class, both probes agree, and it is a design lane held with #16596's parent. Building one inside a routing fix is how a controller ships without a design review.
- **Whether ~560 MiB was a leak or a bounded working set** — #16463's question. Raising a ceiling to hide unbounded growth converts a fast failure into a slow one, so a `raiseCeiling` recommendation is not a verdict that the growth is legitimate.
- **Chroma's ceiling** — #16595 / #16596.
- **Lowering the restart-churn threshold from 3** — rejected in #16630 and still rejected: a heap abort is authoritative at n=1 and the defect was never the threshold.

## Avoided Traps

- **Routing every service-class exhaustion to `raiseCeiling`.** This is what #16630's AC-5 said literally, and it is wrong: a service with no headroom above its ceiling cannot be healed by raising it, and a Node process's heap — unlike a store's resident corpus — genuinely is freed by a restart. The condition is headroom, not class.
- **Emitting the undeclared-ceiling signal as a health fact** because it is the smallest diff. Tried in #16630, reverted; the 3 broken assertions are the evidence, and `selectEvidenceFacts` receiving the whole `facts` array is the mechanism.
- **Amending ADR-0026 concurrently with #16596.** Two PRs editing the same matrix section is a merge conflict in the worst place — the document that sanctions what the actuator may do.
- **Treating `raise-ceiling`'s presence in the enum as evidence it is a sanctioned action.** It reads as sanctioned precisely because it is spelled like its wired siblings. The falsifier was one grep against `learn/`.
