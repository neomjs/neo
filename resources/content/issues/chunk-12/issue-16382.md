# Detect miniSummary generation-timeout starvation and name the binding timeout

## Context

The ADR-0025 detect half of `#14418`'s homeostatic window controller, carved out as a deliverable leaf so a complete producer has an honest close-target. Consumes the branch counters shipped by `#16377`.

`#16223` measured the live cost on a CPU-only deployment: ~43 pending memories × ~20s of generation each, every ~19 minutes, around the clock — ~2.3 CPU-cores burned for days producing zero summaries. Nothing in the system reports that as a fault, because the Memory Core answers A2A and persists memory throughout: by `ADR-0025 §2.1`'s own definition it is healthy.

## The Problem

**Nothing turns "the loop is processing rows and completing none" into a diagnosis a controller can consume.** The backfill reports its tallies to a log line and returns them to its caller; no producer converts a window of those into the `recovery-diagnosis` the actuator's controller interface expects.

Two properties make this harder than a threshold:

**It is a model-dependent canary.** `ADR-0025 §2.4` is explicit that such a signal *"classifies as contention / degraded first, never restart now"* — the anchoring example is the embedding canary that false-fails while the service is functionally fine. Summary generation depends on the chat model, so starvation here is saturation, not liveness. A producer that emitted `crash` would invite a restart that fixes nothing and costs an outage.

**The failure branch is not stable.** The path has two nested timeouts — `generateMiniSummaryTimeoutMs` fires *inside* `buildMiniSummary`, whose `try/catch` swallows it into a falsy return; `miniSummaryTimeoutMs` wraps the call from *outside*, so its rejection escapes to the sweep's `catch`. **Which branch a failure lands on is a function of the window a controller moves.** A diagnosis built on totals alone goes blind at exactly the boundary an adaptive controller actuates toward — and a detector whose blind spot correlates with the actuator's activity reads healthy under load, which is worse than no detector.

## The Architectural Reality

- `ai/daemons/orchestrator/services/` — five existing pure `*Diagnosis.mjs` producers (`dataIntegrityCoverageDiagnosis`, `vectorCountMonotonicityDiagnosis`, `sqliteIntegrityDiagnosis`, `dimensionConsistencyDiagnosis`, `storeBloatDiagnosis`). Sibling-lift placement; no novel directory.
- `ai/services/memory-core/helpers/recoveryRunStateStore.mjs` — `createRecoveryDiagnosisEvent` + the `RECOVERY_CLASSES` enum, which already contains `contention`.
- `ai/services/memory-core/MemoryService.mjs` — the pass result, carrying `failedInner` / `failedOuter` since `#16377`.
- `ADR-0025 §2.1` (detect-signal ≠ actuator-authority), `§2.4` (false-positive-safe detect model).

## The Fix

A pure producer mirroring the sibling shape: injected samples, no I/O, `null` when clean.

- Emits `recoveryClass: 'contention'`, never `crash`.
- Requires starvation **sustained** across a window — a single starved pass is advisory per `§2.4`.
- Carries the per-pass branch split as evidence, and a `dominantBranch` verdict naming which timeout boundary the failures are hitting.

## Decision Record impact

`aligned-with ADR-0025` — implements its detect half for a new signal; changes no ADR authority. Consumed by `ADR-0026`'s controller interface without extending it.

## Acceptance Criteria

- [ ] A sustained starved window yields a diagnosis with `recoveryClass: 'contention'` — never `crash`, per the model-dependent-canary rule.
- [ ] A single starved pass yields `null`; the sustain threshold is configurable and defaults to a value > 1.
- [ ] Any pass in the window that completed work suppresses the diagnosis entirely.
- [ ] Processed rows failing for non-generation reasons (missing content) do not read as starvation.
- [ ] `dominantBranch` reports which timeout boundary is binding, and a **tie resolves to `outer`** — an ambiguous window must not read as "widen the inner leaf", which is the move that silently flips every item to the other branch.
- [ ] Evidence carries the per-pass split so a consumer can see a flip across the window, not just its endpoints.
- [ ] Missing `serviceId` or a non-finite `observedAt` throw rather than emitting a shapeless diagnosis.
- [ ] The producer performs no I/O, no widening, and no actuator call — detect-only by construction.

## Out of Scope

- The controller that consumes this and selects an action (`#14418`).
- The actuation itself (`#16374`'s `reconfigure`).
- **Scheduling** — wiring this into the diagnostics daemon's sweep, exactly as `#14075` shipped the pure producer and deferred scheduling to `#14026`.
- The multi-fact gate: `§2.4` gates *authoritative actions*, not records, so combining this with a resource fact is the controller's job.

## Avoided Traps

- **Do not emit `crash`.** `§2.1`'s embedding-canary precedent is exactly this shape; a restart on a model-contention signal is a self-inflicted outage.
- **Do not diagnose from a single pass.** A momentary provider spike is not saturation.
- **Do not resolve a branch tie toward `inner`.** The optimistic reading is the one that produces the silent branch flip.
- **Do not fold scheduling in.** The sibling producers are pure precisely so they are testable without a daemon.

## Amended per the terminal D+S on PR #16383 — this ticket now DEPENDS on typed failure causes, and `dominantBranch` as a timeout verdict is withdrawn

@neo-gpt-emmy's Drop+Supersede established that this ticket's central prescription is not implementable from the surface it cites. Verified at source before accepting; PR #16383 closed unmerged.

### What was wrong

`failedInner` / `failedOuter` answer **"which control-flow branch executed"**. This ticket prescribed a `dominantBranch` verdict meaning **"which timeout bound is binding"**. Those are different propositions, and `buildMiniSummary` destroys the second one frame earlier:

| line | condition | returns |
|---|---|---|
| `:1648` | no model | `null` |
| `:1672` | empty output | `null` |
| `:1674-1676` | **any** caught error, including the inner timeout | `null` |

So a summarizer returning `null` instantly — no timeout at all — produces `dominantBranch: 'inner'`. Not a naming problem: the fact a consumer needs is discarded before the counter is incremented and cannot be recovered downstream.

Two secondary defects from the same review, both reproduced:

- an **empty window** with `minSustainedPasses: 0` emitted a diagnosis (`0 < 0` is false, and `[].every(...)` is vacuously true);
- a pass mixing **3 missing-content with 1 branch failure** diagnosed as starvation, defeating this ticket's own Avoided Trap.

### Dependency added

**Blocked on #16388** — `buildMiniSummary` must emit a typed cause (`timeout-inner` / `timeout-outer` / `no-model` / `empty-output` / `provider-error`) and the sweep must tally causes. This ticket cannot be delivered before it.

### AC changes

**Withdrawn** — the branch-derived timeout verdict. Not reworded: a timeout claim cannot be repaired while its input contract does not carry the fact.

- [ ] ~~`dominantBranch` reports which timeout boundary is binding, ties resolve to `outer`~~ — **withdrawn**; superseded below.

**Replacing it, once #16388 lands:**

- [ ] The binding-timeout verdict derives from **typed causes** (`timeout-inner` / `timeout-outer`), never from branch counters. Falsifier: a window of `no-model` or `empty-output` failures must produce **no** timeout verdict, however starved the loop looks.
- [ ] Tie-safety is preserved on the typed signal — a tie between typed inner and typed outer timeouts still resolves to `outer`, for the original reason (the optimistic reading is the move that flips every item to the other branch).

**Added from the review's negative probes, both live defects:**

- [ ] A pass whose failures are **not** generation failures does not read as starvation — a sweep that correctly skipped un-summarizable rows and hit one unrelated failure must not diagnose. Falsifier: 3 missing-content + 1 branch failure × window → `null`.
- [ ] An invalid or degenerate sustain threshold cannot emit. Falsifier: an empty window, and a single-pass window, must both yield `null` at **any** threshold including `0` and `1`.

### Salvage retained

The pure-producer placement, the `contention` class (a model-dependent canary must not classify as liveness), the recovery-event envelope, the sustained-window policy, and the per-pass evidence shape all survive and are reusable as-is.

### Corrections to this ticket's own text

`dev` carries **six** pure lowercase `*Diagnosis.mjs` producers including `taskOutcomeDiagnosis.mjs`, not five. And `#16377` remains **resolved** — its counters were correct within their stated bound of branch observation, and the crossing happened here, not there.

`[RETROSPECTIVE]` from the review, worth keeping on this ticket: **observability fields must name what was mechanically observed; branch counters become actuator guidance only after independent cause evidence exists.** A field named `failedInner` reads as *"the inner timeout fired"* and means *"the falsy branch ran"* — the name invites the causal upgrade.
