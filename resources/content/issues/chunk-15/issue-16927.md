# Roster names a degraded presence producer — the capability-envelope chip

**The delivered slice of `#16737`'s tier-degradation AC** — split per the one-PR-resolvable rule (the `#16787` precedent, same parent): this leaf carries exactly what its PR ships; the parent keeps the horizon-band vocabulary, wake-route health, and viewer-scoping ACs.

## Context

Operator falsifier, live 2026-08-10 ~23:50 (evidence: `#16737` comment `IC_kwDODSospM8AAAABOLNxVg`): the plane's `who_is_online` surface entered a degradation wave, the producer correctly emitted the `degraded/none` capability envelope (`fleetPresenceStateAdapter.mjs:153-159`), every card's presence band correctly vanished (absence of signal, never a verdict) — and the operator read the unnamed absence as **"no one is online"**, a verdict. The naming half of the AC ("renders from tiers that ANSWERED **and names them**") was undelivered for the all-tiers-failed case: `grep capabilities.presence apps/agentos/` → zero consumers; `loadRoster` destructured `{rows}` and dropped the envelope.

## The Fix (as shipped)

- `FleetCockpit.loadRoster` retains `capabilities` from the assembler DTO and plumbs `capabilities.presence ?? null` onto the grid on every ADMITTED snapshot (generation-fenced; recovery clears on the next poll — the polls already re-read, verified across two live degradation/recovery cycles).
- `FleetGrid` gains the reactive `presenceCapability_` config + a header chip (`fleet-presence-cap`, `role=status`) rendered by an idempotent applier: **degraded → "presence unobservable · <producer's retained reason>"**; `wired` renders nothing (bands speak); `not-wired` renders nothing (an expected-absent axis must not become another permanent line — the `#16924` doctrine); a11y label mirrors the visible words.
- SCSS: one chip class riding existing tokens (idle-amber border — informational, below the wedged alarm register).
