## Why this exists

`ai/scripts/swarm-heartbeat.sh` is a continuous-loop daemon (`while true; sleep $POLL_INTERVAL`). It only runs while an operator manually invokes it and keeps a terminal open. Operator-sleep / system-reboot / terminal-close all kill the daemon. Even with `wakeSafetyGate` untripped, the daemon must be RUNNING for the gate to be consulted at all. The mutual-idle-stall pattern (#10399, #10396) cannot auto-resolve while the daemon isn't running. Empirically demonstrated multiple times in session 2026-05-05.

## Verify-before-assert (load-bearing)

Empirically verified daemon's path assumptions before drafting plist. Findings drove three required keys:

- **`WorkingDirectory` REQUIRED.** Daemon uses 4 RELATIVE paths (`DB_PATH`, `CONCURRENCY_LOCK`, `SWEEP_LOG`, parent dir creation). Without `WorkingDirectory=<repo-root>`, launchd runs script with `cwd=/` and relative paths silently no-op every poll.
- **`EnvironmentVariables.PATH` REQUIRED.** launchd's default PATH excludes Homebrew `gh` (`/opt/homebrew/bin` Apple Silicon, `/usr/local/bin` Intel) and Node version managers. Operator must list every dir containing required tools.
- **`KeepAlive=true` + `ThrottleInterval=10`** matches `while true` intent, prevents tight crash-loop without papering over real bugs.

Plist text marked as TEMPLATE with `[OPERATOR_SUBSTITUTE_*]` placeholders + inline gotcha comments + verify-before-assert notice. Operator runs `plutil -lint` + `launchctl bootstrap` for empirical correctness verification (procedure in `PersistentProcessManagement.md §3`).
