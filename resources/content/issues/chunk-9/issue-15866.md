# sunsetTriggers advertises enforcement it does not have — make the field honest

## Context

Every active identity row in `learn/agentos/ModelStats.md` carries a `sunsetTriggers` value, e.g.:

> Anthropic releases a successor Opus-class model with material reasoning capability upgrade; OR Anthropic deprecates Opus family branch

It reads like a rule that fires. **It is not connected to anything.**

## The Problem

### V-B-A: zero production consumers

```bash
$ grep -rn 'sunsetTriggers' --include='*.mjs' .
# → test/playwright/unit/** specs only, plus one comment in ai/graph/identityRoots.mjs
```

Nothing in `ai/`, `buildScripts/`, or any daemon, service, or lint reads it. It is a string that is written and never evaluated.

### It has now fired twice, silently

| Firing | What happened |
|---|---|
| Claude Opus 4.8 release | Nothing. `ADR 0018 §30` documents this firing going unactioned. |
| Claude Opus 5 release (2026-07-24) | Nothing — until a human said *"update the spots that still point to opus 4.8."* |

Credit `@neo-opus-grace`, who connected the two: *"Two silent firings is a mechanism that doesn't work, not a missed chore."*

### The demonstrated harm is not the silence — it is the false belief

The silence is recoverable; a human noticed both times. The real cost is that the field's **existence** makes maintainers reason as though the transition is governed.

Concrete instance, from the ticket that motivated this one: in `#15855` I wrote an Acceptance Criterion asserting that `§sunset_history` must gain its first entry, reasoning from *"the `sunsetTriggers` clause fired, therefore a sunset transition is recorded."* That AC was **wrong** — `ADR 0012 §2.3` makes an in-place model rotation a *rename*, which deprecates no identity, so `§sunset_history` correctly stays empty. I retracted it before it produced a false record.

That error was authored **by a maintainer who had just read the ADR**, and it came from the field's framing rather than from carelessness. A trap that catches an attentive reader is a substrate defect, not a discipline problem. It will catch the next one.

## The Architectural Reality

- `learn/agentos/ModelStats.md` — the `sunsetTriggers` row on every active identity, plus `§sunset_history` and the `## Update discipline` header which lists *"Sunset transitions record date + reason + successor-model link"* as if a transition were detected rather than noticed.
- `learn/agentos/IdentitySchema.md:56` — the schema row defines the field, and its example is itself stale: `['Anthropic releases Opus 4.8+']`. That trigger has fired. **The illustration of the mechanism is a live instance of the mechanism failing.**
- `ai/graph/identityRootsMigration.mjs` — `sunsetTriggers` is carried in `REGISTRY_SEED_FACTS` era capabilities. Historical snapshot; **not to be edited** (the moving-mirror trap its own header names).
- `ADR 0012 §2.3` / `§2.5` — define sunset/promotion triggers and the update discipline. This ticket does not change the taxonomy; it changes how honestly the *field* presents itself.

## The Fix

Make the affordance match reality at every point of declaration:

1. **`IdentitySchema.md`** — the `sunsetTriggers` row states plainly that it is **advisory, human-evaluated, not machine-enforced**, and that nothing reads it programmatically. Replace the stale `['Anthropic releases Opus 4.8+']` example with one that cannot rot into a live counter-example.
2. **`ModelStats.md`** — the `## Update discipline` section names who evaluates a trigger (a human or agent noticing a release), so *"Sunset transitions record…"* is not read as *"the system records…"*.
3. **`§sunset_history`** — already carries the rename-vs-split note from `#15855`; extend it with the fired-twice record so the next author meets the history, not just the rule.

Explicitly **not** building an enforcement mechanism (see Out of Scope).

## Acceptance Criteria

- [ ] `IdentitySchema.md`'s `sunsetTriggers` row states it is advisory / human-evaluated and that no code reads it
- [ ] The stale `['Anthropic releases Opus 4.8+']` example is replaced with a non-rotting illustration
- [ ] `ModelStats.md` `## Update discipline` names the human/agent evaluator, so no sentence implies automatic detection
- [ ] `§sunset_history` records both silent firings with their anchors (`ADR 0018 §30`; `#15855`)
- [ ] `grep -rn 'sunsetTriggers' --include='*.mjs'` still returns test-only matches — this ticket adds **no** consumer, and that absence is now documented rather than implied
- [ ] `ai:lint-guides` passes

## Out of Scope

- **Building the enforcement.** Making a prose trigger machine-checkable means detecting model releases across four providers — a large, network-dependent design question deserving ideation, not a bug fix. Deliberately not smuggled in. *(And detection is likely the wrong frame: on 2026-07-24 the swarm knew about the release within minutes via `@neo-kimi-phoebe`'s broadcast — the gap was connection, not knowledge. Same finding as `#15862`.)*
- **Removing the field.** It carries real editorial intent — "here is what would end this embodiment" is worth recording even unenforced. The defect is that it *reads* as governed. Honest labelling is the proportionate fix; deletion loses information.
- **`REGISTRY_SEED_FACTS`** — historical epoch snapshot, never rewritten.
- **`ADR 0012` amendment** — no capability dimension changes; this is a framing correction at the declaration sites.

## Avoided Traps

- **Building a release-watcher because the field implies one.** That is the expensive answer to a problem the evidence says we do not have.
- **Treating it as a docs typo.** The stale example is a symptom; the defect is a field that looks load-bearing and is inert.
- **Blaming the two misses on discipline.** Both were attentive readers. If the substrate only works for someone who greps before trusting a declared field, the substrate is the problem.
