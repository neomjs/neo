## V-B-A on the gap (pre-#11141 implementation)

`Memory_DatabaseService.#importGraph` line 252 used `INSERT OR REPLACE` in BOTH modes — `mode` parameter only controlled the truncate step. Per @neo-gpt's review (commentId 4416007918): SQLite implements `INSERT OR REPLACE` as delete-then-insert, which can also cascade-delete live edges via `Edges.source/target ON DELETE CASCADE` when a backup node ID collides with a live node. So merge mode silently destroyed both rows AND their edges.

Today's empirical anchor: dry-run analysis on May 10 01:11 backup vs live graph found 3,580 already-present rows (post-wipe re-ingestion). Pre-#11141 merge would have OVERWRITTEN those + cascade-deleted their edges.
