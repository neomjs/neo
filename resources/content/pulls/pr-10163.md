## Summary

Extends the \`pull-request\` skill with a new §6 **Review Response Protocol** covering the author-side response cycle when a reviewer posts \`Status: Request Changes\` with Required Actions. Adds a structural template (\`.agent/skills/pull-request/assets/review-response-template.md\`) and a reciprocal cross-reference in \`pr-review\` §4 so reviewer-side and author-side tags form one unified taxonomy.

Resolves #10109 (Review Response Protocol addition; part of the ticket's broader PR lifecycle hygiene scope per the 2026-04-20 extension comment and the 2026-04-21 Review Response Protocol extension comment).

## Why

Cross-review pilots this session surfaced a gap the existing skill doesn't cover: after a reviewer posts Required Actions, the author pushes a fix commit but posts no structured response. Reviewer then has to discover commits, diff them, and match-against-own-Required-Actions manually. No per-item acknowledgment. No status for deferred/rejected items. No signal to the Retrospective daemon that a review-negotiation cycle completed.

Empirical artifact: PR #10161 (this session) received \`Status: Request Changes\` from Gemini with one Required Action. I pushed the fix commit \`c0cfb08bf\`, halted without a comment, and flagged the gap to @tobiu. Retroactively posted an Addressed comment dogfooding the proposed pattern. This PR formalizes it.

## Design Decisions

### Per-item status tags mirror \`pr-review\` §4

Three tags — \`[ADDRESSED]\` / \`[DEFERRED]\` / \`[REJECTED_WITH_RATIONALE]\` — parallel the reviewer-side \`[KB_GAP]\` / \`[TOOLING_GAP]\` / \`[RETROSPECTIVE]\` taxonomy. The Retrospective daemon already regex-matches those; extending to author-side is symmetric and consistent.

### Silent-skip is forbidden

Per §6.2, every Required Action MUST receive an explicit tagged status. If the author disagrees with the reviewer, they use \`[REJECTED_WITH_RATIONALE]\` with documented reasoning — NOT silent omission. This preserves the architectural-negotiation thread as a reviewable artifact.

### Authorship-respect rule (from #10109's 2026-04-20 extension)

Post as NEW comment, never edit the reviewer's comment or retroactively edit the PR body. The commit + new comment are the canonical record.

### \"Done\" reframed as per-handoff

The prior \"PR opened = Done\" framing in §5 was accurate for the first handoff but incomplete for the full lifecycle. §5 now carries a Cross-Review Response Cycle paragraph explicitly saying re-review response is a second handoff. No contradiction — just a clarification.

### Commit message convention is unchanged

Standard \`fix(scope): <description> (#TICKET_ID)\`. The commit doesn't need to reference specific Required Action numbers — the Addressed comment carries the SHA↔item mapping. Keeps commit messages short and skill-orthogonal.
