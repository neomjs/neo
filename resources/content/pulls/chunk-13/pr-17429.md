## The census was run by navigation target, not filename

A filename sweep finds one e2e spec (`ThumbDragDevIndex`). A content sweep finds nine. **Neither is the answer.** Four of those nine mention DevIndex in prose while actually driving `/examples/grid/lockedColumns/` — their comments were already stale before this change. Exactly five call `goto('/apps/devindex/…')`, and exactly those five moved. The stale four are corrected here rather than carried.

## The boot mandate was the real blocker, and it is not in the ticket

`AGENTS_STARTUP.md` **Step 1** made `learn/guides/devindex/frontend/Architecture.md` a mandatory read for *every agent, every session*. Deleting it breaks every boot — and reverting Step 1 to `CodebaseOverview.md` regresses the boot quality that guide was introduced to fix.

Its content is engine architecture — Minimal Main Thread, App Worker, VDOM deltas, hierarchical MVC/MVVM — taught through the app. My first instinct was to relocate and de-app it. Checking first showed that was wrong: **both halves already exist as engine-canonical guides**, `fundamentals/WorkerArchitecture.md` (197 lines, covers Main Thread / App Worker / VDom Worker) and `datahandling/StateProviders.md`. The devindex guide was a *duplicate* of documentation this repo already had.

So Step 1 now points at the canonical pair, and no new file was written. Net substrate reduction rather than a relocation — had I not checked, this PR would have added a third copy.

## Coverage is repointed, not dropped

The trap in a removal like this is deleting a test *along with* the app it happened to use as a fixture.

- **`checkPackageContents.spec.mjs`** asserted that a prefix rule survives its tree being renamed, where a path+extension rule goes vacuous. That property belongs to the rule **shape**, not to the DevIndex tree, so it now asserts against `.neo-ai-data/`, which has the identical prefix-plus-carve-out form. The two DevIndex-path-specific cases are dropped; this one is kept because it is the sharpest case in the file.
- **`lintRetryBounds`** kept a true-verdict retry site by moving to `src/manager/DragCoordinator.mjs`, a real registry-listed retry-growth site (verified against `retry-bound-registry.json`, not assumed).
- **`unit-profiling` is removed rather than left empty.** Its only two members were the DevIndex profiling specs, and `neomjs/devindex` already carries both *and* the same barrier-plus-`workers: 1` isolation. A project whose `testMatch` selects nothing does not fail — it reports zero tests and reads as passing.

## The pipeline, and a comment that was already wrong

`dataSyncPipeline.mjs` drives the live hourly job, so it got checked rather than edited blind. Its allowlist and `isGeneratedDataPath` drop the devindex clause. Separately, its `// The four DevIndex stages below` comment described stages that **left in #17391** — there are none below it. Corrected to say why the deferral flag outlived them, since the property it protects is structural rather than DevIndex-specific.

`sitemap.xml` and `llms.txt` are **regenerated**, not hand-edited, so the tree does not ship public URLs pointing at deleted guides.
