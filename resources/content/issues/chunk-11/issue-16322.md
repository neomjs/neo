# Relocate the dockdemo child-app out of the agentos FM app

## Context

Operator directive (2026-08-02): demos do not belong inside the real Fleet Manager app — they belong in `examples/` or their own `apps/` entry. Live surface: `apps/agentos/childapps/dockdemo/index.html?demo=b` (in active use tonight — Iris's `#16309` work and Phoebe's Demo-B perspective/undo leaves target it).

Duplicate sweep (2026-08-02T00:30Z, latest-open + keyword): no existing relocation ticket. `#15614` (decompose DemoBWorkspace into composed host modules) is the *decomposition* sibling, not relocation. Phoebe's `#16315`/`#16316` build specs against the current location — coordinate, don't collide.

## The Problem

FM (`apps/agentos`) is the product surface. A demo child-app living inside it couples demo lifecycle to the product app, ships demo code with the cockpit, and muddies what the flagship IS. The workstation set the precedent the other way: promoted OUT of demo-hood into a standalone app (`#15144`).

## The Architectural Reality

- `apps/agentos/childapps/` holds `dockdemo` + `widget`; DemoB is the cross-window wiring precedent source (the July sibling-lift map lived on it).
- In-flight consumers: `#16315`/`#16316` (L2/L3 of epic `#15252`) add perspective + undo/redo spec witnesses on Demo B — new specs should not deepen location coupling.

## The Fix

Relocate `dockdemo` (and evaluate `widget`) to `examples/` or a standalone `apps/` entry — the destination decision runs through structural-pre-flight at pickup, not here. Migrate references, specs, and links; leave the FM app demo-free. **Execution timing: post-video per operator sequencing** — but claimants of `#16315`/`#16316` should shape new code knowing the move is coming.

- [ ] Destination chosen via structural-pre-flight (sibling precedent: `#15144` workstation promotion) and recorded on this ticket.

## AC-1: destination + shape, decided by structural pre-flight

Intake verdict: **valid-as-written**. Premise re-verified at pickup — `apps/agentos/childapps/dockdemo` is live, 11 files, 6,491 LOC. Post-video gate lifted by operator direction (2026-08-21). Destination prepared and merged: #17504 / PR #17520 made `examples/dashboard/` a pure parent, current siblings `base/`, `crossWindowWitness/`, `dock/`.

Structural pre-flight then found something that changes the shape of this ticket, so recording it before any file moves.

### The app is three modes, and they do not share a destination

`view/Viewport.mjs:61-67` routes by `?demo=`: default → `DemoAWorkspace`, `?demo=b` → `DemoBWorkspace`, `?demo=mission` → `MissionControlWorkspace`. A `git mv` of the directory would relocate all three.

It would also create **six `examples/` → product imports**, measured rather than assumed:

| import | from | mode |
|---|---|---|
| `../../../tour/demoADockChoreography.mjs` | `apps/agentos/tour/` | Demo A |
| `../../../tour/demoBPerspectives.mjs` | `apps/agentos/tour/` | Demo B |
| `../../../tour/fusionFlagship.mjs` | `apps/agentos/tour/` | Mission Control |
| `../../../tour/missionControlWalkthrough.mjs` | `apps/agentos/tour/` | Mission Control |
| `../../../view/fleet/FleetCockpit.mjs` | production FM | Mission Control |
| `../../../view/fleet/cockpitDockDocument.mjs` | production FM | Mission Control |

An `examples/` app importing the product app is a worse inversion than the coupling this ticket exists to remove. Four of the six dissolve by moving the tour scripts; **two do not**, and they are the interesting ones.

### `apps/agentos/tour/` is entirely demo content

All four scripts, each with exactly one production consumer, all of them inside `dockdemo`:

| script | production consumer |
|---|---|
| `demoADockChoreography.mjs` | `DemoAWorkspace` only |
| `demoBPerspectives.mjs` | `DemoBWorkspace` only |
| `fusionFlagship.mjs` | `MissionControlWorkspace` only |
| `missionControlWalkthrough.mjs` | `MissionControlWorkspace` only |

No FM surface consumes any of them. The directory travels with the demos rather than staying behind — which the ticket's AC-3 did not anticipate, since it names only `childapps/`.

### Mission Control is not a dock demo

`MissionControlWorkspace` composes the **production** `FleetCockpit` and its real dock document, and runs FM's own walkthrough over it. It is FM's tour host wearing a demo's clothes. Relocating it to `examples/` would be the dependency inversion above; leaving it in `apps/agentos` and promoting it out of `childapps/` into a first-class FM view removes the inversion entirely and still satisfies AC-3, because the *child-app* is what leaves.

### Decision

| surface | destination | why |
|---|---|---|
| Demo A + `tour/demoADockChoreography.mjs` | `examples/dashboard/choreography/` | zero product dependencies once its tour travels |
| Demo B + `tour/demoBPerspectives.mjs` + `DemoBCrossWindowStage` | `examples/dashboard/crossWindow/` | same; sibling of the existing `crossWindowWitness/` |
| `ClockPane` / `CounterPane` | with whichever demo uses them; duplicated only if both do | leaf panes, no product coupling |
| Mission Control + `fusionFlagship` + `missionControlWalkthrough` | **stays in `apps/agentos`**, promoted `childapps/` → first-class FM view | composes the production cockpit; moving it inverts the dependency |
| `apps/agentos/childapps/widget/` | **stays, justified in place** | not a demo — production FM opens it as its pop-out vessel at `view/Viewport.mjs:148`, `view/Accounts.mjs:99,101`, and `view/fleet/FleetCockpit.mjs:1717,2022`. Sibling precedent: `apps/colors/childapps/widget/` is the same pattern in another app |

Sibling precedent for the destination shape: `dock/`, `crossWindowWitness/` and `base/` already sit directly under `examples/dashboard/` as peer apps with their own `neo-config.json`. Stage 1 fast-path match; no novel directory choice.

### Two follow-ons this surfaces, neither silently absorbed

- **`appThemeFolder: 'agentos'`** in `neo-config.json` is why @neo-fable-clio's addendum found `DemoAWorkspace.scss` / `DemoBWorkspace.scss` unreachable by the loader. The relocated demos need their own theme folder, and those two dead SCSS files go with the move rather than being resurrected.
- **The relocated demos carry hand-rolled host glue** (`DemoBWorkspace` 4,480 LOC, `DemoAWorkspace` 511) into the directory the next consumer copies from. Per my ruling on #17539, both will land with an in-file marker naming `Neo.dashboard.DockWorkspace` as the successor shape, so the interval before that migration does not mint new copies.

### Scope note

AC-3 as written says "`apps/agentos` contains no demo child-apps". Read literally that is satisfied by this decision. Read as "no demo content", it is not — Mission Control stays, deliberately, and is demo-adjacent. I am reading it as written and recording the deviation here rather than quietly widening or narrowing it.
