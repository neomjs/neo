# FM cockpit catch-up view: what happened since you last looked

## Context

T7.26 of Epic #14560 and the S3 Catch-up View in the Fleet cockpit design SSOT (`apps/agentos/design/fleet-manager-cockpit-plan.html`). This is the historical complement to the bounded live `ActivityStream`: an operator returning after an absence needs an invoked, provenance-bearing account of what happened, not a longer firehose tail.

The source contracts are now shipped:

- #14435 / PR #15096: `explore_memory_history` (Memory/session Bird View).
- #15088 / PR #15131: `explore_pull_request_history` (resolved-PR Bird View).
- Both return query-time `notAuthority` envelopes with window, coverage, source-manifest, synthesis availability, and citations. They own synthesis and source completeness; Fleet must not reproduce either.

Live V-B-A on 2026-07-18 confirmed the important two-sided contract: the daily Memory call returned a complete 63-source envelope with synthesis; the daily resolved-PR call returned exhaustive live-GitHub child evidence but withheld synthesis because the local corpus projection was incomplete. The latter is a valid product result, not an error to hide.

## Problem

The cockpit can answer “what is happening now,” but not “what happened since I last looked?” without manual archaeology. A static digest or cockpit-side summary would create a second synthesis authority and erase degraded coverage into plausible prose. The product needs a thin invoked view over the two source-owned runtime tools, with viewer-scoped temporal anchoring and honest absence/degradation.

## Intended solution

1. Add a capability-separated Fleet history read adapter behind the authenticated Fleet ingress. It invokes the two source-owned operations through injected read seams and returns their envelopes without synthesis, ranking, merging, or caching.
2. Add `CatchUpPane` as an auto-hidden secondary rail item. Fleet history is the entry; optional per-agent Memory history is the drill-down. `ActivityStream` and detail views remain drill-through adjacency, never history authority.
3. Keep `lastSeen` as Fleet-service runtime state keyed by the transport-stamped viewer. An explicit **Mark caught up** action advances it through a validated timestamp. Cockpit reload preserves it; Fleet-service restart resets it; no graph or browser-storage write exists.
4. Render `notAuthority`, coverage counts, degraded/unavailable reasons, synthesis availability, source manifests, citations, and honest empty windows. A source may be healthy while another is degraded; do not collapse them into one green/red status.
