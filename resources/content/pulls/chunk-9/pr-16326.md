Resolves #16325

The deference detector missed `unless you'd rather` — a phrase sitting in the gap between two entries it already had. `DEFERENCE_PHRASES` carried `if you'd rather` and `unless you want me`, so the composition read as covered while returning `null`. The human operator caught a live turn-terminal of mine using it to hand back a lane I had already named and V-B-A'd; the hook that exists to catch exactly that stayed silent. One entry, one regression spec, no change to matching mechanics.

Evidence: L4 (pure-function unit coverage; the matcher is deterministic and fully reachable in-sandbox, so the achieved level meets the required level) → L4 required (all close-target ACs are assertions on `matchDeferencePhrase` return values). Residual: none.

## Deltas from ticket

**One correction to my own filed diagnosis, and it is the reason this PR is three lines instead of a refactor.** I opened the investigation believing the cause was the `operatorInLoop` blanket carve in `detectDeferencePhrase` — the phrase landed in live operator dialogue, where matching is bypassed entirely, and that told a satisfying architectural story about the carve being scoped on the wrong axis (context-present rather than decision-ownership). Running the matcher falsified it: the **autonomous** path returns `null` too, so the carve was never reached. The defect is a missing string.

`#16325` records this, and the ticket's Out of Scope keeps the carve untouched deliberately. `#14093` is the precedent — there I proposed a carve-out for this same hook, ran the detector, and found it already discriminated correctly; implementing it *"would have been net-negative."* Same hook, same pull, opposite direction. The measurement says neither widening nor narrowing is needed here.

No scope additions beyond that.
