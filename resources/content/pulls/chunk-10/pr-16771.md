Resolves #16763

Delivers the observation channel only: a Node service can now state its own heap/non-heap split, and the deployment-state bridge publishes it bounded. **No fact is emitted and no threshold moves** — `#16630` keeps the saturation semantics that will consume this.

Evidence: L2 (unit specs + the real collector executed inside the shipped `neo-local-agent-os-mc-server` image under a real 1 GiB cgroup) → L3 required (AC-9: a live reading from the running deployment with its environment stated). Residual: AC-9 [#16763].

Three measurements shaped the design and are recorded because each one changed a decision:

- **The gap over a declared ceiling is `3 × max-semi-space-size`**, which V8 sizes from the memory limit it detects at boot — `+3 / +48 / +96 / +192` MiB at a 512m / 1g / 2g / 4g cgroup, saturating. So `heapSizeLimitBytes` is stored as **observed**, never derived, and no constant enters the substrate. A `+192` figure measured on two developer hosts had briefly shipped as an acceptance criterion on `#16630`; it is corrected there.
- **Container memory moves ~93 MiB inside 45 s** under ordinary maintenance load. That forced the reporter cadence to 10 s and made pairing a bounded question rather than an assumption.
- **This server's dominant allocation lands in old space** — `TextEmbeddingService:1006` returns embeddings straight off parsed JSON as plain `Array<Number>`, ~32 KB per 4096-dim vector, with no `Float32Array` on the live path (@neo-opus-grace verified independently, and the ollama branch has the same shape). So the declared ceiling bounds the space that actually fills.

## Deltas

- **`pairable` is its own field rather than a stricter `status`.** Because the container `stats` sample is stamped with the collection's `observedAt`, staleness and skew are **the same measurement at two thresholds**, not two independent checks — the JSDoc says so rather than implying rigor it does not have. An observation can be fresh enough to describe the service and still too far away to enter a ratio with the container number.
- **Two reasons beyond the ticket's list:** `identity-mismatch` (a record stamped by a different `serviceKey` is refused rather than mis-attributed — the falsifier `incarnationBounded` applies to log slices) and `clock-skew` (a future timestamp reports its own cause, because pairing across disagreeing clocks is the hazard the bound exists to prevent).
- **The reader and reporter each take one injected seam** (`config` / `dir`) defaulting to the use-site read, so specs isolate against a temp directory. The shared `AiConfig` singleton is never mutated — ADR-0019 §4's live-DB-bleed mechanism.
- **A parity-plane placement fix was required and is not in the ticket.** `heapObservation.dir` is a plane member, so relocating profiles must bind it explicitly or the plane is partially moved and fails boot. Found by reading `docker-compose.dev.yml`, not by any test — nothing cross-checks `PLANE_MEMBER_PATHS` against a profile's `x-plane-env`, which is filed separately.

## Test Evidence

- `npm run test-unit -- <the four touched specs> --workers=1` — **115 passed** at `f0e349a085`.
- **Single-instant capture is mutation-convicted.** Converting the collector to `async` with one `await` between source reads reds the guard (`Expected length: 4, Received length: 2` — only pre-await sources had run). A call-count assertion would have passed that mutation, which is why the guard uses a pending microtask.
- **The non-Node scoping guard is mutation-convicted.** Replacing `nodeCommand !== true` with `false` flips exactly the red control (`Expected "unavailable", Received "available"`) and leaves the other eight tests green.
- **AC-8's control is non-vacuous by construction.** Two collections differ only in the heap outcome (`absent` vs `not-node`) with a real `memory-saturation` fact in both, the diagnosis is asserted deep-equal, and a handoff witness proves `diagnose()` is never offered the field at all.
- **Real runtime, not only fixtures.** The collector run inside the shipped image under a 1 GiB cgroup returned `declaredMiB 768 / heapLimitMiB 816 / oldGenUsed 3.64 / newGenUsed 0.39 / usedHeap 4.03 / rss 47.32`, and `oldGen + newGen` reconciles to V8's own `used_heap_size` **exactly** across all 13 spaces — an independent check of the "every space that is not a `new_` space" partition that the mocked specs could not supply.
