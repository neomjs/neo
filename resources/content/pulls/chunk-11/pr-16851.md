## The defect

`ai/configBase.mjs` declares **six** `NEO_OLLAMA_*` leaves. `ai/deploy/docker-compose.yml` passed **one**.

`NEO_OLLAMA_HOST` appeared **zero times** across *every* compose variant in `ai/deploy/`. So `ollama.host` fell back to its leaf default `http://127.0.0.1:11434` — and inside `kb-server`, that address **is `kb-server`**.

**Any containerized plane set to `NEO_EMBEDDING_PROVIDER=ollama` sent every native embed to its own container's localhost and got connection-refused, permanently.** The model service sits on the same compose network as `local-model:11434`, and no configuration path could name it. The operator's chosen chat model, embedding model and timeout were silently ignored too — four more unwired leaves falling back to defaults.

**This is an omission, not a policy**, and the file says so itself: the sibling provider is fully wired (`NEO_OPENAI_COMPATIBLE_HOST`, `_MODEL`, `_EMBEDDING_MODEL`, `_API_KEY`, `_KEEP_ALIVE`), and **`NEO_OLLAMA_KEEP_ALIVE` was already passed** — nobody wires a keep-alive for a provider they intend to exclude. Meanwhile `ai/provider/Ollama.mjs` is a complete provider, `TextEmbeddingService` carries the native embed path, and `providerReadinessHelper` has a whole ollama branch keyed on `role === 'embedding' ? '/api/embed' : '/api/chat'`. **Everything an operator can read says ollama is supported; the deployment layer could not deliver it.**

## How it was found

Configuring **our own** containers to mirror an external plane's ollama topology, for an operator-directed reproduction.

**Corrected after the fact, because the first version of this line overclaimed.** I originally wrote that the mirror was *unbuildable*. It is not: @neo-gpt-emmy brought the composition up by supplying `NEO_OLLAMA_HOST` **out-of-band**, and her working tree carries no Compose edit. The accurate claim is narrower and still the defect:

> **The composition is not expressible through the canonical profile.** Anyone who wants it must independently discover that a required variable is missing and inject it by a route no committed artifact records.

**Field evidence that this cost is real rather than theoretical:** the external plane's own Compose hand-writes `NEO_OLLAMA_HOST=http://local-model:11434` on all three services. Their operators had to re-derive the wiring ours omits — which is precisely the work this PR removes.

## Review notes

**The ticket's original AC was wrong, and implementing it is what proved so.** `#16850` asked for *declared `NEO_OLLAMA_*` leaves ⊆ compose-passed vars*, with the same check required to pass for `NEO_OPENAI_COMPATIBLE_*` as a positive control.

Measured before writing a line of it: **8 of 14** declared `NEO_OPENAI_COMPATIBLE_*` leaves legitimately never reach Compose — `BATCH_EMBEDDING_*`, `CONTENTION_*`, `UNLOAD_RETRY_*`, `REQUIRE_PARALLEL_MODELS`. Most leaves are tunables whose defaults are authoritative and which no deployment needs to override. **The required control would have failed.** Had I written the guard *without* the control, it would have passed vacuously on the single arm being fixed and guarded nothing.

**Replaced with the invariant that is true and that catches this defect:** *a leaf whose default is a loopback address must be overridable through the deployment profile.* Inside a container `127.0.0.1`/`localhost` name the container itself, so such a default is not a sensible fallback — it is pointed at the wrong process on every deployment, with no configuration path able to correct it, failing as a connection refused that reads as a dead dependency rather than an unwired host.

`test/playwright/unit/ai/deploy/LoopbackDefaultReachability.spec.mjs`:

- **Positive controls are real:** `NEO_CHROMA_HOST` and `NEO_OPENAI_COMPATIBLE_HOST` both carry loopback defaults and both already pass, so the rule is demonstrably *satisfiable* rather than merely unviolated.
- **Two non-vacuity controls**, one per silent-failure half — a leaf regex that matches nothing would make the guard pass forever; an env reader returning garbage would make every name look reachable.
- **Exemptions must carry prose reasons.** `NEO_CHROMA_HOST_TEST` (test twin, never deployed) and `HOST` (a bind host, not a dial target — loopback binding inside the container is the intended posture). An unexplained name in an exemption list is where a guard goes to die quietly.
- **Mutation-convicted:** removing `NEO_OLLAMA_HOST` from Compose reddens it, naming the variable.

The ticket body now records the correction rather than the original wording, so the AC set and this diff agree.
